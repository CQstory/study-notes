# 第六章 总线

---

## 6.1 总线的基本概念

### 6.1.1 总线的定义

- **总线**是连接计算机各部件的一组公共信息传输线
- 总线是多个部件共享的传输通道
- 同一时刻只允许一个部件向总线发送信息，但多个部件可以同时接收信息

### 6.1.2 总线的特性

| 特性 | 说明 |
|:-----|:-----|
| 物理特性 | 总线的物理连接方式（线缆、插头、插座等） |
| 功能特性 | 每根线的功能（地址线、数据线、控制线） |
| 电气特性 | 信号的传递方向、电平标准 |
| 时间特性 | 信号的时序关系 |

### 6.1.3 总线的优缺点

| 优点 | 缺点 |
|:-----|:-----|
| 简化系统结构 | 同一时刻只能有一个发送方 |
| 便于系统扩展 | 带宽受限 |
| 降低系统成本 | 总线竞争可能导致延迟 |
| 标准化设计 | 成为系统性能瓶颈 |

## 6.2 总线的分类

### 6.2.1 按功能层次分类

```
┌─────────────────────────────────────────────┐
│              片内总线                         │
│     （芯片内部，连接CPU内部各部件）              │
├─────────────────────────────────────────────┤
│              系统总线                         │
│     （连接CPU、主存、I/O接口）                  │
│     ├── 数据总线                              │
│     ├── 地址总线                              │
│     └── 控制总线                              │
├─────────────────────────────────────────────┤
│              通信总线                         │
│     （连接计算机之间或计算机与外设之间）          │
│     （USB、PCIe、SATA等）                     │
└─────────────────────────────────────────────┘
```

| 总线类型 | 位置 | 功能 | 说明 |
|:---------|:-----|:-----|:-----|
| 片内总线 | CPU芯片内部 | 连接寄存器、ALU等 | 距离短、速度快 |
| 系统总线 | 主板上的系统级总线 | 连接CPU、主存、I/O接口 | 计算机内部通信 |
| 通信总线 | 计算机之间/计算机与外设 | 远程通信 | USB、PCIe、SATA等 |

#### 完整层次总线链（五级，越往外越慢）

```
CPU ←片内总线→ Cache ←Cache-主存总线→ 主存 ←系统总线→ I/O接口 ←I/O总线→ 外设/辅存
                                                              ↕
                                                     通信总线 → 其他计算机
```

| 相邻对 | 总线 | 本机实例 |
|:---|:---|:---|
| CPU 内部各部件 | 片内总线 | 核内 ALU↔寄存器↔L1 |
| CPU ↔ Cache | 片内总线/片内互连 | Infinity Fabric |
| Cache ↔ 主存 | **Cache-主存总线** | IMC + DDR5-5200 通道 |
| 主存/CPU ↔ I/O接口 | **系统总线** | PCIe Root Complex |
| I/O接口 ↔ 外设 | **I/O 总线** | PCIe ×16显卡、NVMe、USB、SATA |
| 计算机 ↔ 计算机 | **通信总线** | 网卡（细节归计网） |

> [!note] 分类澄清
> USB/SATA/PCIe 严格属于 **I/O 总线**（接口↔外设）；**通信总线**专指机间（网卡、以太网）。无论哪一级，都由**数据/地址/控制**三类线组成（见6.2.2）

> [!note] "Cache-主存总线"是抽象层次名，不是标准名
> 它是教材为描述"Cache 与主存之间的数据通路"而设的**层次名**：模型中 **CPU、Cache、主存三者并联**挂在同一组线上（不是串联，详见 [[第三章——存储器层次结构#CPU–Cache–主存的交互通路：并联而非串联|第三章·并联而非串联]]）。
>
> 在实机上它由两段组成：
> - **L3 ↔ IMC**：片内互连（Ring Bus / Mesh / Infinity Fabric），严格说属**片内总线**，不跨芯片
> - **IMC ↔ DIMM**：**DDR 通道**（本机 DDR5-5200），这才是真正跨封装的总线——即第三章所说"教材的 Cache-主存总线在这里出片"
>
> 同一条路径在南北桥时代叫 **FSB（前端总线）**——层次相同、名字不同，详见下方"总线体系的三个时代"。

#### 关键缺口：主存与辅存之间没有直接总线

辅存（磁盘/SSD）**挂在 I/O 总线上**，不在 Cache-主存总线上，所以主存↔辅存必须绕道：

```
辅存 → I/O总线 → I/O接口 → DMA控制器 → 系统总线 → 主存
```

CPU/Cache/主存 在**主存地址空间**内（load/store 直接访问）；辅存及外设是 **I/O 设备**（只能 I/O 指令+中断/DMA）。详见 [[第三章——存储器层次结构#CPU、Cache、主存、辅存四者两两通信判定|第三章·四者通信判定表]]

#### 现代演变：从共享总线到点对点链路

- 严格定义的**总线** = 共享介质、多点挂接、分时使用、需要仲裁（传统 PCI、ISA）
- 现代高速互连（**PCIe、UPI/Infinity Fabric、DDR 通道**）已是**点对点链路**：一条链路只连两个端点，靠交换结构扩展
- 这解释了为何 PCIe 每加一个设备就多一组 lane，而不像老 PCI 那样抢同一组线；408 仍统称"总线"

#### 总线体系的三个时代（共享型 → 南北桥分层 → 现代集成）

6.2.1 的五级链是**抽象层次**；这些层次在硬件史上换过三代实体结构，**层次不变、名字全变**。

**时代一：单一共享系统总线（1975~1990）**

```
CPU ── 系统总线（唯一一条，所有部件分时共享，必须仲裁）
        ├── 主存
        ├── I/O 接口 ── 外设
        └── 其他 CPU（SMP 时抢占同一条线）
```

- 所有部件挂在**同一条**总线上，分时共享，必须仲裁
- 代表：**Unibus**（PDP-11，1970）、**S-100**（Altair，1975）、**Multibus**、IBM **PC Bus**(8位/4.77MHz) → **ISA**(16位/8.33MHz)
- 死因：CPU 与主存速度差拉大到 300~500 倍，慢速 I/O 拖累整条总线

**时代二：分层总线 + 南北桥（1993~2008）**

```
CPU ──FSB 前端总线──┐
                    ▼
              ┌──────────┐──存储器总线(DDR)──→ 内存 DIMM
              │ 北桥 MCH │──AGP / PCIe ×16──→ 显卡
              └────┬─────┘
                   │ Hub Interface / DMI / A-Link / V-Link（桥间总线）
                   ▼
              ┌──────────┐──PCI / PCI-X─────→ 扩展卡
              │ 南桥 ICH │──ISA / LPC───────→ Super I/O（BIOS、串口）
              └────┬─────┘──IDE / SATA / USB→ 硬盘、光驱、外设
                   └──────SMBus / AC'97─────→ 传感器、音频
```

| 桥 | 别名 | 管什么 | 为什么这么分 |
|:---|:-----|:-------|:-------------|
| **北桥** | MCH（Memory Controller Hub）、GMCH（带核显） | CPU 接口（FSB）、**内存控制器**、**AGP/PCIe 显卡** | 全是高速设备，必须离 CPU 近 |
| **南桥** | ICH（I/O Controller Hub）、PCH 前身 | PCI、ISA/LPC、IDE/SATA、USB、BIOS、时钟发生器、Super I/O、音频、SMBus | 全是低速设备，不必占高速通道 |
| **桥间链路** | Intel **Hub Interface**(266MB/s) → **DMI**(1.0=1GB/s、2.0=2GB/s、3.0=3.94GB/s、4.0=7.88GB/s)；AMD **A-Link**；VIA **V-Link**；SiS **MuTIOL** | 北桥 ↔ 南桥 | 早期直接复用一条 PCI 作桥间链路，成瓶颈后才独立 |

> [!note] 为什么叫"南北"
> 主板布局图上北桥在 CPU 附近（上方 = 北），南桥在下方靠近扩展槽与外设接口（下方 = 南）。

**时代三：现代集成化（2003~至今）**

```
CPU 封装（SoC / Chiplet）：核0…核N + L3 + IMC + PCIe RC + 核显 + NPU
        ├── 片内互连（Ring / Mesh / IFOP）：核 ↔ L3 ↔ IMC ↔ PCIe RC
        ├── DDR 通道 ──→ 内存 DIMM
        ├── PCIe lane ──→ 显卡、NVMe SSD、网卡
        ├── DMI / IF ──→ PCH（原南桥）──→ USB / SATA / 音频 / 低速 I/O
        └── UPI / xGMI ──→ 另一颗 CPU（多路服务器）
```

> [!important] 一句话记忆：北桥死了，工作被拆成三份
> - 内存控制器 → **IMC，进 CPU**
> - PCIe 控制器 → **进 CPU**
> - 剩余高速互连职责 → **Infinity Fabric / UPI**
>
> 南桥活下来了，改名 **PCH（Platform Controller Hub）**，通过 **DMI** 挂在 CPU 下面。

**核心对照表：教材抽象层次 × 三个时代的实名**

| 教材抽象层次 | 时代一（单一共享） | 时代二（南北桥） | 时代三（现代集成） |
|:-------------|:-------------------|:-----------------|:-------------------|
| **片内总线** | CPU 内寄存器总线（无专名） | 同左 | **Ring Bus**（Intel 环形）、**Mesh**（Skylake-SP 起）、AMD **IFOP**（Infinity Fabric On-Package） |
| **Cache-主存总线** | 与系统总线合一（无独立名） | **FSB 前端总线**（CPU↔北桥）＋ **BSB 后端总线**（CPU↔卡带式外置 L2，Pentium II/III） | **片内互连（L3↔IMC）＋ DDR 通道（IMC↔DIMM）** |
| **系统总线**（主存/CPU↔I/O 接口） | **系统总线**本体：PC Bus、**ISA**、Unibus、Q-bus、Multibus、S-100 | 桥间：**Hub Interface / DMI / A-Link / V-Link / MuTIOL**；扩展卡：**PCI / PCI-X** | **PCIe**（CPU 直出 lane）＋ **DMI 4.0**（CPU↔PCH） |
| **I/O 总线**（接口↔外设） | ISA 插槽设备 | PCI、**AGP**、**IDE/PATA**、USB 1.x、**LPC**（取代 ISA 连 Super I/O） | PCIe、**SATA**、**NVMe(over PCIe)**、USB 3.x/4、**雷电/USB4** |
| **通信总线**（机间） | RS-232 串口、早期以太网 | 以太网（PCI 网卡） | 以太网（PCIe 网卡/板载）、**InfiniBand**、Wi-Fi |
| **多 CPU 互连** | 共享同一条系统总线（SMP） | 共享 FSB / 专用 SMP 总线 | Intel **QPI → UPI**；AMD **HyperTransport → Infinity Fabric（xGMI/IFIS）** |
| **芯粒互连**（新层次） | — | — | **UCIe**（Chiplet die-to-die）、**CXL**（基于 PCIe 物理层的缓存一致性互连） |

**本机实例（AMD Ryzen 9 8945HX，Zen 4 Dragon Range，无北桥）**

| 教材层次 | 本机实名 |
|:---------|:---------|
| 片内总线 | **Infinity Fabric On-Package (IFOP)** 连 CCX 内各核与 L3 |
| Cache-主存总线 | L3 ↔ 片内互连 ↔ **IMC** ↔ **DDR5-5200 通道**（实际时钟 2600MHz，双沿 → 5200 MT/s，见 [[专题01——周期]]） |
| 系统总线 | **PCIe 4.0 Root Complex**（CPU 直出）；若有 FCH 则通过 **IFIS** 连接 |
| I/O 总线 | PCIe ×16（显卡）、NVMe SSD、USB 3.2/4 |
| 通信总线 | 板载 2.5G 网卡、Wi-Fi 6E |
| 多芯粒互连 | **CCD ↔ IOD** 走 IFOP（Chiplet 架构，非单片） |

> [!warning] Chiplet 带来的再细分
> Zen 4 的 CPU 核在 **CCD**（Core Complex Die），而**内存控制器、PCIe、核显在 IOD**（I/O Die），两者靠 Infinity Fabric 互连。所以"IMC 在 CPU 封装内"还要再细一层：**IMC 在 IOD 上，不在 CCD 上**。

> [!important] 408 只考层次，不考标准名
> 发展史的作用是解释**为什么需要分层**：各部件速度差 300~500 倍（见 [[专题01——周期]]），一条总线无法同时伺候 CPU 和串口。考试只考层次分类（片内/系统/通信）、三组线、并行 vs 串行、带宽计算与仲裁方式，**FSB/DMI/Infinity Fabric 等具体名称不考**。

### 6.2.2 系统总线的组成

系统总线按功能分为三组：

#### 数据总线（Data Bus）

- **功能**：传输数据信息
- **方向**：双向
- **宽度**：决定每次传输的数据位数（如32位、64位）
- **特点**：数据总线宽度决定了系统的数据处理能力

#### 地址总线（Address Bus）

- **功能**：传输地址信息
- **方向**：单向（CPU→存储器/I/O）
- **宽度**：决定可寻址的存储空间大小
- **特点**：n根地址线可寻址 2^n 个存储单元

> [!example] 地址总线与寻址空间
> - 32根地址线 → 可寻址 2^32 = 4GB 空间
> - 64根地址线 → 可寻址 2^64 空间（理论上）

#### 控制总线（Control Bus）

- **功能**：传输控制信号和时序信号
- **方向**：部分单向，部分双向
- **常见信号**：

| 信号 | 方向 | 功能 |
|:-----|:----:|:-----|
| 读信号（RD） | CPU→外 | 通知存储器/I/O执行读操作 |
| 写信号（WR） | CPU→外 | 通知存储器/I/O执行写操作 |
| 存储器请求（MREQ） | CPU→外 | 访问存储器 |
| I/O请求（IORQ） | CPU→外 | 访问I/O设备 |
| 总线请求（BR） | 外→CPU | 申请总线使用权 |
| 总线应答（BG） | CPU→外 | 总线使用权授予 |
| 中断请求（INTR） | 外→CPU | 请求中断 |
| 中断应答（INTA） | CPU→外 | 中断应答 |
| 时钟信号（CLK） | CPU→外 | 同步时序 |

### 6.2.3 按数据传输方式分类

| 类型 | 说明 | 举例 |
|:-----|:-----|:-----|
| 并行总线 | 多位数据同时传输 | ISA、PCI |
| 串行总线 | 数据逐位传输 | USB、SATA、PCIe |

### 6.2.4 按时序方式分类

按时序（定时）方式可分为**四种**。机制、优缺点、握手与等待细节统一在 [[#6.4.2 总线通信方式|6.4.2]] 展开，此处只列分类，不重复：

| 类型 | 本质一句话 |
|:-----|:-----------|
| 同步总线 | 统一时钟，固定节拍 |
| 异步总线 | 无统一时钟，靠请求-应答握手 |
| 半同步总线 | 同步 + WAIT 等待信号 |
| 分离式事务 | 一次事务拆成两个子周期，中间**释放总线**给别人用 |

## 6.3 总线仲裁方式

当多个设备同时请求使用总线时，需要通过**总线仲裁**来决定总线的使用权。

### 6.3.1 集中仲裁

仲裁逻辑集中在一处（如CPU或总线控制器中）。

#### 链式查询（菊花链查询）

```
总线请求 ──→ 总线忙 ──→ BG ──→ 设备1 ──→ 设备2 ──→ 设备3
                        ↑          ↑          ↑
                      离仲裁器最近的设备优先级最高
```

- **工作原理**：总线授权信号（BG）串行通过各设备，离仲裁器最近的设备优先级最高
- **优点**：结构简单，扩展容易，控制线少（3根：BR、BG、BS）
- **缺点**：
  - 优先级固定，离仲裁器远的设备难以获得总线
  - 对电路故障敏感（一个设备故障会影响后续设备）
  - 速度慢（BG信号需要逐级传递）

#### 计数器定时查询

```
总线请求 ──→ 设备地址计数器 ──→ 设备地址线 ──→ 各设备
```

- **工作原理**：总线仲裁器中有一个计数器，计数器值通过设备地址线发送，与设备号匹配的设备获得总线
- **计数方式**：
  - 从0开始计数：优先级与设备号相关（类似链式查询）
  - 从上次停止处开始计数：优先级循环，公平性好
- **优点**：优先级可调，比链式查询灵活
- **缺点**：需要额外的设备地址线（log2(n)根），速度仍受计数影响

#### 独立请求方式

```
设备1 ──BR1──→ ┌─────────┐
设备2 ──BR2──→ │  总线    │──BG1──→ 设备1
设备3 ──BR3──→ │  仲裁器  │──BG2──→ 设备2
               │         │──BG3──→ 设备3
               └─────────┘
```

- **工作原理**：每个设备有独立的总线请求（BR）和总线授权（BG）线
- **优点**：
  - 速度最快（仲裁时间固定）
  - 优先级可以灵活设置
  - 不受设备故障影响
- **缺点**：控制线数量多（2n根），硬件复杂

#### 三种集中仲裁方式对比

| 特征 | 链式查询 | 计数器定时查询 | 独立请求方式 |
|:-----|:--------:|:------------:|:------------:|
| 控制线数量 | 3根 | log2(n)+2根 | 2n根 |
| 速度 | 最慢 | 中等 | 最快 |
| 优先级 | 固定 | 可调 | 灵活 |
| 扩展性 | 好 | 中等 | 差 |
| 硬件复杂度 | 低 | 中 | 高 |
| 故障敏感性 | 高 | 低 | 低 |

> [!important] 考点
> - 链式查询：3根线（BR、BG、BS），优先级固定，离仲裁器近的优先
> - 计数器定时查询：log2(n)+2根线，优先级可调
> - 独立请求：2n根线，速度最快，但硬件复杂

### 6.3.2 分布仲裁

- **原理**：不需要中央仲裁器，每个设备都有自己的仲裁号和仲裁逻辑
- **工作方式**：各设备通过竞争方式获取总线使用权
- **常见方法**：
  - 自举分布式仲裁：各设备将自己的仲裁号发送到总线上，编号最大的设备获得总线
  - 冲突检测分布式仲裁：类似以太网的CSMA/CD
- **优点**：可靠性高，无单点故障
- **缺点**：控制逻辑复杂

## 6.4 总线操作周期

### 6.4.1 总线操作的基本过程

一次总线操作（总线事务）通常包含以下步骤：

```
1. 总线请求（Request）    → 申请总线使用权
2. 总线仲裁（Arbitration）→ 决定总线使用权归属
3. 寻址（Addressing）      → 发送目标地址
4. 数据传输（Transfer）    → 传输数据
5. 结束（Ending）          → 释放总线
```

#### 总线事务的定义与主从模块

**总线事务（Bus Transaction）= 一次完整的总线传输过程**：从主模块申请总线开始，到释放总线结束。它是总线工作的**基本单位**，上面五个阶段构成一个事务。

| 概念 | 关系 |
|:-----|:-----|
| 事务 vs 总线周期 | 一个事务占用**一个或多个**总线周期 |
| 事务 vs 指令 | 一条访存指令至少触发一个读/写事务；间接寻址触发**两个**（取 EA 一次、取数据一次） |

| 角色 | 别名 | 职责 | 举例 |
|:-----|:-----|:-----|:-----|
| **主模块** | Master、主设备 | **发起**事务：申请总线、发地址与命令 | CPU、DMA 控制器、显卡（Bus Master） |
| **从模块** | Slave、从设备 | **响应**事务：识别地址、执行读写、返回应答 | 主存、I/O 接口 |

- 同一部件可以**既是主又是从**：DMA 控制器对总线是主模块，对 CPU 是从属
- 一次事务**有且只有一个主模块**（否则要靠 6.3 的仲裁决定）；从模块可以有多个，靠地址选中

#### 事务的类型

| 类型 | 发起者 | 说明 |
|:-----|:-------|:-----|
| 读事务 / 写事务 | CPU、DMA | 最基本的两类 |
| 中断事务 | I/O 接口 | 送中断类型号（INTR/INTA，见 6.2.2 控制总线） |
| DMA 事务 | DMA 控制器 | 外设↔主存成块交换，**不经过 CPU**，详见 [[第七章——输入输出系统]] |
| **突发事务（Burst）** | CPU、DMA | **一次寻址、连续传多个数据**，省去重复的寻址阶段；Cache 行填充靠它，详见 [[第三章——存储器层次结构]] |
| **一致性事务** | Cache 控制器 | 多核下的监听（Snoop）、无效化、读独占、写回，是 MESI 协议在总线上的体现，详见第三章 Cache 一致性 |

#### 各阶段的时序参数

| 阶段 | 关键时序 | 说明 |
|:-----|:---------|:-----|
| 寻址 | **地址建立时间**、地址保持时间 | 地址必须在时钟沿前稳定足够久，从模块才能可靠锁存 |
| 传数 | **数据建立时间**、数据保持时间 | 同理；不满足就要插入等待状态（见 6.4.2 半同步） |
| 整体 | **事务延迟**、占用总线周期数 | 决定总线吞吐率 |

#### 总线复用（地址/数据线分时复用）

用同一组线**分时**传地址和数据，线数减半：

| 项目 | 不复用 | 复用（如 PCI 的 AD[31:0]） |
|:-----|:-------|:---------------------------|
| 线数 | 地址线、数据线分开 | 共用一组 AD 线 |
| 额外信号 | — | **ALE**（地址锁存使能）：地址有效时打一拍，从模块锁存 |
| 时序代价 | 地址与数据阶段可重叠 | 地址先独占一拍，**事务至少多 1 拍** |
| 适用 | 高速总线 | 引脚/线数受限的场合 |

> [!warning] 与"DRAM 引脚复用"不是一回事
> | 对比 | **总线复用** | **DRAM 引脚复用** |
> |:-----|:-----------|:-----------------|
> | 层级 | 总线级（主模块↔从模块） | 芯片级（引脚↔存储阵列） |
> | 复用什么 | **地址线与数据线**共用一组 | **行地址与列地址**共用一组 |
> | 锁存信号 | ALE | RAS/CAS（低电平有效） |
> | 详见 | 本节 | [[第三章——存储器层次结构#3.2.2 DRAM刷新与引脚复用]] |

> [!important] 事务率 ≠ 带宽
> 带宽 = **事务率 × 每事务传输的字节数**。所以提高带宽只有两条路：
> ① 加宽数据总线（每事务多传字节）；② 提高事务率（缩短事务、用突发把多次寻址摊薄）。
> 这也解释了突发传输为何对 Cache 行填充关键：64B 的行若逐字寻址要 8 个事务，用突发只需 1 个。

#### 总线事务的错误处理

| 机制 | 作用 |
|:-----|:-----|
| 超时（Timeout） | 从模块长时间不应答 → 主模块放弃并重试，避免总线死锁 |
| 重试（Retry） | 从模块忙时回 Retry 信号，主模块稍后重新申请 |
| 奇偶校验 / ECC | 检测（并纠正）传输中的数据错误 |

### 6.4.2 总线通信方式

#### 同步通信

- 使用统一的时钟信号，所有操作在固定时钟周期内完成
- **优点**：控制简单，速度快
- **缺点**：时钟频率受最长传输路径限制，灵活性差

#### 异步通信

- 使用握手信号（请求/应答）进行通信
- **三种握手方式**：

| 握手方式 | 说明 |
|:---------|:-----|
| 不互锁 | 主方发出请求后不等应答，直接执行 |
| 半互锁 | 主方发出请求后等待从方应答 |
| 全互锁 | 主方和从方互相等待确认 |

- **优点**：灵活，不受时钟限制
- **缺点**：控制复杂，速度慢

#### 半同步通信

- 在同步总线基础上增加一根 **WAIT（等待）信号线**
- 从模块来不及响应时拉高 WAIT，主模块插入**等待状态 Tw**，直到 WAIT 撤销
- **优点**：兼顾速度（多数事务仍按固定节拍）与灵活性（慢设备不至于被淘汰）
- **缺点**：等待状态个数不确定，最长事务时间受最慢设备制约

> [!example] 等待状态对带宽的影响
> 某同步总线时钟 100MHz（10ns/拍），基本总线周期 4 拍，数据宽度 32 位（4B）：
> - 无等待：4B / 40ns = **100MB/s**
> - 插入 3 个 Tw：4B / ((4+3) × 10ns) = 4B / 70ns ≈ **57MB/s**
>
> 同一根总线，慢设备一插等待，带宽直接掉 43%。

#### 分离式事务（Split Transaction）

把一个总线周期**拆成两个子周期**，中间**释放总线**给其他模块使用：

| 阶段 | 谁占用总线 | 做什么 |
|:-----|:-----------|:-------|
| **子周期 1** | 主模块 | 申请总线 → 发送**地址 + 命令** → **立即释放总线**（不等数据） |
| 中间间隙 | **其他模块** | 从模块在内部准备数据，这段时间总线被别人使用 |
| **子周期 2** | **从模块**（身份反转为主模块） | 准备就绪后**重新申请总线** → 发送**数据 + 原地址** → 释放总线 |

**特点**：

- 各模块**都有权申请总线**；从模块在子周期 2 里就是主模块
- 采用**同步方式**通信，但**不互锁**——主模块发完地址就撒手，不占着总线空等
- **优点**：总线利用率**大幅提高**（消除了"发完地址干等数据"的空闲期）
- **缺点**：控制复杂；地址要在子周期 2 重发一次，额外开销

> [!important] 四种定时方式对比
> | 方式 | 统一时钟 | WAIT 信号 | 中途释放总线 | 总线利用率 | 控制复杂度 |
> |:-----|:----:|:----:|:----:|:----:|:----:|
> | 同步 | ✅ | ❌ | ❌ | 低 | 最低 |
> | 异步 | ❌ | — | ❌ | 中 | 中 |
> | 半同步 | ✅ | ✅ | ❌ | 低~中 | 低 |
> | **分离式** | ✅ | ❌ | ✅ | **最高** | 最高 |

### 6.4.3 总线带宽

$$总线带宽 = \frac{数据宽度}{总线周期}$$

> [!example] 总线带宽计算
> 某总线时钟频率为 200MHz，总线宽度为 32位
> - 总线周期 = 1/200MHz = 5ns
> - 每个周期传输 32位 = 4字节
> - 总线带宽 = 4B / 5ns = 4B × 200 × 10^6 = 800MB/s

> [!example] 更复杂的带宽计算
> 某同步总线时钟频率为 100MHz，宽度为 32位
> - 每个总线周期（5个时钟周期）完成一次传输
> - 实际传输速率 = 32位 / (5 × 10ns) = 4B / 50ns = 80MB/s

#### ISA 的同名歧义：总线 ISA ≠ 指令集 ISA

408 里 **ISA 有两个完全不同的含义**，选择题常在此设坑：

| 缩写 | 全称 | 含义 | 出现章节 |
|:-----|:-----|:-----|:---------|
| ISA | **Industry Standard Architecture** | 工业标准架构，IBM PC/AT 的 **16 位并行总线标准**（8.33MHz、16MB/s） | 本章 6.5 |
| ISA | **Instruction Set Architecture** | **指令集体系结构**，软硬件之间的界面 | 第四章 4.0 |

指令集 ISA 的完整说明（七大类规定内容、透明性辨析、控制信号归属）见 [[第四章——指令系统#4.0 ISA 概述|第四章 4.0 ISA 概述]]。

> [!warning] 判读方法
> 看上下文：谈**带宽、频率、插槽、并行/串行** → 总线 ISA；谈**指令格式、寻址方式、程序员可见性** → 指令集 ISA。

> [!warning] PCIe 的三个易错点
> 1. **×16 不是位宽，是 lane（通道）数**。每 lane = 1 对差分串行线，且**全双工**（收、发各一对），所以 ×16 共 64 根线。
> 2. **带宽还要乘编码效率**：
>    - 每 lane 单向带宽 = 传输速率(GT/s) × 编码效率 ÷ 8（字节）
>    - Gen1/Gen2 用 **8b/10b** 编码 → 效率 80%（2.5GT/s → 250MB/s）
>    - Gen3 起用 **128b/130b** → 效率 ≈98.5%（8GT/s → 985MB/s）
>    - Gen3 ×16 单向 = 985MB/s × 16 ≈ **15.75GB/s**
> 3. **并行转串行的根本原因**：并行总线在高频下会产生**时钟偏斜**（各线到达时刻不一致）与线间串扰，频率上不去；串行靠嵌入式时钟 + 差分信号反而能跑更高。

#### 其他易混辨析

| 易错 | 正解 |
|:-----|:-----|
| AGP 是串行 | AGP 是**并行、显卡专用**；PCIe 才是串行通用 |
| USB/SATA/PCIe 是通信总线 | 它们是 **I/O 总线**（接口↔外设）；通信总线专指机间（网卡/以太网） |
| SCSI 已彻底淘汰 | 并行 SCSI 淘汰了，后继 **SAS** 仍在企业存储大量使用 |
| 总线标准 = 总线分类 | 标准是**具体产品规范**，分类是**抽象维度**（见 [[#6.2.3 按数据传输方式分类]] 的并行/串行） |

### 6.5.2 总线标准的发展趋势

- 从并行总线向串行总线发展（PCIe取代PCI）
- 传输速率不断提高
- 支持热插拔和即插即用
- 向点对点通信发展（取代共享总线）
- 铜互连向**光互连**发展（硅光、CPO 共封装光学）
- **协议融合**：一根线跑多种协议（USB4 = PCIe + DisplayPort + USB；雷电同理）

## 6.6 考点总结

### 高频考点

1. **总线的分类**：片内总线、系统总线（数据/地址/控制总线）、通信总线
2. **总线仲裁方式**：链式查询、计数器定时查询、独立请求方式的对比
3. **总线带宽计算**：带宽 = 数据宽度 / 总线周期
4. **集中仲裁 vs 分布仲裁**：特点对比
5. **总线定时四种方式**：同步、异步（不互锁/半互锁/全互锁三种握手）、半同步（WAIT 信号 + 等待状态 Tw）、**分离式事务**（两子周期、中途释放总线、从模块身份反转为主模块）
6. **总线事务**：主模块（Master）/从模块（Slave）、事务类型（读写/中断/DMA/突发/一致性）、**总线复用**（AD 线 + ALE）与 DRAM 引脚复用的区别、**事务率 ≠ 带宽**

### 易错点

- 地址总线是单向的（CPU→存储器/I/O），数据总线是双向的
- 链式查询中离仲裁器最近的设备优先级最高
- 控制总线中有些信号是单向的，有些是双向的
- 总线带宽计算时注意单位统一
- 独立请求方式需要2n根控制线（n为设备数）

### 常用公式速查

| 公式 | 说明 |
|:-----|:-----|
| 总线带宽 = 数据宽度 / 总线周期 | 带宽计算 |
| 总线周期 = 1 / 总线频率 | 周期计算 |
| 链式查询控制线 = 3根 | BR、BG、BS |
| 独立请求控制线 = 2n根 | n个设备 |
| 计数器定时查询控制线 = log2(n) + 2根 | 设备地址线+BR+BS |
