# 第五章 中央处理器

---

## 5.1 CPU的功能和基本结构

### 5.1.1 CPU的基本功能

CPU（中央处理器）是计算机的核心部件，主要功能包括：

| 功能 | 说明 |
|:-----|:-----|
| 指令控制 | 取指令、分析指令、执行指令，控制程序执行顺序 |
| 操作控制 | 产生各种操作信号，控制各部件完成指令规定的操作 |
| 时间控制 | 对各种操作进行定时，控制操作执行的时间顺序 |
| 数据加工 | 对数据进行算术运算和逻辑运算 |

### 5.1.2 CPU的基本结构

CPU由**运算器**和**控制器**两大部分组成。

#### 运算器

```
┌─────────────────────────────────────────────┐
│  ALU（算术逻辑单元）                          │
│  ├── 算术运算：加、减、乘、除                  │
│  └── 逻辑运算：与、或、非、异或               │
│                                              │
│  通用寄存器组（R0~Rn）                        │
│  ├── 暂存操作数                               │
│  └── 保存运算结果                             │
│                                              │
│  累加寄存器（ACC）                            │
│  ├── 存放ALU运算结果                          │
│  └── 作为ALU的一个输入                        │
│                                              │
│  程序状态字寄存器（PSW）                       │
│  ├── 存放运算结果的状态标志                    │
│  └── OF/SF/ZF/CF等标志位                     │
│                                              │
│  暂存寄存器                                   │
│  └── 暂存从主存取来的数据                      │
│                                              │
│  移位器                                       │
│  └── 实现移位操作                             │
└─────────────────────────────────────────────┘
```

#### 控制器

```
┌─────────────────────────────────────────────┐
│  PC（程序计数器）                              │
│  └── 存放下一条要执行的指令地址                 │
│                                              │
│  IR（指令寄存器）                              │
│  └── 存放当前正在执行的指令                     │
│                                              │
│  指令译码器（ID）                              │
│  └── 对IR中的指令进行译码                      │
│                                              │
│  MAR（存储器地址寄存器）                       │
│  └── 存放要访问的主存单元地址                   │
│                                              │
│  MDR（存储器数据寄存器）                       │
│  └── 存放从主存读出或要写入主存的数据            │
│                                              │
│  时序系统                                     │
│  └── 产生各种时序信号                          │
│                                              │
│  微操作信号发生器                              │
│  └── 根据指令产生各种控制信号                   │
└─────────────────────────────────────────────┘
```

### 5.1.3 CPU中主要寄存器

| 寄存器 | 功能 | 用户可见性 |
|:-------|:-----|:----------:|
| PC（程序计数器） | 存放下一条指令地址 | 不可见（部分架构可见） |
| IR（指令寄存器） | 存放当前指令 | 不可见 |
| MAR（存储器地址寄存器） | 存放要访问的存储器地址 | 不可见 |
| MDR（存储器数据寄存器） | 存放要读/写的数据 | 不可见 |
| 通用寄存器（GR） | 存放操作数和结果 | 可见 |
| PSW（程序状态字） | 存放状态标志 | 部分可见 |

> [!important] 考点
> - PC、IR、MAR、MDR对用户是透明的（不可见的）
> - 通用寄存器和PSW对用户是可见的
> - PC自动加1指向下一条指令，遇到转移指令时修改PC

## 5.2 指令周期与节拍时序

### 5.2.1 时序层级（四级）

| 层级 | 名称 | 含义 |
|:----:|:-----|:-----|
| 1 | 指令周期 | 取出并执行一条指令的全部时间，各条指令长短不一 |
| 2 | 机器周期（CPU周期） | 通常以一次访存时间为基准 |
| 3 | 节拍（T周期） | 机器周期的细分，每拍完成一个或几个微操作，是时序基本单位 |
| 4 | 时钟脉冲（主频） | CPU最小时间单位，一拍含若干个时钟周期 |

指令周期的构成：

```
指令周期 = 取指周期（必有） + 间址周期（间接寻址才有）
         + 执行周期（必有） + 中断周期（有中断才有）
```

**关键约定：每个访存动作占一个机器周期，固定切为 T0~T3 四拍**（送地址→译码→送数据→取回数据）。

### 5.2.2 各周期节拍级微操作序列

#### 取指周期（把指令从主存取进CPU）

| 节拍 | 微操作 | 说明 |
|:----:|:-----|:-----|
| T0 | `PC → MAR`，`1 → R`（发读命令） | 指令地址送MAR，通知主存读 |
| T1 | 主存地址译码；`(PC)+1 → PC`（并行） | PC自增是CPU内部操作，不占额外节拍 |
| T2 | `M(MAR) → MDR` | 指令经数据总线进MDR |
| T3 | `MDR → IR`，指令译码 | 指令入IR，译码得操作码与操作数信息 |

#### 间址周期（仅间接寻址，取真正的有效地址）

| 节拍 | 微操作 |
|:----:|:-----|
| T0 | `Ad(IR) → MAR`，发读命令 |
| T1 | 主存地址译码 |
| T2 | `M(MAR) → MDR`（读出真正的操作数地址） |
| T3 | `Ad(MDR) → MAR` |

#### 执行周期（因指令而异）

**加法指令 `ADD (X)`（直接寻址）**

| 节拍 | 微操作 |
|:----:|:-----|
| T0 | `Ad(IR) → MAR`，发读命令 |
| T1 | 主存地址译码 |
| T2 | `M(MAR) → MDR` |
| T3 | `ACC ← (ACC) + (MDR)`，更新PSW |

**存数指令 `STA (X)`（写主存）**

| 节拍 | 微操作 |
|:----:|:-----|
| T0 | `ACC → MDR` |
| T1 | `Ad(IR) → MAR`，发写命令 |
| T2 | 主存地址译码 |
| T3 | `MDR → M(MAR)` |

#### 中断周期（保存断点、转向中断服务程序）

| 节拍 | 微操作 |
|:----:|:-----|
| T0 | `SP → MAR`，发写命令 |
| T1 | `PC → MDR`，写主存；`SP-1`；中断向量 → `PC` |

> [!important] 考点
> - 访存固定模式：**MAR送地址→译码→MDR收数据→送目标寄存器**，一次访存 = 一个机器周期 = 4拍
> - **PC+1 与访存并行**，不占额外节拍（按字节编址时加的是指令字长，不一定是1）
> - 执行周期节拍数随指令而异：寄存器型1拍、访存型4拍、写主存4~5拍；寄存器操作指令不访存，最快
> - 同一节拍内可并存多个微操作，前提是资源不冲突（不打开两个三态门、同一寄存器不同时作源和目的）

### 5.2.3 微命令与微操作（因与果）

| 概念 | 本质 | 存在形式 | 举例 |
|:-----|:-----|:-----|:-----|
| **微命令** | 控制器发出的电平控制信号（因） | 微指令操作控制字段中置1的位 | `PCout`、`MARin` |
| **微操作** | 部件在微命令控制下完成的动作（果） | 用 `A → B` 记法，一拍内的最小动作 | `PC → MAR` |

层级链：

```
机器指令（如 ADD）
   │ 对应
微程序（存于控制存储器CM）
   │ 由若干条组成，每拍取一条执行一条
微指令 ──操作控制字段──→ 若干微命令（置1有效）→ 驱动微操作并行完成
      └──顺序控制字段──→ 下一条微指令地址
```

> [!note] 编码方式注意（详见5.3.2）
> "某位置1就生效"只在**直接编码**下成立；字段直接编码需一组位译码，字段间接编码还要由另一字段决定含义。
> 另外：**微指令 ≠ 机器指令**，一条机器指令对应一段微程序。

### 5.2.4 总线传输控制：三态门与锁存

总线数据传输靠**三态门（输出闸门）+ 门控寄存器（装载端）**实现：

| 控制端 | 对应微命令 | 控制方式 |
|:-----|:-----|:-----|
| 输出端（接三态门） | `PCout` 类 | **电平控制**：使能=1立即导通，=0高阻断开 |
| 输入端（装载端） | `MARin` 类 | **时钟边沿触发**：信号有效后等时钟沿才写入 |

三态门三种状态：使能+输入0→输出0；使能+输入1→输出1；**禁止→高阻态**（输出端等效断开，不驱动总线）。高阻态是总线能被多部件共享的根本原因：**一个节拍内只能有一个三态门使能**。

锁存与关闭使能是两件独立的事：

- **锁存**：节拍内时钟上升沿，目的寄存器把总线数据复制进内部保存，此后内容与总线无关（再变总线也不受影响）
- **关闭使能**：不是任何一条微指令——节拍切换时下一条微指令没再置1的位自动为0，三态门自然回高阻，**"置1才生效、不置即关闭"**

时钟沿须安排在节拍末尾附近，给三态门使能后的总线留出稳定时间（建立时间）。

### 5.2.5 完整示例：`ADD R1, R2` 全过程微操作（共7拍）

以微程序控制器为例，每拍开始先从CM取一条微指令装入μIR，其操作控制字段置1的位即本拍微命令：

| 节拍 | 微命令（置1） | 微操作 | 部件行为 |
|:----:|:-----|:-----|:-----|
| T0 | `PCout`、`MARin`、`1→R` | `PC→MAR` | PC三态门导通，时钟沿锁存进MAR，读命令发主存 |
| T1 | `PCout`、`加1`、`PCin` | `(PC)+1→PC` | 加法器自增打回；主存并行译码 |
| T2 | `MDRin` | `M(MAR)→MDR` | 指令经数据总线锁存进MDR |
| T3 | `MDRout`、`IRin` | `MDR→IR` | 指令入IR；ID译码得操作码和寄存器号，CU定位微程序入口 |
| T4 | `R1out`、`ALU_Ain`、`R2out`、`ALU_Bin` | `R1→ALU_A`，`R2→ALU_B` | 寄存器堆双读口按编号并行送出（**这就是读寄存器**） |
| T5 | `ALU加`、`PSW写` | `(ALU_A)+(ALU_B)→结果` | ALU运算，同步更新标志位 |
| T6 | `ALUout`、`R1in` | `结果→R1` | 结果经内部总线写回寄存器堆写口 |

全序列速览：

```
T0: PC→MAR，1→R
T1: (PC)+1→PC（主存并行译码）
T2: M(MAR)→MDR
T3: MDR→IR（译码）
T4: R1→ALU_A，R2→ALU_B   ← 读寄存器：一拍、两条微操作、双读口并行、不碰主存
T5: (ALU_A)+(ALU_B)→结果，更新PSW
T6: 结果→R1
```

> [!important] 结论与对比
> - 读寄存器只需**一拍、两条微操作**，全程走CPU内部总线：寄存器堆按编号从读口输出，和主存"按地址读"同理但快几个数量级
> - 若操作数在主存，执行周期固定多4拍（MAR→译码→MDR→目标）；有Cache时CPU动作不变，命中与否由Cache控制器幕后处理（对CPU透明）
> - 寄存器间传送、算术运算、访存、控制类（如PC自增）都是微操作，判断标准：一拍内、微命令直接控制的最小动作

> [!tip] 延伸：十种数据寻址方式的节拍级对比
> 本节的"7 拍"是**寄存器型指令**的细拆口径（5.2.2 考点则用"寄存器型 1 拍"的并拍口径）。把**十种数据寻址方式**全部按同一节拍模型展开——MAR 数据来源差异、间址周期 12 拍全流程、进出栈微操作、拍数速算公式——见 [[专题02——十种数据寻址方式的节拍级微操作对比|专题 02：十种数据寻址方式的节拍级微操作对比]]，其节拍约定即以本节 5.2.2 的模型为准。

## 5.3 控制器的工作方式

### 5.3.1 硬布线控制器（组合逻辑控制器）

- **原理**：根据指令操作码、时序信号、状态反馈，通过**组合逻辑电路**直接产生控制信号
- **设计方法**：列出所有指令的微操作序列，用布尔逻辑表达式综合，用门电路实现

**特点**：

| 优点 | 缺点 |
|:-----|:-----|
| 速度快 | 设计复杂、繁琐 |
| 不需要控制存储器 | 不易修改和扩展 |
| 适合RISC | 灵活性差 |

### 5.3.2 微程序控制器

- **原理**：将每条机器指令编写成一个**微程序**，存放在**控制存储器（CM）**中，执行时逐条取出微指令产生控制信号
- **基本概念**：

| 概念 | 定义 |
|:-----|:-----|
| 微命令 | 控制部件产生的最基本控制信号 |
| 微操作 | 微命令控制下的基本操作 |
| 微指令 | 若干微命令的集合，包含操作控制字段和顺序控制字段 |
| 微程序 | 若干微指令的有序集合，对应一条机器指令 |
| 控制存储器（CM） | 存放全部微程序的ROM |

#### 微指令格式

```
┌──────────────────────┬──────────────────────┐
│  操作控制字段          │  顺序控制字段          │
│  （产生微命令）         │  （下地址/判别逻辑）    │
└──────────────────────┴──────────────────────┘
```

| 编码方式 | 说明 | 优缺点 |
|:---------|:-----|:-------|
| 直接编码 | 每一位对应一个微命令 | 直观，但微指令字太长 |
| 字段直接编码 | 分组编码，每组互斥 | 缩短字长，需译码 |
| 字段间接编码 | 一个字段的含义由另一个字段决定 | 进一步缩短，但更复杂 |

### 5.3.3 硬布线控制器 vs 微程序控制器对比

| 特征 | 硬布线控制器 | 微程序控制器 |
|:-----|:-----------:|:-----------:|
| 实现方式 | 组合逻辑电路 | 控制存储器+微指令寄存器 |
| 速度 | 快 | 较慢 |
| 设计复杂度 | 高 | 低 |
| 灵活性/可扩展性 | 差 | 好 |
| 规整性 | 不规整 | 规整 |
| 适用场景 | RISC | CISC |
| 修改指令 | 需重新设计电路 | 只需修改CM内容 |

> [!important] 考点
> - 硬布线控制器速度快但不易修改，适合RISC
> - 微程序控制器灵活但速度慢，适合CISC
> - 微程序存放在控制存储器（CM）中，是ROM

## 5.4 指令流水线

### 5.4.1 流水线的基本概念

流水线技术将指令执行过程分为多个阶段，每个阶段由不同的部件并行处理不同的指令。

#### 五段流水线

```
指令1:  IF → ID → EX → MEM → WB
指令2:       IF → ID → EX → MEM → WB
指令3:            IF → ID → EX → MEM → WB
指令4:                 IF → ID → EX → MEM → WB
指令5:                      IF → ID → EX → MEM → WB
```

| 阶段 | 名称 | 功能 |
|:----:|:-----|:-----|
| IF | 取指令（Instruction Fetch） | 从存储器取指令 |
| ID | 译码/读寄存器（Instruction Decode） | 译码并读取操作数 |
| EX | 执行（Execute） | ALU运算 |
| MEM | 访存（Memory Access） | 读写存储器数据 |
| WB | 写回（Write Back） | 将结果写回寄存器 |

### 5.4.2 流水线性能计算

#### 吞吐率（Throughput，TP）

$$TP = \frac{n}{T_{total}}$$

- n：指令条数
- T_total：执行n条指令的总时间

**理想情况下（无冲突）**：

$$TP = \frac{1}{\Delta t}$$

- $\Delta t$：最长流水段的时间

#### 加速比（Speedup，S）

$$S = \frac{T_{顺序}}{T_{流水线}}$$

**理想情况下**：

$$S = \frac{n \times k \times \Delta t}{(k + n - 1) \times \Delta t} = \frac{n \times k}{k + n - 1}$$

- k：流水线段数

当 n → ∞ 时，S → k

#### 效率（Efficiency，E）

$$E = \frac{n \times k \times \Delta t}{k \times (k + n - 1) \times \Delta t} = \frac{n}{k + n - 1}$$

当 n → ∞ 时，E → 1

> [!example] 流水线性能计算示例
> 设一条指令的执行过程分为取指（200ns）、分析（100ns）、执行（200ns）三个阶段
> 每个阶段的时间为该阶段所需时间
>
> **问题1**：流水线时钟周期应取多少？
> - $\Delta t = \max(200, 100, 200) = 200$ns
>
> **问题2**：100条指令在流水线方式下执行需要多长时间？
> - $T_{流水线} = (3 + 100 - 1) \times 200 = 102 \times 200 = 20400$ns = 20.4μs
>
> **问题3**：顺序执行需要多长时间？
> - $T_{顺序} = 100 \times (200 + 100 + 200) = 100 \times 500 = 50000$ns = 50μs
>
> **问题4**：加速比和效率？
> - 加速比 = 50000 / 20400 ≈ 2.45
> - 效率 = 100 × 3 / (3 + 100 - 1) = 300 / 102 ≈ 2.94（这个不对）
> - 效率 = 100 × 3 × 200 / (3 × 102 × 200) = 100/102 ≈ 0.98

> [!example] 另一个流水线计算示例
> 设5段流水线，每段耗时100ns，执行10条指令
>
> - 总时间 = (5 + 10 - 1) × 100 = 14 × 100 = 1400ns
> - 顺序执行时间 = 10 × 5 × 100 = 5000ns
> - 加速比 = 5000 / 1400 ≈ 3.57
> - 吞吐率 = 10 / 1400ns = 1/140ns ≈ 7.14 × 10^6 条/秒
> - 效率 = 10 × 5 × 100 / (5 × 14 × 100) = 10/14 ≈ 0.714 = 71.4%

### 5.4.3 流水线冲突（Hazards）

#### 结构冲突（Structural Hazard）

- **原因**：不同指令在同一时刻争用同一硬件资源
- **解决方法**：
  - 指令和数据分开存储（哈佛结构）
  - 停顿（插入气泡）
  - 资源重复配置（如多个ALU）

#### 数据冲突（Data Hazard）

- **原因**：后续指令需要用到前面指令的结果，但结果尚未产生
- **三种类型**：

| 类型 | 说明 | 示例 |
|:-----|:-----|:-----|
| RAW（写后读） | 后续指令读前面指令写的值 | `ADD R1, R2; SUB R3, R1` |
| WAR（读后写） | 前面指令写后面指令读的值 | 较少出现 |
| WAW（写后写） | 两条指令写同一寄存器 | 较少出现 |

- **解决方法**：

**方法1：数据旁路/转发（Forwarding/Bypassing）**

- 将ALU的结果直接转发给后续指令，无需等待写回
- 可以减少大部分数据冲突的停顿

```
ADD R1, R2, R3    → EX段产生结果
SUB R4, R1, R5    → 通过转发直接使用EX段结果，无需等待WB
```

**方法2：插入气泡（Stall）**

- 当无法通过转发解决时，暂停后续指令
- 在流水线中插入"气泡"（NOP）

**方法3：编译器调度**

- 编译器通过重新排列指令顺序来避免冲突

#### 控制冲突（Control Hazard）

- **原因**：转移指令（分支）需要确定是否跳转，但判断结果尚未产生
- **解决方法**：

| 方法 | 说明 | 代价 |
|:-----|:-----|:-----|
| 分支预测 | 预测分支方向，猜对则继续执行 | 预测错误需要清空流水线 |
| 延迟分支 | 在分支指令后安排延迟槽 | 需要编译器支持 |
| 静态预测 | 总是预测不跳转（或总是跳转） | 简单但准确率低 |
| 动态预测 | 根据历史记录预测分支方向 | 准确率高，硬件复杂 |

> [!important] 分支预测
> - **静态预测**：总是预测不跳转（简单）
> - **动态预测**：使用分支历史表（BHT）记录分支行为
> - 2位预测器：只有连续两次预测错误才改变预测方向
> - 预测准确率越高，流水线性能越好

### 5.4.4 流水线冲突综合示例

> [!example] 数据冲突与转发
> 考虑以下指令序列在5段流水线中的执行：
> ```
> I1: ADD R1, R2, R3    (R1 = R2 + R3)
> I2: SUB R4, R1, R5    (R4 = R1 - R5)  ← RAW冲突
> I3: AND R6, R1, R7    (R6 = R1 & R7)  ← RAW冲突
> I4: OR  R8, R1, R9    (R8 = R1 | R9)  ← RAW冲突
> ```
>
> - I2需要I1的R1结果：I1在EX段结束时产生结果，I2在ID段需要R1
>   → I2需要停顿1个周期（或通过转发解决）
> - 通过**转发**：I1的EX段结果直接转发给I2的EX段，**无需停顿**
> - I3和I4同理，通过转发解决
>
> 如果没有转发机制：
> - I2需要停顿2个周期（等I1的WB段完成）
> - I3需要停顿1个周期
> - I4不需要停顿（I3不修改R1）

### 5.4.5 流水线的访存点：Cache缺失与TLB缺失可能发生在哪一段

#### 判据：缺失只跟着「访存」走

5.4.1 的五段里，真正**把地址送进主存地址空间**的只有两段。而每一次这样的访存，都要依次过两条**正交**的轴（同 [[专题02——十种数据寻址方式的节拍级微操作对比#一、先分清三条正交的轴|寻址方式专题·三条轴]]）：

```
一次访存必经的三步（只有后两步存在「缺失」）

① 算地址 EA        ← ID / EX 的事：纯算术，不访存，不会缺失
② VA → PA 查 TLB      ← 轴②：缺失 → 查页表（页表在主存，这次访存本身再过 Cache）
③ 用 PA 查 Cache      ← 轴③：缺失 → 访主存调块
```

② 与 ③ 都发生在「地址被真正送出去」的那一段，所以 **TLB 缺失发生在「翻译时刻」、Cache 缺失发生在「存取时刻」**，两者都锁定在有访存需求的那一段——**没有访存，就没有缺失**。

#### 五段逐一判定

| 阶段 | 本段做什么 | TLB 缺失 | Cache 缺失 | 判定依据 |
|:----:|:-----|:--:|:--:|:-----|
| IF | 取指令：PC 是**虚地址**，需 MMU 翻译后从 I-Cache 取 | ✅ **I-TLB 缺失** | ✅ **I-Cache 缺失** | 每条指令必经取指，这是**必然**经过的两道关卡 |
| ID | 译码、读寄存器堆 | ❌ | ❌ | 寄存器堆在 CPU 内，**不碰主存地址空间**，无从缺失 |
| EX | ALU 运算；LW/SW 在此**算出 EA** | ❌ | ❌ | 算地址是纯算术，**地址还没送进 MMU/Cache**：「算出 EA」≠「访问 EA」 |
| MEM | LW/SW 用 EA 访存：先过 D-TLB 翻译，再过 D-Cache 取/存数据 | ✅ **D-TLB 缺失** | ✅ **D-Cache 缺失** | 只有 load/store 类指令才真正走这一段 |
| WB | 结果写回**寄存器** | ❌ | ❌ | 目标是寄存器堆，不是存储器 |

> [!important] 口诀
> **五段里只有 IF 和 MEM 两段碰主存地址空间，缺失也只在这两段。**
> ID/EX/WB 全程走 CPU 内部通路与寄存器堆，主存的地址翻译层和存储层次都够不着。

#### 四个高频陷阱

> [!warning] 陷阱1：「WB 段把脏块写回主存，所以 WB 会缺失」
> 错。脏行写回是 **Cache 控制器在后续某次替换发生时**（或经**写缓冲**异步）完成的动作，归属于**那一次缺失的代价**，不是 Store 指令 WB 段的事（写回流程见 [[第三章——存储器层次结构#未命中的完整时序（替换在写入之前）|第三章 3.3.1]]）。WB 段只有 `MDR → 寄存器` 一类 CPU 内部通路。

> [!warning] 陷阱2：「EX 段算 EA，所以 EX 段查 TLB」
> **教材口径：错**——EX 只算出虚地址，翻译与访存都压在 MEM 段，考试按此作答。
> **实机补充：不完全错**——真实设计常把 **TLB 查询与 ALU 算地址并行**（甚至 VIPT 用虚地址 Index 位提前并行查 L1，省掉一个 TLB 延迟，见 [[第三章——存储器层次结构#Cache 有独立的地址空间吗？|第三章 3.3.2]] 末尾的 PIPT/VIPT 表），目的是把缺失延迟藏进流水段。答题按 MEM，理解实机知道「可与 EX 重叠」即可。

> [!warning] 陷阱3：「一次 TLB 缺失 ≈ 一次 Cache 缺失的代价」
> 错，且差一个量级。TLB 未命中 → 查页表 → **页表在主存里** → 这次查页表的访存**本身又要过 Cache**（多级页表最多 4 次访存，每次都可能 D-Cache 缺失）。所以一次 D-TLB 缺失的真实代价 = page walk 的若干次 Cache/主存访问 + 填 TLB + 重试原访存。**TLB 缺失可以「套娃」引发额外的 Cache 缺失**，二者不是并列的两种小概率事件。

> [!warning] 陷阱4：「一条指令只可能缺一次」
> 哈佛结构下 I-Cache/D-Cache、I-TLB/D-TLB **彼此独立**（正是 5.4.3 结构冲突用「指令和数据分开存储」的同一套硬件）。流水线满载时，**某拍的 IF 段取指缺失与同一拍的 MEM 段访存缺失可以同时发生**，各算各的代价，性能计算里**指令缺失与数据缺失必须分别统计**，不能合并成一次。

#### 三类「取不到」的处理层次（勿混）

| 事件 | 可能段 | 谁来处理 | 对流水线的影响 |
|:-----|:---:|:-----|:-----|
| **Cache 缺失** | IF / MEM | **纯硬件**自动调块，CPU 无感、对软件透明 | 插入 **stall/气泡**，损失若干时钟周期；**不产生异常** |
| **TLB 缺失**（页在主存） | IF / MEM | 硬件 page walker 或 OS 填快表 | 停顿，周期数远大于 Cache 缺失 |
| **缺页**（页不在主存） | IF / MEM | **内中断·故障（fault）→ OS 调页（DMA 搬运）** | **精确中断**：断点用「出事那条指令自己带下来的 PC」，回来**重新执行**该指令 |

> [!note] 缺页与流水线的交汇：精确中断
> 缺页发生在 IF（取指时发现指令页不在）或 MEM（访存时发现数据页不在），属于**故障型内中断**，必须满足精确中断三条件——断点前指令全提交、断点后全冲刷、断点可精确恢复。流水线里的实现是**按序提交（retire）+ ROB + flush**，详见 [[专题总结/专题02——中断#3.6 ★ 流水线遇到中断怎么办？——精确中断（Precise Interrupt）|跨科目专题02：3.6 精确中断]]；调页全链条见 [[操作系统/第三章——内存管理/虚拟页式存储|OS 第三章：虚拟页式存储]]。

#### 与 5.2.2 节拍模型的衔接，以及对 CPI 的影响

> [!tip] 两套口径别打架
> - **非流水线节拍模型**（5.2.2）：一次访存 = 1 个机器周期 = **4 拍**（送地址 MAR → 主存译码 → 数据入 MDR → 送目标）。
> - **流水线口径**（本节）：这 4 拍被压缩进 MEM **一个时钟周期**，前提是 **Cache 命中**；一旦缺失，MEM 段必须 stall 到数据回来为止。
>
> 这正是「流水线时钟周期取最长段」的现实根源之一：访存段（IF 与 MEM）天生带两套慢路径（轴②与轴③），所以现代机器宁可把 MEM 拆成多级（ME/DF/…）或加深流水级，也不让一个周期等主存。周期层级的完整辨析见 [[专题01——周期|专题 01：周期]]。

缺失对性能的量化影响（与 5.4.2 的 CPI/吞吐率口径一致）：

$$CPI = CPI_{基础} + \underbrace{f_{I}\times mr_{I}\times mc_{I}}_{\text{IF 段：I-Cache 缺失}} + \underbrace{f_{D}\times mr_{D}\times mc_{D}}_{\text{MEM 段：D-Cache/TLB 缺失}}$$

- $f_I$：**每条指令的取指次数**（恒为 1）；$f_D$：**每条指令的数据访存次数**（LW/SW 占比 × 每次的访存次数）。**间址寻址要翻倍**：多一个完整间址周期 = 多一套 TLB+Cache 双重缺失的可能（见 [[专题02——十种数据寻址方式的节拍级微操作对比#十二、易错点汇总|寻址方式专题·误区 4]]）
- $mr$：**缺失率**、$mc$：**缺失代价（需 stall 的周期数）**——I 侧与 D 侧**各自一套**，分别对应 IF 与 MEM 两段
- 若题目另给 TLB 命中率与页表访存次数，按 [[第三章——存储器层次结构#TLB（Translation Lookaside Buffer，快表）|第三章 3.4.2]] 的 TLB+Cache 联合访问模型先算平均访存时间，再把它换算成缺失代价乘进上式
- 典型陷阱：把 $mc_D$ 直接当主存访问时间，**漏掉 TLB 缺失套娃出的页表 walk 开销**（见上文陷阱 3）

## 5.5 考点总结

### 高频考点

1. **CPU基本结构**：运算器和控制器的组成、各寄存器功能
2. **硬布线 vs 微程序控制器**：对比、特点、适用场景
3. **流水线性能计算**：吞吐率、加速比、效率的计算公式
4. **流水线冲突**：结构冲突、数据冲突（转发/旁路）、控制冲突（分支预测）
5. **微程序相关概念**：微命令、微操作、微指令、微程序（见5.2.3）
6. **指令周期时序**：四级时序、指令周期构成、取指/间址/执行/中断周期的节拍级微操作序列（见5.2.2）
7. **总线传输控制**：三态门电平控制与寄存器装载端时钟沿触发的区别（见5.2.4）
8. **流水线各段的缺失位置**：只有 IF（I-TLB/I-Cache）与 MEM（D-TLB/D-Cache）两段碰主存地址空间，ID/EX/WB 不可能缺失；TLB 缺失会套娃引发页表 walk 的额外 Cache 缺失（见5.4.5）

### 易错点

- PC、IR、MAR、MDR对用户透明（不可见），通用寄存器可见
- 流水线时钟周期取最长段的时间
- 加速比公式中，理想最大加速比等于流水线段数k
- 数据冲突中最常见的是RAW（写后读）
- 转发可以解决大部分数据冲突，但不能解决所有情况（如Load-Use冲突）（见5.4.3）
- **PC+1 与访存并行**，不占额外节拍；访存固定4拍：MAR送地址→译码→MDR收数据→送目标寄存器（见5.2.2）
- **锁存是时钟沿把总线数据写入寄存器；关闭使能是节拍切换的自然失效，不是微指令**——"置1才生效、不置即关闭"（见5.2.4）
- 微指令≠机器指令；"某位置1就生效"仅限直接编码（见5.2.3）
- **算出 EA ≠ 访问 EA**：EX 段只是 ALU 算出虚地址，翻译与存取都在 MEM 段，所以 EX 段不会发生 TLB/Cache 缺失（实机可并行查询是优化，不改教材口径）（见5.4.5）
- **脏行写回不属 WB 段**：写回是后续替换发生时 Cache 控制器的动作，代价记在那一次缺失上（见5.4.5）
- **I 侧与 D 侧独立**：取指缺失与访存缺失可在同一拍同时发生，性能计算须分别统计（见5.4.5）

### 常用公式速查

| 公式 | 说明 |
|:-----|:-----|
| T_流水线 = (k + n - 1) × Δt | 流水线总执行时间 |
| S = n × k / (k + n - 1) | 加速比 |
| E = n / (k + n - 1) | 效率 |
| TP = 1 / Δt | 理想吞吐率 |
