# 待议草稿——中断处理全流程与多重嵌套

> [!note] 临时文件
> 本文件整理 **CPU 响应并处理中断时执行的各项操作**（保护现场、开/关中断、恢复现场、中断返回等）及其**软硬件分工**，并重点理清**多重中断（中断嵌套）的逐层过程**。定稿后可并入 [[第七章——输入输出系统]]、OS 中断相关章节，或并入跨科目专题 [[专题总结/专题02——中断|专题02——中断]]，亦可删除。

---

## 一、一条主线：硬件做 vs 软件做

理解所有中断操作的前提，是先钉死一条分界线——**"关中断、保存断点、找向量入口、IRET 恢复断点"由硬件自动完成（中断隐指令）；"保护/恢复现场、开中断、设备服务"由中断服务程序 ISR（软件）完成**。

> [!important] 为什么开关中断反复出现
> 因为不同阶段对"**能不能再被打断**"的需求不同：
> - **"保存"和"恢复"两串动作要关中断**——现场还没存好 / 正在还原，被搅乱就全错，必须原子完成；
> - **中间"真正干活"那段要开中断**——现场已安全，希望更高优先级中断能进来，实现嵌套。

---

## 二、完整流程与软硬件分工（单重中断基准）

| 阶段 | 顺序 | 操作 | 执行者 | 作用 |
|:-----|:----:|:-----|:------:|:-----|
| **响应**（中断隐指令） | 1 | **关中断** | 硬件 | 屏蔽新中断，保证保存断点不被打断 |
|  | 2 | **保存断点** | 硬件 | 把 **PC + PSW** 压栈，供返回时恢复 |
|  | 3 | **找 ISR 入口** | 硬件 | 按中断类型号查中断向量表，向量→PC |
| **处理**（ISR 软件） | 4 | **保护现场** | 软件 | 保存**通用寄存器**与原**中断屏蔽字** |
|  | 5 | **开中断** | 软件 | （多重中断才做）允许更高级中断进入 → 嵌套 |
|  | 6 | **执行中断服务** | 软件 | 真正的设备服务逻辑 |
|  | 7 | **关中断** | 软件 | 恢复现场前必须先关，保证原子 |
|  | 8 | **恢复现场** | 软件 | 弹栈还原通用寄存器与屏蔽字 |
| **返回** | 9 | **开中断 + 中断返回 `IRET`** | 硬件 | 弹出断点恢复 PC/PSW，回被打断处 |

**ISR 内部口诀**：保护现场 → 开中断 → 中断服务 → 关中断 → 恢复现场 → 开中断、中断返回。

> [!warning] 单重 vs 多重，差别就在第 5 步
> - **单重中断**：进入 ISR 后**不开中断**（跳过第 5 步），整个服务期间不再响应任何新中断，处理完才恢复；实现简单。
> - **多重中断（嵌套）**：**保护现场后立即开中断**（执行第 5 步），允许被更高优先级中断再次打断。

---

## 三、多重中断（中断嵌套）逐层过程 ⭐

### 3.1 两个必要条件

1. **ISR 在保护现场之后主动"开中断"**——否则 CPU 一直处于关中断态，永远不会嵌套。
2. **中断优先级 + 屏蔽字**——开中断只是"放开大门"，但谁能进来由**中断屏蔽字**决定：只有**优先级高于当前正在处理的 ISR** 的中断才能打断它；同级或更低级的仍被屏蔽字挡住。

### 3.2 完整过程表（沿用第二节表模式：外层 S 段内嵌一个完整 H→S→H）

> 以设备 A（低优先级）处理中途被设备 B（高优先级）打断的**两层嵌套**为例，把整个过程逐拍铺成表。注意 **B 的一整套「响应→处理→返回」被夹在 A 的「处理」段中间**（第 5 步开中断之后）。

| 阶段 | 顺序 | 操作 | 执行者 | 作用 |
|:-----|:----:|:-----|:------:|:-----|
| **①A 响应**（硬件） | 1 | **关中断** | 硬件 | 屏蔽新中断，保证保存 A 断点不被打断 |
|  | 2 | **保存断点 A** | 硬件 | 主程序的 **PC + PSW** 入栈（栈底第 1 层） |
|  | 3 | **向量→PC，跳 ISR_A** | 硬件 | 进入 A 的服务程序 |
| **①A 处理·前半**（软件） | 4 | **保护现场 A** | 软件 | 存通用寄存器 + 装 A 的中断屏蔽字 |
|  | 5 | **开中断** ⭐ | 软件 | 嵌套的前提——正是这句让 B 有机会挤进来 |
| **②B 响应**（硬件） | 6 | **关中断** | 硬件 | B 来打断，先关中断保护保存过程 |
|  | 7 | **保存断点 B** | 硬件 | 把当前 **PC（此刻在 ISR_A 内）+ PSW** 再压一层（栈第 2 层） |
|  | 8 | **向量→PC，跳 ISR_B** | 硬件 | 转入 B 的服务程序 |
| **②B 处理·全套**（软件） | 9 | **保护现场 B** | 软件 | 存通用寄存器 + 装 B 的屏蔽字 |
|  | 10 | **开中断** | 软件 | B 也允许被**更高级**中断再嵌套（本例无更高级，可省） |
|  | 11 | **执行 B 服务** | 软件 | B 的设备处理逻辑 |
|  | 12 | **关中断** | 软件 | 恢复现场前必关，保证原子 |
|  | 13 | **恢复现场 B** | 软件 | 弹回 B 的通用寄存器与屏蔽字 |
| **②B 返回**（硬件） | 14 | **`IRET_B`** | 硬件 | 弹断点 B → **回到 ISR_A 第 5 步之后**继续 |
| **①A 处理·后半**（软件） | 15 | **执行 A 服务** | 软件 | A 的设备处理（从被 B 打断处接着跑） |
|  | 16 | **关中断** | 软件 | 恢复现场前必关 |
|  | 17 | **恢复现场 A** | 软件 | 弹回 A 的通用寄存器与屏蔽字 |
| **①A 返回**（硬件） | 18 | **开中断 + `IRET_A`** | 硬件 | 弹断点 A → 回主程序 |

> [!tip] 读表要点
> - **每层各自仍是完整的 H→S→H**：A = 步 1–3(进 H) · 4–5+15–17(S) · 18(出 H)；B = 步 6–8(进 H) · 9–13(S) · 14(出 H)。
> - **B 的整段（6→14）嵌在 A 的软件段里**（第 5 步与第 15 步之间）——这就是"套娃"：**外层 S 段中间插进一个完整的内层 H→S→H**。
> - **顺序 1→5→6→14→15→18 体现 LIFO**：断点压栈由外向内（A 先、B 后），`IRET` 弹栈由内向外（B 先回、A 后回）。
> - **只有第 5 步开了中断，才有后面的嵌套**；若这步不开（单重中断），6–14 整段根本进不来。

### 3.3 逐层时序图（设备 A 低优先级、设备 B 高优先级）

```
主程序运行
   │  ← 设备A发中断(低)
   ▼
[硬件] 关中断 → 保存断点(PC_A, PSW_A)入栈 → 跳 ISR_A
   │
[软件] ISR_A: 保护现场(通用寄存器 + 屏蔽字mask_A) → 开中断 ──┐
   │                                                        │ 此间设备B发中断(高)
   │  ← 因为已开中断，且B优先级高于mask_A允许的门槛          │
   ▼                                                        │
[硬件] 关中断 → 保存断点(PC_B, PSW_B)再次入栈 → 跳 ISR_B     │  ← 第二层嵌套
   │
[软件] ISR_B: 保护现场 → 开中断 → 服务B → 关中断 → 恢复现场 → IRET
   │  ← IRET 弹出 PC_B/PSW_B，回到 ISR_A 被打断的那条指令
   ▼
[软件] ISR_A: (从开中断之后继续) → 服务A → 关中断 → 恢复现场 → IRET
   │  ← IRET 弹出 PC_A/PSW_A，回到主程序
   ▼
主程序继续
```

### 3.4 关键点拆解

- **栈式（LIFO）保存**：每嵌套一层，就再压一份断点(含 PSW)和现场；恢复时**从最内层往外**逐层弹出。所以 B 一定先于 A 返回。
- **嵌套不是无限**：受**栈空间**和**屏蔽字**双重限制。屏蔽字可以设计成"处理 B 时屏蔽除更高优先级外的一切"，防止低优先级中断无限抢占。
- **屏蔽字决定"谁能打断谁"**：常见做法是每级 ISR 装填自己的屏蔽字。例如 mask_B 屏蔽 A（低）和自身同级，只放行比 B 更高的；这样即使开中断，A 也挤不进来打断 B。
- **恢复现场前必关中断**（每层的第 7 步）：保证寄存器/屏蔽字这一串弹栈动作不被打断，否则还原到一半又被中断，现场全乱。
- **`IRET` 通常自带开中断**：它弹出 PSW，而 PSW 里含中断允许位——恢复 PSW 即恢复到“进 ISR 那一刻”的开/关状态，所以返回后能重新响应中断。

### 3.5 对照场景：B 的优先级低于 A（不发生嵌套）

> 同样在 A 的第 5 步“开了中断”，但这次来请求的 **B 优先级低于 A**。结论：**不嵌套**——B 被 A 的屏蔽字挡在门外，只能挂起等待，直到 A 全程处理完才轮到它。

| 阶段 | 顺序 | 操作 | 执行者 | 作用 |
|:-----|:----:|:-----|:------:|:-----|
| **①A 响应**（硬件） | 1 | 关中断 | 硬件 | 保护保存 A 断点 |
|  | 2 | 保存断点 A | 硬件 | PC + PSW 入栈 |
|  | 3 | 向量→PC，跳 ISR_A | 硬件 | 进入 A 服务程序 |
| **①A 处理**（软件） | 4 | 保护现场 A | 软件 | 存通用寄存器 + **装 A 的屏蔽字（把 B 位置 1 屏蔽）** |
|  | 5 | **开中断** | 软件 | 打开了总闸 IF…… |
|  | — | **⚠ B 发中断请求（低）** | — | 但 B 的屏蔽位 = 1 → **请求被挡在接口、传不到 CPU** → A 继续，不被打断 |
|  | 6 | 执行 A 服务 | 软件 | A **独占**跑到结束 |
|  | 7 | 关中断 | 软件 | 恢复现场前必关 |
|  | 8 | 恢复现场 A | 软件 | 弹回通用寄存器 + **还原旧屏蔽字**（此时 B 不再被屏蔽） |
| **①A 返回**（硬件） | 9 | 开中断 + IRET_A | 硬件 | 回主程序，IF=1、屏蔽字回到主程序态 |
| **②B 响应**（硬件） | 10 | 关中断 → 保存断点 B → 向量→PC | 硬件 | **A 已结束**，B 的请求此刻才被 CPU 看到 → 顺序响应 |
| **②B 处理→返回** | … | 保护现场 B → 开中断 → 服务 B → 关中断 → 恢复现场 → IRET_B | 软/硬 | B **完整独立**地跑完（不在 A 内部） |

> [!important] 与 3.2 的关键对比
> | 对比维度 | B 优先级**高于** A（3.2） | B 优先级**低于** A（本节） |
> |:--|:--|:--|
> | A 的屏蔽字对 B | 放行（B 位 = 0） | **屏蔽**（B 位 = 1） |
> | B 能否进 CPU | 能，第 5 步开中断后立即抢占 | **不能**，请求被挡在接口挂起 |
> | B 的 H→S→H 位置 | **嵌在 A 的 S 段中间**（嵌套） | **在 A 全部结束之后**（顺序，不嵌套） |
> | 处理（完成）次序 | **B 先于 A** 完成 | **A 先于 B** 完成 |
> | 栈最大层数 | 2 层 | 1 层（无压栈叠加） |

- **本质**：开中断（IF=1）只是“允许响应”的**必要条件**，不是充分条件；**能不能真打断当前 ISR，由屏蔽字这道逐源闸决定**。低优先级源屏蔽位 = 1，请求到不了 CPU，自然打断不了。
- **B 什么时候才被服务**：等 A 走完 `IRET_A`、恢复现场时把旧屏蔽字装回、并重新开中断后，B 的请求才浮现到 CPU 眼前，被**顺序**响应——这属于“排队/响应优先级”层面的处理，而非嵌套。

> [!tip] 记忆钩子
> **开中断 = 允许嵌套的那把钥匙；屏蔽字 = 决定谁能进门的名单。** 两者同时具备，才形成多重中断。断点与现场像叠盘子一样层层压栈，返回时反过来逐层揭盘。

## 四、三个高频易错点

1. **保存断点 ≠ 保护现场**：断点只存 **PC + PSW**（硬件）；通用寄存器是后面软件"保护现场"才存的。
2. **中断 vs 子程序调用**：子程序调用**只压 PC，不压 PSW、不关中断**；中断处理一定保存 PSW 且要关中断。二者的"压栈保护现场"动作范围不同。
3. **软硬件分界（最爱考排序）**：凡"关中断、保存断点、找向量入口、IRET 恢复断点"= **硬件**，发生在 ISR 之前/边界；"保护现场、开中断、服务、关中断、恢复现场"= **软件 ISR 内部**。
