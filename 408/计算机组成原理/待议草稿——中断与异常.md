## 一、已达成的共识（可直接采信）

### 1. 总线层次：主存与辅存之间**没有直接总线**

辅存在硬件上被归类为 **I/O 设备**（不是存储器），挂在 I/O 总线上。主存↔辅存必须绕道：

```
辅存 → I/O总线 → I/O接口(含DMA引擎) → 系统总线 → 主存
```

本机实名：`NAND →闪存接口→ SSD控制器 →PCIe 4.0×4→ Root Complex →Infinity Fabric→ IMC →DDR5通道→ DIMM`（**跨三段总线**）。

### 2. "系统总线"是教材抽象名，三个时代实体不同

| 时代 | "主存/CPU ↔ I/O 接口"这一段是谁 |
|:-----|:-------------------------------|
| 一（单一共享） | 就是那唯一一条总线：PC Bus / **ISA** / Unibus / Multibus ← **教材模型的原型** |
| 二（南北桥） | 裂成四段：**FSB** → 北桥 → **Hub Interface/DMI** → 南桥 → **PCI** |
| 三（现代集成） | 已不存在：拆成 **DDR 通道**（归 Cache-主存层）+ **PCIe**（CPU 直出）+ **DMI**（通 PCH）+ **IF/UPI** |

**"数据+地址+控制"三组线模型只适用于并行总线**；PCIe 靠 TLP 打包，DDR5 把命令与地址合并成一条 CA 总线（总线复用的活例）。

### 3. I/O 接口的 7 个部件，且**端口 ≠ 接口**

- 部件：数据缓冲寄存器、状态寄存器、控制寄存器、**地址译码**、**控制与时序逻辑**、**数据格式转换电路**、**中断/DMA 逻辑**
- **端口** = 接口中能被 CPU 读写的寄存器（有地址）；**接口** = 整个电路模块（含端口 + 译码 + 控制 + 转换逻辑）

### 4. 控制方式与编址方式是**两条正交的轴**

| 轴 | 选项 |
|:---|:-----|
| **控制方式**（谁搬数据、CPU 怎么知道完成） | 程序查询 / 程序中断 / DMA / 通道 |
| **编址方式**（端口地址在哪个空间） | 统一编址 MMIO（普通访存指令）/ 独立编址（IN/OUT，靠 IORQ vs MREQ 区分） |

- 任意组合都成立：x86 PS/2 键盘在 BIOS 里是「**查询 + 独立编址**（端口 0x64）」
- **两种编址方式下数据格式完全一样，不发生任何转换**；"数据格式转换"（串并/模数）由接口的转换电路完成，发生在接口↔外设之间
- 现代 MSI-X 中断本质是 **MMIO 写** → 连中断都统一到存储器映射了

### 5. DMA 里有**三条独立的信息流**

| 流 | 谁 → 谁 | 载体 | 内容 |
|:---|:--------|:-----|:-----|
| **命令流** | CPU → 接口 | 普通指令（OUT / MMIO 写） | 设备命令、**LBA**、长度 |
| **数据流** | 接口 ↔ 主存 | **DMA 引擎搬运** | 真正的数据 |
| **地址流** | DMA 引擎内部 | AR 自增 / PRP 列表 | **主存物理地址 PA** |

⭐ **主存地址只存在于 DMA 侧，从不发给设备**；设备只拿到 LBA。

### 6. DMA 引擎是**纯硬件**，指挥它的是**内核软件**

| | 内容 |
|:--|:-----|
| **硬件**（DMA 引擎） | AR（自增计数器）、WC（递减计数器 + 零检测）、DR、控制/状态逻辑、**总线仲裁状态机**、寄存器接口与译码、中断机构。现代 Bus Master 版另有：描述符取指引擎、多队列调度器、Scatter-Gather 引擎、IOMMU 接口、PCIe 事务层 |
| **软件**（内核态驱动） | 分配并**锁页**（pin）、VA→PA 映射、构造描述符/PRP、写设备寄存器、敲 Doorbell、处理完成中断。**用户态完全碰不到 DMA** |
| 为什么必须内核态 | ① 需要物理地址 ② 访问设备寄存器是特权指令 ③ 目标页必须锁住不被换出 |

### 7. 地址翻译发生**两次**，两套机制互不相干

| | 第一级 | 第二级 |
|:--|:-------|:-------|
| 谁做 | **MMU**（CPU 内） | **FTL**（SSD 内处理器 + 映射表） |
| 输入 → 输出 | VA → **PA**（主存页框） | LBA → **闪存物理地址**（die/plane/block/page） |
| 查什么表 | 页表（在主存，OS 维护） | FTL 映射表（在 SSD 自带 DRAM，固件维护） |
| 主机可见吗 | ✅ | ❌ 完全透明（GC/磨损均衡后随时变） |

机械硬盘对应物：LBA → CHS + 坏道重映射。

### 8. 数据回程有两条完全不同的路

| 方式 | 路径 | 终点 |
|:-----|:-----|:-----|
| 程序查询 / 程序中断 | 设备 → I/O总线 → 接口 → 系统总线 → MDR → CPU 寄存器 | **CPU** |
| **DMA / 通道** | 设备 → I/O总线 → 接口 → 系统总线 → (RC→Fabric→IMC) → Cache-主存总线 → 主存 | **主存** |

**对偶关系**：查询/中断 = 数据进寄存器、绕过主存；DMA/通道 = 数据进主存、绕过 CPU。

### 9. 缺页**不一定**用 DMA

| 情况 | 需要 DMA |
|:-----|:--------:|
| 目标页在磁盘 / swap | ✅ 换入 |
| 牺牲页 **dirty = 1** | ✅ 换出 |
| 牺牲页 **dirty = 0**（干净页） | ❌ 直接丢弃，零传输 |
| 首次访问的**零页** | ❌ OS 把页框清零，不碰磁盘 |
| 文件映射页已在 **page cache** | ❌ 只建立映射 |

### 10. 四种方式的节拍成本（教材模型，传 512B）

| 方式 | CPU 花费 | 中断次数 | 成本正比于 |
|:-----|:---------|:--------:|:-----------|
| 程序查询 | ≈3×10⁷ 拍（空转 150 万圈）+ 2048 拍搬运 | 0 | **外设速度**（越慢越致命） |
| 程序中断 | ≈12800 拍 | 128 | **数据量**（每字一次全套现场保护） |
| DMA | ≈122 拍（32 预处理 + 90 后处理） | 1 | **一次性** |
| 通道 | ≈140 拍，与数据量无关 | 1 | **任务数** |

### 11. DMA 的正确时序：驱动**主动发起**，不是"收到信号才开始"

```
① 驱动【主动】配置 DMA 引擎（软件，一次性，几条指令）
        ↓
② DMA 硬件【自主】搬运整块（微操作由硬件按节拍逐拍完成）
        ↓
③ DMA 硬件发中断（WC=0 / CQ 写完 → INTR 或 MSI-X）
        ↓
④ 驱动的【中断服务程序】接收信号 → 校验、置完成、唤醒进程
```

⭐ **④ 是结果不是起因**。且微操作（`AR→地址总线`、`数据→M(AR)`、`AR+1`、`WC-1`）**全由硬件时序逻辑自动完成**，驱动不逐条驱动——否则就不叫 DMA 了。

## 二、争议焦点：中断部分（待深入讨论）

### 争议 1 · 缺页触发的是“中断”还是“异常”？术语边界在哪　✅ 已收敛 → 专题02

- 广义中断 = **内中断（异常）** + **外中断（interrupt）**
- 当前立场：缺页 = **故障（fault）**，属内中断/异常
- **待确认**：408 教材（王道 / 唐朔飞）说"中断"时取广义还是狭义？答题该写哪个？"缺页中断"这个常见说法在考卷上算对吗？

### 争议 2 · “由中断进行页的替换”——中断与 OS 的角色　✅ 已收敛 → 专题02

- 当前立场：中断只是**交接控制权的机制（门铃）**，做置换决策的是 **OS 缺页处理程序（开门的人）**
- **待讨论**：这个分歧是纯术语之争，还是对机制理解有实质差别？

### 争议 3 · 返回语义：重新执行 vs 执行下一条　✅ 已收敛 → 专题02

| 类型 | 返回后 | 例 |
|:-----|:-------|:---|
| **故障 fault** | **重新执行**当前指令 | 缺页 #PF、除零 |
| **陷阱 trap** | 执行**下一条** | syscall、断点 |
| **终止 abort** | **不可恢复** | 硬件校验错、双重故障 |
| **外中断 interrupt** | 执行**下一条** | I/O 完成、时钟、DMA 完成 |

- **待讨论**：x86 的 `#PF`（向量 14，出错 VA 存 CR2）属 fault，返回后重新执行那条 `MOV` —— 这一点是否认同？

### 争议 4 · 中断隐指令 vs 中断服务程序的边界

| | 谁做 | 内容 |
|:--|:-----|:-----|
| **中断隐指令** | **硬件**（占节拍，不占指令条数） | 关中断、保存断点 `PC→栈`、`PSW→栈`、向量→PC |
| **中断服务程序** | **软件** | 保护现场与屏蔽字、（多重中断时）开中断、服务、关中断、恢复现场与屏蔽字、`IRET` |

- **待讨论**：之前提到的"**唤醒寄存器**"这个说法，对应的是上表哪一步？（推测指隐指令里的"保存断点与现场"，但需确认）

### 争议 5 · 中断响应时机与优先级　✅ 已收敛 → 专题02

- 外中断：**当前指令执行结束**时响应（不是每个时钟周期）
- 异常：在**指令执行过程中**立即产生（该指令无法完成）
- 笔记 7.3.3 优先级表：硬件故障 > **DMA 请求** > 程序中断（外设）> 程序中断（软件）> 用户程序
- **待讨论**：DMA 完成中断与缺页异常同时到达时谁优先？"DMA 请求"在优先级表里指的是 **DMA 总线请求（HOLD）**还是 **DMA 完成中断**？这两者被混在同一张表里了吗？

### 争议 6 · MSI-X 还算不算教材意义上的"中断"

- MSI-X 本质：设备往一个**特定内存地址写一个特定值**（MMIO 写）→ 中断控制器（APIC）翻译成向量
- **没有**专用中断引脚、**没有** INTR/INTA 握手、**没有**中断向量寄存器
- **待讨论**：教材的 INTR/INTA + 中断隐指令模型，如何映射到 MSI-X？两者在"保护断点、向量→PC"这些步骤上还一致吗？

### 争议 7 · 单重中断 vs 多重中断在缺页场景下怎么走

- 缺页处理期间要不要开中断？（开 → 可被时钟中断抢占，实现"阻塞进程 + 调度别的进程"）
- **待讨论**：笔记 7.3.4 的屏蔽字模型能否直接套到缺页处理流程上？
