# 专题02——十种数据寻址方式的节拍级微操作对比

> [!abstract] 专题问题
> 十种数据寻址方式在**微命令/微操作**层面到底差在哪？各需要多少**节拍**？每一拍是哪些部件在干活？为什么"直接寻址"不等于"命中 Cache"、"相对寻址"不等于"虚实地址转换"？

---

## 一、先分清三条正交的轴

学习寻址方式最常见的错误，是把三件互不相干的事混为一谈。它们是**串联**关系：

```
① 寻址方式        ② 地址转换           ③ 存储访问
EA 怎么算出来  →   VA → PA（TLB/页表） →  用 PA 取数据（Cache/主存）
   第四章 4.3         第三章 3.4            第三章 3.3
```

| 轴 | 决定什么 | 失败/慢的表现 |
|:---|:---------|:--------------|
| ① 寻址方式 | 有效地址 EA 的**计算公式**与**取操作数的访存次数** | 间接寻址多一次访存 |
| ② 地址转换 | 虚拟地址→物理地址 | TLB 未命中 → 查页表（多次访存） |
| ③ 存储访问 | 用物理地址在哪一级取到数据 | Cache 未命中 → 访主存 |

> [!important] 核心结论
> **寻址方式与 Cache/TLB 命中与否完全无关**。任何需要访存的寻址方式，其访存都要依次经过 ② 和 ③。说"直接寻址命中 Cache、间接寻址命中 page"是把三条轴混成了一条。

---

## 二、十种数据寻址方式总表

指令格式统一为：`OP | 寻址方式字段(2~4 位) | 形式地址 A`

| # | 方式 | EA | 取操作数访存次数 | 指令中给出什么 |
|:--:|:-----|:---|:----:|:---------------|
| 1 | 立即寻址 | 无 | **0** | 操作数本身 |
| 2 | 隐含寻址 | 无（由 OP 指定） | **0** | 什么都不给 |
| 3 | 寄存器寻址 | Ri（编号即地址） | **0** | 寄存器编号（几位） |
| 4 | 直接寻址 | A | 1 | 主存地址 |
| 5 | 寄存器间接寻址 | (Ri) | 1 | 寄存器编号 |
| 6 | 相对寻址 | (PC) + A | 1 | 有符号位移量 |
| 7 | 基址寻址 | (BR) + A | 1 | 偏移量（BR 归 OS 管） |
| 8 | 变址寻址 | (IX) + A | 1 | 基准地址（IX 归用户改） |
| 9 | 堆栈寻址 | (SP)（隐含） | 0（硬栈）/ 1（软栈） | 什么都不给 |
| 10 | 间接寻址 | (A) | **2** | 主存地址（其内容是地址） |

> [!note] 与第四章的分工
> [[第四章——指令系统#4.3 数据寻址方式|第四章 4.3]] 已列全 **10 种**方式（4.3.1~4.3.10）的定义、EA 公式与优缺点，并在 4.3.11 给出十种对比表；本专题聚焦**节拍级微操作差异**与拍数计算。

## 三、统一节拍约定（沿用第五章 5.2 模型）

| 约定 | 内容 |
|:-----|:-----|
| 一次访存 | = 1 个机器周期 = **4 拍**：T0 送地址+发命令 / T1 主存译码 / T2 `M(MAR)→MDR` / T3 数据送目标 |
| 取指周期 | 所有寻址方式**完全相同**，固定 **4 拍** |
| CPU 内部操作 | 读寄存器、ALU 算 EA、`SP±1`、`(PC)+1` 均与访存**并行**，不占额外拍 |
| 运算+写回 | `ACC ← (ACC) + (MDR)` 与访存的 T3 **合并为一拍**（MDR 直接作 ALU 输入） |

取指周期（所有方式共用，详见 [[第五章——中央处理器#5.2.2 各周期节拍级微操作序列|第五章·取指周期]]）：

| 节拍 | 微操作 | 部件行为 |
|:----:|:-------|:---------|
| T0 | `PC → MAR`，`1 → R` | PC 三态门导通，MAR 时钟沿锁存，读命令发往主存 |
| T1 | 主存译码；`(PC)+1 → PC` | PC 自增走内部加法器，与译码并行 |
| T2 | `M(MAR) → MDR` | 指令经数据总线锁存进 MDR |
| T3 | `MDR → IR`，指令译码 | CU 由 OP 定位微程序入口，由**寻址方式字段**选通 EA 形成通路 |

**下面各节只展开执行周期。**

## 四、零访存三兄弟：立即 / 隐含 / 寄存器

| 节拍 | 立即寻址 | 隐含寻址 | 寄存器寻址 |
|:----:|:---------|:---------|:-----------|
| T0 | `Ad(IR) → ALU_B`（IR 的地址字段**本身就是数据**；有符号立即数需先符号扩展） | 无微操作——CU 从 OP 已知另一操作数是 ACC | `Ri → ALU_B`（寄存器堆读口按编号输出，双读口可并行送两个） |
| T1 | `ACC + ALU_B → ACC`，`PSW写` | `ACC + (操作数) → ACC`，`PSW写` | `ALU_A + ALU_B → 结果 → 目标`，`PSW写` |

**参与部件**：IR / 寄存器堆 / ALU / PSW / 内部总线。**MAR、MDR、主存、Cache 一个都没动**——这就是它们最快的原因。

> [!note] 隐含寻址的准确定义
> **某个操作数的地址不出现在地址码字段中，而由操作码隐含指定。** 三种典型：
> - 单地址指令 `ADD A`：另一个操作数与结果都隐含为 **ACC**
> - 一地址自增 `INC R1`：目的操作数隐含 = 源操作数
> - 零地址栈指令：操作数隐含在**栈顶**（由 SP 指向）
>
> 价值：**节省地址码字段 → 缩短指令字长**。`i++` 就是"隐含（R1）+ 立即（常数 1）"的组合，0 次访存。

---

## 五、一次访存六兄弟：差异全部集中在 T0

这是本专题最关键的结论——**T1、T2、T3 完全相同，唯一差别是 MAR 的地址从哪来**：

| 方式 | **T0：MAR 的数据来源** | 经过 ALU？ | 参与部件 |
|:-----|:-----------------------|:----:|:---------|
| 直接寻址 | `Ad(IR) → MAR` | ❌ | IR → 内部总线 → MAR |
| 寄存器间接 | `(Ri) → MAR` | ❌ | 寄存器堆读口 → 总线 → MAR |
| 相对寻址 | `(PC) + A → MAR` | ✅ | PC + IR 的 A 字段 → ALU → MAR |
| 基址寻址 | `(BR) + A → MAR` | ✅ | BR + A → ALU → MAR |
| 变址寻址 | `(IX) + A → MAR` | ✅ | IX + A → ALU → MAR |
| 堆栈寻址 | `(SP) → MAR` | ❌ | SP → 总线 → MAR |

后续三拍所有方式一致：

| 节拍 | 微操作 | 部件行为 |
|:----:|:-------|:---------|
| T1 | 主存（或 Cache）地址译码 | 若命中 Cache，此拍与 T2 被压缩为 Cache 访问时间 |
| T2 | `M(MAR) → MDR` | 数据经数据总线进 MDR |
| T3 | `ACC + (MDR) → ACC`，`PSW写` | ALU 以 MDR 为一路输入，结果同拍写回 |

> [!important] 一句话总纲
> **十种寻址方式的差别，本质只是"MAR 输入端接哪一路数据、要不要先过 ALU"。**
> 基址+变址组合 `EA = (BR) + (IX) + A` 需要**两次加法**，若 ALU 只有两个输入端，就要多占 1 拍。

## 六、间接寻址：唯一多一个"间址周期"的（12 拍全流程）

| 节拍 | 所属周期 | 微操作 | 部件行为 |
|:----:|:---------|:-------|:---------|
| T0 | 取指 | `PC → MAR`，`1 → R` | 取指令 |
| T1 | 取指 | 主存译码；`(PC)+1 → PC` | 并行自增 |
| T2 | 取指 | `M(MAR) → MDR` | 指令进 MDR |
| T3 | 取指 | `MDR → IR`，译码 | CU 识别"间接"，转间址周期 |
| T4 | **间址** | `Ad(IR) → MAR`，`1 → R` | 把形式地址 A 送 MAR，**再访存一次** |
| T5 | **间址** | 主存译码 | 第一次访存的译码 |
| T6 | **间址** | `M(MAR) → MDR` | 读出的是**真正的 EA，不是数据** |
| T7 | **间址** | `Ad(MDR) → MAR`，`1 → R` | EA 送 MAR 并立即发读命令（资源不冲突，可并拍） |
| T8 | 执行 | 主存译码 | 第二次访存的译码 |
| T9 | 执行 | `M(MAR) → MDR` | 这次读出的才是操作数 |
| T10 | 执行 | `ACC + (MDR) → ACC`，`PSW写` | ALU 运算 |
| T11 | 执行 | 写回完成 | 结果锁存进 ACC |

- **严格口径 12 拍**（T7 不并拍）；**优化口径 11 拍**（`Ad(MDR)→MAR` 与 `1→R` 同拍）
- **代价**：两次访存 = 两次可能 Cache 未命中 = 最坏两次访主存
- **多次间接**（`@@A`）：每多一层间接，再加 4 拍
- 指令周期构成变为：`取指 + 间址 + 执行`（见 [[第五章——中央处理器#5.2.1 时序层级（四级）|第五章·指令周期构成]]）

## 七、堆栈寻址：进出栈微操作（软堆栈、递减栈）

| 操作 | 逐拍微操作 | 拍数 |
|:-----|:-----------|:----:|
| **PUSH**（压栈） | T0 `数据 → MDR`；T1 `SP-1 → SP`（并行，内部操作）；T2 `SP → MAR`，`1 → W`；T3 主存译码；T4 `MDR → M(MAR)` | 5 |
| **POP**（出栈） | T0 `SP → MAR`，`1 → R`；T1 主存译码；T2 `M(MAR) → MDR`；T3 `MDR → 目标寄存器`，`SP+1 → SP`（并行） | 4 |

| 堆栈类型 | 栈顶位置 | 取操作数访存 | 速度 |
|:---------|:---------|:----:|:-----|
| **硬堆栈**（寄存器堆栈） | CPU 内寄存器 | **0 次** | 最快，进出栈各 1 拍 |
| **软堆栈**（主存堆栈） | 主存 | 1 次 | 需访存，但容量大 |

**特点**：指令中**不含地址码** → 零地址指令 → 指令字最短。408 常考：栈底/栈顶方向、满递减/空递增、`SP` 修改能否与访存并行、栈溢出判断。

## 八、硬件视角：一个 MUX 解释所有差异

```
IR 的寻址方式字段（2~4 位）
        │ 作为选择信号
        ▼
   ┌─────────┐   Ad(IR)          ← 直接
   │  MUX +  │   (Ri)            ← 寄存器间接
   │   ALU   │   (PC) + A        ← 相对
   │         │   (BR) + A        ← 基址
   │         │   (IX) + A        ← 变址
   └────┬────┘   (SP)            ← 堆栈
        ▼
       MAR  ──→ 地址总线 ──→ [TLB/页表] ──→ [Cache/主存] ──→ MDR
```

- EA 形成是**组合逻辑**，在同一拍内完成 → 408 通常**不给它单独计拍**
- ISA 里每多一种寻址方式，硬件就多一路 MUX 输入 + 译码逻辑
- **这正是 CISC/RISC 之争的硬件成本来源**：RISC 只保留 Load/Store 的少数几种寻址方式，就是为了砍掉这块面积与延迟（见 [[第四章——指令系统#4.4 CISC与RISC对比|第四章·CISC 与 RISC]]）

## 九、拍数汇总与速算公式

**速算主线**：

```
执行周期拍数 = 访存次数 × 4 + 运算写回 1 拍（与末次访存的 T3 合并）
指令总拍数   = 4（取指） + 执行周期拍数
```

| 方式 | 访存次数 | 执行周期（408 常用口径：EA 形成不计拍） | 执行周期（严格口径：ALU 算 EA 占 1 拍） | 指令总拍数 |
|:-----|:----:|:----:|:----:|:----:|
| 立即 | 0 | 1 | 1 | 5 |
| 隐含 | 0 | 1 | 1 | 5 |
| 寄存器 | 0 | 1（目的为 ACC）/ 3（目的为寄存器堆） | 同左 | 5 / 7 |
| 堆栈（硬栈） | 0 | 1 | 1 | 5 |
| 直接 | 1 | 4 | 4 | 8 |
| 寄存器间接 | 1 | 4 | 4 | 8 |
| 堆栈（软栈） | 1 | 4 | 4 | 8 |
| 相对 | 1 | 4 | **5** | 8 / 9 |
| 基址 | 1 | 4 | **5** | 8 / 9 |
| 变址 | 1 | 4 | **5** | 8 / 9 |
| 间接 | 2 | 8（间址 4 + 执行 4） | 8 | **12** |

> [!warning] 两种口径都算对，但必须自洽
> [[第五章——中央处理器#5.2 指令周期与节拍时序|第五章 5.2]] 里的 **5.2.5（ADD R1, R2 共 7 拍）** 用的是**细拆口径**（读寄存器、ALU、写回各 1 拍 → 寄存器型执行周期 3 拍）；**5.2.2 考点**用的是**并拍口径**（寄存器型 1 拍、访存型 4 拍）。答题时任选一种，但**全题必须统一**，且快慢排序不变：`立即/隐含 = 寄存器 < 一次访存类 < 间接`。

## 十、两组最易混的对比

### 寄存器寻址 vs 直接寻址

| 对比项 | 寄存器寻址 | 直接寻址 |
|:-------|:-----------|:---------|
| 操作数在哪 | **CPU 内**寄存器 | **主存**单元 |
| 指令中给的 | 寄存器编号（如 5 位 → 32 个） | 主存地址（如 32 位） |
| 取数微操作 | `Ri → ALU_B`（内部总线，1 拍） | `Ad(IR)→MAR` / 译码 / `M(MAR)→MDR`（4 拍） |
| 访存次数 | **0** | **1** |
| 指令字长 | 短 | 长 |
| 寻址范围 | 受寄存器**个数**限制 | 受地址码**位数**限制 |
| 速度 | 快几个数量级 | 受主存/Cache 制约 |

### 寄存器间接寻址 vs 间接寻址

| 对比项 | 寄存器间接 | 间接 |
|:-------|:-----------|:-----|
| EA 存在哪 | **寄存器 Ri 里** | **主存单元 A 里** |
| 取 EA 要访存吗 | 不要（读寄存器，内部 1 拍） | **要**（多一个间址周期，4 拍） |
| 取操作数访存次数 | **1** | **2** |
| 关键微操作 | `(Ri) → MAR` | `Ad(IR)→MAR` … `Ad(MDR)→MAR` |
| 指令周期组成 | 取指 + 执行 | 取指 + **间址** + 执行 |
| 寻址范围 | 受 Ri **位长**限制（32 位 → 2^32） | 受地址码位数限制，且可**多次间接** |
| 典型用途 | 遍历数组（改 Ri 即可，指令不动） | 扩大寻址范围、指针的指针 |

> [!tip] 一句话记忆
> **"间接"就是 EA 不直接给、要再去取一次；差别只在于去哪里取——寄存器里取（免费）还是主存里取（多 4 拍）。**

## 十一、真实 ISA 案例

| ISA | 寻址方式体现 | 说明 |
|:----|:-------------|:-----|
| **x86（CISC）** | `MOV EAX, [EBX + ECX*4 + 8]` | 一条指令同时用上**基址(EBX) + 变址(ECX×比例) + 偏移(8)**，EA 形成需多次加法，故 x86 译码与 EA 计算部件极复杂 |
| **x86** | `INC EAX` | **隐含寻址**（目的 = 源）+ **立即**（常数 1 隐含在 OP 中）→ 0 次访存 |
| **x86** | `JMP rel8` | **相对寻址**，位移量仅 8 位有符号 → 短跳转，位置无关代码 |
| **x86** | `0F` 前缀 | 操作码区的**逃逸字节**，是"扩展操作码预留码点位于操作码区"的实证 |
| **MIPS / RISC-V（RISC）** | `lw $t0, 8($s0)` | **只允许"基址 + 偏移"一种访存寻址**；无间接、无变址、无存储器操作数运算 |
| **ARM** | `LDR R0, [R1, R2, LSL #2]` | 基址 + 变址（带移位），但依然只有 Load/Store 访存 |
| **栈机（JVM 字节码）** | `iadd` | **零地址 + 堆栈寻址**，操作数全隐含在栈顶 |

> [!important] 由案例回看 CISC/RISC
> RISC 把寻址方式砍到只剩"基址+偏移"，换来的是：**EA 形成通路只有一条** → 译码简单、便于流水线、硬布线可行。这就是第四章 4.4 里"寻址方式：多种 vs 少数"那一行的硬件含义。

## 十二、易错点汇总

| # | 误区 | 正解 |
|:--:|:-----|:-----|
| 1 | 直接寻址 = 命中 Cache，间接寻址 = 未命中 Cache | 寻址方式与 Cache 命中**完全正交**，任何访存都要过 Cache 层 |
| 2 | 相对寻址 = 把虚拟地址转成物理地址 | 相对寻址算出的仍是**同一地址空间**的地址；VA→PA 是 MMU/TLB 的活 |
| 3 | 隐含寻址 = "全程在 CPU 内完成" | "不访存"是**立即/寄存器**寻址的特征；隐含寻址的定义是**地址由 OP 隐含指定** |
| 4 | 间接寻址就是"多一层指针"，代价不大 | 多一个**完整间址周期（4 拍）**，且两次访存都可能 Cache 未命中 |
| 5 | 基址和变址一样，都是"寄存器 + 偏移" | **BR 由 OS 管理**（改动需特权指令），用于**多道程序重定位**；**IX 由用户改**，用于**遍历数组** |
| 6 | 相对寻址的基准是当前指令地址 | 取指阶段 PC 已自增，**基准是"当前指令地址 + 指令字长"** |
| 7 | 堆栈寻址需要给出栈顶地址 | 栈顶由 **SP 隐含**给出 → 零地址指令，指令字最短 |
| 8 | 寄存器寻址的寻址范围 = 2^寄存器位长 | 寄存器寻址**编址的是寄存器个数**（如 5 位 → 32 个），不是主存空间；寄存器**间接**寻址才用 Ri 的位长去寻址主存 |
| 9 | 立即寻址可以放任意大的数 | 立即数受**指令字长**限制，且需**符号扩展**到 ALU 位宽 |
| 10 | EA 形成要单独占一拍 | 组合逻辑同拍完成，408 常用口径**不计拍**（严格口径则 +1 拍） |
