## 4.0 ISA 概述

### 4.0.1 ISA 的定义：软硬件之间的界面

ISA（Instruction Set Architecture，指令集体系结构）指**程序员（编译器、汇编器、操作系统）所能看到的计算机属性**，即计算机的**概念性结构与功能特性**。

它的本质是**软件与硬件之间的界面（契约）**：

- 对**上**（软件）：只要按 ISA 编写程序，就无需关心硬件如何实现
- 对**下**（硬件）：只要实现符合 ISA 的机器，就能运行该 ISA 下的全部程序

```
软件：应用程序 / 编译器 / 汇编器 / 操作系统
────────────────────────────────
ISA ：指令集体系结构 —— 软硬件之间的界面
════════════════════════════════
硬件：计算机组成与实现（流水线 / Cache / 控制器 / ALU）
```

> [!important] 考点：ISA ≠ 计算机组成
> - ISA 回答"**做什么**"（What）→ 第四章（本章）
> - 计算机组成/实现回答"**怎么做**"（How）→ [[第五章——中央处理器|第五章]] 的数据通路、控制器设计、指令流水线
> - 两者不可混为一谈：判断一个属性是否属于 ISA，标准是"**程序员能否感知/是否影响程序可见行为**"

> [!warning] 缩写歧义：ISA 在 408 里有两个含义
> - 本章的 **ISA = Instruction Set Architecture**（指令集体系结构）
> - [[第六章——总线#6.5 总线标准|第六章 6.5]] 里的 **ISA = Industry Standard Architecture**（IBM PC/AT 的 16 位并行总线标准，8.33MHz、16MB/s）
>
> 两者同名不同义，选择题常在此设坑：**谈带宽/频率/插槽 → 总线 ISA；谈指令格式/寻址方式/程序员可见性 → 指令集 ISA**。详见第六章的"ISA 的同名歧义"小节。

### 4.0.2 ISA 规定的七大类内容

| 序号 | 类别 | 具体规定内容 | 关联章节 |
|:----:|:-----|:-------------|:---------|
| 1 | 指令格式与指令集 | 操作码/地址码字段划分、指令字长、操作码编码方式（扩展操作码）、指令种类与条数、每条指令的功能语义与对标志位的影响 | [[#4.1 指令格式]]、[[#4.5 指令类型]] |
| 2 | 寻址方式 | 指令寻址（顺序、跳跃）与数据寻址（9 种）的有效地址 EA 计算规则、地址码字段位数 | [[#4.2 指令寻址方式]]、[[#4.3 数据寻址方式]] |
| 3 | 数据类型与表示 | 支持的数据类型（整数、浮点、字符）、数据长度、字节序（大端/小端）、对齐要求 | [[第二章——数据的表示和运算]] |
| 4 | 寄存器组织 | 程序员可见寄存器的数量、位长、编号与用途（通用寄存器、PC、SP、PSW/标志位） | [[第五章——中央处理器]] |
| 5 | 地址空间（存储组织） | 最大可寻址空间、编址单位（按字节编址）、访问方式 | [[第三章——存储器层次结构]] |
| 6 | I/O 与中断/异常 | I/O 编址方式（统一编址/独立编址）、I/O 指令、中断与异常的类型与响应机制 | [[第七章——输入输出系统]] |
| 7 | 工作状态与保护 | 特权级划分（用户态/核心态）、特权指令与非特权指令、存储保护机制 | 呼应操作系统第一章 |

> [!note] ISA 规定的是"指令 + 指令赖以工作的全部环境"
> 很多人误以为 ISA 只是"一张指令表"。实际上，指令要能正确执行，必须同时规定**数据怎么表示**（第 3 类）、**数据放在哪**（第 4、5 类）、**如何找到数据**（第 2 类）、**遇到外部事件怎么办**（第 6 类）、**谁能执行什么**（第 7 类）。

### 4.0.3 ISA 不规定的内容（透明性辨析）

以下内容属于**计算机组成/实现**，ISA 不作规定，对程序员**透明**：

| 不规定的内容 | 归属层次 | 为什么可以透明 |
|:-------------|:---------|:---------------|
| 流水线级数、是否超标量、分支预测策略 | 计算机组成 | 只影响速度，不影响指令的执行结果 |
| Cache 容量、映射方式、替换算法、写策略 | 计算机组成 | 属于加速部件，命中与否结果相同 |
| 控制器用硬布线还是微程序实现 | 计算机组成 | 同一指令可用不同方式产生控制信号 |
| ALU 内部结构、总线宽度、主频、制造工艺 | 组成/硬件 | 纯实现细节 |

> [!important] 考点："透明"= 客观存在但程序员看不见
> 计组中"透明"是实现被隐藏，**不是"不存在"**。Cache、微指令、流水线寄存器都真实存在，只是对应用程序员透明；只有系统程序员（OS、性能调优）才可能感知其部分影响。

**推论**：同一 ISA 可以有多种实现——x86 指令集下 Intel 与 AMD 的微架构完全不同，但**二进制兼容**，同一份可执行程序在两家芯片上都能运行。这正是"ISA 是界面"的价值所在。

#### 控制信号与操作细节的归属辨析

**指令的"功能语义"属于 ISA，但执行指令产生的"控制信号"属于计算机组成。** 完整三层划分如下：

| 层次 | 研究什么 | 典型内容 | 对程序员 |
|:-----|:---------|:---------|:--------:|
| 计算机体系结构（ISA） | 概念性结构与功能特性——"做什么" | 指令格式与语义、操作码编码、寻址方式、数据类型、寄存器组织、异常行为 | **可见** |
| 计算机组成（Organization） | ISA 的逻辑实现——"怎么组织" | **控制信号（微命令）**、微操作序列、指令周期与节拍、数据通路、控制器（硬布线/微程序）、流水线、总线组织 | 透明 |
| 计算机实现（Implementation） | 物理实现——"怎么造" | 门电路、ALU 内部电路、器件选型、集成度、封装、电源与散热 | 透明 |

本章（第四章）讲第一层；[[第五章——中央处理器]] 讲第二层；第三层属于器件与工艺。

**控制信号的层次链条**（详见 [[第五章——中央处理器#5.2.3 微命令与微操作（因与果）|第五章·微命令与微操作]]）：

```
机器指令（ISA 层，程序员可见）
      ↓ 译码
微命令 = 控制信号（组成层，控制器发出的电位/脉冲）  ← 因
      ↓ 驱动
微操作（组成层，如 PCout、MARin、1→R、Read）        ← 果
      ↓ 由…实现
电平 / 门电路（实现层）
```

> [!important] 考点：机器指令 ≠ 微指令
> 微指令/微程序是**组成层面**的实现手段，对程序员透明；**机器指令**才是 ISA 层面的内容。二者混淆是高频错误选项。
>
> **铁证**：Intel 与 AMD 实现同一条 x86 `ADD`，节拍数、微操作序列、数据通路各不相同，但程序结果完全一致——若控制信号属于 ISA，两家就不可能二进制兼容。

**"操作细节"必须二分**（同样叫"细节"，归属完全不同）：

| 细节类型 | 归属 | 例子 |
|:---------|:----:|:-----|
| **影响程序可见结果**的细节 | **ISA** | 运算类型、操作数类型与长度、溢出/饱和行为、浮点舍入模式、字节序、对齐要求、对标志位（ZF/CF/OF/SF）的影响、异常触发条件 |
| **不影响结果**的细节 | 组成/实现 | 分几拍完成、走哪条数据通路、用几个微命令、是否流水线化、ALU 用几位加法器、Cache 命中与否 |

判据：**程序员能否通过读寄存器、读存储单元、观察异常来"探测"到它**——能探测 → ISA；探测不到（只影响快慢） → 组成。

**万能判定尺**：

> 换一台 ISA 相同但实现不同的机器，这个属性会不会变？
> - **会变**（节拍数、控制信号、Cache 大小、流水线级数）→ 不是 ISA
> - **不变**（指令功能、寻址结果、标志位、异常行为）→ 属于 ISA

> [!example] 判断题速练
> | 命题 | 判断 |
> |:-----|:----:|
> | 指令的功能（语义）属于 ISA | ✅ |
> | 指令执行所需的控制信号属于 ISA | ❌（属于计算机组成） |
> | 指令的执行时间 / CPI 属于 ISA | ❌（属于组成，只影响性能） |
> | 指令对标志位的影响属于 ISA | ✅（程序员可读 PSW） |
> | 微指令格式属于 ISA | ❌（微程序控制器的实现细节） |
> | 字节序（大端/小端）属于 ISA | ✅（影响程序可见的数据解释） |

### 4.0.4 CISC 与 RISC：两种 ISA 设计哲学

CISC 与 RISC 之争发生在 **ISA 层面**，是两种设计哲学的选择，不是"实现优劣"：

| 哲学 | 复杂性的承担者 | ISA 特征 |
|:-----|:---------------|:---------|
| CISC | 交给**硬件/微程序** | 指令丰富、格式多样、寻址方式多、允许存储器操作数 |
| RISC | 交给**编译器** | 指令精简、格式规整、寻址方式少、只有 Load/Store 访存 |

> [!warning] 易错点
> 对比表中"控制器用微程序还是硬布线"这一项，本质是**实现手段**而非 ISA 内容。它出现在对比表里，是因为"ISA 选择会影响实现方式"——RISC 精简并规整了指令之后，硬布线控制器才成为可能。做辨析题时注意区分这类"由 ISA 派生的实现特征"。

> [!note] 关联
> 两种指令集的完整特征对比与 RISC 六条设计原则见 [[#4.4 CISC与RISC对比]]。

## 4.1 指令格式

### 4.1.1 指令的基本格式

一条指令由两部分组成：

```
┌──────────────┬──────────────┐
│   操作码(OP)  │   地址码(A)   │
└──────────────┴──────────────┘
```

| 组成部分 | 功能 | 说明 |
|:---------|:-----|:-----|
| 操作码（OP） | 指明指令要完成的操作 | 如加、减、传送、跳转等 |
| 地址码（A） | 指明操作数的地址或操作数本身 | 可以是寄存器号、存储器地址或立即数 |

### 4.1.2 指令字长

| 类型 | 说明 | 优缺点 |
|:-----|:-----|:-------|
| 定长指令字 | 所有指令长度相同 | 简化控制器设计，但浪费空间 |
| 变长指令字 | 不同指令长度不同 | 节省空间，但控制器复杂 |

### 4.1.3 按地址码数目分类

| 类型 | 地址码个数 | 说明 |
|:-----|:----------:|:-----|
| 三地址指令 | 3 | OP A1, A2, A3 → A1 = (A1) OP (A2) |
| 二地址指令 | 2 | OP A1, A2 → A1 = (A1) OP (A2) |
| 一地址指令 | 1 | OP A1 → ACC = (ACC) OP (A1) |
| 零地址指令 | 0 | 无地址码，如空操作、停机 |

> [!example] 指令含义示例
> - 三地址：`ADD R1, R2, R3` → R1 = R2 + R3
> - 二地址：`ADD R1, R2` → R1 = R1 + R2
> - 一地址：`ADD R1` → ACC = ACC + R1

### 4.1.4 扩展操作码编码法

在指令字长固定的情况下，通过**地址码字段和操作码字段的相互借用**来扩展操作码数量。

**原则**：
- 短操作码不能是长操作码的前缀
- 每种指令的地址码个数不同，操作码长度也不同

> [!example] 扩展操作码示例
> 设指令字长16位，每个地址码占4位
>
> | 指令类型 | 操作码位数 | 地址码位数 | 指令条数 |
> |:---------:|:----------:|:----------:|:--------:|
> | 三地址 | 4位 | 12位（3×4） | 15条（0000~1110） |
> | 二地址 | 8位 | 8位（2×4） | 15条（1111 0000~1111 1110） |
> | 一地址 | 12位 | 4位（1×4） | 15条（1111 1111 0000~1111 1111 1110） |
> | 零地址 | 16位 | 0位 | 16条（1111 1111 1111 0000~1111 1111 1111 1111） |
>
> **说明**：
> - 三地址指令：操作码 0000~1110（15条），1111 留给扩展
> - 二地址指令：操作码 1111 0000~1111 1110（15条），1111 1111 留给扩展
> - 一地址指令：操作码 1111 1111 0000~1111 1111 1110（15条）
> - 零地址指令：操作码 1111 1111 1111 0000~1111 1111 1111 1111（16条）
> - 总共：15 + 15 + 15 + 16 = **61条指令**

> [!important] 考点
> - 扩展操作码的核心：短操作码不能是长操作码的前缀
> - 留出全1（或全0）作为扩展标志
> - 需要能根据要求计算各类型指令的条数

#### 扩展操作码的通用计算方法

设指令字长 $L$ 位，每个地址码字段 $d$ 位，则指令字被切成 $L/d$ 段；各级指令的操作码位数依次为 $L-3d$、$L-2d$、$L-d$、$L$。

记 $M_i$ 为 i 地址指令的**最大可用条数**，$x_i$ 为其**实际用掉的条数**（$x_i ≤ M_i$）：

| 级别 | 操作码位数 | 最大条数（递推式） |
|:-----|:----------:|:-------------------|
| 三地址 | $L-3d$ | $M_3 = 2^{L-3d}$ |
| 二地址 | $L-2d$ | $M_2 = (M_3 - x_3) × 2^{d}$ |
| 一地址 | $L-d$ | $M_1 = (M_2 - x_2) × 2^{d}$ |
| 零地址 | $L$ | $M_0 = (M_1 - x_1) × 2^{d}$，且可**全部用满** |

**核心机制**：每预留 1 个短操作码编码，就能向下一级扩展出 $2^{d}$ 条长操作码。因此"剩多少"决定**能扩几组**，$2^{d}$ 决定**每组多少条**，二者相乘才是条数——不要记成"剩多少就扩多少倍"。

> [!warning] 易错点：最后一级（零地址）不用再预留
> 零地址指令后面**已无地址字段可借**，所以最后一段的 $2^{d}$ 个编码可以全部用满（含全 1）。这就是 16 位例中最后一行为 **16** 条而非 15 条、32 位例中为 **256** 条而非 255 条的原因，也是最容易少算 1 的扣分点。

> [!example] 算例：指令字长 32 位，每段 8 位（$d = 8$）
> | 指令类型 | 固定前缀 | 操作码字段 | 地址码字段 | 可用条数 |
> |:---------|:---------|:-----------|:-----------|:--------:|
> | 三地址 | 无 | 第 1 段（8 位） | 第 2、3、4 段 | 255 |
> | 二地址 | 第 1 段全 1 | 第 2 段（8 位） | 第 3、4 段 | 255 |
> | 一地址 | 第 1、2 段全 1 | 第 3 段（8 位） | 第 4 段 | 255 |
> | 零地址 | 第 1、2、3 段全 1 | 第 4 段（8 位） | 无 | **256** |
>
> **递推过程**：$2^{8} = 256$ → 用 255 → $(256-255) × 256 = 256$ → 用 255 → 256 → 用 255 → 256
>
> **合计**：$255 × 3 + 256 = 1021$ 条
>
> **反向验证**：若三地址指令用满 256 条不预留，则二地址及以下**一条都不能有**。

#### 扩展操作码与子网划分（VLSM）的类比

| 计网子网划分 | 扩展操作码 |
|:-------------|:-----------|
| 网络前缀（高位） | 操作码（高位段） |
| 主机号（低位） | 地址码（低位段） |
| VLSM 可变长子网掩码 | 不同类型指令使用不同长度的操作码 |
| 一个 /8 网段占 $2^{24}$ 个地址 | 一条三地址指令占 $2^{24}$ 个编码空间 |
| 最长前缀匹配无歧义 | 短操作码不能是长操作码的前缀 |

本质上扩展操作码是一种**前缀码**（与 Huffman 编码同一数学性质）：任一编码都不能是另一编码的前缀，否则译码器无法判断操作码在哪里结束。

> [!note] 位号方向的约定
> 教材与考题通常把**最右（最低位）记为第 0 位**，因此"高 8 位是操作码"严格说是第 31~24 位。答题时优先画字段图，或直接写"高 8 位 / 低 8 位"，避免"0-7 位"这类方向歧义。

## 4.2 指令寻址方式

指令寻址方式确定**下一条指令的地址**。

### 4.2.1 顺序寻址

- 通过**PC（程序计数器）自动加1**来实现
- PC ← PC + 1（或 PC ← PC + 指令字长）
- 顺序执行时，指令按地址递增顺序执行

### 4.2.2 跳跃寻址

- 通过**转移指令**修改PC的值来实现
- PC ← 目标地址
- 跳跃寻址用于实现分支、循环、子程序调用等

| 跳转类型 | 说明 |
|:---------|:-----|
| 条件转移 | 满足条件时跳转，否则顺序执行 |
| 无条件转移 | 无论条件如何都跳转 |
| 调用/返回 | CALL跳转子程序，RET返回 |
| 循环控制 | 循环计数器减1，不为0则跳转 |

#### 高级语言控制结构与指令寻址的对应

**判定标准只有一个：看 PC 的内容是怎么形成的**——由硬件自增得到 → 顺序寻址；由指令装载得到 → 跳跃寻址。不能凭高级语言的语义直觉判断。

| 高级语言结构 | 底层实现 | 指令寻址方式 |
|:-------------|:---------|:-------------|
| 顺序语句 | PC 自增 | 顺序寻址 |
| `if / else` | 比较 + 条件转移（跳过 else 块） | 跳跃寻址 |
| `while / for` 循环体 | 无条件往回跳（back edge） | 跳跃寻址 |
| `break` | 无条件转移到循环外 | 跳跃寻址 |
| `continue` | 无条件转移到条件判断/递增处 | 跳跃寻址 |
| `goto` | 无条件转移 | 跳跃寻址 |
| 函数调用 | `CALL`：PC 装入入口地址，返回地址压栈或存链接寄存器 | 跳跃寻址 |
| `return` | `RET`：从栈/链接寄存器取返回地址送 PC | 跳跃寻址 |
| **中断 / 异常** | **中断隐指令**把服务程序入口地址送 PC | ❌ **不属于跳跃寻址** |

> [!warning] 易错点一：中断/异常不是跳跃寻址
> 中断与异常确实改变了执行流，但它由**中断隐指令**（硬件自动完成）送入口地址给 PC，**不是转移指令**，也不占用指令条数。选择题问"下列哪些属于跳跃寻址"时，中断响应不能选。

> [!warning] 易错点二："循环条件不满足"不一定是跳跃
> 退出循环是跳跃还是顺序，取决于**编译方案**——见下方两种典型编译结果对比。

**方案 A（条件在顶部，跳出式）**：

```
LOOP:  条件判断
       B_false → EXIT     ← 条件不满足时转移被采取 → 跳跃寻址
       循环体
       JMP LOOP           ← 每轮迭代都往回跳 → 也是跳跃寻址
EXIT:
```

**方案 B（条件在底部，落入式 fall-through）**：

```
       JMP COND
BODY:  循环体
COND:  B_true → BODY      ← 条件满足才往回跳
EXIT:                      ← 条件不满足时 PC 自增直接落入 → 顺序寻址
```

> [!note] 结论
> 方案 B 中"条件不满足"恰恰是**顺序寻址**（fall-through）。判断归属只能看"PC 是自增还是被装载"，不能看高级语言语义。
>
> 另外：**循环的每一轮迭代都至少含一次跳跃寻址**（往回跳），跳跃不是只在退出时发生；且往回跳比往前跳更常见。

**跳跃寻址的实现手段**：转移指令的地址码字段通常给出的不是绝对地址，而是**相对位移量**，即 EA = (PC) + A（详见 [[#4.3.8 相对寻址（Relative Addressing）]]）。

- 优点：生成**位置无关代码**，程序整体搬到内存别处仍能运行
- 陷阱：取指阶段 PC 已自增，**基准是"当前指令地址 + 指令字长"**
- 位移量是**有符号数**，往回跳时 A 为负

> [!note] 指令寻址 vs 数据寻址（别混）
> | 对比项 | 指令寻址 | 数据寻址 |
> |:-------|:---------|:---------|
> | 关心什么 | **下一条指令**在哪 | **操作数**在哪 |
> | 种数 | 2 种（顺序、跳跃） | 9 种（见 [[#4.3 数据寻址方式]]） |
> | 由谁完成 | PC 自增 / 转移指令 | 地址形成部件按寻址方式字段计算 EA |

**性能联系**：顺序寻址对流水线友好（PC 可预取）；跳跃寻址会造成**分支冒险与分支惩罚**，这正是 [[第五章——中央处理器#5.4 指令流水线|第五章·指令流水线]] 需要分支预测的原因——ISA 层面存在转移指令，微架构层面就必须付出这个代价。

## 4.3 数据寻址方式

数据寻址方式确定**操作数的地址**。以下为10种常见数据寻址方式。

### 4.3.1 立即寻址（Immediate Addressing）

- 操作数直接包含在指令中
- 指令格式：`OP #立即数`
- **优点**：不需要访问存储器，速度快
- **缺点**：数值大小受指令字长限制
- **有效地址**：无（操作数在指令中）

### 4.3.2 直接寻址（Direct Addressing）

- 指令中直接给出操作数的有效地址
- 指令格式：`OP A`，其中A就是有效地址
- **优点**：简单直观
- **缺点**：寻址范围受地址码位数限制
- **有效地址**：EA = A

### 4.3.3 间接寻址（Indirect Addressing）

- 指令中给出的是操作数地址的地址
- 指令格式：`OP @A`，A指向的单元中存放有效地址
- **优点**：扩大寻址范围
- **缺点**：需要多次访存，速度慢
- **有效地址**：EA = (A)

### 4.3.4 寄存器寻址（Register Addressing）

- 操作数存放在寄存器中，指令中给出寄存器编号
- 指令格式：`OP Ri`
- **优点**：不需要访存，速度快，指令字长短
- **缺点**：寄存器数量有限
- **有效地址**：EA = Ri

### 4.3.5 寄存器间接寻址（Register Indirect Addressing）

- 寄存器中存放的是操作数的有效地址
- 指令格式：`OP (Ri)`
- **优点**：扩大寻址范围
- **缺点**：需要访存
- **有效地址**：EA = (Ri)

### 4.3.6 基址寻址（Base Addressing）

- 基址寄存器的内容加上指令中的偏移量形成有效地址
- **有效地址**：EA = (BR) + A
- **特点**：基址寄存器内容由操作系统管理，用户不可修改
- **用途**：多道程序设计中的地址重定位、扩大寻址范围

### 4.3.7 变址寻址（Indexed Addressing）

- 变址寄存器的内容加上指令中的基准地址形成有效地址
- **有效地址**：EA = (IX) + A
- **特点**：变址寄存器内容由用户修改
- **用途**：数组访问、循环处理（A为数组首地址，IX为下标）

> [!note] 基址寻址 vs 变址寻址
> - 基址寻址：基址寄存器内容由OS管理，偏移量由指令给出
> - 变址寻址：基准地址由指令给出，变址寄存器内容由用户修改
> - 两者可以组合使用：EA = (BR) + (IX) + A

### 4.3.8 相对寻址（Relative Addressing）

- 程序计数器PC的内容加上指令中的偏移量形成有效地址
- **有效地址**：EA = (PC) + A
- **特点**：偏移量A是相对于当前指令的有符号数
- **用途**：转移指令，实现位置无关代码

> [!warning] 注意
> 相对寻址中，PC的值通常是当前指令地址加指令字长（即PC已指向下一条指令）

### 4.3.9 隐含寻址（Implicit Addressing）

- 某个操作数的地址**不出现在指令的地址码字段中，而由操作码隐含指定**
- **优点**：节省地址码字段 → 缩短指令字长，或腾出空间给更多操作码
- **缺点**：指令功能固定、灵活性差，需记住隐含约定
- **有效地址**：无（操作数位置由 OP 直接确定，不需计算 EA）
- **访存次数**：0（隐含对象通常是 CPU 内部寄存器）

三种典型形式：

| 形式 | 隐含的操作数 | 举例 |
|:-----|:-------------|:-----|
| 单地址指令 | 另一个操作数与结果都在 **ACC** | `ADD A` → ACC = (ACC) + (A) |
| 一地址自增/自减 | 目的操作数 = 源操作数 | `INC R1` → R1 = (R1) + 1 |
| 零地址栈指令 | 操作数在**栈顶**（由 SP 指向） | 栈机 `ADD` → 弹出两个、压回结果 |

> [!example] `i++` 的拆解
> `INC R1` 同时用了两种寻址方式：
> - **隐含寻址**：目的操作数隐含为 R1（结果写回 R1，指令中不出现第二个地址）
> - **立即寻址**：常数 1 隐含在操作码里（指令中连"1"都不用给，x86 的 `INC` 就是这样）
>
> 因此全程 **0 次访存**，是执行最快的指令形态之一。

> [!note] 与"不访存"不是一回事
> "全程在 CPU 内完成"是**立即寻址、寄存器寻址**的特征；隐含寻址的定义特征是**地址不出现在指令中**。两者常同时出现（如 `INC R1`），但不是同一件事。

### 4.3.10 堆栈寻址（Stack Addressing）

- 操作数隐含在**栈顶**，EA = (SP)，指令中**不含地址码** → 零地址指令
- **堆栈**：只允许在一端（栈顶）存取的线性结构，LIFO（后进先出）
- SP（堆栈指针）始终指向栈顶单元

| 堆栈类型 | 栈顶位置 | 取操作数访存 | 特点 |
|:---------|:---------|:----:|:-----|
| 硬堆栈（寄存器堆栈） | CPU 内的一组寄存器 | **0 次** | 最快，但容量极小 |
| 软堆栈（主存堆栈） | 主存中划出的一段 | 1 次 | 容量大，实际机器的主流 |

进出栈微操作（软堆栈、**递减栈**：向低地址生长）：

| 操作 | 微操作序列 |
|:-----|:-----------|
| **PUSH**（压栈） | `SP-1 → SP`；`数据 → MDR`；`SP → MAR`，`1 → W`；`MDR → M(MAR)` |
| **POP**（出栈） | `SP → MAR`，`1 → R`；`M(MAR) → MDR`；`MDR → 目标寄存器`；`SP+1 → SP` |

> [!important] 考点
> - 堆栈寻址对应**零地址指令**，指令字最短
> - `SP` 的修改是 CPU 内部操作，**可与访存并行**，不占额外节拍
> - 常考辨析：栈底/栈顶方向、**满递减/空递增**、栈溢出判断
> - 硬堆栈取操作数 **0 次访存**，软堆栈 **1 次访存**
> - 堆栈寻址是隐含寻址的**特例**：隐含的对象是"栈顶"，而栈顶由 SP 给出

### 4.3.11 十种寻址方式对比

| 寻址方式 | 有效地址 | 是否访存 | 速度 | 特点 |
|:---------|:---------|:--------:|:----:|:-----|
| 立即寻址 | 操作数在指令中 | 否 | 最快 | 数值受指令字长限制 |
| 直接寻址 | EA = A | 是 | 较快 | 简单，但寻址范围受限 |
| 间接寻址 | EA = (A) | 是（多次） | 慢 | 扩大寻址范围 |
| 寄存器寻址 | EA = Ri | 否 | 最快 | 寄存器数量有限 |
| 寄存器间接寻址 | EA = (Ri) | 是 | 较快 | 扩大寻址范围 |
| 基址寻址 | EA = (BR) + A | 是 | 较快 | OS管理基址，用于重定位 |
| 变址寻址 | EA = (IX) + A | 是 | 较快 | 用户修改变址，用于数组 |
| 相对寻址 | EA = (PC) + A | 是 | 较快 | 用于转移指令 |
| 隐含寻址 | 无（OP 指定） | 否 | 最快 | 缩短指令字长，但灵活性差 |
| 堆栈寻址 | EA = (SP) | 硬栈否/软栈是 | 硬栈最快 | 零地址指令，用于栈机与子程序调用 |

> [!important] 考点
> - 立即寻址和寄存器寻址不需要访存，速度最快
> - 间接寻址可能需要多次访存，速度最慢
> - 基址寻址用于OS地址重定位，变址寻址用于数组访问
> - 相对寻址常用于转移指令
> - 隐含寻址靠 OP 指定操作数（如单地址指令的 ACC），价值在于缩短指令字长
> - 堆栈寻址是隐含寻址的特例（SP 指向栈顶），对应零地址指令

## 4.4 CISC与RISC对比

### 4.4.1 基本概念

| 类型 | 全称 | 设计思想 |
|:-----|:-----|:---------|
| CISC | Complex Instruction Set Computer（复杂指令集计算机） | 指令丰富、功能强大、指令长度可变 |
| RISC | Reduced Instruction Set Computer（精简指令集计算机） | 指令精简、格式规整、只有Load/Store访存 |

### 4.4.2 详细对比

| 特征 | CISC | RISC |
|:-----|:-----|:-----|
| 指令数量 | 多（>200条） | 少（<100条） |
| 指令长度 | 可变 | 固定 |
| 指令格式 | 多种格式 | 一种或少数几种格式 |
| 寻址方式 | 多种 | 少数（Load/Store） |
| 指令执行时间 | 差异大 | 大部分在一个周期内完成 |
| 访存方式 | 允许存储器操作数 | 只有Load/Store访存 |
| 流水线 | 难以实现 | 易于实现 |
| 控制器实现 | 微程序为主 | 硬布线为主 |
| 寄存器数量 | 较少 | 较多 |
| 代表 | x86 | ARM、MIPS、RISC-V |

### 4.4.3 RISC的设计原则

1. **指令精简**：只保留最常用的基本指令
2. **Load/Store结构**：只有取数和存数指令访问存储器，其余指令在寄存器间操作
3. **硬布线控制**：采用硬布线控制器提高速度
4. **流水线优化**：指令格式规整，适合流水线执行
5. **大量通用寄存器**：减少访存次数
6. **指令长度固定**：简化指令译码

> [!important] 考点
> - RISC的核心特征：Load/Store结构、指令长度固定、硬布线控制、流水线友好
> - CISC的代表是x86，RISC的代表是ARM、MIPS、RISC-V
> - 现代x86处理器在内部将CISC指令翻译为类似RISC的微操作
