# 第三章——数据链路层

## 3.1 数据链路层功能概述

数据链路层在物理层提供服务的基础上，向网络层提供服务。其主要功能包括：

| 功能       | 说明                    |
| -------- | --------------------- |
| **封装成帧** | 将网络层的数据报加上首部和尾部，封装成帧  |
| **透明传输** | 无论数据内容是什么，都能在链路上正确传输  |
| **差错控制** | 检测和纠正传输中的比特差错         |
| **流量控制** | 控制发送方的发送速率，防止接收方来不及处理 |
| **链路管理** | 建立和维护数据链路连接           |

### 3.1.1 封装成帧

- **帧（Frame）**是数据链路层的PDU
- 帧由**帧头（首部）**、**数据部分**和**帧尾（尾部）**组成
- 帧头和帧尾中包含帧定界符（标志字段），用于标识帧的起始和结束
- 最大传输单元（MTU）：帧中数据部分的最大长度

### 3.1.2 透明传输

- **透明传输**是指数据链路层对上层交付的数据没有任何限制
- 当数据中恰好出现与帧定界符相同的比特组合时，需要采取措施避免误判
- 实现方法：
  - **字节填充（字符填充）**：在数据中的特殊字符前添加转义字符（ESC）
  - **比特填充**：采用零比特填充法（如HDLC协议）

#### 零比特填充法（HDLC）

- 帧定界符为 `01111110`
- 发送方：在数据中每遇到5个连续的1，就插入一个0
- 接收方：在数据中每遇到5个连续的1后面跟一个0，就去掉这个0

## 3.2 差错控制

### 3.2.1 差错类型

| 类型 | 说明 | 举例 |
|------|------|------|
| **比特差错** | 帧中某个比特发生了翻转（0变1或1变0） | 最常见 |
| **帧差错** | 帧丢失、帧重复或帧失序 | 需要序号机制解决 |

### 3.2.2 CRC循环冗余校验

#### 基本原理

- 发送方和接收方事先约定一个**生成多项式** $G(x)$
- 发送方在数据后面附加**冗余码（FCS，帧检验序列）**
- 接收方用相同的生成多项式进行校验

#### CRC计算步骤

1. 设数据为 $M$，生成多项式 $G(x)$ 的最高次幂为 $r$
2. 在数据 $M$ 后面添加 $r$ 个0，得到 $M \cdot 2^r$
3. 用 $M \cdot 2^r$ 除以 $G(x)$（模2除法），得到余数 $R$
4. 将余数 $R$（$r$ 位）附加到原始数据 $M$ 后面，作为FCS
5. 发送 $M + R$（即被 $G(x)$ 整除的比特串）

> [!example] CRC计算示例
> 设数据 $M = 1101011011$，生成多项式 $G(x) = x^4 + x + 1$，即 $G = 10011$（$r=4$）
>
> **步骤1**：在M后添加4个0：$11010110110000$
>
> **步骤2**：模2除法运算：
> ```
>       1100001010
>       ___________
> 10011 ) 11010110110000
>         10011
>         ----
>          10011
>          10011
>          -----
>           00001
>           00000
>           -----
>            00011
>            00000
>            -----
>             00110
>             00000
>             -----
>              01101
>              00000
>              -----
>               11011
>               10011
>               -----
>                10000
>                10011
>                -----
>                 00111
>                 00000
>                 -----
>                  01110
>                  00000
>                  -----
>                   11100
>                   10011
>                   -----
>                    11110
>                    10011
>                    -----
>                     1101  ← 余数
> ```
>
> **步骤3**：余数 $R = 1110$（4位）
>
> **步骤4**：发送的帧为 $1101011011\|1110 = 11010110111110$

#### 常见生成多项式

| 标准 | 生成多项式 | 应用 |
|------|-----------|------|
| CRC-8 | $x^8 + x^2 + x + 1$ | ATM |
| CRC-16 | $x^{16} + x^{15} + x^2 + 1$ | USB |
| CRC-32 | $x^{32} + x^{26} + x^{23} + ... + 1$ | 以太网 |

### 3.2.3 海明码

#### 基本原理

- 海明码是一种能**纠正一位错误**的编码方式
- 通过在数据位中插入若干校验位来实现
- 校验位放在 $2^k$ 的位置上（第1、2、4、8、16...位）

#### 校验位数计算

设数据位为 $m$ 位，校验位为 $k$ 位，则需满足：
$$2^k \geq m + k + 1$$

即校验位 $k$ 需满足 $2^k \geq m + k + 1$。

| 数据位 $m$ | 校验位 $k$ | 总位 $m+k$ |
|-----------|-----------|-----------|
| 1 | 2 | 3 |
| 2~4 | 3 | 5~7 |
| 5~11 | 4 | 9~15 |
| 12~26 | 5 | 17~31 |

#### 海明码计算步骤

1. 确定校验位数 $k$（满足 $2^k \geq m + k + 1$）
2. 确定校验位位置（放在 $2^k$ 位置上）
3. 每个校验位负责校验特定的数据位（被校验位的位置编号中包含该校验位编号的2的幂次）
4. 用**偶校验**（或奇校验）计算每个校验位的值

> [!example] 海明码计算示例
> 设数据为 $D_3 D_2 D_1 = 101$（3位数据），求海明码。
>
> **步骤1**：$m=3$，需要 $2^k \geq 3+k+1$，即 $2^k \geq k+4$。当 $k=3$ 时，$8 \geq 7$，满足。
>
> **步骤2**：总位数为 $3+3=6$ 位，位置编号1~6：
> - 校验位位置：$P_1$ 在位1，$P_2$ 在位2，$P_3$ 在位4
> - 数据位位置：$D_1$ 在位3，$D_2$ 在位5，$D_3$ 在位6
>
> **步骤3**：各校验位负责的位：
> - $P_1$（位1）：负责位1、3、5（二进制末位为1的位）
> - $P_2$（位2）：负责位2、3、6（二进制倒数第2位为1的位）
> - $P_3$（位4）：负责位4、5、6（二进制倒数第3位为1的位）
>
> **步骤4**：采用偶校验：
> - $P_1 \oplus D_1 \oplus D_2 = 0$，即 $P_1 \oplus 1 \oplus 0 = 0 \Rightarrow P_1 = 1$
> - $P_2 \oplus D_1 \oplus D_3 = 0$，即 $P_2 \oplus 1 \oplus 1 = 0 \Rightarrow P_2 = 0$
> - $P_3 \oplus D_2 \oplus D_3 = 0$，即 $P_3 \oplus 0 \oplus 1 = 0 \Rightarrow P_3 = 1$
>
> **结果**：海明码为 $P_1 P_2 D_1 P_3 D_2 D_3 = 101101$
>
> **纠错**：接收方重新计算校验位，若 $S_3 S_2 S_1$ 不全为0，则 $S_3 S_2 S_1$ 的十进制值就是出错位的编号。

## 3.3 流量控制与可靠传输

### 3.3.1 停止-等待协议（Stop-and-Wait, SW）

#### 工作原理

- 发送方发送一帧后，必须等待接收方的确认（ACK）才能发送下一帧
- 接收方收到帧后发送确认

#### 工作过程

```
发送方                    接收方
  |----DATA 0------------>|
  |                        | (处理、校验)
  |<---ACK 0---------------|
  |----DATA 1------------>|
  |                        |
  |<---ACK 1---------------|
  |                        |
```

#### 超时重传

- 发送方发送帧后启动超时计时器
- 若在规定时间内未收到ACK，则重传该帧
- 帧和ACK都需要编号（0和1交替使用）

#### 信道利用率计算

在无差错情况下，信道利用率为：
$$U = \frac{T_f}{T_f + RTT + T_a}$$

其中：
- $T_f$：发送一个帧的时间
- $RTT$：往返时间
- $T_a$：确认帧的发送时间（通常很小，可忽略）

简化后：
$$U \approx \frac{T_f}{T_f + RTT} = \frac{1}{1 + 2a}$$

其中 $a = \frac{传播时延}{发送时延}$

> [!example] 例题
> 链路长度为 2000km，数据率为 1Mbps，帧长为 1000bit，信号传播速率为 $2 \times 10^8$ m/s。
>
> 发送时延 $T_f = 1000 / (1 \times 10^6) = 10^{-3}$ s = 1 ms
>
> 传播时延 $T_p = 2000 \times 10^3 / (2 \times 10^8) = 10^{-2}$ s = 10 ms
>
> 信道利用率 $U = \frac{1}{1 + 2 \times 10/1} = \frac{1}{21} \approx 4.76\%$

### 3.3.2 后退N帧协议（Go-Back-N, GBN）

#### 工作原理

- 发送方可以连续发送多个帧，不需要等待ACK
- 采用**滑动窗口**机制，发送窗口大小为 $W_T$（$W_T \leq 2^n - 1$，$n$ 为序号位数）
- 接收窗口大小为 **1**（只按序接收）
- 若某一帧出错，接收方丢弃该帧及后续所有帧，发送方回退到出错帧重传

#### GBN协议要点

| 要点 | 说明 |
|------|------|
| 发送窗口大小 | $1 \leq W_T \leq 2^n - 1$ |
| 接收窗口大小 | 固定为 1 |
| 确认方式 | 累积确认（ACK n 表示n及之前的帧都已正确收到） |
| 重传方式 | 出错帧及其后所有帧全部重传 |

#### 信道利用率

$$U = \frac{W_T \times T_f}{T_f + RTT + T_a} \approx \frac{W_T}{1 + 2a}$$

当 $W_T \geq 1 + 2a$ 时，信道利用率可达100%。

### 3.3.3 选择重传协议（Selective Repeat, SR）

#### 工作原理

- 发送方可以连续发送多个帧
- 接收窗口大小大于1，可以接收乱序到达的帧并缓存
- 只重传出错的帧，不重传已正确接收的帧

#### SR协议要点

| 要点 | 说明 |
|------|------|
| 发送窗口大小 | $1 \leq W_T \leq 2^{n-1}$ |
| 接收窗口大小 | $1 \leq W_R \leq 2^{n-1}$ |
| 发送窗口+接收窗口 | $W_T + W_R \leq 2^n$ |
| 确认方式 | 逐帧确认（非累积确认） |
| 重传方式 | 只重传出错帧 |

#### 三种协议对比

| 对比项 | SW | GBN | SR |
|--------|----|----|----|
| 发送窗口 | 1 | $2^n - 1$ | $2^{n-1}$ |
| 接收窗口 | 1 | 1 | $2^{n-1}$ |
| 信道利用率 | 最低 | 较高 | 最高 |
| 缓存需求 | 最小 | 最小 | 较大 |
| 重传策略 | 重传一帧 | 重传多帧 | 只重传出错帧 |
| 确认方式 | 逐帧确认 | 累积确认 | 逐帧确认 |
| 复杂度 | 最简单 | 中等 | 最复杂 |

> [!warning] 易错点
> - GBN发送窗口最大为 $2^n - 1$（不是 $2^n$）
> - SR发送窗口最大为 $2^{n-1}$（不是 $2^n - 1$）
> - SR中 $W_T + W_R \leq 2^n$，当 $W_T = W_R = 2^{n-1}$ 时达到最大

## 3.4 介质访问控制

介质访问控制（MAC）解决多个站点共享同一信道时的信道分配问题，分为两大类：

| 类型 | 说明 | 典型协议 |
|------|------|----------|
| **信道划分** | 将信道划分为子信道，各站点独占子信道 | FDM、TDM、STDM、WDM、CDM |
| **随机访问** | 站点争用信道，可能冲突 | ALOHA、CSMA/CD、CSMA/CA |
| **轮询访问** | 按规则轮流使用信道 | 令牌传递、轮询 |

### 3.4.1 信道划分介质访问控制

#### 频分多路复用（FDM）

- 将频带划分为多个不重叠的子频带，每个子频带分配给一个用户
- 用户在时间上同时占用不同频率
- 各子频带之间需留**保护频带**以防串扰
- 适用于模拟信号传输（如广播电视、无线电）

#### 时分多路复用（TDM）

- 将时间划分为等长的**TDM帧**（时间帧），每个帧内为每个用户分配固定的时隙
- 用户在频率上相同，在时间上轮流占用
- 适用于数字信号传输

#### 统计时分多路复用（STDM）

- 又称**异步时分多路复用**
- 不固定分配时隙，而是**按需动态分配**
- 每个时隙需携带地址信息，开销略大
- 利用率高于TDM（TDM中空闲时隙被浪费）

> [!tip] TDM vs STDM
> - TDM：固定时隙，无额外开销，但空闲时隙浪费
> - STDM：动态分配，利用率高，但需额外地址开销

#### 波分多路复用（WDM）

- 光纤通信中的频分多路复用
- 不同波长（频率）的光信号在同一根光纤中传输
- **密集波分复用（DWDM）**：波长间隔很小，复用信道数多

#### 码分多路复用（CDM）

- 又称**码分多址（CDMA）**
- 每个用户分配一个唯一的**码片序列（Chip Sequence）**
- 所有用户使用同一频率、同一时间发送，靠不同码片序列区分

> [!important] CDMA码片序列规则
> 1. 分配给每个站的码片序列必须**相互正交**
> 2. 规格化内积：$S_i \cdot S_j = \begin{cases} 1 & i = j \\ 0 & i \neq j \end{cases}$
> 3. 发送1：发送自己的码片序列；发送0：发送码片序列的反码
> 4. 接收方用发送方的码片序列与收到的信号做**规格化内积**，结果为+1表示发送了1，-1表示发送了0，0表示未发送

> [!example] CDMA计算示例
> 设4个站的码片序列为：
> - $S_1 = (-1\ -1\ -1\ +1\ +1\ -1\ +1\ +1)$
> - $S_2 = (-1\ +1\ -1\ +1\ +1\ +1\ -1\ -1)$
> - $S_3 = (-1\ +1\ -1\ -1\ -1\ +1\ -1\ +1)$
> - $S_4 = (-1\ -1\ +1\ -1\ +1\ +1\ +1\ -1)$
>
> 收到的叠加信号 $S = (-1\ +1\ -3\ +1\ -1\ -3\ +1\ +1)$
>
> 分别计算内积：
> - $S \cdot S_1 = \frac{1}{8}[(−1)(−1)+(1)(−1)+(−3)(−1)+(1)(1)+(−1)(1)+(−3)(−1)+(1)(1)+(1)(1)] = \frac{8}{8} = 1$ → $S_1$发送了**1**
> - $S \cdot S_2 = \frac{1}{8}[(-1)(-1)+(1)(1)+(-3)(-1)+(1)(1)+(-1)(1)+(-3)(1)+(1)(-1)+(1)(-1)] = \frac{-1-1-1+1-1-3-1-1}{8} = \frac{-8}{8} = -1$ → $S_2$发送了**0**
> - $S \cdot S_3 = \frac{1}{8}[1+1+3-1+1-3-1+1] = \frac{2}{8} \neq \pm1$ → $S_3$**未发送**
> - $S \cdot S_4 = \frac{1}{8}[1-1-3-1-1-3+1-1] = \frac{-8}{8} = -1$ → $S_4$发送了**0**

### 3.4.2 ALOHA协议

#### 纯ALOHA（Pure ALOHA）

- 最早的无线的随机访问协议，1970年代由夏威夷大学提出
- **工作原理**：任何站点有数据就立即发送
- **冲突检测**：发送后等待ACK，超时未收到则认为冲突，随机等待后重传
- **脆弱时间（冲突窗口）**：$2 \times T_f$（两倍帧发送时间）
  - 因为两个站点只要在 $2T_f$ 时间窗口内发送就会冲突

**纯ALOHA的效率**：

$$S = G \times e^{-2G}$$

其中 $G$ 为每个帧时间内的平均发送次数（包括新帧和重传帧）。

当 $G = 0.5$ 时，吞吐量最大：$S_{max} = 0.5 \times e^{-1} \approx 18.4\%$

#### 时隙ALOHA（Slotted ALOHA）

- 将时间划分为等长的**时隙（Slot）**，每个时隙等于一帧的发送时间
- **工作原理**：站点有数据时不能立即发送，必须等待下一个时隙开始才能发送
- **冲突窗口**：$T_f$（一个帧发送时间），比纯ALOHA减半
- 所有发送只能在时隙边界开始，减少了冲突可能性

**时隙ALOHA的效率**：

$$S = G \times e^{-G}$$

当 $G = 1$ 时，吞吐量最大：$S_{max} = 1 \times e^{-1} \approx 36.8\%$

#### 两种ALOHA对比

| 对比项 | 纯ALOHA | 时隙ALOHA |
|--------|---------|-----------|
| 发送时机 | 随时发送 | 时隙开始时发送 |
| 冲突窗口 | $2T_f$ | $T_f$ |
| 最大吞吐量 | 18.4% | 36.8% |
| 最优G值 | 0.5 | 1.0 |
| 实现复杂度 | 简单 | 需要时间同步 |
| 公式 | $S = Ge^{-2G}$ | $S = Ge^{-G}$ |

> [!important] 考点提示
> - 时隙ALOHA的最大效率是纯ALOHA的**2倍**
> - 冲突窗口：纯ALOHA = $2T_f$，时隙ALOHA = $T_f$
> - ALOHA是CSMA/CD的前身，CSMA/CD在ALOHA基础上增加了**载波监听**

### 3.4.3 CSMA/CD协议

#### 基本原理

**CSMA/CD（载波监听多路访问/冲突检测）**，用于有线局域网（以太网）。

- **先听后发**：发送前先监听信道是否空闲
- **边发边听**：发送过程中持续检测是否发生冲突
- **冲突停发**：若检测到冲突，立即停止发送
- **随机重发**：冲突后等待随机时间再尝试发送

#### 争用期

- **争用期（冲突窗口）** = $2 \times$ 传播时延（往返时延）
- 发送方在争用期内未检测到冲突，则该帧发送过程中不会发生冲突
- 最小帧长要求：帧的发送时间必须大于等于争用期

#### 最小帧长计算

$$最小帧长 = 2 \times \frac{传播时延}{1} \times 数据率 = 2 \times \frac{信道长度}{传播速率} \times 数据率$$

即：$L_{min} = 2 \times \frac{d}{v} \times R$

> [!example] 例题
> 以太网中，信道长度为 2km，信号传播速率为 $2 \times 10^8$ m/s，数据率为 10Mbps。
>
> 传播时延 $T_p = \frac{2000}{2 \times 10^8} = 10^{-5}$ s
>
> 争用期 $= 2 \times 10^{-5}$ s
>
> 最小帧长 $= 2 \times 10^{-5} \times 10 \times 10^6 = 200$ bit = 25 Byte
>
> （实际以太网最小帧长为64字节，因为考虑了其他因素）

#### 截断二进制指数退避算法

冲突后，第 $k$ 次重传前等待的随机时间为：
$$t = r \times \tau$$
其中：
- $\tau$ 为争用期
- $r$ 为从 $\{0, 1, 2, ..., 2^{\min(k,10)} - 1\}$ 中随机选取的整数
- 当 $k \leq 10$ 时，$r$ 从 $\{0, 1, ..., 2^k - 1\}$ 中选取
- 当 $10 < k \leq 16$ 时，$r$ 从 $\{0, 1, ..., 2^{10} - 1\}$ 中选取
- 当 $k = 16$ 时，丢弃该帧，向上层报告错误

### 3.4.4 CSMA/CA协议

**CSMA/CA（载波监听多路访问/冲突避免）**，用于无线局域网（IEEE 802.11）。

- 无线环境中难以实现冲突检测（隐蔽站问题、暴露站问题）
- 采用**预约信道**和**ACK确认**机制来避免冲突
- 使用**RTS/CTS**握手机制：发送方先发送RTS（请求发送），接收方回复CTS（允许发送），其他站收到CTS后推迟发送

### 3.4.5 令牌传递

- 网络中有一个特殊帧称为**令牌（Token）**，沿环网循环传递
- 只有持有令牌的站点才能发送数据
- 发送完成后释放令牌
- 适用于负载较重的网络，不会发生冲突

### 3.4.6 以太网MAC帧格式

```
| 前导码 8B | 目的地址 6B | 源地址 6B | 类型 2B | 数据 46~1500B | FCS 4B |
```

| 字段 | 长度 | 说明 |
|------|------|------|
| 前导码 | 8字节 | 前7字节为同步码（10101010），第8字节为帧开始定界符（10101011） |
| 目的地址 | 6字节 | 目的MAC地址 |
| 源地址 | 6字节 | 源MAC地址 |
| 类型 | 2字节 | 标识上层协议类型 |
| 数据 | 46~1500字节 | 上层交付的数据，最小46字节（不足需填充） |
| FCS | 4字节 | 帧检验序列（CRC-32校验） |

> [!tip] 考点提示
> - 以太网MAC帧最小长度为 **64字节**（不含前导码），最大为 **1518字节**
> - 最小帧长 = 6 + 6 + 2 + 46 + 4 = 64字节
> - 最大帧长 = 6 + 6 + 2 + 1500 + 4 = 1518字节

## 3.5 局域网技术

### 3.5.1 局域网概述

局域网（LAN）的特点：

| 特性 | 说明 |
|------|------|
| 覆盖范围 | 较小（校园、建筑、房间） |
| 传输速率 | 高（10Mbps~10Gbps） |
| 误码率 | 低 |
| 拓扑结构 | 星型、总线型、环型 |
| 传输介质 | 双绞线、光纤、无线 |
| 共享性 | 多个设备共享同一信道 |

IEEE 802标准委员会将数据链路层拆分为两个子层：

| 子层 | 功能 | 标准 |
|------|------|------|
| **LLC（逻辑链路控制）** | 向网络层提供统一接口，与传输介质无关 | IEEE 802.2 |
| **MAC（介质访问控制）** | 管理设备对物理介质的访问 | IEEE 802.3/802.5/802.11 |

### 3.5.2 MAC地址

MAC地址（硬件地址/物理地址）是数据链路层使用的地址。

| 属性 | 说明 |
|------|------|
| 长度 | 48位（6字节） |
| 格式 | 前24位为OUI（厂商代码），后24位为厂商分配 |
| 表示 | 如 `08-00-2B-9E-E5-1C`（十六进制） |
| 类型 | 单播（第1字节最低位=0）、组播（=1）、广播（全1，`FF-FF-FF-FF-FF-FF`） |
| 唯一性 | 全球唯一（由IEEE分配OUI） |
| 所在层次 | 数据链路层（MAC子层） |

> [!important] MAC地址 vs IP地址
> - IP地址是**网络层**地址，逻辑地址，可变
> - MAC地址是**数据链路层**地址，物理地址，固化在网卡中
> - 帧在链路上传输时，源MAC和目的MAC不变（同一链路内）
> - IP地址在整个网络传输中可能变化（经过路由器）

### 3.5.3 以太网

以太网（IEEE 802.3）是目前最主流的局域网技术。

| 版本 | 速率 | 传输介质 | 特点 |
|------|------|----------|------|
| 10BASE-T | 10Mbps | 双绞线 | 星型拓扑，集线器连接 |
| 100BASE-TX | 100Mbps | 双绞线 | 快速以太网 |
| 1000BASE-T | 1Gbps | 双绞线 | 千兆以太网 |
| 10GBASE-T | 10Gbps | 双绞线/光纤 | 万兆以太网 |

以太网使用CSMA/CD协议，但现代交换式以太网（全双工）不再需要CSMA/CD。

### 3.5.4 虚拟局域网（VLAN）

#### VLAN概述

- VLAN通过软件将一个物理局域网划分为多个**逻辑局域网**
- 同一VLAN内的设备可以直接通信，不同VLAN间需要通过路由器/三层交换机
- IEEE 802.1Q标准定义了VLAN帧格式

#### VLAN帧格式

在以太网MAC帧的源地址和类型字段之间插入4字节的**VLAN标签**：

```
| 前导码 8B | 目的地址 6B | 源地址 6B | VLAN标签 4B | 类型 2B | 数据 46~1500B | FCS 4B |
```

VLAN标签结构：

| 字段 | 位数 | 说明 |
|------|------|------|
| TPID | 16位 | 标签协议标识符，固定为0x8100 |
| TCI | 16位 | 标签控制信息 |
| - PRI | 3位 | 优先级 |
| - CFI | 1位 | 规范格式指示 |
| - VID | 12位 | VLAN ID，范围1~4094（0和4095保留） |

#### VLAN的划分方式

| 划分方式 | 说明 | 优缺点 |
|----------|------|--------|
| **基于端口** | 按交换机端口划分 | 简单，但主机移动需重新配置 |
| **基于MAC地址** | 按网卡MAC地址划分 | 主机移动无需重配，但配置量大 |
| **基于IP地址** | 按网络层IP划分 | 跨VLAN路由方便，但需检查IP |
| **基于协议** | 按网络层协议划分 | 适用于多协议环境 |

#### VLAN的优势

- **限制广播域**：每个VLAN是一个独立的广播域，减少广播风暴
- **增强安全性**：不同VLAN间默认隔离
- **灵活管理**：逻辑分组不受物理位置限制
- **节省带宽**：广播流量被限制在VLAN内

### 3.5.5 数据链路层设备

#### 网桥

- 工作在**数据链路层**（MAC子层）
- 根据**MAC地址**转发帧
- 连接多个局域网段，每个端口对应一个冲突域
- 具有**自学习**功能：通过查看帧的源MAC地址学习MAC地址与端口的映射

**透明网桥的自学习过程**：

1. 网桥收到一帧时，查看**源MAC地址**，将（源MAC, 端口）记录到转发表中
2. 查看**目的MAC地址**：
   - 若在转发表中找到，且端口≠入端口，则从对应端口转发
   - 若在转表中找到，且端口=入端口，则丢弃（无需转发）
   - 若不在转发表中，则**泛洪**（向除入端口外所有端口转发）

> [!example] 网桥转发表学习示例
> 假设网桥有端口1和端口2，初始转发表为空：
>
> | 步骤 | 收到的帧 | 源MAC | 目的MAC | 入端口 | 网桥动作 | 转发表更新 |
> |------|----------|-------|---------|--------|----------|------------|
> | 1 | A→B | A | B | 1 | 泛洪 | (A, 1) |
> | 2 | B→A | B | A | 2 | 从端口1转发 | (A,1), (B,2) |
> | 3 | A→C | A | C | 1 | 泛洪（C未知） | (A,1), (B,2) |
> | 4 | C→A | C | A | 2 | 从端口1转发 | (A,1), (B,2), (C,2) |

#### 交换机

- 交换机本质上是**多端口网桥**
- 工作在数据链路层
- 每个端口独占带宽（独享冲突域）
- 全双工通信，无CSMA/CD冲突

**交换机的转发方式**：

| 方式 | 说明 | 优缺点 |
|------|------|--------|
| **直通交换** | 收到目的地址后立即转发 | 延迟小，但不检查错误 |
| **存储转发** | 收到完整帧后校验再转发 | 可检测错误，延迟较大 |
| **碎片隔离** | 收到前64字节后转发 | 过滤冲突碎片 |

> [!important] 冲突域与广播域
> | 设备 | 冲突域 | 广播域 |
> |------|--------|--------|
> | 集线器（Hub） | 1个（所有端口共享） | 1个 |
> | 交换机（Switch） | 每个端口1个 | 1个（默认） |
> | 路由器（Router） | 每个接口1个 | 每个接口1个 |
> | VLAN交换机 | 每个端口1个 | 每个VLAN 1个 |

## 3.6 广域网协议

### 3.6.1 PPP协议

PPP（Point-to-Point Protocol，点对点协议）是目前最广泛使用的广域网数据链路层协议，用于在点对点链路上传输数据。

#### PPP协议的组成

PPP由三个部分组成：

| 组成部分 | 功能 | 对应协议 |
|----------|------|----------|
| **链路控制协议（LCP）** | 建立、配置、测试和管理数据链路 | LCP |
| **网络控制协议（NCP）** | 为不同网络层协议配置和协商 | IPCP（IP）、IPXCP（IPX）等 |
| **封装方式** | 将网络层数据报封装到串行链路 | HDLC-like帧格式 |

#### PPP帧格式

PPP帧格式与HDLC类似，采用面向字节的帧结构：

```
| 标志F 1B | 地址A 1B | 控制C 1B | 协议P 2B | 数据 0~1500B | FCS 2~4B | 标志F 1B |
```

| 字段 | 长度 | 说明 |
|------|------|------|
| **标志（F）** | 1字节 | 帧定界符，固定为 `0x7E`（01111110） |
| **地址（A）** | 1字节 | 固定为 `0xFF`（全1），表示所有站（点对点链路不需要寻址） |
| **控制（C）** | 1字节 | 固定为 `0x03`，表示无序号帧（无连接服务） |
| **协议（P）** | 2字节 | 标识数据部分所属的网络层协议 |
| **数据** | 不定 | 上层数据，默认MTU为1500字节 |
| **FCS** | 2~4字节 | 帧检验序列（CRC校验） |

**协议字段常见值**：

| 协议字段值 | 含义 |
|------------|------|
| 0x0021 | IP数据报 |
| 0xC021 | LCP数据 |
| 0x8021 | NCP数据（IPCP） |
| 0xC023 | PAP认证 |
| 0xC223 | CHAP认证 |

#### PPP的透明传输

PPP支持两种传输方式，透明传输方法不同：

| 传输方式 | 透明传输方法 | 说明 |
|----------|-------------|------|
| **异步传输**（字符） | 字节填充（转义字符法） | 遇到 `0x7E` → `0x7D, 0x5E`；遇到 `0x7D` → `0x7D, 0x5D` |
| **同步传输**（比特） | 零比特填充（同HDLC） | 每5个连续1后插入一个0 |

#### PPP的工作状态

PPP链路的状态转换：

```
        链路不可用（Dead）
              │
              ↓ 物理链路建立
        建立链路（Establish）
              │ LCP协商成功
              ↓
        鉴别（Authenticate） ← 可选
              │ 鉴别通过
              ↓
        网络层协议（Network）  ← NCP协商分配IP
              │ 数据传输完成
              ↓ LCP终止
        链路终止（Terminate）
              │
              ↓
        链路不可用（Dead）
```

> [!important] PPP状态转换要点
> 1. **Dead → Establish**：物理层链路建立后，进入LCP协商阶段
> 2. **Establish → Authenticate**：LCP协商成功后，可选进行身份认证
> 3. **Authenticate → Network**：认证通过后，进入NCP协商（分配IP等）
> 4. **Network**：数据传输阶段，可正常收发网络层数据
> 5. **Network → Terminate → Dead**：LCP发送Terminate-Request终止链路

#### PPP的认证协议

| 协议 | 全称 | 特点 |
|------|------|------|
| **PAP** | 口令认证协议 | 明文传输密码，两次握手，安全性低 |
| **CHAP** | 质询握手认证协议 | 密文传输（MD5加密），三次握手，安全性高 |

**CHAP认证过程**：
1. 服务器发送**质询**（随机数）
2. 客户端用密码和质询做MD5运算，返回**应答**
3. 服务器验证应答，返回**成功/失败**

#### PPP协议的特点

- **简单**：不提供纠错、不提供流量控制、不需要序号、不支持多点链路
- **不可靠**：只做检错（FCS），不做纠错和重传
- **面向字节**：帧长度为整数个字节
- **支持多种网络层协议**：通过协议字段区分
- **支持认证**：PAP和CHAP

> [!warning] 易错点
> - PPP帧的地址字段固定为 `0xFF`，控制字段固定为 `0x03`
> - PPP**不使用**序号和确认机制，因此不可靠
> - PPP是**点对点**协议，不支持多点通信
> - PPP可以在**异步**和**同步**链路上工作

### 3.6.2 HDLC协议

HDLC（High-level Data Link Control，高级数据链路控制）是面向比特的数据链路层协议。

#### HDLC的基本概念

- 面向**比特**的协议（帧格式以比特为单位）
- 采用**零比特填充**实现透明传输
- 支持**全双工**通信
- 传输效率高，可靠性高

#### HDLC的站类型和工作方式

| 类型 | 说明 |
|------|------|
| **主站** | 负责控制链路，发送命令帧 |
| **从站** | 在主站控制下工作，发送响应帧 |
| **复合站** | 兼具主站和从站功能 |

| 工作方式 | 说明 |
|----------|------|
| **正常响应方式（NRM）** | 主站控制，从站需主站允许才能发送 |
| **异步平衡方式（ABM）** | 复合站平等，可自主发送 |
| **异步响应方式（ARM）** | 从站可自主发送，但主站负责链路维护 |

#### HDLC帧格式

```
| 标志F 1B | 地址A 1~多B | 控制C 1~2B | 数据 N | FCS 2~4B | 标志F 1B |
```

| 字段 | 长度 | 说明 |
|------|------|------|
| **标志（F）** | 1字节 | 帧定界符，固定为 `0x7E`（01111110） |
| **地址（A）** | 1~多字节 | 从站地址 |
| **控制（C）** | 1~2字节 | 帧类型和序号信息 |
| **数据** | 不定 | 传输的数据 |
| **FCS** | 2~4字节 | 帧检验序列（CRC校验） |

#### HDLC的三种帧类型

| 帧类型 | 控制字段格式 | 功能 |
|--------|-------------|------|
| **信息帧（I帧）** | 第1位=0 | 传送用户数据，带序号和确认 |
| **监督帧（S帧）** | 前两位=10 | 流量控制和差错控制（RR/REJ/RNR/SREJ） |
| **无编号帧（U帧）** | 前两位=11 | 链路管理（建链/拆链等） |

#### PPP vs HDLC对比

| 对比项 | PPP | HDLC |
|--------|-----|------|
| 面向 | 字节 | 比特 |
| 地址字段 | 固定0xFF | 实际的从站地址 |
| 协议字段 | 有（2字节） | 无 |
| 序号/确认 | 无 | 有（I帧带序号） |
| 可靠性 | 不可靠（只检错） | 可靠（检错+重传） |
| 认证 | 支持PAP/CHAP | 不支持 |
| 多协议支持 | 支持（协议字段区分） | 不支持 |
| 应用 | 广域网拨号、路由器互联 | 专用线路、早期广域网 |
| 标准化 | RFC标准，跨厂商互通 | 厂商私有实现较多 |

> [!important] 考点提示
> - PPP和HDLC的帧定界符都是 `0x7E`
> - PPP**面向字节**，用字节填充；HDLC**面向比特**，用零比特填充
> - PPP**不可靠**（无重传），HDLC**可靠**（有重传）
> - PPP支持**多种网络层协议**，HDLC通常不支持
> - PPP帧中地址固定 `0xFF`，HDLC帧中地址是实际从站地址

## 3.7 交换

### 3.7.1 电路交换

- 通信前建立一条从源到目的的专用物理通路
- 通信过程中独占该通路
- 通信结束后释放通路

**特点**：
- 建立连接有延迟
- 一旦建立连接，传输延迟小
- 线路利用率低（独占）
- 适用于实时大量数据传输（如电话通信）

### 3.7.2 报文交换

- 以**报文**为单位进行存储转发
- 整个报文先存储在交换节点，再转发到下一个节点
- 无需建立连接

**特点**：
- 无建立连接延迟
- 但每个节点的存储转发延迟大
- 线路利用率较高
- 不适用于实时通信

### 3.7.3 分组交换

- 以**分组（Packet）**为单位进行存储转发
- 将报文分成较小的分组，每个分组独立传输和路由
- 每个分组有首部（含目的地址等信息）

**特点**：
- 存储转发延迟较小（分组比报文小）
- 线路利用率高
- 可靠性高（每个分组可独立选路）
- 有额外开销（每个分组都需要首部）

### 3.7.4 三种交换方式对比

| 对比项 | 电路交换 | 报文交换 | 分组交换 |
|--------|---------|---------|---------|
| 建立连接 | 需要 | 不需要 | 不需要（虚电路方式需要） |
| 传输单位 | 整个报文 | 整个报文 | 分组 |
| 存储转发 | 无 | 有 | 有 |
| 传输延迟 | 小（建立后） | 大 | 较小 |
| 线路利用率 | 低 | 较高 | 高 |
| 额外开销 | 无 | 无 | 分组首部 |
| 适用场景 | 实时通信 | 非实时 | 数据通信 |

## 3.8 考点总结

> [!warning] 高频考点
> 1. CRC循环冗余校验的计算（模2除法）
> 2. 海明码的计算（校验位数确定、校验位计算、纠错）
> 3. 三种可靠传输协议的对比（SW、GBN、SR）
> 4. 信道利用率的计算（含发送窗口大小）
> 5. CSMA/CD协议的最小帧长计算
> 6. 以太网MAC帧格式
> 7. 三种交换方式的对比
> 8. **ALOHA协议的吞吐量公式和最大效率**（纯ALOHA 18.4%，时隙ALOHA 36.8%）
> 9. **CDMA码片序列的正交性和内积计算**
> 10. **PPP协议的帧格式、状态转换和特点**
> 11. **PPP vs HDLC的对比**
> 12. **VLAN的帧格式和划分方式**
> 13. **网桥/交换机的自学习过程**
> 14. **冲突域与广播域的区分**

> [!note] 易错点
> - CRC模2除法中，除数（生成多项式）的最高位必须为1
> - 海明码中校验位的位置是 $2^k$（1、2、4、8...），不是随意放置
> - GBN的发送窗口最大为 $2^n - 1$，SR的发送窗口最大为 $2^{n-1}$
> - 以太网最小帧长64字节（不含前导码），数据部分最小46字节
> - CSMA/CD中，争用期 = $2 \times$ 单程传播时延
> - 纯ALOHA冲突窗口是 $2T_f$，时隙ALOHA是 $T_f$，时隙ALOHA效率是纯ALOHA的2倍
> - CDMA接收方做**规格化内积**（需除以码片长度），结果+1=发送1，-1=发送0，0=未发送
> - PPP面向字节，地址固定0xFF，控制固定0x03，**不可靠**（无序号无重传）
> - HDLC面向比特，有三种帧（I帧/S帧/U帧），**可靠**（有重传）
> - PPP和HDLC的帧定界符都是0x7E
> - 交换机每个端口是一个冲突域，但默认所有端口属于同一个广播域
> - VLAN通过802.1Q标签划分广播域，VLAN间通信需要路由器/三层交换机
