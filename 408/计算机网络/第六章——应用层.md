# 第六章——应用层

## 6.1 DNS域名系统

### 6.1.1 域名结构

DNS（Domain Name System，域名系统）采用**层次化树状结构**的命名方式。

#### 域名层次

```
                    根域（.）
                   /   |   \
              com   edu   org   cn
             / | \   |    |     \
          ...  ...  ...  ...  ...  ...
```

- **根域**：最高层次，用 `.` 表示（通常省略）
- **顶级域（TLD）**：分为国家顶级域（.cn、.us）和通用顶级域（.com、.edu、.org、.net）
- **二级域**：如 `tsinghua.edu.cn` 中的 `tsinghua`
- **三级域及以下**：如 `mail.tsinghua.edu.cn` 中的 `mail`

#### 域名书写规则

- 域名不区分大小写
- 每个标号不超过63个字符
- 完整域名不超过255个字符
- 从右向左层次递减

### 6.1.2 DNS服务器层次

| 层次 | 说明 |
|------|------|
| **根DNS服务器** | 全球共13组（逻辑上），知道所有顶级域DNS服务器的地址 |
| **顶级域DNS服务器** | 管理各自顶级域下的授权DNS服务器 |
| **权威DNS服务器** | 负责特定区域的域名解析，存储区域内主机的域名到IP的映射 |
| **本地DNS服务器** | 也称递归解析器，通常由ISP提供，负责处理用户的DNS查询请求 |

### 6.1.3 域名解析过程

#### 递归查询

- 主机向本地DNS服务器发出查询请求
- 本地DNS服务器代替主机进行迭代查询，最终返回结果
- 主机只需发出一次请求，等待最终结果

#### 迭代查询

- 本地DNS服务器向根DNS服务器查询
- 根DNS服务器返回顶级域DNS服务器的地址
- 本地DNS服务器再向顶级域DNS服务器查询
- 顶级域DNS服务器返回权威DNS服务器的地址
- 本地DNS服务器再向权威DNS服务器查询
- 权威DNS服务器返回最终结果

#### 完整解析过程

```
主机 → 本地DNS服务器 → 根DNS服务器 → 顶级域DNS服务器 → 权威DNS服务器
  |         |                |                  |                  |
  |  递归查询  |              |                  |                  |
  |<---------|              |                  |                  |
  |         |  迭代查询      |                  |                  |
  |         |-------------->|                  |                  |
  |         |<-- 顶级域DNS地址|                  |                  |
  |         |  迭代查询      |                  |                  |
  |         |------------------------------>|                  |
  |         |<-- 权威DNS地址                  |                  |
  |         |  迭代查询      |                  |                  |
  |         |----------------------------------------------->|
  |         |<-- IP地址                                        |
  |<--------|  返回结果                                        |
```

> [!tip] 考点提示
> - 主机到本地DNS服务器之间通常是**递归查询**
> - 本地DNS服务器到其他DNS服务器之间通常是**迭代查询**
> - DNS使用**UDP**协议，端口为**53**
> - DNS缓存可以加速后续查询（有TTL）

## 6.2 HTTP协议

### 6.2.1 HTTP概述

- **HTTP（HyperText Transfer Protocol，超文本传输协议）**是万维网的应用层协议
- 基于 **TCP** 协议，默认端口 **80**（HTTPS为443）
- HTTP是无状态协议（不记录用户状态）
- HTTP/1.0 是非持久连接，HTTP/1.1 默认使用持久连接

### 6.2.2 HTTP报文格式

#### HTTP请求报文

```
方法  URL  HTTP版本          ← 请求行
首部字段名: 值               ← 首部行
首部字段名: 值
                            ← 空行（表示首部结束）
请求体（可选）               ← 请求体
```

**常见请求方法**：

| 方法 | 说明 |
|------|------|
| **GET** | 请求获取URL指定的资源 |
| **POST** | 向指定资源提交数据 |
| **PUT** | 上传文件 |
| **DELETE** | 删除指定资源 |
| **HEAD** | 只获取响应首部（不获取资源体） |

#### HTTP响应报文

```
HTTP版本  状态码  状态短语      ← 状态行
首部字段名: 值               ← 首部行
首部字段名: 值
                            ← 空行（表示首部结束）
响应体                       ← 响应体
```

**响应报文示例**：
```
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234
Connection: keep-alive

<html>
<body>...</body>
</html>
```

### 6.2.3 HTTP状态码

| 状态码类别 | 范围 | 含义 | 常见状态码 |
|-----------|------|------|-----------|
| **信息类** | 1xx | 请求已接收，继续处理 | 100 Continue |
| **成功类** | 2xx | 请求已成功处理 | 200 OK |
| **重定向类** | 3xx | 需要进一步操作 | 301 Moved Permanently（永久重定向）、302 Found（临时重定向）、304 Not Modified |
| **客户端错误** | 4xx | 客户端请求有误 | 400 Bad Request、401 Unauthorized、403 Forbidden、404 Not Found |
| **服务器错误** | 5xx | 服务器处理出错 | 500 Internal Server Error、503 Service Unavailable |

> [!tip] 考点提示
> - 301：永久重定向（搜索引擎会更新索引）
> - 302：临时重定向（搜索引擎不更新索引）
> - 304：资源未修改，可使用缓存版本
> - 404：请求的资源不存在

### 6.2.4 HTTP/1.0与HTTP/1.1持久连接对比

| 对比项 | HTTP/1.0 | HTTP/1.1 |
|--------|----------|----------|
| 连接方式 | **非持久连接**（每个对象一个TCP连接） | **默认持久连接**（一个TCP连接传输多个对象） |
| 连接管理 | 每次请求都建立和释放TCP连接 | 支持流水线（pipelining） |
| 状态码 | 无100 Continue | 支持100 Continue |
| Host头 | 不需要 | 必须包含（支持虚拟主机） |
| 断开方式 | Connection: close（默认） | Connection: keep-alive（默认） |

#### 非持久连接的缺点

- 每个对象都需要一个TCP连接（三次握手+四次挥手）
- 每个连接都要分配缓冲区和变量
- 浪费网络资源和服务器资源

#### 持久连接的优势

- 一个TCP连接可以传输多个对象
- 减少了TCP连接建立和释放的开销
- HTTP/1.1还支持**流水线**：客户端可以连续发送多个请求，不需要等待前一个响应

### 6.2.5 Cookie与Session

#### Cookie

- HTTP本身是无状态协议，**Cookie**用于在客户端存储用户状态信息
- 服务器在响应中通过 `Set-Cookie` 首部向客户端发送Cookie
- 客户端后续请求中通过 `Cookie` 首部将Cookie发回服务器
- Cookie存储在客户端浏览器中

**工作过程**：
1. 用户首次访问网站，服务器生成唯一标识（如Session ID）
2. 服务器通过 `Set-Cookie` 将标识发送给客户端
3. 客户端浏览器保存Cookie
4. 后续请求中，浏览器自动附带Cookie
5. 服务器根据Cookie识别用户

#### Session

- **Session**将用户状态信息存储在**服务器端**
- 客户端只保存一个Session ID（通常通过Cookie传递）
- 相比Cookie更安全（敏感信息不暴露在客户端）

#### Cookie与Session对比

| 对比项 | Cookie | Session |
|--------|--------|---------|
| 存储位置 | 客户端浏览器 | 服务器端 |
| 安全性 | 较低（可被篡改） | 较高 |
| 存储容量 | 有限（约4KB） | 无限制 |
| 生命周期 | 可设置过期时间 | 默认浏览器关闭后失效 |
| 跨域支持 | 支持跨域 | 不支持跨域 |

## 6.3 电子邮件系统

### 6.3.1 电子邮件系统组成

电子邮件系统由三个主要部分组成：

| 组件 | 说明 |
|------|------|
| **用户代理（UA）** | 用户读写邮件的软件（如Outlook、Foxmail） |
| **邮件服务器** | 存储和转发邮件的服务器 |
| **协议** | 发送和接收邮件的协议 |

### 6.3.2 电子邮件发送与接收过程

```
发送方UA → 发送方邮件服务器 → 接收方邮件服务器 → 接收方UA
   |              |                    |              |
   |   SMTP        |     SMTP           |   POP3/IMAP  |
   |  (推送)       |    (推送)          |   (拉取)      |
```

1. 发送方用户代理使用 **SMTP** 将邮件发送到发送方邮件服务器
2. 发送方邮件服务器使用 **SMTP** 将邮件转发到接收方邮件服务器
3. 接收方用户代理使用 **POP3** 或 **IMAP** 从接收方邮件服务器拉取邮件

### 6.3.3 SMTP协议

| 特性 | 说明 |
|------|------|
| **传输层协议** | TCP |
| **端口号** | 25 |
| **通信方式** | 基于文本的命令/响应交互 |
| **特点** | 推式协议（服务器主动推送）、只能传送7位ASCII码 |
| **方向** | 发送方→接收方（单向） |

#### SMTP常用命令与响应

| 命令 | 说明 |
|------|------|
| HELO | 客户端向服务器标识自己 |
| MAIL FROM | 指定发件人 |
| RCPT TO | 指定收件人 |
| DATA | 开始传输邮件内容 |
| QUIT | 结束会话 |

### 6.3.4 POP3协议

| 特性 | 说明 |
|------|------|
| **传输层协议** | TCP |
| **端口号** | 110 |
| **通信方式** | 拉式协议（客户端主动拉取） |
| **特点** | 下载并删除 / 下载并保留 |
| **认证** | 需要用户名和密码认证 |

#### POP3工作模式

| 模式 | 说明 |
|------|------|
| **下载并删除** | 邮件从服务器下载后立即从服务器删除 |
| **下载并保留** | 邮件从服务器下载后仍保留在服务器上 |

### 6.3.5 IMAP协议

| 特性 | 说明 |
|------|------|
| **传输层协议** | TCP |
| **端口号** | 143 |
| **特点** | 邮件保留在服务器上，支持在线操作（创建文件夹、标记邮件等） |
| **优势** | 多设备同步，用户可以在不同设备上看到相同的邮件状态 |

#### POP3与IMAP对比

| 对比项 | POP3 | IMAP |
|--------|------|------|
| 邮件存储 | 下载到本地 | 保留在服务器 |
| 多设备同步 | 不支持 | 支持 |
| 文件夹管理 | 不支持服务器端 | 支持服务器端 |
| 离线访问 | 支持 | 有限支持 |
| 服务器负载 | 低 | 较高 |

## 6.4 FTP协议

### 6.4.1 FTP概述

- **FTP（File Transfer Protocol，文件传输协议）**用于在网络上进行文件传输
- 基于 **TCP** 协议
- FTP使用**两个并行的TCP连接**：控制连接和数据连接

### 6.4.2 控制连接与数据连接

| 连接类型 | 端口 | 说明 |
|---------|------|------|
| **控制连接** | 21 | 传输FTP命令和响应（在整个会话期间保持打开） |
| **数据连接** | 20（主动模式） | 传输文件内容（每次传输文件时建立，传输完毕后关闭） |

#### FTP工作过程

```
客户端                                  服务器
  |                                      |
  |==== 控制连接（TCP端口21）============|
  |                                      |
  |  用户名/密码（认证）                  |
  |  ----------------------------------->|
  |  认证成功                             |
  |  <-----------------------------------|
  |                                      |
  |==== 数据连接（TCP端口20）============|
  |  请求下载/上传文件                    |
  |  <----------------------------------->|
  |                                      |
  |==== 数据连接关闭 ====================|
  |                                      |
  |==== 控制连接保持 ====================|
  |  请求下载另一个文件                    |
  |  ----------------------------------->|
  |==== 新的数据连接 =====================|
  |  <----------------------------------->|
  |==== 数据连接关闭 ====================|
  |                                      |
  |  QUIT                                |
  |  ----------------------------------->|
  |==== 控制连接关闭 ====================|
```

### 6.4.3 FTP传输模式

| 模式 | 说明 |
|------|------|
| **主动模式（PORT）** | 服务器从端口20主动连接客户端指定的端口 |
| **被动模式（PASV）** | 服务器打开一个随机端口等待客户端连接 |

> [!tip] 考点提示
> - FTP控制连接在整个会话期间保持打开
> - FTP数据连接在每次文件传输时建立，传输完毕后关闭
> - FTP使用**带外控制**（控制信息与数据分开传输）
> - HTTP使用**带内控制**（控制信息与数据在同一个连接中传输）

## 6.5 考点总结

> [!warning] 高频考点
> 1. DNS域名解析过程（递归查询与迭代查询的区别）
> 2. HTTP请求报文与响应报文格式
> 3. HTTP状态码（200、301、302、304、404的含义）
> 4. HTTP/1.0与HTTP/1.1的区别（持久连接）
> 5. Cookie与Session的区别
> 6. 电子邮件协议（SMTP、POP3、IMAP）的对比
> 7. FTP控制连接与数据连接的区别
> 8. 各协议使用的传输层协议和端口号

> [!note] 易错点
> - DNS使用UDP（端口53），不是TCP
> - HTTP是无状态协议，Cookie用于补充状态管理
> - SMTP是推式协议（端口25），POP3/IMAP是拉式协议（端口110/143）
> - FTP控制连接在整个会话期间保持，数据连接每次传输时建立和关闭
> - HTTP/1.0默认非持久连接，HTTP/1.1默认持久连接
> - HTTP基于TCP，不是UDP

### 6.5.1 应用层协议汇总表

| 协议 | 全称 | 功能 | 传输层协议 | 端口号 |
|------|------|------|-----------|--------|
| DNS | Domain Name System | 域名解析 | UDP/TCP | 53 |
| HTTP | HyperText Transfer Protocol | 万维网数据传输 | TCP | 80 |
| HTTPS | HTTP Secure | 安全HTTP | TCP | 443 |
| SMTP | Simple Mail Transfer Protocol | 邮件发送 | TCP | 25 |
| POP3 | Post Office Protocol v3 | 邮件接收 | TCP | 110 |
| IMAP | Internet Mail Access Protocol | 邮件接收（在线） | TCP | 143 |
| FTP | File Transfer Protocol | 文件传输 | TCP | 21（控制）/20（数据） |
| TELNET | Telecommunication Network | 远程登录 | TCP | 23 |
| SSH | Secure Shell | 安全远程登录 | TCP | 22 |
| SNMP | Simple Network Management Protocol | 网络管理 | UDP | 161/162 |
| DHCP | Dynamic Host Configuration Protocol | 动态配置 | UDP | 67/68 |
