# 第四章——网络层

## 4.1 IPv4地址

### 4.1.1 分类IP地址

IPv4地址长度为32位，通常用点分十进制表示（如 192.168.1.1）。

| 类别 | 前缀 | 网络号位数 | 主机号位数 | 网络数范围 | 每个网络最大主机数 | 默认子网掩码 |
|------|------|-----------|-----------|-----------|-----------------|------------|
| **A类** | 0 | 8 | 24 | $2^7 - 2 = 126$ | $2^{24} - 2 = 16777214$ | 255.0.0.0 (/8) |
| **B类** | 10 | 16 | 16 | $2^{14} = 16384$ | $2^{16} - 2 = 65534$ | 255.255.0.0 (/16) |
| **C类** | 110 | 24 | 8 | $2^{21} = 2097152$ | $2^8 - 2 = 254$ | 255.255.255.0 (/24) |
| **D类** | 1110 | — | — | — | — | 用于多播 |
| **E类** | 1111 | — | — | — | — | 保留 |

> [!warning] 注意
> - A类地址中，网络号全0表示"本网络"，网络号127（01111111）保留为环回地址
> - 主机号全0表示"本主机"，全1表示广播地址
> - 每个网络中可用主机数 = $2^{主机号位数} - 2$（减去全0和全1）

### 4.1.2 特殊IP地址

| 地址 | 含义 |
|------|------|
| 0.0.0.0 | 本网络 |
| 127.x.x.x | 环回地址（localhost） |
| 255.255.255.255 | 受限广播地址（本网络广播） |
| 主机号全1 | 直接广播地址 |
| 10.0.0.0/8 | A类私有地址 |
| 172.16.0.0/12 | B类私有地址 |
| 192.168.0.0/16 | C类私有地址 |

### 4.1.3 子网划分

#### 子网掩码

- 子网掩码用于区分网络号和主机号
- 子网掩码中网络号对应位为1，主机号对应位为0
- IP地址与子网掩码做**按位与运算**得到网络地址

> [!example] 例题
> IP地址为 192.168.1.130，子网掩码为 255.255.255.192（/26）
>
> 子网掩码二进制：11111111.11111111.11111111.11000000
> IP地址二进制：  11000000.10101000.00000001.10000010
>
> 网络地址（按位与）：11000000.10101000.00000001.10000000 = 192.168.1.128
>
> 主机号：00000010 = 2
>
> 该子网的主机地址范围：192.168.1.129 ~ 192.168.1.190
> 广播地址：192.168.1.191
> 可用主机数：$2^6 - 2 = 62$

#### 子网划分计算

从主机号中借 $n$ 位作为子网号：
- 原网络被划分为 $2^n$ 个子网
- 每个子网可用主机数 = $2^{主机号剩余位数} - 2$

> [!example] 例题
> 将一个C类网络 192.168.1.0/24 划分为4个子网。
>
> 需要借2位主机号作为子网号（$2^2 = 4$）。
>
> 子网掩码变为 /26（255.255.255.192）。
>
> 四个子网：
> - 192.168.1.0/26（主机范围：.1 ~ .62）
> - 192.168.1.64/26（主机范围：.65 ~ .126）
> - 192.168.1.128/26（主机范围：.129 ~ .190）
> - 192.168.1.192/26（主机范围：.193 ~ .254）

### 4.1.4 CIDR（无类域间路由）

- CIDR消除了传统的A/B/C分类和子网划分的概念
- 使用**任意长度的网络前缀**来表示网络
- 表示方法：a.b.c.d/n（n为网络前缀位数）
- CIDR支持**路由聚合（超网构造）**

#### 超网构造

将多个连续的小网络合并为一个大网络：
- 找到多个网络地址的共同前缀
- 缩短前缀长度

> [!example] 例题
> 将 192.168.0.0/24、192.168.1.0/24、192.168.2.0/24、192.168.3.0/24 合并为一个超网。
>
> 四个地址的二进制：
> - 192.168.0.0 = 11000000.10101000.00000000.00000000
> - 192.168.1.0 = 11000000.10101000.00000001.00000000
> - 192.168.2.0 = 11000000.10101000.00000010.00000000
> - 192.168.3.0 = 11000000.10101000.00000011.00000000
>
> 共同前缀为22位，超网地址为 192.168.0.0/22。

## 4.2 IP协议

### 4.2.1 IP数据报格式

```
 0               16              31
 +-------+-------+---------------+
 | 版本  | 首部长度| 服务类型(TOS)  |
 +-------+-------+---------------+
 |        总长度（字节数）          |
 +-------------------------------+
 |        标识（Identification）    |
 +-------+-------+---------------+
 | 标志  |   片偏移（Offset）      |
 +-------+-------+---------------+
 | 生存时间（TTL） |  协议          |
 +---------------+---------------+
 |       首部检验和               |
 +-------------------------------+
 |         源IP地址               |
 +-------------------------------+
 |         目的IP地址              |
 +-------------------------------+
 |         数据（可选字段+数据）     |
 +-------------------------------+
```

| 字段 | 长度 | 说明 |
|------|------|------|
| **版本** | 4位 | IPv4为4，IPv6为6 |
| **首部长度** | 4位 | 以4字节为单位，最小为5（20字节），最大为15（60字节） |
| **服务类型** | 8位 | 指示数据报的优先级和服务质量 |
| **总长度** | 16位 | 首部+数据的总长度，最大65535字节 |
| **标识** | 16位 | 同一数据报各分片共享相同标识 |
| **标志** | 3位 | DF（禁止分片）、MF（更多分片）、保留位 |
| **片偏移** | 13位 | 以8字节为单位，表示该片在原始数据报中的位置 |
| **生存时间（TTL）** | 8位 | 每经过一个路由器减1，为0时丢弃（防止环路） |
| **协议** | 8位 | 指示上层协议（TCP=6，UDP=17，ICMP=1） |
| **首部检验和** | 16位 | 仅校验首部，不含数据 |
| **源IP地址** | 32位 | 发送方IP地址 |
| **目的IP地址** | 32位 | 接收方IP地址 |

### 4.2.2 IP数据报分片与重组

#### 分片条件

当IP数据报长度超过链路的MTU时，需要进行分片。

#### 分片规则

- 标识字段：同一数据报的所有分片具有相同的标识
- MF（More Fragment）标志：MF=1表示后面还有分片，MF=0表示是最后一片
- 片偏移：以8字节为单位，表示该片的数据在原始数据报数据部分的起始位置

> [!example] 例题
> 一个IP数据报的数据部分长度为3800字节，需要经过MTU为1420字节的链路传输（IP首部20字节）。
>
> 每个分片的数据部分最大为 $1420 - 20 = 1400$ 字节。
>
> 分片情况：
> - 分片1：数据1400字节，偏移0，MF=1
> - 分片2：数据1400字节，偏移 $1400/8 = 175$，MF=1
> - 分片3：数据1000字节，偏移 $2800/8 = 350$，MF=0
>
> 总数据：$1400 + 1400 + 1000 = 3800$ 字节（正确）

### 4.2.3 TTL（生存时间）

- TTL防止数据报在网络中无限循环
- 每经过一个路由器，TTL减1
- TTL为0时，路由器丢弃该数据报，并发送ICMP超时报文
- 常见初始TTL值：Linux为64，Windows为128

## 4.3 ARP协议

### 4.3.1 ARP协议概述

**ARP（Address Resolution Protocol，地址解析协议）**用于将IP地址解析为MAC地址。

### 4.3.2 ARP工作过程

1. 主机A要向同一局域网中的主机B发送数据
2. A先查看自己的**ARP缓存表**，查找B的IP对应的MAC地址
3. 若缓存中没有，A广播发送**ARP请求**（包含B的IP地址）
4. 局域网中所有主机都收到ARP请求
5. 只有IP地址匹配的主机B向A单播发送**ARP响应**（包含自己的MAC地址）
6. A将B的IP-MAC映射存入ARP缓存表
7. A使用B的MAC地址封装帧并发送数据

> [!tip] 考点提示
> - ARP只能在**同一局域网**内使用
> - ARP请求是**广播**帧，ARP响应是**单播**帧
> - ARP缓存表有**老化机制**，条目会定期删除
> - 跨网段通信时，ARP解析的是**下一跳路由器**的MAC地址

## 4.4 ICMP协议

### 4.4.1 ICMP协议概述

**ICMP（Internet Control Message Protocol，网际控制报文协议）**用于在IP主机和路由器之间传递控制消息和差错报告。

### 4.4.2 ICMP报文类型

| 类型 | 报文 | 说明 |
|------|------|------|
| **差错报告报文** | 目的不可达 | 路由器或主机无法交付数据报 |
| | 源点抑制 | 由于拥塞而丢弃数据报 |
| | 时间超过 | TTL为0或重组超时 |
| | 参数问题 | 数据报首部字段有错 |
| | 改变路由（重定向） | 路由器告知更好的路由 |
| **询问报文** | 回送请求和回答 | 测试目的站是否可达（ping命令） |
| | 时间戳请求和回答 | 获取网络延迟 |

> [!warning] 注意
> - ICMP差错报告报文**不发送**关于ICMP差错报文、第一个分片以外的数据报、多播地址、特殊地址（127.x.x.x等）的差错报告

### 4.4.3 ping与traceroute原理

#### ping命令

- 使用ICMP**回送请求和回答**报文
- 发送方发送回送请求，接收方返回回送回答
- 通过RTT判断网络连通性

#### traceroute命令

- 利用IP数据报中**TTL逐跳递减**的特性
- 发送一系列TTL递增的IP数据报（封装ICMP回送请求）
- 第1个数据报TTL=1，被第一个路由器丢弃并返回ICMP超时报文
- 第2个数据报TTL=2，被第二个路由器丢弃并返回ICMP超时报文
- ...以此类推，直到到达目的主机
- 最终到达目的主机时返回ICMP回送回答
- 根据返回的ICMP报文可追踪路径上的所有路由器

## 4.5 路由算法与协议

### 4.5.1 自治系统与路由协议分类

#### 自治系统（AS）

- **自治系统（Autonomous System, AS）**是在单一技术管理下的一组路由器和网络
- 每个AS有一个全球唯一的**AS号（ASN）**
- AS内部使用统一的内部路由协议

#### 路由协议分类

| 类型 | 全称 | 说明 | 典型协议 |
|------|------|------|----------|
| **IGP**（内部网关协议） | Interior Gateway Protocol | AS内部使用的路由协议 | RIP、OSPF、IS-IS |
| **EGP**（外部网关协议） | Exterior Gateway Protocol | AS之间使用的路由协议 | BGP-4 |

### 4.5.2 路由算法概述

路由算法是路由协议的核心，决定了如何计算最优路径。

#### 距离向量算法

- 每个节点仅知道其**直接相邻节点**和到邻居的链路费用
- 每个节点维护一张**距离向量表**，记录到所有目的节点的最短距离估计
- 节点周期性地将自己的距离向量发送给**所有邻居**
- 邻居收到后，根据Bellman-Ford方程更新自己的距离向量：
  $$D_x(y) = \min_v \{ c(x,v) + D_v(y) \}$$
- 其中 $c(x,v)$ 是节点 $x$ 到邻居 $v$ 的链路费用，$D_v(y)$ 是邻居 $v$ 到目的 $y$ 的距离

**特点**：
- 好消息传得快，坏消息传得慢（计数到无穷问题）
- 交换的信息量较小，但可能需要多次交换才能收敛
- 典型协议：RIP

> [!example] 距离向量算法计算示例
> 设三个节点A、B、C，链路费用：c(A,B)=1, c(A,C)=4, c(B,C)=1
>
> 初始距离向量：
> - A: [A=0, B=1, C=4]
> - B: [A=1, B=0, C=1]
> - C: [A=4, B=1, C=0]
>
> A收到B的距离向量后更新：
> - D_A(B) = min{c(A,B)+D_B(B)} = min{1+0} = 1
> - D_A(C) = min{c(A,B)+D_B(C), c(A,C)+D_C(C)} = min{1+1, 4+0} = min{2, 4} = **2**
>
> 更新后A的距离向量：[A=0, B=1, C=2]（C从4降为2）

#### 链路状态算法

- 每个节点获得**全网拓扑**信息
- 每个节点向全网**洪泛**广播自己的链路状态（与邻居的链路费用）
- 所有节点收集到完整的链路状态信息后，构建全网的拓扑图
- 每个节点独立运行**Dijkstra最短路径算法**计算到各目的节点的最短路径

**Dijkstra算法步骤**：
1. 初始化：源节点 $u$ 到自身的距离为0，到其他节点为∞
2. 选取当前距离最小的未确定节点 $v$，标记为已确定
3. 对 $v$ 的每个邻居 $w$，若 $D(u,v)+c(v,w) < D(u,w)$，更新 $D(u,w)$
4. 重复步骤2~3，直到所有节点都已确定

**特点**：
- 每个节点拥有全局信息，收敛快
- 交换信息量大（洪泛LSA），但只需在拓扑变化时发送
- 无计数到无穷问题
- 典型协议：OSPF

> [!example] Dijkstra算法计算示例
> 拓扑：A-B(1), A-C(4), B-C(1), B-D(5), C-D(2)
>
> 从A出发：
> | 步骤 | 已确定节点 | A的距离向量 [A, B, C, D] |
> |------|-----------|--------------------------|
> | 初始 | {} | [0, 1, 4, ∞] |
> | 1 | 选B(1) | [0, 1, 2, 6]（B更新C:1+1=2<4, D:1+5=6<∞） |
> | 2 | 选C(2) | [0, 1, 2, 4]（C更新D:2+2=4<6） |
> | 3 | 选D(4) | [0, 1, 2, 4] |
>
> 最终最短路径：A→B(1), A→B→C(2), A→B→C→D(4)

#### 两种算法对比

| 对比项 | 距离向量算法 | 链路状态算法 |
|--------|-------------|-------------|
| 信息来源 | 仅从邻居获得 | 全网拓扑 |
| 交换内容 | 距离向量（到各目的的距离） | 链路状态（与邻居的链路信息） |
| 交换范围 | 仅邻居 | 全网洪泛 |
| 计算方式 | 分布式Bellman-Ford | 每节点独立Dijkstra |
| 收敛速度 | 慢 | 快 |
| 健壮性 | 差（错误信息会传播） | 好（每节点独立计算） |
| 计数到无穷 | 存在 | 不存在 |
| 代表协议 | RIP | OSPF |

### 4.5.3 路由表与转发

#### 路由表项内容

路由表中的每个条目包含：

| 字段 | 说明 |
|------|------|
| **目的网络地址** | 要到达的目标网络 |
| **子网掩码** | 用于匹配目的网络 |
| **下一跳地址** | 下一跳路由器的IP地址 |
| **接口** | 从哪个接口转发 |
| **跳数/开销** | 到达目的网络的度量值 |

#### 最长前缀匹配

- 当路由表中有多个条目匹配目的IP地址时，选择**前缀最长**的条目
- 即子网掩码最长的条目（最精确匹配）

> [!example] 例题
> 目的IP地址为 192.168.1.100，路由表中有以下条目：
> - 192.168.0.0/16 → 下一跳 A
> - 192.168.1.0/24 → 下一跳 B
> - 192.168.1.64/26 → 下一跳 C
>
> 192.168.1.100 与 /26 前缀匹配（192.168.1.64~192.168.1.127），选择下一跳 C。

#### 分组转发流程

1. 从IP数据报中提取**目的IP地址**D
2. 若D在直连网络中，则直接交付（通过ARP解析MAC地址后封装成帧发送）
3. 若路由表中有D的**主机特定路由**，则按该路由转发
4. 用路由表中各条目的子网掩码与D做按位与运算，与目的网络地址匹配，选择**最长前缀匹配**的条目
5. 若有匹配条目，将数据报转发给下一跳路由器
6. 若无匹配条目，查看是否有**默认路由**（0.0.0.0/0），有则按默认路由转发
7. 若无默认路由，丢弃数据报，向源主机发送ICMP目的不可达报文

> [!important] 默认路由
> - 默认路由的目的网络为 `0.0.0.0/0`，子网掩码为 `0.0.0.0`
> - 前缀长度为0，匹配优先级最低
> - 适用于将所有未知流量发送到上游路由器的场景

### 4.5.4 RIP协议

#### 基本概念

- **RIP（Routing Information Protocol）**是一种基于**距离向量**的路由协议
- 使用**跳数（hop count）**作为度量，最大15跳（16跳表示不可达）
- 每30秒广播/组播整个路由表

#### 工作原理

1. 每个路由器维护一张路由表，记录到达各目的网络的距离和下一跳
2. 路由器仅与**相邻路由器**交换信息
3. 交换的是**完整的路由表**
4. 根据收到的信息更新自己的路由表

#### 距离更新规则

$$D(x, y) = \min\{D(x, y), D(x, v) + D(v, y)\}$$

其中 $v$ 是相邻路由器。

#### 特点

| 特点 | 说明 |
|------|------|
| 算法类型 | 距离向量算法 |
| 度量 | 跳数 |
| 信息交换范围 | 仅与邻居交换 |
| 信息交换内容 | 完整路由表 |
| 收敛速度 | 慢（存在好消息传播快、坏消息传播慢的问题） |
| 适用规模 | 小型网络 |
| 传输层协议 | UDP（端口520） |

### 4.5.5 OSPF协议

#### 基本概念

- **OSPF（Open Shortest Path First）**是一种基于**链路状态**的路由协议
- 使用**Dijkstra最短路径算法**
- 向本自治系统内所有路由器发送链路状态信息

#### 工作原理

1. 每个路由器向系统中所有路由器发送**链路状态通告（LSA）**
2. LSA包含与该路由器相邻的所有链路的状态和开销
3. 每个路由器收集所有LSA，构建**完整的网络拓扑图**
4. 使用Dijkstra算法计算到各目的网络的最短路径

#### 特点

| 特点 | 说明 |
|------|------|
| 算法类型 | 链路状态算法 |
| 度量 | 可自定义（带宽、延迟等） |
| 信息交换范围 | 洪泛法向全网广播 |
| 信息交换内容 | 链路状态变化 |
| 收敛速度 | 快 |
| 适用规模 | 大型网络 |
| 传输层协议 | IP（协议号89，直接封装在IP数据报中） |

### 4.5.6 BGP协议

#### 基本概念

- **BGP（Border Gateway Protocol）**是一种**路径向量**路由协议
- 用于**自治系统（AS）之间**的路由选择（外部网关协议）
- 使用TCP连接（端口179）交换路由信息

#### 工作原理

1. 每个BGP路由器维护到达各自治系统的路径信息
2. BGP路由器与相邻BGP路由器建立TCP连接
3. 交换的是**到达某个网络所经过的路径（AS序列）**
4. 选择路由时考虑策略因素（如安全、政治等）

### 4.5.7 三种路由协议对比

| 对比项 | RIP | OSPF | BGP |
|--------|-----|------|-----|
| 类型 | 内部网关协议 | 内部网关协议 | 外部网关协议 |
| 算法 | 距离向量 | 链路状态 | 路径向量 |
| 度量 | 跳数 | 开销（可配置） | 策略 |
| 信息交换 | 与邻居交换完整路由表 | 向全网洪泛链路状态 | 与邻居交换路径向量 |
| 收敛速度 | 慢 | 快 | 较慢 |
| 规模 | 小型网络 | 大型网络 | 互联网规模 |
| 传输层 | UDP | IP | TCP |
| 端口 | 520 | — | 179 |
| 适用范围 | AS内部 | AS内部 | AS之间 |

## 4.6 NAT与DHCP

### 4.6.1 NAT（网络地址转换）

#### 基本概念

- **NAT（Network Address Translation）**将私有IP地址转换为公有IP地址
- 解决IPv4地址不足的问题
- 私有地址不能直接在互联网上路由

#### NAT工作过程

1. 内部主机使用私有地址发送数据报
2. NAT路由器收到数据报后，将源IP地址替换为公有IP地址
3. NAT路由器维护一张**NAT转换表**，记录私有地址与公有地址的映射
4. 外部响应到达时，NAT路由器根据转换表将目的地址还原为私有地址

#### NAPT（网络地址端口转换）

- 也称为**PAT（端口地址转换）**
- 在转换IP地址的同时，还转换端口号
- 多个内部主机可以共享一个公有IP地址

### 4.6.2 DHCP（动态主机配置协议）

#### 基本概念

- **DHCP（Dynamic Host Configuration Protocol）**自动为主机分配IP地址和其他网络配置
- 基于**UDP**，使用端口67（服务器）和68（客户端）

#### DHCP工作过程（四步）

| 步骤 | 报文 | 方向 | 说明 |
|------|------|------|------|
| 1 | DHCP DISCOVER | 客户端→服务器 | 广播，客户端发现DHCP服务器 |
| 2 | DHCP OFFER | 服务器→客户端 | 服务器提供IP地址及配置信息 |
| 3 | DHCP REQUEST | 客户端→服务器 | 客户端请求使用提供的地址 |
| 4 | DHCP ACK | 服务器→客户端 | 服务器确认分配 |

> [!tip] 考点提示
> - DHCP DISCOVER 和 DHCP REQUEST 是广播帧
> - DHCP分配的IP地址有**租期**，到期后需要续租
> - DHCP可以分配：IP地址、子网掩码、默认网关、DNS服务器地址

## 4.7 SDN（软件定义网络）

### 4.7.1 SDN基本概念

**SDN（Software Defined Network）**是一种网络架构范式，其核心思想是将网络的**数据平面**和**控制平面**分离。

| 平面 | 功能 | 传统网络 | SDN |
|------|------|----------|-----|
| **数据平面** | 转发数据分组 | 路由器内置转发逻辑 | 交换机仅负责转发 |
| **控制平面** | 计算路由、生成转发表 | 每个路由器独立运行路由协议 | 集中式控制器统一计算 |
| **管理平面** | 网络管理、策略配置 | 网管系统 | 控制器北向接口 |

### 4.7.2 SDN架构

SDN架构分为三层：

```
┌─────────────────────────────┐
│     应用层（网络应用程序）      │
│  路由、防火墙、负载均衡等       │
├─────────────────────────────┤
│  北向接口（Northbound API）   │  ← REST API等
├─────────────────────────────┤
│   控制层（SDN控制器）         │  ← 集中式控制
│  全局网络视图、流表下发        │
├─────────────────────────────┤
│  南向接口（Southbound API）  │  ← OpenFlow等
├─────────────────────────────┤
│   数据层（SDN交换机）         │  ← 仅转发
│  按流表匹配并执行动作          │
└─────────────────────────────┘
```

| 层次 | 功能 | 接口 |
|------|------|------|
| **应用层** | 实现网络应用（路由、负载均衡、防火墙等） | 北向接口（REST API） |
| **控制层** | SDN控制器，维护全局网络视图，计算转发表 | — |
| **数据层** | SDN交换机，根据流表转发分组 | 南向接口（OpenFlow） |

### 4.7.3 OpenFlow协议

OpenFlow是SDN中最常用的**南向接口协议**，用于控制器与交换机之间的通信。

#### 流表（Flow Table）

SDN交换机的核心数据结构是**流表**，每个流表项包含：

| 字段 | 说明 |
|------|------|
| **匹配字段（Match Fields）** | 入端口、源/目的MAC、源/目的IP、协议号、源/目的端口等 |
| **计数器（Counters）** | 统计匹配的包数、字节数等 |
| **动作（Actions）** | 转发到指定端口、丢弃、修改头部、发送给控制器等 |
| **优先级（Priority）** | 流表项的优先级，高优先级优先匹配 |
| **超时（Timeouts）** | 流表项的过期时间 |
| **Cookie** | 控制器使用的标识 |

#### 工作流程

1. 交换机收到分组后，在流表中**按优先级从高到低匹配**
2. 若匹配成功，执行对应**动作**
3. 若匹配失败，将分组发送给**控制器**（Packet-In消息）
4. 控制器决定如何处理，并通过**Flow-Mod消息**下发新的流表项
5. 后续匹配该流表项的分组直接按动作转发，无需再询问控制器

### 4.7.4 SDN vs 传统网络

| 对比项 | 传统网络 | SDN |
|--------|----------|-----|
| 控制方式 | 分布式（每路由器独立） | 集中式（控制器统一） |
| 数据/控制平面 | 耦合在路由器中 | 分离 |
| 全局视图 | 无（仅有局部信息） | 有（控制器掌握全网拓扑） |
| 转发决策 | 按路由表最长前缀匹配 | 按流表匹配（可基于多层字段） |
| 配置管理 | 逐设备配置 | 通过控制器集中配置 |
| 可编程性 | 低 | 高（通过北向API编程） |
| 单点故障 | 不易全局瘫痪 | 控制器故障影响大（需冗余） |

> [!important] 考点提示
> - SDN的核心是**数据平面与控制平面分离**
> - 控制平面集中到**SDN控制器**，数据平面仅负责转发
> - OpenFlow是南向接口协议，流表是交换机的核心数据结构
> - SDN转发基于**流表匹配**，不限于目的IP（可基于MAC、端口、协议等多字段）

## 4.8 IPv6基本概念

### 4.8.1 IPv6与IPv4对比

| 对比项 | IPv4 | IPv6 |
|--------|------|------|
| 地址长度 | 32位 | 128位 |
| 地址表示 | 点分十进制 | 冒号分隔的十六进制 |
| 地址空间 | 约 $4.3 \times 10^9$ | 约 $3.4 \times 10^{38}$ |
| 首部长度 | 20~60字节（可变） | 固定40字节 |
| 分片 | 路由器和源主机都可以分片 | 只有源主机可以分片 |
| 校验和 | 有首部校验和 | 无校验和（由传输层处理） |
| 安全性 | 可选（IPsec） | 内置（IPsec强制） |
| 地址配置 | 手动/DHCP | 支持自动配置 |
| 头部字段数 | 12个 | 8个（简化） |

### 4.8.2 IPv6地址表示

- 8组4位十六进制数，用冒号分隔
- 例如：`2001:0DB8:0000:0000:0000:0000:0000:0001`
- 简写规则：
  - 每组前导零可省略：`2001:DB8:0:0:0:0:0:1`
  - 连续的全零组可用 `::` 替代（只能用一次）：`2001:DB8::1`

### 4.8.3 IPv6地址分类

IPv6地址分为三大类：

| 类型 | 前缀 | 说明 |
|------|------|------|
| **单播地址（Unicast）** | — | 一对一通信，标识一个接口 |
| **组播地址（Multicast）** | `FF00::/8` | 一对多通信，标识一组接口 |
| **任播地址（Anycast）** | — | 一对最近通信，标识一组接口，发给最近的 |

> [!important] IPv6 vs IPv4地址类型
> - IPv6**取消了广播地址**，用组播替代
> - IPv6新增了**任播地址**（发送到最近的一个）
> - IPv6没有A/B/C分类

#### 单播地址细分

| 类型 | 前缀 | 说明 |
|------|------|------|
| **全球单播地址** | `2000::/3` | 相当于IPv4的公有地址，全球可路由 |
| **链路本地地址** | `FE80::/10` | 仅在同一链路上有效，用于邻居发现等 |
| **唯一本地地址** | `FC00::/7` | 相当于IPv4的私有地址 |
| **环回地址** | `::1` | 相当于IPv4的127.0.0.1 |
| **未指定地址** | `::` | 相当于IPv4的0.0.0.0 |

#### IPv6首部格式

```
| 版本 4b | 流量类型 8b | 流标签 20b |
| 载荷长度 16b | 下一首部 8b | 跳数限制 8b |
|         源地址（128位）           |
|         目的地址（128位）          |
```

| 字段 | 长度 | 说明 |
|------|------|------|
| **版本** | 4位 | 值为6 |
| **流量类型** | 8位 | 类似IPv4的TOS |
| **流标签** | 20位 | 标识同一流的数据报，便于QoS处理 |
| **载荷长度** | 16位 | 除首部外的数据长度 |
| **下一首部** | 8位 | 类似IPv4的协议字段，标识上层协议或扩展首部 |
| **跳数限制** | 8位 | 类似IPv4的TTL |

> [!tip] IPv6首部特点
> - 固定**40字节**，比IPv4首部更简洁
> - **无校验和**字段（由传输层负责，提高转发效率）
> - **无分片相关字段**在基本首部中（移到扩展首部）
> - 路由器**不分片**，只有源主机分片

### 4.8.4 ICMPv6

ICMPv6是IPv6中的控制报文协议，合并了IPv4中多个协议的功能。

| IPv4中的协议 | ICMPv6中的对应功能 |
|-------------|-------------------|
| ICMP | 差错报告、信息询问 |
| ARP | 邻居发现（NDP） |
| IGMP | 组播侦听发现（MLD） |
| 路由器发现 | 路由器发现（NDP的一部分） |

**ICMPv6报文类型**：

| 类型 | 报文 | 说明 |
|------|------|------|
| 差错报告 | 目的不可达 | 类似ICMPv4 |
| | 包过大 | 替代IPv4的分片功能，通知源主机减小包 |
| | 时间超过 | 跳数限制为0 |
| | 参数问题 | 首部字段有错 |
| 信息询问 | 回送请求/回答 | ping命令 |
| | 路由器请求/通告 | 路由器发现 |
| | 邻居请求/通告 | 地址解析（替代ARP） |

> [!important] ICMPv6核心考点
> - IPv6中**没有ARP**，用ICMPv6的**邻居发现协议（NDP）**替代
> - NDP使用**邻居请求（NS）和邻居通告（NA）**消息解析MAC地址
> - ICMPv6的"包过大"报文实现**路径MTU发现**，源主机据此分片
> - 路由器不分片IPv6数据报，源主机收到"包过大"后自行分片

### 4.8.5 IPv6向IPv4过渡

| 方式 | 说明 |
|------|------|
| **双栈策略** | 主机同时运行IPv4和IPv6协议栈 |
| **隧道技术** | 将IPv6数据报封装在IPv4数据报中穿越IPv4网络 |

## 4.9 IP组播

### 4.9.1 组播基本概念

| 通信方式 | 说明 | 典型应用 |
|----------|------|----------|
| **单播（Unicast）** | 一对一通信 | 网页浏览、邮件 |
| **广播（Broadcast）** | 一对所有（同一网络） | ARP请求 |
| **组播（Multicast）** | 一对多（特定组） | 视频会议、直播、股票行情 |

组播的优势：发送方只需发送一份数据，网络中的路由器在需要时**复制**分组，高效利用带宽。

### 4.9.2 IP组播地址

- IPv4组播地址使用**D类地址**：`224.0.0.0 ~ 239.255.255.255`
- 组播地址不标识单个主机，而是标识一个**组播组**

| 地址范围 | 说明 |
|----------|------|
| `224.0.0.0/24` | 链路本地范围（TTL=1，不转发） |
| `224.0.1.0 ~ 238.255.255.255` | 全球可路由组播地址 |
| `239.0.0.0/8` | 管理权限范围（组织内部使用） |

**常用永久组播地址**：

| 地址 | 含义 |
|------|------|
| `224.0.0.1` | 本子网所有主机 |
| `224.0.0.2` | 本子网所有路由器 |
| `224.0.0.5` | OSPF路由器 |
| `224.0.0.6` | OSPF DR/BDR |

### 4.9.3 组播MAC地址

以太网组播MAC地址范围为 `01-00-5E-00-00-00 ~ 01-00-5E-7F-FF-FF`。

- IP组播地址的低23位映射到MAC地址的低23位
- MAC地址前25位固定为 `01-00-5E-` + 第4字节最高位为0

> [!example] IP组播地址到MAC地址映射
> IP组播地址 `224.1.2.3`：
> - D类地址低23位：`1.2.3` = `00000001 00000010 00000011`
> - MAC地址：`01-00-5E-01-02-03`

> [!warning] 映射不唯一
> 由于IP组播地址有28位可变，而MAC地址只有23位映射，因此**32个IP组播地址映射到同一个MAC地址**。接收方需要通过上层协议过滤。

### 4.9.4 IGMP协议

**IGMP（Internet Group Management Protocol）**用于主机与路由器之间的组播组成员管理。

| 版本 | 特点 |
|------|------|
| IGMPv1 | 主机加入组时发送报告，路由器周期性查询 |
| IGMPv2 | 增加离开组机制（Leave Group消息） |
| IGMPv3 | 支持SSM（指定源组播），可指定只接收哪些源的组播 |

**IGMP工作过程**：
1. 主机想加入组播组时，发送**IGMP成员报告**（目标地址为组播组地址）
2. 路由器定期发送**IGMP查询**（目标地址 `224.0.0.1`）
3. 组中至少一台主机响应报告
4. 主机想离开时（v2/v3），发送**离开组消息**（目标 `224.0.0.2`）
5. 路由器收到离开消息后，发送**特定组查询**确认是否还有成员

### 4.9.5 组播路由协议

组播路由协议负责在路由器之间构建组播分发树：

| 协议 | 类型 | 说明 |
|------|------|------|
| **PIM-SM** | 稀疏模式 | 使用RP（汇聚点），适用于组成员稀疏分布 |
| **PIM-DM** | 密集模式 | 洪泛+修剪，适用于组成员密集分布 |
| **DVMRP** | 距离向量组播 | 基于RIP的组播路由协议 |
| **MOSPF** | 链路状态组播 | 基于OSPF的组播路由协议 |

**组播分发树类型**：

| 类型 | 说明 | 适用 |
|------|------|------|
| **源树（最短路径树SPT）** | 以源为根，到每个接收者走最短路径 | 路径最优，但状态多 |
| **共享树（RP树）** | 以RP为根，所有源先发到RP再分发 | 状态少，但路径可能非最优 |

## 4.10 移动IP

### 4.10.1 移动IP基本概念

移动IP允许主机在**改变网络接入点**时，不改变IP地址仍能保持通信。

| 术语 | 说明 |
|------|------|
| **移动节点（MN）** | 可以改变网络接入位置的主机 |
| **家乡代理（HA）** | 移动节点家乡网络中的路由器，负责拦截发给MN的数据报 |
| **外地代理（FA）** | 移动节点访问网络中的路由器，协助MN通信 |
| **家乡地址（HoA）** | MN的永久IP地址（家乡网络中分配） |
| **转交地址（CoA）** | MN在外地网络获得的临时IP地址 |
| **隧道** | HA到FA之间的数据报封装通道 |

### 4.10.2 移动IP工作过程

```
步骤1：代理发现
  MN移动到外地网络后，通过代理通告发现FA
  MN获得转交地址CoA

步骤2：注册
  MN向HA注册CoA
  MN → FA → HA（注册请求）
  HA → FA → MN（注册应答）
  HA建立HoA与CoA的绑定

步骤3：数据传输（其他主机→MN）
  ① 对端主机发数据报到MN的家乡地址HoA
  ② HA拦截该数据报
  ③ HA将数据报封装在隧道中（IP-in-IP），目的为CoA
  ④ FA收到后解封装，转发给MN

步骤4：数据传输（MN→对端主机）
  MN直接使用HoA作为源地址发送数据报
  （标准路由，无需经过HA）
```

### 4.10.3 三角路由问题

```
对端主机 ──→ HA ──→ FA ──→ MN    （对端到MN：经过HA绕行）
对端主机 ←────────────────── MN    （MN到对端：直接发送）
```

- **三角路由**：对端到MN的路径经过HA转发，形成"三角形"
- 路径不是最优的（增加延迟和HA负载）
- 解决方案：路由优化，HA通知对端MN的CoA，对端直接隧道发送

> [!important] 移动IP考点
> - 移动节点改变位置后**IP地址不变**（保持HoA）
> - HA通过**隧道**将数据报转发给MN的CoA
> - MN发送数据**直接发送**，不需经过HA
> - 三角路由问题：接收路径绕行HA，发送路径直接

## 4.11 网络层设备

### 4.11.1 路由器

路由器是工作在**网络层**的设备，负责在不同网络之间转发IP数据报。

#### 路由器的结构

```
┌───────────────────────────────────────┐
│           路由处理器（CPU）             │  ← 控制平面
│     运行路由协议、维护路由表            │
├───────────────────────────────────────┤
│           交换结构（Switch Fabric）     │  ← 连接输入/输出端口
├───────┬───────┬───────┬───────────────┤
│ 输入  │ 输入  │ 输入  │    ...        │
│ 端口1 │ 端口2 │ 端口3 │               │
├───────┼───────┼───────┼───────────────┤
│ 输出  │ 输出  │ 输出  │    ...        │
│ 端口1 │ 端口2 │ 端口3 │               │
└───────┴───────┴───────┴───────────────┘
```

| 组件 | 功能 |
|------|------|
| **输入端口** | 接收数据报、链路层解封装、查找路由表（最长前缀匹配） |
| **交换结构** | 将数据报从输入端口传送到输出端口 |
| **输出端口** | 缓存数据报、链路层封装、发送数据报 |
| **路由处理器** | 运行路由协议、维护路由表、执行管理功能 |

> [!important] 数据平面 vs 控制平面
> - **数据平面**：输入端口→交换结构→输出端口（转发数据报，硬件实现）
> - **控制平面**：路由处理器（运行路由协议，软件实现）
> - 转发由数据平面完成，路由表由控制平面维护

#### 交换结构的三种方式

| 方式 | 说明 | 特点 |
|------|------|------|
| **通过内存交换** | 数据报写入内存，再从内存读出到输出端口 | 最慢，受内存带宽限制 |
| **通过总线交换** | 数据报通过共享总线传输到输出端口 | 总线竞争，一次只能传一个 |
| **通过互联网络交换** | 使用多级交换网络（如Crossbar） | 最快，可并行传输多个数据报 |

#### 输入端口排队

- 当交换结构速度不足以处理所有输入端口的分组时，输入端口产生排队
- **队头阻塞（HOL Blocking）**：队头分组等待交换结构时，后面的分组即使目标输出端口空闲也无法转发

#### 输出端口排队

- 当多个输入端口的分组同时到达同一输出端口时，输出端口产生排队
- 排队导致**延迟**和**丢包**（缓存溢出）
- 需要调度策略：FIFO、优先级队列、加权公平队列（WFQ）

### 4.11.2 三层交换机

- 三层交换机具有**路由功能**的交换机
- 结合了二层交换的线速转发和三层路由的功能
- 通过**硬件（ASIC）**实现路由查找和转发，速度快于软件路由器
- 适用于VLAN间路由

### 4.11.3 路由器 vs 交换机 vs 集线器

| 对比项 | 集线器 | 交换机 | 路由器 |
|--------|--------|--------|--------|
| 工作层次 | 物理层 | 数据链路层 | 网络层 |
| 转发依据 | 信号广播 | MAC地址 | IP地址 |
| 冲突域 | 1个 | 每端口1个 | 每接口1个 |
| 广播域 | 1个 | 1个（默认） | 每接口1个 |
| 隔离广播 | 否 | 否 | 是 |
| 路由功能 | 无 | 无（二层交换机） | 有 |

> [!note] 易错点
> - 子网划分时，可用主机数要减去网络地址和广播地址（-2）
> - IP数据报分片中，片偏移以**8字节**为单位
> - ARP只能在同一局域网内使用，跨网段解析的是下一跳路由器的MAC地址
> - OSPF直接封装在IP数据报中（协议号89），不使用TCP或UDP
> - BGP使用TCP连接（端口179），是外部网关协议
> - IPv6中只有源主机可以分片，路由器不能分片
> - IPv6**没有广播地址**，用组播替代；IPv6**没有ARP**，用NDP替代
> - IPv6首部固定40字节，**无校验和**字段
> - 距离向量算法存在**计数到无穷**问题，链路状态算法不存在
> - SDN转发基于**流表匹配**（可基于多层字段），不限于最长前缀匹配
> - IP组播地址28位可变，MAC地址只映射23位，因此**32个IP组播地址映射同一个MAC地址**
> - 移动IP中MN**接收**数据经HA隧道转发，**发送**数据直接发送
> - 路由器的**队头阻塞（HOL Blocking）**发生在输入端口
