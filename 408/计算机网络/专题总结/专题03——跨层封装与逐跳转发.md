# 专题03——跨层封装与逐跳转发

> [!abstract] 知识定位
> 本专题串起**链路层**（以太网帧、802.11 无线帧、CSMA/CA、AP 桥）与**网络层**（IPv4/IPv6、ARP、NAT、子网）在「一个数据报跨越多个网络」时的**逐跳协作流程**。
>
> **收录范围**：以数据报「封装 → 转发 → 换装 → 递送」的全生命周期为主线，回答这类跨章节综合题：
> - 每一跳帧头里的源/目的 MAC 到底是什么？
> - ARP 什么时候工作、解析谁、每次填几个地址？
> - AP 是桥还是路由？要不要改 IP 首部？
> - 手机和 AP 是不是同一个子网？IP 层的最后一站是谁？
>
> **与其他视图的分工**（三足鼎立）：
> - [[专题01——协议全景图谱]] §3：**语法视图**——每个协议首部字段的静态定义
> - [[专题02——流量控制与拥塞控制]]：**机制视图**——滑动窗口/拥塞算法的动态原理
> - **本专题**：**流程视图**——一个数据报穿越多网络、多链路的动态旅程

---

## 一、三条正交主线（先建分层框架）

| 主线 | 谁定 | 端到端 | 逐跳 |
|:-----|:-----|:------|:-----|
| **IP 线**（源/目的 IP） | 网络层首部 | **源 IP 与目的 IP 全程不变**（除 NAT） | 路由器不改 IP 地址，除 TTL−1 |
| **MAC 线**（源/目的 MAC） | 链路层帧头 | **无端到端概念** | **每一跳重写一对新的**（路由器、桥都会换） |
| **MAC 槽位数**（2/3/4） | **帧格式**（以太网 2 / 802.11 3-4） | — | 由这一跳是「有线」还是「无线电」决定 |

> [!important] 一句话贯通
> **IP 决定「最终去哪」，MAC 决定「这一跳交给谁的手」，NAT 决定「出门时把内部地址换成对外地址」。** 三件事不同层、不同时机。

---

## 二、封装流水线全景（自上而下 × 逐跳）

```
┌── 应用层 ──┐
│  HTTP/DNS/…  │                                     ┌──────────┐
└── 传输层 ──┘  + TCP/UDP 首部（端口）              │ 应用数据 │
┌──────────┐                                       └──────────┘
│ TCP/UDP  │  + IP 首部（源 IP + 目的 IP + 协议字段）        ▲
└──────────┘                                       ┌────────┴────────┐
┌──────────┐  ── 交 L2 封装 → ARP 解析「下一跳」──► │ IP 数据报       │
│ IP 数据报 │                                       └────────┬────────┘
└──────────┘                                       ┌────────▼────────┐
┌──────────┐                                       │ L2 帧（以太/无线）│
│  L2 帧   │                                       └────────┬────────┘
└──────────┘                                       ┌────────▼────────┐
┌──────────┐                                       │  比特流上线路    │
│  比特流  │                                       └─────────────────┘
└──────────┘
```

关键顺序：**IP 层决定下一跳 IP → 链路层用 ARP 把下一跳 IP 解析成 MAC → 组装帧 → CSMA/CD 或 CSMA/CA 上线**。接收侧对称：CSMA 收 → L2 剥壳验 MAC → 上交 IP 层。

## 三、谁负责哪一层（动作矩阵）

| 动作 | 谁做 | 频率 | 改哪个字段 |
|:-----|:-----|:-----|:-----------|
| 决定「下一跳 IP」 | 网络层（子网判断 / 路由表最长前缀匹配） | 每跳 | — |
| **ARP** | 主机/路由器，**封帧前** | 一次**只解析一个** MAC | 帧头**目的 MAC** |
| NAT | 边界路由器，**转发时** | 一次 | IP 首部源/目的地址 + 传输层端口，重算 IP 检验和 |
| 决定帧头**源 MAC** | 发送设备的**出口网卡**（自报身份） | 每跳 | 帧头源 MAC |
| 决定**几个 MAC 槽** | 链路层**帧格式**（以太网 vs 802.11） | 每段独立看 | 帧头结构 |

> [!tip] 关键分工
> **ARP 每次只填一个 MAC；MAC 槽数是帧格式定的。** 二者独立——不要因为「无线 3 地址」就以为 ARP 一次解析三个，剩下两格另有来源（见 §五）。

---

## 四、桥 vs 路由：一台设备到底做什么

| 特征 | **桥**（AP、二层交换机） | **路由**（路由器、网关） |
|:-----|:-------------------------|:-------------------------|
| 工作层 | **L2** | **L3** |
| 查什么表 | 桥接/转发表（按 **MAC**） | 路由表（按 **IP**，最长前缀匹配） |
| 剥到哪层 | **只剥 L2 头**，IP 数据报当 payload **过手不改** | 上交 IP 层处理，TTL−1、可能 NAT、重算 IP 检验和 |
| 目的 MAC 来源 | **沿用**原以太网 dst 或从桥接表已学到的 | **重新 ARP** 下一跳 IP 得到新 MAC |
| 隔离广播域 | ❌ 不隔离 | ✅ 隔离 |
| 隔离冲突域 | ✅ 交换机每端口一个 | ✅ |

**判据**：拿到一台"中间设备"，问它「剥到 L2 还是剥到 L3、有没有查路由、有没有改 IP 首部」即可分类。

---

## 五、AP 桥接的具体流程（换装工，不是路由）

**AP 定义上就是「802.11 站 + 与 DS 之间的桥」**，做 L2 换装：

```
   以太网帧（2 MAC）到 AP 有线口:
   ┌────────┬──────────┬──────────────┬─────────┐
   │ dst MAC│ src MAC  │  ★IP 数据报★ │  FCS    │
   │ =手机  │ =d       │  (原封不动)  │         │
   └────────┴──────────┴──────────────┴─────────┘
                    │ AP 桥接: 拆 L2 → 查桥接表 → 重封 L2
                    ▼
   802.11 帧（3 MAC）从无线口发出:
   ┌─────────────┬────────────┬────────────┬──────────────┐
   │ Addr1(RA)   │ Addr2(TA)  │ Addr3(SA)  │ ★IP 数据报★  │
   │ =手机        │ =AP BSSID  │ =d         │ (原封不动)   │
   │ (抄以太网dst)│ (AP 自报)  │ (抄以太网src)│             │
   └─────────────┴────────────┴────────────┴──────────────┘
```

**三格各自来源**：

| 槽位 | 值 | 怎么来的 | 是否 ARP 参与 |
|:--:|:--|:--------|:--:|
| **Addr1**（RA）| 手机 MAC | 沿用以太网 dst MAC（早先由 d ARP 解析手机 IP 得到） | 有人（d）做过 ARP，**但 AP 没做** |
| **Addr2**（TA/BSSID）| AP 自己 MAC | AP 自报身份，无需解析 | ❌ |
| **Addr3**（SA）| 上一跳 d 的 MAC | 沿用以太网 src MAC（d 自己网卡） | ❌ |

> AP **不做额外 ARP**——它只是「换装工」，把同一份 IP 数据报从 2-MAC 外套换成 3-MAC 外套。

---

## 六、手机、AP、LAN 是不是同子网？——桥模式下是同子网

- **手机 = AP 的有线口 = AP 所在的有线 LAN，三者同属一个 IP 子网**。AP 只是把无线侧「桥进」这块 LAN。
- **IP 层的「最后一站」是手机本身，不是 AP**。路由器发出的以太网帧 dst MAC **就已经是手机 MAC**（因为手机被桥到同一 L2 域、可 ARP 直达），AP 只换装成无线帧发出。
- **家用「无线路由一体机」** 塞了两个角色：WAN↔LAN 边界做**路由 + NAT**；LAN 内部（含无线）做 **AP 桥接**——手机和家里 PC 同网段、能直接 ARP。

```
                        ┌──────── 同一个 IP 子网（如 192.168.1.0/24）────────┐
                        │                                                    │
   外网/其他网 ──► R(网关) ── 有线 LAN ── [AP] ══ 无线电 ══ 手机             │
                        │              ▲           ▲            ▲            │
                        │           192.168.1.1  192.168.1.5  192.168.1.100 │
                        │        （网关 IP）（AP 管理 IP）（手机 IP）        │
                        └────────────────────────────────────────────────────┘
                            ↑ 从 R 到 AP 到手机，全在同一子网；AP 对 IP 层透明
```

**例外**：若 AP 单独开三层路由模式（少见），无线客户端会被分到另一个子网——此时**「AP」这个角色已经和「路由器」这个角色捆在同一台设备**里了，判据看**无线客户端 IP 前缀**是否与上游同网。

## 七、逐跳速查表：a → b → c → d → AP → 手机（跨子网，中间都走路由器）

| 段 | 链路类型 | 帧格式 | 源 MAC | 目的 MAC | 本段 ARP 解析谁 |
|:--|:--|:--|:--|:--|:--|
| a→b | 有线 | 以太网 2 | a 出接口 | b 入接口 | a 解析 b 入接口 IP |
| b→c | 有线 | 以太网 2 | b 出接口 | c 入接口 | b 解析 c 入接口 IP |
| c→d | 有线 | 以太网 2 | c 出接口 | d 入接口 | c 解析 d 入接口 IP |
| d→AP | 有线 | 以太网 2 | d 出接口 | **手机 MAC**（经 AP 桥到同一 L2） | d 解析手机 IP |
| AP→手机 | **无线** | **802.11 3** | Addr2=AP BSSID | Addr1=手机 | ❌ AP 不 ARP，沿用以太网 dst |

**全程不变**：目的 IP = 手机 IP。
**每跳都换**：源 MAC 和目的 MAC 都是全新的一对（除 AP→手机 是换格式）。

> [!tip] 无线段 Addr3 语义的精确表述
> Addr3 = 「在 AP 的有线端口看来，把帧送到我面前的那台设备的 MAC」。
> - **跨子网（中间都是路由器）→ Addr3 = 最后跳路由器 d 的出接口 MAC**（因为 d 会重写 src）。
> - **纯二层桥接（中间只有交换机）→ Addr3 = 最初源 a 的 MAC**（交换机不改 src）。

## 八、NAT 在整条链里的位置

NAT 只发生在**公私网边界的路由器**上、**转发那一刻**：

| | 位置 | 时机 | 改什么 |
|:--|:--|:--|:--|
| **ARP** | 每台主机/路由器 | **封帧前**，每跳都做 | 填帧头**目的 MAC**（一次一个） |
| **NAT** | 边界路由器 | 路由转发时 | 改 **IP 首部**源/目的 IP + 传输层端口，重算 IP 首部检验和 |

**要点**：
- NAT **不改变 ARP 的位置**——源主机侧照样先 ARP 网关 MAC 把帧发出去，NAT 是网关收到后才做的。
- 内网通信（同子网）不需要 NAT，但**照样需要 ARP**——证明两者独立。
- 家用一体机的 NAT 在**路由部分**做，与 AP 桥接无关；AP 只是换装。

## 九、判据速查（做题三步走）

> [!important] 三步定信号
> 1. **这一跳是有线还是无线电？**
>    - 有线 → 以太网 2 MAC（源 MAC + 目的 MAC）
>    - 无线电 → 802.11 3/4 MAC（Addr1=RA、Addr2=TA/BSSID、Addr3=DS 端、Addr4=WDS 才用）
> 2. **中间设备是桥还是路由？**
>    - 桥（AP / 交换机）→ 只换或沿用 MAC，IP 数据报过手不改
>    - 路由 → 交 IP 层处理，TTL−1 / NAT / 重算 IP 检验和，MAC 换
> 3. **ARP 解析谁？**
>    - **永远解析「下一跳 IP」**
>    - 同子网 → 下一跳 = 目标主机本身
>    - 跨子网 → 下一跳 = 本网通往下一跳的**路由器接口**（源主机视角就是**默认网关**）

## 十、五条高频误解纠正

> [!warning] 五条必纠错
> 1. ❌「同子网就不用链路层封装」→ ✅ **任何跨主机传输都要 L2 封装**，同子网只是「下一跳就是目标本身」，ARP 也照样要跑（解析的就是目标主机的 MAC）。
> 2. ❌「源 MAC 要保持」→ ✅ 保持的是**源 IP**；MAC 本就逐跳换，CSMA/CD 只管单链路抢信道，作用域就是「当前这一段局域网」，压根没有跨跳一致性的需求。
> 3. ❌「AP 会解封装到 IP 层查路由」→ ✅ AP 是**二层桥**，只拆 L2、按 MAC 桥接表转发，IP 数据报当 payload **过手不改**。上交 IP 层查路由是**路由器**的动作。
> 4. ❌「手机在 AP 的下一个子网」→ ✅ 桥模式下手机、AP、AP 的 LAN **同属一个子网**，AP 对 IP 层透明；家用一体机的「路由 + AP」两个角色要分开看。
> 5. ❌「ARP 一次填 3 个 MAC」→ ✅ ARP 每次只解析**一个**（下一跳）MAC，填进「目的 MAC」位；无线帧剩下两格 AP 用「自报 BSSID + 抄以太网 src」凑齐，**不是 ARP 干的**。

## 十一、综合例题

**题**：内网服务器 a（192.168.1.10，MAC_A）要向无线手机（192.168.1.100，MAC_P）发送一个 IP 数据报。路径 a → R1 → R2 → AP → 手机，R1、R2 是路由器，AP 是桥模式。问：

（1）在 R2 出接口发出的以太网帧的源 MAC 和目的 MAC 各是谁？
（2）手机最终收到的 802.11 帧里 Addr1、Addr2、Addr3 各填什么？
（3）整个过程中，ARP 一共被调用了多少次？各解析谁的 IP？

**解**：

（1）**R2 出的以太网帧**：源 MAC = R2 出接口 MAC（记为 MAC_R2o）；目的 MAC = **手机 MAC_P**（因为手机被 AP 桥到 R2 出接口所在的同一 L2 域，R2 早先 ARP 手机 IP 得到的就是 MAC_P）。

（2）**手机收到的 802.11 帧**（下行，From DS=1）：
- Addr1（RA）= **MAC_P**（手机）
- Addr2（TA）= **MAC_AP**（AP 的 BSSID）
- Addr3（SA）= **MAC_R2o**（沿用以太网 src，即上一跳 R2 的出接口 MAC）

（3）**ARP 调用**：
- a 发第一帧时 ARP 一次，解析 **R1 入接口 IP**（跨子网，下一跳是 R1）；
- R1 转发时 ARP 一次，解析 **R2 入接口 IP**；
- R2 转发时 ARP 一次，解析 **手机 IP**（同 L2 域）；
- AP **不做 ARP**（直接沿用 R2 送来的以太网帧的两个 MAC）。
- 合计 **3 次 ARP**。若各家缓存有旧条目命中，可能更少；首次通信即 3 次。

> [!tip] 检查
> 全程 IP 数据报的目的 IP 都是 192.168.1.100（手机）不变；MAC 每一段都是全新的一对；AP 只换格式，不改 IP 首部。
