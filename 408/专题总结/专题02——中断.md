# 专题02——中断（从硬件机制到内核行为）

> **横跨科目**：计组第七章（7.3 程序中断方式）+ 第五章（5.2.2 中断周期、5.4 指令流水线）｜操作系统第一章（中断异常与系统调用）+ 第二章（时钟中断与调度）+ 第三章（缺页）+ 第五章（I/O 中断）

## 一、主题问题引入

**问题**：缺页发生的那一刻，我们嘴里的"中断"到底指什么？由谁干活？何时响应？如何返回？

- 教材把"缺页"叫**缺页中断**，可它明明由 CPU 内部（MMU 查页表发现页不在内存）触发，和键盘、时钟那种"从外面来的"中断不是一回事；
- 计组第七章讲的**程序中断方式**，其实只讲了"从外面来的"那一类（外中断）；
- OS 讲**中断**时，既包括外中断（时钟 → 调度、I/O → 唤醒进程），也包括内中断 / 异常（缺页 → 调页、syscall → 系统调用）。

**同一个词，两科站在两个角度用**——这正是本专题要横向拉通的地方。

> [!important] 门铃 vs 开门人（先给结论，收敛争议 2）
> **中断只是"交接控制权的机制"（门铃），做决策的是"中断处理程序"（开门的人）。**
> 缺页时：`#PF 异常`负责把 CPU 控制权交给内核；真正决定"换哪一页、要不要启动 DMA 调页"的是 **OS 缺页处理程序**。这不是术语之争，而是**机制与策略分离**的实质区别。

## 二、中断的完整分类谱系

### 2.1 先分清"广义"与"狭义"（收敛争议 1）

| 用法 | 含义 | 出现在哪 |
|:--|:--|:--|
| **广义中断**（中断事件） | 凡是打断 CPU 正常取指-执行流、迫使它转去处理特殊事件的**所有**情况 | "中断的分类""中断系统" |
| **狭义中断**（= 外中断 interrupt） | **只**指来自 CPU 外部、与当前指令无关的异步事件 | 第七章"程序中断方式"讲的其实是这一类 |

> [!important] 一句话结论（争议 1）
> **广义中断 = 内中断（异常 exception）+ 外中断（interrupt，狭义）**。
> 题目问"中断分类"取**广义**；问"I/O 程序中断方式"取**狭义**。答题先判断语境，再决定口径。
> **"缺页中断"这个叫法算不算对？** 严格按分类它是**内中断 → 故障(fault)**，不是外中断；但"缺页中断"是约定俗成说法，考卷上这么写**不算错**，只要分类时归对门类即可。

### 2.2 两门三轴：主干分类

**第一根轴（最主干）——中断源在 CPU 内还是外：**

**A. 内中断 / 异常（Exception）——同步、由当前指令引起**

来自 CPU 内部，是正在执行的指令"自己出了事"，因此**可预测、可复现**（同一条指令重跑必然再触发）。按返回语义再细分三类（详见 2.3）：

| 子类 | 返回后 | 可恢复性 | 典型例子（x86 向量号） |
|:--|:--|:--|:--|
| **故障 Fault** | **重新执行**当前那条指令 | 可恢复 | **缺页 #PF(14)**、除零 #DE(0)、非法操作码、一般保护错 #GP(13) |
| **陷阱 Trap** | 执行**下一条**指令 | 有意为之 | **系统调用**（`syscall`/`int 0x80`）、断点 #BP(3) |
| **终止 Abort** | **不返回**，进程 / 机器崩 | 不可恢复 | 硬件校验错、**双重故障 #DF(8)**、机器检查 |

- **软中断 / 自陷**：由中断指令 `INT n` 主动触发，本质归入 **trap**（"程序员故意安排的异常"，不是外部来的）。
- 内中断一般**不可屏蔽**——指令都出错了，屏蔽没有意义（个别调试异常除外）。

**B. 外中断（Interrupt，狭义）——异步、与当前指令无关**

来自 CPU 外部设备，何时来不确定，因此**不可预测**。在**当前指令执行结束**时由 CPU 采样响应（不是每个时钟周期都查，详见第三节）：

| 子类 | 谁发的 | 干什么用 |
|:--|:--|:--|
| **时钟中断** | 定时器 / RTC / APIC Timer | **OS 抢占式调度的命根子**：时间片轮转、进程切换、计时 |
| **I/O 中断** | 外设 / 接口 | 设备完成或需服务：键盘输入、**DMA 传输完成**、网卡收包 |
| **硬件故障中断** | 电源 / 内存校验 | 掉电、奇偶校验错等，优先级最高 |

**第二根轴——能否被屏蔽（只对外中断有意义）：**

| 类型 | 说明 | 例 |
|:--|:--|:--|
| **可屏蔽中断** | 受中断屏蔽字 / 标志位（x86 的 IF）控制，可暂不理 | 普通 I/O 中断 |
| **不可屏蔽中断 NMI** | 不能被屏蔽，必须立即处理 | 掉电、严重硬件故障 |

### 2.3 返回语义（收敛争议 3）

| 类型 | 返回后 PC 指向 | 例 |
|:--|:--|:--|
| **故障 Fault** | **重新执行**当前指令（PC = 出错指令地址） | 缺页 #PF、除零 |
| **陷阱 Trap** | 执行**下一条**（PC = 下条指令地址） | syscall、断点 |
| **终止 Abort** | **不可恢复**，不返回 | 硬件校验错、双重故障 |
| **外中断 Interrupt** | 执行**下一条**（断点 = 被打断处的下条） | I/O 完成、时钟、DMA 完成 |

> [!important] 结论（争议 3）
> x86 的 `#PF`（向量 14，出错虚拟地址存入 **CR2**）属 **fault**：ISR 把缺的页调进来后，**重新执行**那条触发缺页的 `MOV`——此立场**成立并采纳**。区分 fault 与 trap 的唯一尺子就是"**返回后重跑当前指令，还是走下一条**"。

### 2.4 谱系图

```
中断事件（广义中断）
├── 内中断 / 异常（Exception）  ← 同步、指令内因、CPU 内部、一般不可屏蔽
│   ├── 故障 Fault   → 返回后【重新执行】当前指令   （缺页 #PF、除零、#GP）
│   ├── 陷阱 Trap    → 返回后【执行下一条】         （系统调用、断点、INT n 软中断）
│   └── 终止 Abort   → 【不可恢复】                 （双重故障 #DF、机器检查）
└── 外中断（Interrupt，狭义）   ← 异步、指令外因、CPU 外部
    ├── 时钟中断      → OS 调度、计时
    ├── I/O 中断      → 外设完成 / DMA 完成 / 网卡收包
    └── 硬件故障中断  → 掉电、校验错（优先级最高）
        按可否屏蔽再分：可屏蔽中断（IF / 屏蔽字）｜不可屏蔽中断 NMI
```

### 2.5 计组视角 vs OS 视角的分工（本专题"横跨"的价值）

| | **计组（第七章 / 第五章）关心** | **OS 关心** |
|:--|:--|:--|
| 关注点 | **硬件机制怎么实现** | **内核行为怎么被驱动** |
| 具体内容 | 中断隐指令、向量 → PC、INTR/INTA 握手、优先级排队器、屏蔽字 / 多重中断、单重 vs 多重、**流水线精确中断** | 时钟中断 → **进程调度**、I/O 中断 → **唤醒阻塞进程**、缺页异常 → **虚拟内存调页**、trap → **系统调用**、中断上半部 / 下半部 |

## 三、计组视角：中断是怎么发生的

本节先讲**内中断（异常）怎么发生**（3.0），再讲**外中断怎么发生**（3.1~3.5），最后是两者在流水线里的统一处理（3.6）。

### 3.0 内中断（异常）是怎么发生的

外中断是"从外面拉根线、指令结束时采样"；**内中断 / 异常**恰好相反——它由 **CPU 内部的硬件单元在执行当前指令的过程中自己检测到条件不满足**而触发，没有外部请求线，也不在指令边界采样。

**谁在哪个阶段检测什么：**

| 异常 | 检测单元（流水线阶段） | 触发条件 | x86 向量号 |
|:--|:--|:--|:--:|
| 除零 #DE | ALU / 除法器（EX） | 除数为 0 | 0 |
| **缺页 #PF** | **MMU**（访存做地址翻译时） | 页表 valid=0，出错 VA 存 **CR2** | 14 |
| 非法指令 #UD | 译码器（ID） | 操作码不合法 | 6 |
| 溢出 #OF | ALU（EX） | 结果超范围 | 4 |
| 一般保护 #GP | 多种单元 | 越权 / 越界 | 13 |

**与外中断的对照：**

| | 外中断 | 内中断 / 异常 |
|:--|:--|:--|
| 来源 | CPU 外部设备 | CPU 内部，由**当前指令**引起 |
| 时序 | **异步**，指令结束时采样 | **同步**，指令执行中即时产生（该指令无法完成） |
| 可否屏蔽 | 可屏蔽（IF） | **一般不可屏蔽**（错了就是错了） |
| 流水线里 | 提交边界被接受 | 异常标记**附着指令**带到提交点才处理（精确异常，见 3.6） |

> [!note] 陷阱 trap 是"故意安排的异常"
> 系统调用（`syscall` / `int 0x80`）也是内中断、也同步，但它由**执行一条主动陷入指令**触发——译码 / 执行单元识别这条指令后陷入内核，返回后走**下一条**（不重跑，区别于 fault）。

> [!important] 硬件 vs 软件：中断到底是谁完成的？
> **响应机制靠硬件，处理逻辑靠软件**（对应 3.3 的隐指令 vs ISR）：
> - **硬件（中断隐指令）**：检测请求 / 异常条件、中断判优、关中断、保存断点(PC→栈)与 PSW、**向量→PC**（查表取 ISR 入口）——占节拍、不占指令条数。
> - **软件（ISR）**：保护现场与屏蔽字、（多重中断时开中断）、**真正的服务逻辑**（缺页调页 / 读设备 / 调度决策）、恢复现场、`IRET`。
>
> 一句话：**硬件管"安全跳进去"，软件管"跳进去干什么"**。缺页时硬件只做"检测 valid=0、存 CR2、跳 #PF 入口"这几件事，**换哪页、要不要 DMA 全是 OS 软件决策**（呼应争议 2 门铃 vs 开门人）。

### 3.1 中断请求与中断响应：为什么是"每条指令结束时"检测

外中断是**异步**的——设备什么时候拉低 INTR 线不确定。CPU 不可能在每个时钟周期都停下去查，否则一条指令执行到一半被打断，现场会一团糟。所以约定：

```
① 设备把数据 / 状态准备好 → 通过 I/O 接口向中断控制器拉出【中断请求 INTR】
② CPU【在当前这条指令的最后一个节拍结束时】采样 INTR（不是每拍都查）
③ 若 INTR 有效且未屏蔽（IF=1）→ CPU 发【中断响应 INTA】
④ 进入中断周期：保存断点 → 向量送 PC → 转去执行 ISR
```

> [!note] 关键辨析
> - **外中断**：在**指令执行结束**时响应（指令已完整完成，断点天然清晰）。
> - **内中断 / 异常**：在**指令执行过程中**立即产生（那条指令根本没法正常完成，如除零、缺页）。
> - 这就是为什么"指令结束时检测"这句话**只适用于外中断**。

### 3.2 中断周期：硬件微操作（引 [[计算机组成原理/第五章——中央处理器#5.2.2 各周期节拍级微操作序列|第五章 5.2.2]]）

指令周期 = 取指 + 间址 + 执行 + **中断周期（有中断才有）**。中断周期本身也是一段节拍级微操作，由**硬件**完成：

| 节拍 | 微操作 | 说明 |
|:--:|:--|:--|
| T0 | `SP → MAR`，发写命令 | 栈顶地址送 MAR，准备压栈保存断点 |
| T1 | `PC → MDR`，写主存；`SP-1`；中断向量 → `PC` | 断点（PC）压栈、栈指针减一、把中断服务程序入口地址装入 PC |

### 3.3 中断隐指令 vs 中断服务程序：谁做哪一步

这是理解"机制 vs 策略"边界的钥匙（草稿争议 4 的核心，此处按既有共识固化）：

| | 谁做 | 内容 |
|:--|:--|:--|
| **中断隐指令** | **硬件**（占节拍，不占指令条数） | 关中断、保存断点 `PC → 栈`、`PSW → 栈`、向量 → PC |
| **中断服务程序 ISR** | **软件** | 保护现场与屏蔽字、（多重中断时）开中断、服务、关中断、恢复现场与屏蔽字、`IRET` |

> [!tip] 一句话记忆
> **隐指令是"CPU 自动做的三件事"**（关中断、存断点、跳向量），程序员看不见、写不出对应指令；**ISR 是"你写的那段程序"**。断点由**硬件**保存（隐指令），其余现场由**软件**保存（ISR）。

> [!warning] 中断向量的两个常见误区
> **误区①：向量号是"独热码 / 微命令格式"？——不是。**
> - 先分清术语：**中断类型号（向量号）** = 标记"哪种中断"的小整数（x86 是 0~255，如 #PF=14）；**中断向量** = 该号对应的 **ISR 入口地址**；关系是 `向量号(索引) → 查中断向量表 IVT/IDT → 取出入口地址 → 送 PC`。
> - 256 个源用独热要 **256 位**，用二进制编码只要 **8 位**（2⁸=256），所以向量号是**编码整数、当索引用**，不是一源一线的独热。
> - 真正"一源一位"（类独热）的是**中断请求寄存器 / 屏蔽字**（见 7.3.4），别和向量号混。
> - 微命令是**控制信号**（触发微操作）；向量号是**数据 / 地址**，本身不控制部件，只是被查表的下标——把它送进 PC 的那个 `PCin` 才是微命令。故**中断向量 ≠ 微命令格式**。
>
> **误区②：向量表写死在硬件上？——不是。** 分清哪部分硬件固定、哪部分软件配置：
> - **硬件 / ISA 固定**：向量号的**分配**（x86 的 0~31 保留给异常、32~255 给外中断 / 软中断）+ **异常检测逻辑**（什么条件触发什么号）。
> - **软件（OS）配置**：**向量号 → ISR 入口**的映射表存在**内存**里、可随时改——实模式 **IVT**（0x00000~0x003FF，256 项 ×4B）、保护模式 **IDT**（由 IDTR 指向、`LIDT` 加载）；哪个号挂哪个处理程序由 OS 填。
> - 一句话：**"号怎么分、什么条件触发什么号"硬件定死；"这个号的服务程序在哪"软件填表**。
> - 外中断向量号也**可编程**：8259A 由软件设基址（ICW2）、现代 MSI-X 靠内存写传号；RISC-V `mcause` 存异常码（硬件定）、`mtvec` 存处理程序基址（软件设）。

### 3.4 中断优先级与屏蔽字（引 [[计算机组成原理/第七章——输入输出系统#7.3 程序中断方式|第七章 7.3]]）—— 收敛争议 5

多个中断同时到达时，按**优先级**决定响应顺序：

| 优先级 | 事件 | 说明 |
|:--:|:--|:--|
| 最高 | 硬件故障 | 机器故障，必须立即处理 |
| 高 | **DMA 请求** | 见下方辨析 |
| 中 | 程序中断（外设） | I/O 设备完成操作 |
| 低 | 程序中断（软件） | 软中断、系统调用 |
| 最低 | 用户程序 | 正常执行 |

> [!important] 结论（争议 5）：优先级表里的"DMA 请求"指的是哪一个？
> 教材把两个不同层面的东西塞进了同一张优先级表，必须拆开：
> - **DMA 总线请求（HOLD / 周期挪用）**：DMA 引擎要**抢总线**去搬数据，属**总线仲裁**层面，发生在数据传送过程中，**不是中断**；
> - **DMA 传输完成中断**：整块数据搬完（WC=0 / 完成队列写完）后，DMA 引擎发一个**外中断**通知 CPU 收尾，属**中断响应**层面。
>
> 优先级表里排在"高"的那一项，指的是**DMA 总线请求（HOLD）**——因为总线不赶紧让出去数据就传不动；而"DMA 完成中断"作为普通外中断，优先级等同外设中断。**"DMA 完成中断 vs 缺页异常同时到达谁优先"**：缺页是内中断（异常），在指令执行中即时产生，先于任何外中断被处理；DMA 完成中断作为外中断在当前指令结束时才采样，故**缺页异常先被响应**。

### 3.5 单重中断 vs 多重中断

| 特征 | 单重中断 | 多重中断（中断嵌套） |
|:--|:--|:--|
| 中断嵌套 | 不允许 | 允许高优先级打断低优先级 |
| 开中断时机 | 整个 ISR 期间关中断 | ISR 中保护现场后**提前开中断** |
| 保护 / 恢复现场 | 一次 | 每次中断各保护 / 恢复一次 |
| 实现 | 简单 | 需**中断屏蔽字**配合（详见 7.3.4） |

### 3.6 ★ 流水线遇到中断怎么办？——精确中断（Precise Interrupt）

这是"每条指令结束时检测中断"这句话在**流水线 CPU** 下的深化，也是本章 5.4 流水线与中断的交汇点。

**问题所在**：五段流水线（IF→ID→EX→MEM→WB）里，同一时刻**有 5 条指令分处不同阶段**。若中断到来时直接停下去跳 ISR，那么"断点之后"的指令可能已经**部分执行**、改了寄存器或内存——现场就乱了。

**目标：精确中断 / 精确异常**，要求同时满足三条：

1. **断点之前**的指令**全部完成**（已提交，效果可见）；
2. **断点那条及其之后**的指令**尚未修改**任何体系结构状态（或效果被回滚）；
3. 保存的 **PC（断点）指向一个确定的位置**：
   - 外中断 / 陷阱 → PC = **下一条**未完成的指令；
   - 故障 fault（如缺页）→ PC = **出错那条指令本身**，以便返回后重跑。

**硬件如何做到：**

| 手段 | 做法 |
|:--|:--|
| **按序提交 / 退休（retire）** | 指令可以在流水线里乱序执行，但**只在提交阶段按程序序"退休"**；退休了效果才可见。中断在**提交边界**被接受 |
| **重排序缓冲 ROB** | 动态调度机器用 ROB 暂存乱序执行的结果，按序提交 → 保证精确（Tomasulo + ROB 的核心动机之一） |
| **流水线冲刷（flush）** | 一旦指令 I 触发中断 / 异常，比 I **年轻**的指令（I+1、I+2…）全部作废变气泡，**永不写回** |
| **异常随指令下传** | 缺页在 MEM / 取指段发现、除零在 EX 段发现，异常标记**附着在该指令上**一路带到提交点，才真正处理 → 精确 |

> [!example] 缺页为什么必须精确
> 触发缺页的那条 `MOV [addr], R1` 若已部分执行（比如写了半个内存），返回后重跑就会写坏数据。**精确中断保证它"就像从没开始过"**：调页完成后，PC 指回这条 `MOV`，干干净净重新执行一次。这也是**虚拟存储器对 CPU 的硬性要求**——没有精确中断就没有可用的缺页机制。

> [!note] 不精确中断（imprecise）
> 早期无 ROB 的简单流水线可能出现**不精确中断**：中断点前后指令状态模糊，OS 得费劲判断哪些指令真正完成了。现代通用 CPU（x86 等）**一律要求精确中断**，否则无法支撑虚拟内存与可靠的异常语义。

**与 3.1 的呼应**：非流水线 CPU 里"指令结束时检测"天然精确（被打断的指令已完整完成）；流水线 CPU 里"指令结束"含义模糊，于是把它**重新定义为"提交 / 退休边界"**，本质是同一件事。

> [!warning] 常见误区：不是"等整批做完"，而是"把没做完的冲掉"
> 很多人以为流水线遇到中断要"**等这一批在飞的指令全部执行完**"再处理——**错**。正确做法是**卡一个提交边界**：
> - **已提交（完成）的**：结果已落账 → **保留**；
> - **正在提交的那条**：让它退休 → 保留，是断点前最后一条；
> - **更年轻、还没提交的**：结果只在 ROB / 流水线寄存器 / store buffer 里当"草稿"，**全部作废(flush)，当没执行过**。
>
> **为什么能"当没执行"？** CPU 故意把"写进正式状态"推迟到**提交(retire)**那一刻，没提交的指令连内存写都还压在 store buffer 里没落地，撕掉草稿即可、**无需回滚**——这正是"先暂存、后按序提交"(ROB + 顺序退休)的价值。反过来"等整批做完"(drain)对 **fault 根本行不通**（出错指令没正确完成，年轻指令建立在错误状态上），还白白拉长中断延迟。

#### 断点定位：PC 已经跑远了，返回地址从哪来？

**矛盾**：PC 在**取指阶段就 +1**（见 5.2.2），流水线里更是**投机取指**跑到好几条之后。中断发生时，**live PC 寄存器的值根本不能当返回地址**。返回地址来自"出事那条指令自己带下来的 PC"：

| 机器模型 | 断点（返回地址）存在哪 |
|:--|:--|
| 教材简单模型 | 无专用寄存器；断点 = 当时的 PC 值，由中断隐指令**压入栈**，IRET 弹回 PC |
| 真实 ISA | 专用返回地址寄存器：MIPS **EPC**、RISC-V **mepc/sepc**、ARM **banked LR**；x86 仍**压栈** |
| 乱序流水线 | 每条在飞指令的 PC 存在自己的 **ROB 表项**，提交 / 出错时读那一条 |

- **断点指向**：外中断 / trap = 已完成指令的**下一条**地址（完成指令 PC + 指令字长）；fault = **出错指令自己**（要重跑）。
- **返回动作**：不是把 PC"倒带递减"，而是**重载(load)**——中断时 `PC ← ISR 入口`，IRET 时 `PC ← 保存的断点`；断点之后在飞的年轻指令全 flush，IRET 后**从断点重新取指执行**（完成那条已落账、不重抄；只有 fault 才从出错这条自己重抄）。

> [!note] 那个"栈"在哪？Cache 还是主存？
> - 栈是**主存里的一段连续区域**，位置由 **SP（栈指针）**精确指定（不是任意位置），且是**虚拟地址**，压栈要经 MMU/TLB 翻译；用户态来的中断会先切到**内核栈**再压。
> - **教材口径**说"PC → 主存"；**实机真相**是栈顶属超热点（时间局部性极强），那几个单元**几乎必然命中 L1 Cache**，压栈 / 出栈实际是一次 **Cache 命中**，几拍完成，**不用真跑 DRAM**。
> - 数据通路确实**走 MDR**：压栈 `SP → MAR、PC → MDR → 写 M[SP]`；出栈 `M[SP] → MDR → PC`。命中 Cache 就快，只有极小概率未命中才走主存慢路径"慢慢传"。

## 四、OS 视角：中断 / 异常驱动内核行为

同一批中断事件，OS 关心的是"跳进内核之后做了什么决策"。四类主线：

### 4.1 时钟中断 → 抢占式调度

- 定时器每隔一个**时间片**发一次外中断；
- 时钟中断处理程序里：更新计时、判断当前进程时间片是否用完 → 用完则**触发调度**，切换到别的进程；
- **没有时钟中断就没有抢占式多道程序**——这是 OS "并发"错觉的硬件底座（联动 [[操作系统/第二章——进程与线程/调度算法与考点|OS 调度算法]]、[[操作系统/专题总结/专题01——饥饿问题|饥饿专题]]）。

### 4.2 I/O 中断 → 唤醒阻塞进程

- 进程发起 I/O 后**阻塞**（让出 CPU），去干别的进程；
- 设备完成 → 发 **I/O 中断**（低速设备逐字中断，高速设备 **DMA 完成后发一次中断 / MSI-X**）；
- 中断处理程序把数据交付、将等待该 I/O 的进程从**阻塞态唤醒**为就绪态（联动 [[操作系统/第二章——进程与线程/进程概念与进程控制|进程状态转换]]）。

### 4.3 缺页异常 → 虚拟内存调页

- 缺页是**内中断 / 故障（fault）**，不是外中断；
- OS 缺页处理程序：判断合法否 → 选牺牲页（可能换出脏页）→ 用 **DMA** 把目标页调入页框 → 填页表 → 刷 TLB → 返回，**重新执行**触发缺页的指令（联动 [[操作系统/第三章——内存管理/虚拟页式存储|虚拟页式存储]]、[[专题总结/专题01——替换算法|跨科目专题01：替换算法]]）。

### 4.4 陷阱 → 系统调用

- 用户程序执行 `syscall` / `int 0x80` 主动陷入内核，属 **trap**，返回后执行下一条；
- 这是用户态进入内核态的**唯一合法主动入口**，实现"受控地借用内核特权"（联动 [[操作系统/第一章——计算机系统概述/操作系统体系结构|OS 体系结构：中断异常与系统调用]]）。

### 4.5 中断上半部 / 下半部（延伸）

- **上半部（top half / 硬中断）**：关中断、极短，只做"抢救现场 + 应答设备"；
- **下半部（bottom half / softirq / tasklet）**：开中断，做耗时的后续处理；
- 目的：让 CPU 尽快从关中断状态出来，保证中断响应延迟可控。

## 六、缺页全链条逐拍走（把两科拼成一条链）

```
用户指令 MOV 执行中，MMU 查页表发现 valid=0
   ↓【内中断 / 故障 fault】
① 硬件隐指令：保存断点(PC→栈，指向这条 MOV)、PSW→栈、缺页向量(14)→PC、出错 VA→CR2
   ↓ 控制权交给内核
② OS 缺页处理程序【决策】：该访问合法吗？→ 选牺牲页（改进 CLOCK）
   ↓
③ 若牺牲页 dirty=1 → 驱动【主动】配置 DMA 引擎，把脏页换出到磁盘
   ↓
④ DMA 硬件【自主】搬运（AR→地址总线、数据→M、AR+1、WC-1，全由硬件时序逐拍完成）
   ↓
⑤ DMA 搬完（WC=0）→ 发【外中断】（INTR 或 MSI-X）
   ↓
⑥ 驱动的【中断服务程序 ISR】收尾：校验、置完成、（若换出）继续调入目标页
   ↓
⑦ 目标页调入页框（同样 DMA）→ 填页表项(valid=1, 物理块号)→ 刷 TLB
   ↓
⑧ IRET 恢复现场 → PC 指回那条 MOV → 【重新执行】(fault 语义)
```

> [!important] 三个"别搞反"
> - **④ 是结果不是起因**：DMA 完成中断是搬运**结束后**发的通知，不是"收到中断才开始搬"。
> - **缺页不一定用 DMA**：干净牺牲页直接丢弃、零页只清零、page cache 命中只建映射——这些都不碰磁盘（草稿共识 9）。
> - **数据落点是主存页框**（DMA/通道，绕过 CPU），不是 CPU 寄存器（查询/中断方式，绕过主存）——两条回程路对偶（草稿共识 8）。

## 七、易错点汇总

1. **"中断"默认广义**：= 内中断（异常）+ 外中断；只有"I/O 程序中断方式"语境才是狭义外中断。
2. **异常同步、中断异步**：判断归类先问"它由当前指令引起吗？"引起 → 内中断 / 异常；无关 → 外中断。
3. **缺页是故障(fault)，不是外中断**：返回后**重新执行**当前指令，不是走下一条。
4. **DMA 请求 ≠ DMA 完成中断**：前者是抢总线的 HOLD（总线仲裁，非中断），后者才是外中断；常被混进同一张优先级表。
5. **缺页先于外中断**：内中断在指令执行中即时产生，外中断在指令结束时才采样。
6. **隐指令 vs ISR**：断点(PC/PSW)由**硬件隐指令**保存，其余现场由**软件 ISR**保存；隐指令占节拍不占指令条数。
7. **中断不属跳跃寻址**：它改变执行流，但由隐指令把向量送 PC，是硬件自动完成，不算"跳跃寻址"（联动 [[计算机组成原理/专题总结/专题02——十种数据寻址方式的节拍级微操作对比|寻址方式专题]]）。
8. **流水线要精确中断**：断点前的指令全完成、断点后的全冲刷；靠**按序提交(retire)+ROB+flush** 实现，缺页机制的硬性前提。
9. **外中断在指令结束时响应，不是每个时钟周期**；这句话只对**外中断**成立，异常在指令执行中即时产生。
10. **MSI-X 本质是 MMIO 写**（草稿共识 4）：现代中断连"拉引脚"都省了，改成往特定内存地址写特定值，由 APIC 翻译成向量——是否还算教材 INTR/INTA 模型意义上的中断，见草稿争议 6（待议）。
