# 专题02——内存分配方式与回收策略对比

> [!abstract] 知识定位
> 内存分配方式是第三章的主线考点，横跨连续分配（单一/固定/动态/伙伴）与离散分配（分页/分段/段页式）。本专题把每种方式从**分配到回收的全流程**逐步理清，重点标注地址修改、页表更新、寄存器操作等细节。

---

## 一、总览对比表

| 方式 | 分配单位 | 分配策略 | 回收策略 | 碎片 | 优点 | 缺点 | 适用 |
|:-----|:---------|:---------|:---------|:-----|:-----|:-----|:-----|
| **单一连续分配** | 整个用户区 | 全部分给唯一进程 | 进程结束整体回收 | 内部碎片 | 最简单 | 只能运行一个进程 | 单用户系统 |
| **固定分区** | 固定大小分区 | 分区使用表找最小够用的 | 表项改"未分配"，分区直接复用 | **内部碎片** | 简单 | 分区固定浪费 | 早期多道批处理 |
| **动态分区** | 按需创建分区 | 首次/最佳/最差/邻近适应 | 回收并**合并相邻空闲区** | **外部碎片** | 无内部碎片 | 需紧凑解决碎片 | 通用 |
| **伙伴系统** | 2的幂的块 | 取最小 $2^k \ge s$，对半拆分 | 与**伙伴合并**，逐级向上 | 内部碎片为主 | 分配回收极快 | 取整浪费、只合并伙伴 | Linux内核页框 |
| **分页** | 页框 | 离散分配，按页表登记 | 收回全部页框入空闲块表 | **内部碎片**（最后一页） | 无外部碎片、支持虚存 | 页表开销 | 现代OS主流 |
| **分段** | 段（长度不定） | 按段连续分配 | 按段回收，合并相邻空闲区 | **外部碎片** | 逻辑清晰、便于共享保护 | 外部碎片、段难增长 | 逻辑导向场景 |
| **段页式** | 段→页 | 段表+页表两级 | 按页表收物理块、再销两级表 | 内部碎片为主 | 兼得两者优点 | 两次地址变换 | 兼顾需求 |

> [!tip] 碎片口诀
> **固页内、动段外**：固定分区与分页产生内部碎片；动态分区与分段产生外部碎片。

### 1.1 内碎片判据：分配单位是否"定长"（含"分段为何无内碎片"辨析）

内碎片是否产生，取决于**分配单位大小是否与程序实际需求一致**：

| 分配方式 | 分配单位大小 | 是否可能多给 | 结果 |
|:---------|:-------------|:---:|:-----|
| 固定分区 | 预先定死 | ✅ 常多给 | **内部碎片** |
| 分页 | 页大小定死，最后一页通常不满 | ✅ 最后一页浪费 | **内部碎片** |
| 伙伴系统 | 向上取整到 $2^k$ | ✅ 最坏浪费近一半 | **内部碎片** |
| **分段** | **按段实际长度分配** | ❌ 不多给 | **无内部碎片** |
| 动态分区 | 按进程实际大小分配 | ❌ 不多给 | 无内部碎片 |

- **关键区别**：分段的分配粒度就是段的**真实长度**——按段长划出"刚好够"的连续区域，不存在"给 100 只用 80"；分页最后一页即使只用 1 字节也占满整页，这才是内碎片的来源。
- **"最后一页"类比失效**：分页是"不足一页也占一页"；分段没有"最后一段必须占满"的规则。
- **代价转移**：分段消灭内碎片的代价是①段要求连续空间 → **外部碎片**；②段长可变，**段增长困难**（见 §2.6）。

> [!important] 一句话记忆
> 分配单位**定长** → 必产生内部碎片（固定分区/分页/伙伴）；分配单位**按需定长** → 无内部碎片但生外部碎片（动态分区/分段）。

## 二、各方式全流程详解

### 2.1 单一连续分配

```
分配：程序装入 → 装入时静态重定位（程序内地址+内存起始地址）→ 运行
回收：进程结束 → 内存整体归还 → 下一程序装入
```

- **细节**：无需重定位寄存器（只有一个用户程序）；可用**界限寄存器**做越界保护
- **局限**：不能有多道程序，内存利用率极低

### 2.2 固定分区分配

**分配流程**：

```
1. 作业装入，查分区使用表：找"状态=未分配 且 大小≥作业"的最小分区
2. 无合适分区 → 作业等待
3. 有 → 修改表项：状态改为"已分配"，记录作业名
4. 装入作业：
   - 静态重定位：装入时把分区起始地址加到程序每条地址上
   - 或动态重定位：设 重定位寄存器=分区始址、界限寄存器=分区长度
```

**运行**：每次访存：逻辑地址 + 重定位寄存器值 → 物理地址（动态重定位方式）；越界由界限寄存器检查。

**回收流程**：

```
1. 作业完成 → 分区使用表中该表项改回"未分配"
2. 无需合并（分区大小位置固定不变）
```

- **细节**：等长分区简单但碎片大；不等长分区灵活但需解决"大分区被小作业占用"的分配选择问题

### 2.3 动态分区分配

**分配流程**：

```
1. 查空闲分区表/链，按算法找目标分区：
   - 首次适应：地址递增找第一个够大的
   - 最佳适应：按大小递增找最小够大的
   - 最差适应：按大小递减取最大的
   - 邻近适应：从上次位置循环找
2. 从该分区划出所需大小：
   - 修改空闲表项：若剩余部分≥最小阈值，缩小表项（始址后移）
   - 否则整个分配，删除表项
3. 装入作业，动态重定位：
   - 重定位寄存器 = 分区始址
   - 界限寄存器 = 分区长度
```

**运行**：每次访存：先查界限寄存器（逻辑地址<界限？），再加 重定位寄存器值 → 物理地址。

**回收流程**（核心是**四种相邻情况**）：

```
1. 作业结束，回收区登记到空闲分区表
2. 检查回收区的上邻、下邻是否空闲：
   - 上邻空闲 → 上邻表项大小 += 回收区，删除回收区表项
   - 下邻空闲 → 回收区表项大小 += 下邻，删除下邻表项
   - 上下都空闲 → 合并三者为一个表项
   - 都不空闲 → 新增一个空闲表项
3. （空闲链组织时）把新表项插入链中合适位置
```

**碎片处理**：外部碎片多时执行**紧凑**——所有进程向一端移动，碎片合并为大空闲区；**必须逐个更新被移动进程的重定位寄存器**（所以依赖动态重定位），开销大、不宜频繁。

### 2.4 伙伴系统

**分配流程**：

```
1. 请求大小 s → 取最小 2^k ≥ s
2. 查 2^k 空闲链表：有 → 直接取下
   无 → 取更大的块反复对半拆分：
     每次拆分：一块变两个伙伴，一个挂回低一级空闲链表，另一个继续拆
3. 得到 2^k 大小的块 → 分配（向上取整部分为内部碎片）
```

**运行**：同动态分区（重定位寄存器 + 界限寄存器）。

**回收流程**（核心是**异或找伙伴**）：

```
1. 回收块 (起始地址 x，大小 2^k)
2. 计算伙伴地址：buddy = x ⊕ 2^k
3. 检查伙伴是否空闲 且 大小相同：
   - 是 → 合并成 (min(x,buddy), 2^(k+1))，回到第2步用新块继续检查
   - 否 → 停止，把当前块挂入 2^k 空闲链表
```

- **细节**：合并只对伙伴进行——相邻但不成伙伴的空闲块不能合并，这是外部碎片残留的根源
- **例题**：起始地址 64、大小 32 的块，伙伴地址 = 64⊕32 = 96

### 2.5 分页存储

**分配流程（进程创建）**：

```
1. 由进程地址空间大小计算页数：页数 = ⌈逻辑大小 / 页面大小⌉
2. 建立页表：在内存分配页表存储区，页表始址登记到 PCB
3. 按页分配物理块：从空闲块表/链取物理块号 → 填入对应页表项
4. 更新空闲块表：被占块标记为已分配
5. 进程运行时：页表基址寄存器 ← 页表始址，页表长度寄存器 ← 页表长度
```

**运行（地址变换，每次访存）**：

```
1. 逻辑地址 → 页号 P、页内偏移 W
2. P ≥ 页表长度寄存器 → 越界中断
3. 查 TLB：
   - 命中 → 直接得物理块号
   - 未命中 → 由页表基址寄存器定位页表，查表得块号；并把该页表项加入TLB（TLB满则按算法淘汰）
4. 物理地址 = 块号 × 页面大小 + W
```

**回收流程（进程终止）**：

```
1. 根据页表逐项回收该进程占有的所有物理块 → 归还空闲块表/链
2. 回收页表存储区本身
3. 清空/刷新 TLB（TLB表项无进程标识时必须清）
4. 销毁 PCB（页表基址、长度等随之消失）
```

- **细节**：进程切换时只需换页表基址/长度寄存器并刷TLB，页表本身常驻内存不搬动；被换出进程的页表可暂存外存交换区

### 2.6 分段存储

**分配流程**：

```
1. 由段表确定段数与每段长度
2. 建立段表（每段一项：段始址、段长）
3. 为每段分配连续内存区（按动态分区方式从空闲区表分配）
4. 把每段始址、段长填入段表，更新空闲区表
5. 运行时：段表始址寄存器 ← 段表始址，段表长度寄存器 ← 段数
```

**运行（地址变换）**：

```
1. 逻辑地址 → 段号 s、段内偏移 w
2. s ≥ 段表长度 → 越界中断
3. w ≥ 该段段长 → 越界中断（分段特有的双重越界检查）
4. 物理地址 = 段始址 + w
```

**回收流程**：

```
1. 按段表逐项回收每段的连续区域（同动态分区回收）
2. 每个区域都要做相邻空闲区四情况合并
3. 回收段表存储区，销毁 PCB
```

- **细节**：段长可变且要求连续 → 段增长困难，是分段的主要缺陷；段可共享（如共享代码段只需段表项指向同一始址）

### 2.7 段页式

**分配流程**：

```
1. 建立段表（每段一项）
2. 每段按页拆分：为该段建立页表
3. 段表项填入该段页表的始址与段长（页数）
4. 按页分配物理块，填入各页表项
```

**运行（两次查表）**：

```
1. 逻辑地址 → 段号 s、页号 p、页内偏移 w
2. 查段表（越界检查）→ 得该段页表始址
3. 查该段页表（配合TLB）→ 得物理块号
4. 物理地址 = 块号 × 页面大小 + w
```

**回收流程**：按各段页表回收物理块 → 释放各页表 → 释放段表 → 销毁PCB。

## 三、寄存器团队速查

| 机制 | 关键寄存器 | 作用 |
|:-----|:-----------|:-----|
| 连续分配（单一/固定/动态） | **重定位寄存器（基址）+ 界限寄存器** | 地址平移 + 越界保护 |
| 分页 | **页表基址寄存器 + 页表长度寄存器 + TLB** | 定位页表 + 越界检查 + 加速变换 |
| 分段 | **段表始址寄存器 + 段表长度寄存器** | 定位段表 + 越界检查 |

> [!warning] 进程切换时的寄存器操作（连续分配视角）
> 旧进程的**重定位寄存器、界限寄存器值要先存入其PCB**，新进程从PCB恢复——这与分页换页表基址、刷TLB是同一思想：**"指向地址空间的指针"随进程切换而切换**。

## 四、回收流程的共性总结

| 环节 | 各方式做法 |
|:-----|:-----------|
| **登记归还** | 固定：改表项；动态：登记空闲表；伙伴：挂空闲链表；分页：物理块归还空闲块表 |
| **合并** | 固定：不合并；动态/分段：相邻四情况合并；伙伴：只与伙伴合并；分页：离散，天然无合并 |
| **清缓存** | 分页/段页式回收或进程切换：刷TLB |
| **销结构** | 页表/段表存储区随进程终止回收，销毁PCB |
| **补充手段** | 外部碎片：紧凑（需动态重定位）；进程级：对换；作业级：覆盖 |

## 五、考点速记

1. **分配算法对比**：首次适应综合最好；最佳适应外碎片最多；最差适应不利大作业；邻近平衡但大分区易耗尽（详见 [[第三章——内存管理/连续分配管理方式|连续分配管理方式]] §3.4）
2. **伙伴地址**：$buddy(x, 2^k) = x \oplus 2^k$，计算题必会
3. **动态分区回收四情况**：上邻空、下邻空、都空、都不空——画图判断
4. **分页地址变换链路**：逻辑地址→页号/偏移→越界检查→TLB→页表→块号→物理地址，画图逐步算访存次数与EAT
5. **紧凑的前提**：动态重定位（重定位寄存器可运行时修改）
6. **越界检查次数**：分页1次（页号对页表长度）；分段2次（段号对段长表、偏移对段长）
7. **内碎片判据**：分配单位定长→内碎片（固定分区/分页/伙伴）；按需定长→无内碎片但生外碎片（动态分区/分段）。**分段按段实际长度分配，无内碎片**（见 §1.1）
