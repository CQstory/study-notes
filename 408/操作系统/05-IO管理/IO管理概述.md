# 5.1 I/O 管理概述

## 5.1.1 I/O 设备分类

I/O 设备种类繁多，可以从不同角度进行分类。理解设备分类是学习 I/O 管理的基础。

### 按传输速率分类

| 类型 | 速率范围 | 典型设备 | 特点 |
|------|----------|----------|------|
| **低速设备** | 每秒几个字节 ~ 数百字节 | 键盘、鼠标、语音输入设备 | 传输速率低，通常以字符为单位传输 |
| **中速设备** | 每秒数千字节 ~ 数万个字节 | 行式打印机、激光打印机 | 传输速率中等，需要一定缓冲 |
| **高速设备** | 每秒数百千字节 ~ 数兆字节 | 磁盘、光盘、磁带 | 传输速率高，通常以块为单位传输 |

> [!note] 考点提示
> 低速设备通常是字符设备，高速设备通常是块设备，但这不是绝对的，需要具体问题具体分析。

### 按信息交换单位分类

这是操作系统中最常用的分类方式，直接影响设备的管理策略。

| 类型 | 交换单位 | 传输速率 | 寻址方式 | 典型设备 | 可寻址性 |
|------|----------|----------|----------|----------|----------|
| **块设备（Block Device）** | 数据块（通常 512B ~ 4KB） | 高 | 可寻址 | 磁盘、光盘、U盘 | 可随机访问 |
| **字符设备（Character Device）** | 字符（1 字节） | 低 | 不可寻址 | 键盘、鼠标、打印机 | 顺序访问 |

#### 块设备特点

- **可寻址**：可以指定数据块的地址进行读写
- **随机访问**：可以直接访问任意数据块，无需按顺序
- **传输速率高**：适合大批量数据传输
- **通常采用 DMA 方式**：减少 CPU 干预

#### 字符设备特点

- **不可寻址**：无法指定地址，只能顺序读写
- **传输速率低**：逐个字符传输
- **常采用中断驱动方式**：每个字符传输完成后产生中断
- **不需要缓存整个块**：通常只需要单字符缓冲

> [!warning] 重要区别
> 块设备和字符设备的根本区别在于**是否可寻址**和**传输单位**。块设备以数据块为单位，可随机访问；字符设备以字符为单位，只能顺序访问。

### 按共享属性分类

| 类型 | 定义 | 特点 | 典型设备 | 分配方式 |
|------|------|------|----------|----------|
| **独占设备** | 一段时间内只能被一个进程占用 | 安全性高，利用率可能低 | 打印机、磁带机 | 静态分配 |
| **共享设备** | 可被多个进程同时访问 | 利用率高，需要并发控制 | 磁盘、光盘 | 动态分配 |
| **虚拟设备** | 通过虚拟技术将独占设备变为共享设备 | 提高独占设备利用率 | SPOOLing 虚拟打印机 | 虚拟分配 |

#### 独占设备

独占设备在一段时间内只能分配给一个进程使用，直到该进程释放后才能分配给其他进程。

```
进程 A 申请打印机 → 分配成功 → 进程 A 使用 → 进程 A 释放
                                      ↓
                               进程 B 等待
```

> [!tip] 思考
> 为什么打印机是独占设备？如果多个进程同时向打印机输出，打印内容会交错混乱，无法得到正确结果。

#### 共享设备

共享设备可以被多个进程同时访问，通过分时使用提高设备利用率。

```
进程 A 请求磁盘块 1 ──┐
                      ├──→ 磁盘调度 → 依次服务
进程 B 请求磁盘块 2 ──┘
```

#### 虚拟设备

通过 SPOOLing 技术，将一台独占设备虚拟为多台逻辑设备，供多个进程同时使用。

```
进程 A ──→ 输出井 ──┐
                    ├──→ 井管理程序 → 实际打印机
进程 B ──→ 输出井 ──┘
```

> [!important] 核心概念
> 虚拟设备技术的核心思想是**以空间换时间**：用磁盘空间（输入井/输出井）换取设备使用效率的提升。

## 5.1.2 I/O 软件层次结构

I/O 软件采用层次化结构设计，从上到下分为四层，每层都有明确的职责和接口。

```
┌─────────────────────────────────────┐
│     用户层 I/O 软件                  │  ← 用户空间
│     （库函数、假脱机系统）            │
├─────────────────────────────────────┤
│     设备独立性软件                   │  ← 内核空间
│     （设备驱动程序的统一接口）         │
├─────────────────────────────────────┤
│     设备驱动程序                     │
│     （与硬件直接交互）                │
├─────────────────────────────────────┤
│     中断处理程序                     │
│     （处理设备中断）                  │
├─────────────────────────────────────┤
│           硬    件                   │
└─────────────────────────────────────┘
```

### 各层功能详解

#### 1. 用户层 I/O 软件

| 项目 | 内容 |
|------|------|
| **位置** | 用户空间 |
| **组成** | 与 I/O 操作相关的库函数、SPOOLing 系统等 |
| **功能** | 为用户提供便捷的 I/O 接口，屏蔽底层细节 |
| **示例** | `printf()`、`scanf()`、`fopen()`、`fread()` 等标准 I/O 函数 |
| **特点** | 不涉及具体的设备操作，通过系统调用进入内核 |

```c
// 用户层示例：C 标准库函数
#include <stdio.h>

int main() {
    FILE *fp = fopen("data.txt", "r");  // 用户层 I/O 函数
    char buffer[1024];
    fread(buffer, 1, 1024, fp);          // 用户层 I/O 函数
    fclose(fp);
    return 0;
}
```

> [!note] 系统调用过程
> 用户层 I/O 函数通过系统调用（如 `read()`、`write()`）陷入内核，由内核完成实际的 I/O 操作。

#### 2. 设备独立性软件（设备无关软件）

| 项目 | 内容 |
|------|------|
| **位置** | 内核空间 |
| **别名** | 设备无关软件、系统调用处理层 |
| **核心功能** | 实现设备独立性，即用户程序与具体物理设备无关 |

**主要职责：**

1. **统一接口**：为所有设备提供统一的 `read()`、`write()` 等接口
2. **设备命名与映射**：将逻辑设备名映射为物理设备名
3. **设备保护**：检查用户是否有权访问指定设备
4. **缓冲管理**：管理内核缓冲区
5. **差错控制**：处理 I/O 操作中的错误
6. **分配与释放**：管理设备的分配和回收

```
用户请求：read("/dev/printer", buffer, size)
              ↓
    设备独立性软件：查找逻辑设备 "printer" 对应的物理设备
              ↓
    映射为物理设备：/dev/lp0
              ↓
    调用对应设备驱动程序
```

> [!important] 设备独立性
> 设备独立性（Device Independence）是指用户程序中使用的设备与物理设备无关，使用逻辑设备名。这样当物理设备更换时，用户程序无需修改。

#### 3. 设备驱动程序

| 项目 | 内容 |
|------|------|
| **位置** | 内核空间 |
| **特点** | 与具体设备相关，每个设备类型有对应的驱动程序 |
| **功能** | 将上层请求转换为设备能理解的命令，直接控制设备 |

**主要职责：**

1. **接收上层请求**：接收来自设备独立性软件的 I/O 请求
2. **转换为设备命令**：将抽象请求转换为具体的设备控制命令
3. **检查设备状态**：检查设备是否就绪
4. **启动设备**：向设备控制器发送命令，启动 I/O 操作
5. **响应中断**：设备完成操作后，响应中断并处理

```c
// 设备驱动程序伪代码示例
void disk_driver_read(int block_num, char *buffer) {
    // 1. 检查磁盘是否就绪
    while (!disk_ready()) {
        // 等待设备就绪
    }
    
    // 2. 设置磁盘控制器寄存器
    set_disk_block(block_num);
    set_disk_buffer(buffer);
    set_disk_command(READ);
    
    // 3. 启动磁盘操作
    start_disk();
    
    // 4. 操作完成后通过中断通知
}
```

> [!warning] 注意
> 设备驱动程序与具体硬件密切相关，不同操作系统、不同设备需要不同的驱动程序。

#### 4. 中断处理程序

| 项目 | 内容 |
|------|------|
| **位置** | 内核空间 |
| **触发方式** | 由硬件中断信号触发 |
| **功能** | 处理设备完成 I/O 操作后产生的中断 |

**处理流程：**

```
1. 保存被中断进程的 CPU 环境（寄存器状态）
2. 检查中断原因（是哪个设备产生的中断）
3. 调用对应设备的中断处理程序
4. 处理中断（如将数据从设备缓冲区复制到内存）
5. 恢复被中断进程的 CPU 环境
6. 返回断点继续执行
```

> [!tip] 中断处理的特点
> 中断处理程序需要尽可能快地执行，以减少对正常程序执行的影响。复杂的中断后续处理通常放在中断返回后由软中断或工作队列完成。

### 层次结构总结

| 层次 | 位置 | 与设备的关联 | 核心职责 |
|------|------|-------------|----------|
| 用户层 I/O 软件 | 用户空间 | 设备无关 | 提供用户接口 |
| 设备独立性软件 | 内核空间 | 设备无关 | 统一接口、设备映射、缓冲管理 |
| 设备驱动程序 | 内核空间 | 设备相关 | 设备控制、命令转换 |
| 中断处理程序 | 内核空间 | 设备相关 | 响应中断、完成后续处理 |

> [!example] 真题示例
> **题目**：I/O 软件层次结构中，负责将逻辑设备名映射为物理设备名的是哪一层？
> 
> **答案**：设备独立性软件（设备无关软件）。

## 5.1.3 I/O 控制方式

I/O 控制方式是指 CPU 控制 I/O 设备完成数据传输的方法。随着技术发展，I/O 控制方式不断进步，CPU 的干预越来越少，系统效率越来越高。

### 四种 I/O 控制方式对比

| 特性 | 程序直接控制方式 | 中断驱动方式 | DMA 方式 | 通道控制方式 |
|------|----------------|-------------|----------|-------------|
| **数据传送单位** | 字（Word） | 字（Word） | 数据块（Block） | 一组数据块 |
| **CPU 干预频率** | 极高（每个字） | 高（每个字） | 中（每个数据块） | 低（一组数据块） |
| **数据流向** | 设备 ↔ CPU ↔ 内存 | 设备 ↔ CPU ↔ 内存 | 设备 ↔ 内存（不经过 CPU） | 设备 ↔ 内存（不经过 CPU） |
| **并行性** | 无 | 部分并行 | 较高 | 最高 |
| **硬件复杂度** | 简单 | 较简单 | 较复杂 | 复杂 |
| **适用设备** | 简单、低速设备 | 低速字符设备 | 高速块设备 | 高速块设备 |
| **CPU 效率** | 最低 | 较低 | 较高 | 最高 |

### 1. 程序直接控制方式（程序查询方式）

#### 工作原理

CPU 通过轮询（Polling）不断查询设备状态，直到设备就绪后进行数据传输。

```
CPU ──→ 查询设备状态 ──→ 设备就绪？
              ↑                │
              └──── 否 ────────┘
                               │ 是
                               ↓
                    CPU ←──→ 数据传输
```

#### 工作流程

```c
// 程序直接控制方式伪代码
void programmed_io_read() {
    while (1) {
        // 1. 读取设备状态寄存器
        status = read_status_register();
        
        // 2. 检查设备是否就绪
        if (status == READY) {
            // 3. 从数据寄存器读取数据
            data = read_data_register();
            
            // 4. 将数据存入内存
            memory[addr++] = data;
            
            // 5. 检查是否传输完成
            if (transfer_complete()) break;
        }
        
        // 设备未就绪，继续轮询
    }
}
```

#### 特点分析

| 优点 | 缺点 |
|------|------|
| 硬件简单，实现容易 | CPU 需要不断轮询，效率极低 |
| 控制精确 | CPU 和 I/O 设备串行工作，无法并行 |
| | 浪费大量 CPU 时间在等待上 |

> [!warning] 致命缺陷
> 在程序直接控制方式中，CPU 需要**不断轮询**设备状态，导致 CPU 利用率极低。假设设备传输一个字需要 1ms，CPU 查询一次需要 1μs，则 CPU 有 99.9% 的时间浪费在轮询上。

### 2. 中断驱动方式

#### 工作原理

CPU 发出 I/O 命令后，无需等待，继续执行其他任务。当设备完成数据传输后，向 CPU 发送中断信号，CPU 响应中断并处理数据。

```
CPU ──→ 发出 I/O 命令 ──→ 继续执行其他任务
                               ↑
设备 ←── 传输数据 ──→ 传输完成 ──┘
                               │
                               ↓ 中断信号
                    CPU 保存现场 → 执行中断处理 → 恢复现场
```

#### 工作流程

```c
// 中断驱动方式伪代码

// 主程序
void main() {
    // 1. 发出 I/O 命令
    issue_io_command(READ, device_id, buffer);
    
    // 2. CPU 继续执行其他任务（无需等待）
    do_other_work();
}

// 中断处理程序（设备完成传输后调用）
void interrupt_handler() {
    // 1. 保存 CPU 现场
    save_context();
    
    // 2. 读取数据
    data = read_data_register();
    memory[buffer_addr++] = data;
    
    // 3. 检查是否完成
    if (!transfer_complete()) {
        // 继续下一次传输
        issue_io_command(READ, device_id, buffer);
    }
    
    // 4. 恢复 CPU 现场
    restore_context();
}
```

#### 特点分析

| 优点 | 缺点 |
|------|------|
| CPU 和 I/O 设备可以部分并行 | 每个字传输都需要中断，开销大 |
| 无需轮询，提高 CPU 利用率 | 数据传输仍需经过 CPU |
| 适合低速字符设备 | 高速设备会产生大量中断，影响性能 |

> [!note] 适用场景
> 中断驱动方式适合键盘、鼠标等低速字符设备，因为这些设备产生数据的频率较低，不会频繁触发中断。

### 3. DMA 方式（直接存储器存取）

#### 工作原理

DMA（Direct Memory Access）方式在内存和设备之间开辟直接数据通路，数据传输不经过 CPU，由 DMA 控制器控制完成。

```
        ┌─────────────────┐
        │      CPU        │
        │  （设置 DMA 参数）│
        └────────┬────────┘
                 │ 命令
                 ↓
        ┌─────────────────┐
        │   DMA 控制器     │←──── 控制数据传输
        │  （管理数据块传输）│
        └────────┬────────┘
                 │ 直接传输
        ┌────────┴────────┐
        ↓                 ↓
   ┌─────────┐      ┌─────────┐
   │  I/O 设备 │←────→│  内  存  │
   └─────────┘      └─────────┘
```

#### DMA 控制器结构

| 寄存器 | 功能 |
|--------|------|
| **内存地址寄存器（AR）** | 存放内存中要交换的数据的地址 |
| **字计数器（WC）** | 记录要传送的数据字（字节）数 |
| **数据缓冲寄存器（BR）** | 暂存每次传送的数据 |
| **控制/状态寄存器** | 存放控制字和状态字 |

#### 工作流程

```
1. CPU 初始化 DMA 控制器：
   - 设置内存起始地址（AR）
   - 设置传输数据量（WC）
   - 设置传输方向（读/写）

2. CPU 发出启动命令，DMA 控制器接管总线

3. DMA 控制器控制数据传输：
   - 从设备读取数据到 BR
   - 将 BR 中的数据写入内存（AR 指向的地址）
   - AR 自动增量，WC 自动减量
   - 重复直到 WC = 0

4. 传输完成，DMA 控制器向 CPU 发中断

5. CPU 响应中断，进行后续处理
```

#### 特点分析

| 优点 | 缺点 |
|------|------|
| 数据传输不经过 CPU，效率高 | 需要额外的 DMA 控制器硬件 |
| 以数据块为单位传输，减少中断次数 | 每个数据块传输前后仍需 CPU 干预 |
| 适合高速块设备 | 只能控制简单的数据传输，复杂操作仍需 CPU |

> [!important] DMA 与中断的区别
> - **中断驱动方式**：每个字传输完成都产生中断，数据经过 CPU
> - **DMA 方式**：每个数据块传输完成才产生一次中断，数据不经过 CPU

### 4. 通道控制方式

#### 工作原理

通道（I/O Channel）是一种专门的 I/O 处理机，具有自己的指令系统（通道指令），可以独立执行通道程序，控制多台设备完成复杂的 I/O 操作。

```
        ┌─────────────────┐
        │      CPU        │
        │ （启动通道、处理中断）│
        └────────┬────────┘
                 │ 启动命令
                 ↓
        ┌─────────────────┐
        │   I/O 通道       │←──── 执行通道程序
        │ （独立的 I/O 处理器）│     控制多台设备
        └────────┬────────┘
                 │
        ┌────────┼────────┐
        ↓        ↓        ↓
   ┌────────┐┌────────┐┌────────┐
   │ 设备 1  ││ 设备 2  ││ 设备 3  │
   └────────┘└────────┘└────────┘
```

#### 通道类型

| 类型 | 连接方式 | 特点 | 适用场景 |
|------|----------|------|----------|
| **字节多路通道** | 连接多台低速设备 | 字节交叉传输，分时服务 | 打印机、终端等低速字符设备 |
| **数组选择通道** | 连接一台高速设备 | 独占通道，传输速率高 | 磁盘等高速设备 |
| **数组多路通道** | 连接多台高速设备 | 块交叉传输，兼顾效率和并发 | 磁盘等高速设备 |

#### 通道指令（通道命令字 CCW）

通道程序由一系列通道指令组成，每条通道指令包含：

| 字段 | 说明 |
|------|------|
| 操作码 | 读、写、控制等操作 |
| 内存地址 | 数据传输的内存起始地址 |
| 传输计数 | 要传输的数据量 |
| 特征位 | 链指针、错误处理等标志 |

```
// 通道程序示例（读取磁盘数据）
通道指令 1：READ  内存地址 0x1000  传输计数 1024  特征位：继续
通道指令 2：READ  内存地址 0x1400  传输计数 1024  特征位：继续
通道指令 3：READ  内存地址 0x1800  传输计数 1024  特征位：结束
```

#### 工作流程

```
1. CPU 执行 "启动 I/O" 指令，启动指定通道

2. 通道从内存中获取通道程序（通道指令序列）

3. 通道独立执行通道程序：
   - 解析通道指令
   - 控制设备完成 I/O 操作
   - 管理数据传输
   - 处理设备状态

4. 通道程序执行完毕，向 CPU 发中断

5. CPU 响应中断，进行后续处理
```

#### 特点分析

| 优点 | 缺点 |
|------|------|
| CPU 干预最少，效率最高 | 硬件最复杂，成本高 |
| 可控制多台设备 | 需要专门的通道处理器 |
| 可执行复杂的 I/O 程序 | 系统设计和维护复杂 |
| 适合大型系统的高速 I/O | |

### I/O 控制方式演进总结

```
程序直接控制 ──→ 中断驱动 ──→ DMA ──→ 通道控制

CPU 干预：   极高        高        中        低
并行性：     无         部分      较高      最高
复杂度：     简单       较简单     较复杂     复杂
适用设备：   简单低速    低速字符   高速块设备  大型系统
```

> [!example] 真题示例
> **题目**：对于磁盘这类高速块设备，最适合采用哪种 I/O 控制方式？
> 
> **答案**：DMA 方式或通道控制方式。对于单台磁盘，DMA 方式即可；对于大型系统中的多台磁盘，通道控制方式效率更高。

## 5.1.4 缓冲技术

缓冲技术是在内存中设置缓冲区，用于缓解 CPU 与 I/O 设备之间速度不匹配的矛盾，减少对 CPU 的中断频率，提高 CPU 和 I/O 设备的并行性。

### 引入缓冲的原因

| 矛盾 | 说明 | 缓冲的作用 |
|------|------|-----------|
| 速度不匹配 | CPU 速度远高于 I/O 设备 | 缓冲区暂存数据，CPU 无需等待 |
| 传输单位不匹配 | CPU 按字处理，设备按块处理 | 缓冲区聚合/拆分数据 |
| 中断频率过高 | 每次数据传输都中断 CPU | 缓冲区减少中断次数 |
| 并行性不足 | CPU 和设备串行工作 | 双缓冲实现并行读写 |

### 1. 单缓冲

#### 工作原理

在内存中设置一个缓冲区，输入时设备先将数据送入缓冲区，CPU 再从缓冲区取走数据；输出时相反。

```
输入操作：
设备 ──→ [缓冲区] ──→ CPU/内存
   T         M         C

T：设备将数据送入缓冲区的时间
M：CPU 将数据从缓冲区移到内存的时间
C：CPU 处理数据的时间
```

#### 时间分析

假设处理每块数据，设备输入时间为 T，CPU 处理时间为 C，数据从缓冲区移到内存时间为 M。

**情况 1：T > C**

```
时间轴：
设备： [====T====]
CPU：       [M][=C=]
              ↓
       处理每块数据时间 = T + M
```

**情况 2：C > T**

```
时间轴：
设备： [====T====]
CPU：       [M][=====C=====]
              ↓
       处理每块数据时间 = C + M
```

#### 单缓冲处理时间公式

> [!important] 核心公式
> **处理每块数据时间 = max(C, T) + M**

> [!note] 公式解释
> - max(C, T)：设备和 CPU 串行部分的最大值
> - M：CPU 从缓冲区取数的时间（必须等设备和 CPU 都完成后才能进行）

#### 单缓冲示例

```
例题：某系统采用单缓冲技术，从磁盘读取数据到缓冲区需要 100μs，
      将数据从缓冲区传送到用户区需要 50μs，CPU 处理数据需要 60μs。
      计算处理每块数据的时间。

解：
T = 100μs（设备输入时间）
C = 60μs（CPU 处理时间）
M = 50μs（缓冲区传送时间）

处理每块数据时间 = max(C, T) + M
                = max(60, 100) + 50
                = 100 + 50
                = 150μs
```

### 2. 双缓冲

#### 工作原理

设置两个缓冲区，设备向一个缓冲区输入数据的同时，CPU 可以从另一个缓冲区读取数据，实现设备和 CPU 的并行工作。

```
缓冲区 A： [========] ← 设备写入
缓冲区 B： [========] → CPU 读取

当 A 满 B 空时，交换角色：
缓冲区 A： [========] → CPU 读取
缓冲区 B： [========] ← 设备写入
```

#### 时间分析

**情况 1：T > C**

```
时间轴：
设备： [====T====][====T====][====T====]
CPU：       [M][=C=]    [M][=C=]    [M][=C=]
              ↓
       处理每块数据时间 = T（设备是瓶颈）
```

**情况 2：C > T**

```
时间轴：
设备： [====T====][====T====][====T====]
CPU：       [M][=====C=====][M][=====C=====]
              ↓
       处理每块数据时间 = C（CPU 是瓶颈）
```

#### 双缓冲处理时间公式

> [!important] 核心公式
> **处理每块数据时间 = max(C, T)**

> [!note] 与单缓冲对比
> 双缓冲消除了 M 的影响，因为当 CPU 处理一个缓冲区的数据时，设备可以同时向另一个缓冲区写入数据。

#### 双缓冲示例

```
例题：某系统采用双缓冲技术，从磁盘读取数据到缓冲区需要 100μs，
      将数据从缓冲区传送到用户区需要 50μs，CPU 处理数据需要 60μs。
      计算处理每块数据的时间。

解：
T = 100μs（设备输入时间）
C = 60μs（CPU 处理时间）
M = 50μs（缓冲区传送时间）

处理每块数据时间 = max(C, T)
                = max(60, 100)
                = 100μs

对比单缓冲：150μs → 双缓冲：100μs，效率提升 33.3%
```

### 3. 循环缓冲

#### 工作原理

设置多个大小相等的缓冲区，排成循环队列。设备依次向各个缓冲区写入数据，CPU 依次从各个缓冲区读取数据。

```
        ┌─────────┐
        │ 缓冲区 0 │←── 写入指针（设备）
        └────┬────┘
             │
        ┌────┴────┐
        │ 缓冲区 1 │
        └────┬────┘
             │
        ┌────┴────┐
        │ 缓冲区 2 │←── 读取指针（CPU）
        └────┬────┘
             │
        ┌────┴────┐
        │ 缓冲区 3 │
        └─────────┘
```

#### 特点

| 优点 | 缺点 |
|------|------|
| 可以平滑处理 I/O 峰值 | 缓冲区数量固定，灵活性不足 |
| 减少设备等待时间 | 需要管理复杂的指针关系 |
| 适合生产和消费速度不匹配的场景 | 缓冲区可能过多或不足 |

### 4. 缓冲池

#### 工作原理

缓冲池是由系统管理的多个缓冲区的集合，根据使用状态分为三类队列：

```
┌─────────────────────────────────────┐
│            缓  冲  池                │
├─────────────────────────────────────┤
│  空闲缓冲区队列  │  装满输入数据队列  │  装满输出数据队列  │
│   (emq)        │    (inq)         │    (outq)        │
├─────────────────────────────────────┤
│  设备输入时：从 emq 取空缓冲区 → 装满后放入 inq   │
│  CPU 处理时：从 inq 取缓冲区 → 处理完后放入 outq  │
│  设备输出时：从 outq 取缓冲区 → 输出完后放入 emq  │
└─────────────────────────────────────┘
```

#### 缓冲区类型

| 类型 | 状态 | 说明 |
|------|------|------|
| **空闲缓冲区** | 未使用 | 等待分配 |
| **装满输入数据的缓冲区** | 已装满输入数据 | 等待 CPU 处理 |
| **装满输出数据的缓冲区** | 已装满输出数据 | 等待设备输出 |
| **正在工作的缓冲区** | 正在被使用 | 不属于任何队列 |

#### 工作流程

```
输入过程：
1. 从空闲队列取一个空缓冲区
2. 设备向该缓冲区输入数据
3. 数据装满后，将该缓冲区放入输入队列

处理过程：
1. 从输入队列取一个装满数据的缓冲区
2. CPU 处理该缓冲区中的数据
3. 处理完后，将结果放入输出队列（或释放到空闲队列）

输出过程：
1. 从输出队列取一个装满输出数据的缓冲区
2. 设备输出该缓冲区中的数据
3. 输出完后，将该缓冲区放回空闲队列
```

#### 特点

| 优点 | 说明 |
|------|------|
| 资源共享 | 多个进程可以共享缓冲池中的缓冲区 |
| 动态分配 | 根据需求动态分配缓冲区，提高利用率 |
| 统一管理 | 系统集中管理，避免资源浪费 |
| 灵活性高 | 可以适应不同的 I/O 需求 |

### 缓冲技术对比总结

| 特性 | 单缓冲 | 双缓冲 | 循环缓冲 | 缓冲池 |
|------|--------|--------|----------|--------|
| **缓冲区数量** | 1 | 2 | N（固定） | N（动态管理） |
| **并行性** | 无 | 有 | 有 | 有 |
| **处理时间** | max(C,T)+M | max(C,T) | ≈max(C,T) | ≈max(C,T) |
| **复杂度** | 低 | 低 | 中 | 高 |
| **适用场景** | 简单系统 | 单设备 | 生产-消费模型 | 多进程复杂系统 |
| **灵活性** | 低 | 低 | 中 | 高 |

> [!example] 真题示例
> **题目**：某文件占 10 个磁盘块，每块读入缓冲区时间为 100μs，从缓冲区送至用户区时间为 50μs，CPU 分析每块时间为 50μs。分别计算单缓冲和双缓冲处理全部文件的时间。
> 
> **解答**：
> - 单缓冲：每块时间 = max(50, 100) + 50 = 150μs，总时间 = 10 × 150 = 1500μs
> - 双缓冲：每块时间 = max(50, 100) = 100μs，总时间 = 10 × 100 = 1000μs

## 5.1.5 设备分配

设备分配是操作系统根据用户请求，将设备分配给进程使用的过程。设备分配需要考虑设备特性、安全性、利用率等因素。

### 设备分配数据结构

操作系统使用四张表来管理设备分配：

```
系统设备表 SDT
├── 设备 1 ──→ 设备控制表 DCT 1
│                  ├── 控制器 1 ──→ 控制器控制表 COCT 1
│                  │                    ├── 通道 1 ──→ 通道控制表 CHCT 1
│                  │                    └── 通道 2 ──→ 通道控制表 CHCT 2
│                  └── 控制器 2 ──→ 控制器控制表 COCT 2
├── 设备 2 ──→ 设备控制表 DCT 2
└── ...
```

### 1. 系统设备表（SDT）

| 字段 | 说明 |
|------|------|
| 设备类型 | 设备的类型标识 |
| 设备标识符 | 设备的唯一标识 |
| 设备控制表指针 | 指向该设备的 DCT |
| 驱动程序入口 | 指向设备驱动程序的指针 |

### 2. 设备控制表（DCT）

| 字段 | 说明 |
|------|------|
| 设备类型 | 设备的类型 |
| 设备标识符 | 设备的唯一标识 |
| 设备状态 | 忙/闲、是否故障等 |
| 与设备连接的控制器表指针 | 指向该设备连接的 COCT |
| 重复执行次数或时间 | 出错时重复尝试的次数 |
| 设备队列的队首指针 | 指向等待该设备的进程队列 |

### 3. 控制器控制表（COCT）

| 字段 | 说明 |
|------|------|
| 控制器标识符 | 控制器的唯一标识 |
| 控制器状态 | 忙/闲 |
| 与控制器连接的通道表指针 | 指向该控制器连接的 CHCT |
| 控制器队列的队首指针 | 指向等待该控制器的进程队列 |

### 4. 通道控制表（CHCT）

| 字段 | 说明 |
|------|------|
| 通道标识符 | 通道的唯一标识 |
| 通道状态 | 忙/闲 |
| 通道队列的队首指针 | 指向等待该通道的进程队列 |

### 数据结构关系图

```
┌─────────────────────────────────────────────────────────┐
│                      SDT（系统设备表）                    │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐                 │
│  │ 设备 A  │  │ 设备 B  │  │ 设备 C  │                 │
│  └───┬─────┘  └────┬────┘  └────┬────┘                 │
│      │             │            │                       │
│      ↓             ↓            ↓                       │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐                 │
│  │ DCT(A)  │  │ DCT(B)  │  │ DCT(C)  │                 │
│  └───┬─────┘  └────┬────┘  └────┬────┘                 │
│      │             │            │                       │
│      ↓             ↓            ↓                       │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐                 │
│  │ COCT(1) │  │ COCT(2) │  │ COCT(3) │                 │
│  └───┬─────┘  └────┬────┘  └────┬────┘                 │
│      │             │            │                       │
│      ↓             ↓            ↓                       │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐                 │
│  │ CHCT(1) │  │ CHCT(2) │  │ CHCT(3) │                 │
│  └─────────┘  └─────────┘  └─────────┘                 │
└─────────────────────────────────────────────────────────┘
```

### 设备分配策略

#### 分配方式

| 方式 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **静态分配** | 进程运行前分配所有需要的设备 | 不会产生死锁 | 设备利用率低 |
| **动态分配** | 进程运行中根据需要申请设备 | 设备利用率高 | 可能产生死锁 |

#### 分配算法

| 算法 | 说明 | 适用场景 |
|------|------|----------|
| **先来先服务（FCFS）** | 按请求顺序分配 | 简单公平，通用 |
| **优先级高者优先** | 优先级高的进程优先分配 | 实时系统 |

### 设备分配流程

```
1. 进程提出 I/O 请求（逻辑设备名）

2. 查找 SDT，找到对应设备的 DCT

3. 检查设备状态：
   ├─ 设备忙 → 将进程插入设备等待队列
   └─ 设备闲 → 继续检查控制器

4. 检查控制器状态：
   ├─ 控制器忙 → 将进程插入控制器等待队列
   └─ 控制器闲 → 继续检查通道

5. 检查通道状态：
   ├─ 通道忙 → 将进程插入通道等待队列
   └─ 通道闲 → 分配成功

6. 将逻辑设备名映射为物理设备名

7. 启动设备进行 I/O 操作
```

> [!warning] 注意
> 设备分配需要依次检查设备、控制器、通道三个层次，只有三者都空闲时，分配才算成功。这种分配方式称为"设备-控制器-通道"三级分配。

### 设备分配安全性

#### 安全分配方式

| 特性 | 说明 |
|------|------|
| **方式** | 进程发出 I/O 请求后阻塞，直到 I/O 完成才唤醒 |
| **优点** | 不会产生死锁（破坏了请求和保持条件） |
| **缺点** | 进程阻塞期间不能继续执行，并行性差 |

#### 不安全分配方式

| 特性 | 说明 |
|------|------|
| **方式** | 进程发出 I/O 请求后继续执行，可以再次申请设备 |
| **优点** | 进程推进速度快，并行性好 |
| **缺点** | 可能产生死锁，需要死锁检测和恢复机制 |

> [!example] 真题示例
> **题目**：设备分配中，为什么需要同时检查设备、控制器和通道的状态？
> 
> **答案**：因为 I/O 操作的完成需要设备、控制器和通道三者的协同工作。任何一个环节被占用，I/O 操作都无法进行，所以必须确保三者都空闲才能分配成功。

## 5.1.6 SPOOLing 技术

SPOOLing（Simultaneous Peripheral Operations On-Line，外部设备联机并行操作）技术是一种虚拟设备技术，通过磁盘上的输入井和输出井，将独占设备改造为共享设备。

### SPOOLing 系统组成

```
┌─────────────────────────────────────────────────────────────┐
│                     SPOOLing 系统                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   输入设备 ──→ 输入缓冲区 ──→ 输入井（磁盘）                  │
│      ↑                                          ↓            │
│      └──────────── 输入进程（预输入）─────────────┘            │
│                                                             │
│   用户进程 ←──────────────────────────────────── 内存         │
│      ↓                                          ↑            │
│      ├──────────── 输出进程（缓输出）─────────────┘            │
│      ↓                                          ↑            │
│   输出井（磁盘）──→ 输出缓冲区 ──→ 输出设备                   │
│                                                             │
│   井管理程序：管理输入井和输出井的存取                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### SPOOLing 系统的组成要素

| 组成部分 | 类型 | 功能说明 |
|----------|------|----------|
| **输入井** | 磁盘空间 | 模拟脱机输入时的磁盘，存放从输入设备预输入的数据 |
| **输出井** | 磁盘空间 | 模拟脱机输出时的磁盘，存放用户进程的输出数据 |
| **输入缓冲区** | 内存区域 | 暂存从输入设备读入的数据，再转存到输入井 |
| **输出缓冲区** | 内存区域 | 暂存从输出井取出的数据，再传送到输出设备 |
| **输入进程** | 系统进程 | 将数据从输入设备预输入到输入井 |
| **输出进程** | 系统进程 | 将数据从输出井缓输出到输出设备 |
| **井管理程序** | 系统程序 | 管理输入井和输出井，控制数据的存取 |

### SPOOLing 工作原理

#### 输入过程（预输入）

```
1. 输入进程启动

2. 从输入设备读取数据到输入缓冲区

3. 将输入缓冲区的数据写入输入井

4. 重复 2-3，直到输入完成

5. 当用户进程需要输入时，直接从输入井读取
```

#### 输出过程（缓输出）

```
1. 用户进程产生输出数据

2. 将输出数据写入输出井

3. 输出进程检查输出井

4. 从输出井读取数据到输出缓冲区

5. 将输出缓冲区的数据传送到输出设备

6. 重复 4-5，直到输出完成
```

### 共享打印机原理

共享打印机是 SPOOLing 技术最典型的应用，将独占的打印机虚拟为多台逻辑打印机。

#### 工作原理

```
进程 A ──→ 请求打印 ──→ 输出井（磁盘文件）
                            ↓
进程 B ──→ 请求打印 ──→ 输出井（磁盘文件）
                            ↓
进程 C ──→ 请求打印 ──→ 输出井（磁盘文件）
                            ↓
                    输出进程（打印机守护进程）
                            ↓
                        实际打印机
```

#### 详细流程

```
1. 用户进程请求打印

2. 输出进程在输出井中申请空闲磁盘块

3. 将要打印的数据写入输出井的磁盘块中

4. 为用户进程填写打印请求表，放入打印请求队列

5. 用户进程继续执行（无需等待打印完成）

6. 打印机守护进程（输出进程）依次处理打印请求队列：
   a. 从打印请求队列取出一个请求
   b. 从输出井读取对应数据到内存缓冲区
   c. 将数据从缓冲区传送到打印机
   d. 打印完成后，释放输出井空间
   e. 处理下一个请求
```

#### 共享打印机的优势

| 优势 | 说明 |
|------|------|
| **提高设备利用率** | 多台进程可以同时"使用"打印机（实际是写入输出井） |
| **用户无需等待** | 用户进程将数据写入输出井后即可继续执行 |
| **实现虚拟设备** | 一台物理打印机虚拟为多台逻辑打印机 |
| **便于管理** | 可以统一调度打印任务，如优先级控制、打印队列管理 |

> [!important] 核心概念
> SPOOLing 技术的本质是**以空间换时间**：用磁盘空间（输入井/输出井）换取设备使用效率的提升，用磁盘设备的共享性弥补字符设备的独占性。

### SPOOLing 技术的特点

| 特点 | 说明 |
|------|------|
| **提高了 I/O 速度** | 数据在磁盘和设备之间传输，速度远高于直接在设备和内存之间传输 |
| **将独占设备改造为共享设备** | 多个进程可以同时使用逻辑设备 |
| **实现了虚拟设备功能** | 用户感觉独占了一台设备，实际上是共享 |
| **需要磁盘空间** | 输入井和输出井需要占用磁盘空间 |
| **需要额外的系统进程** | 输入进程和输出进程消耗系统资源 |

### SPOOLing 与缓冲技术的区别

| 特性 | SPOOLing | 缓冲技术 |
|------|----------|----------|
| **目的** | 将独占设备变为共享设备 | 缓解速度不匹配 |
| **存储位置** | 磁盘（输入井/输出井） | 内存（缓冲区） |
| **数据流向** | 设备 ↔ 磁盘 ↔ 内存 | 设备 ↔ 内存 |
| **适用设备** | 独占设备（如打印机） | 各种 I/O 设备 |
| **实现复杂度** | 高（需要系统进程管理） | 相对较低 |

> [!example] 真题示例
> **题目**：SPOOLing 系统由哪些部分组成？共享打印机是如何实现的？
> 
> **答案**：SPOOLing 系统由输入井、输出井、输入缓冲区、输出缓冲区、输入进程、输出进程和井管理程序组成。共享打印机的实现原理是：用户进程将打印数据写入输出井，输出进程（打印机守护进程）从输出井取出数据并控制打印机输出。这样，多个用户进程可以同时向输出井写入数据，实现了一台物理打印机的共享使用。

## 本章考点总结

### 高频考点

1. **I/O 控制方式对比**：掌握四种方式的数据传送单位、CPU 干预频率、适用设备
2. **缓冲时间计算**：单缓冲 max(C,T)+M，双缓冲 max(C,T)
3. **设备分配数据结构**：SDT → DCT → COCT → CHCT 的层次关系
4. **SPOOLing 系统组成**：七要素及其功能
5. **共享打印机原理**：输出井 + 输出进程实现虚拟设备

### 易混淆概念辨析

| 概念 A | 概念 B | 区别 |
|--------|--------|------|
| 单缓冲 | 双缓冲 | 单缓冲处理时间 = max(C,T)+M；双缓冲处理时间 = max(C,T) |
| DMA 方式 | 通道方式 | DMA 控制单个数据块，通道可执行通道程序控制多个数据块 |
| 缓冲技术 | SPOOLing 技术 | 缓冲在内存，缓解速度不匹配；SPOOLing 在磁盘，实现设备共享 |
| 独占设备 | 虚拟设备 | 独占设备一次只能被一个进程使用；虚拟设备通过 SPOOLing 实现共享 |

### 重要公式汇总

| 公式 | 适用场景 |
|------|----------|
| 单缓冲处理时间 = max(C, T) + M | 单缓冲区，设备和 CPU 串行 |
| 双缓冲处理时间 = max(C, T) | 双缓冲区，设备和 CPU 并行 |
