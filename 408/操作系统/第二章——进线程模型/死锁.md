# 死锁

[[第二章——进线程模型|← 返回目录]]

## 一、死锁的基本概念

### 1.1 死锁的定义
多个进程在执行过程中，因争夺资源而造成的一种互相等待的现象，若无外力作用，它们都将无法推进下去。

### 1.2 死锁的例子

**两个进程两个资源：**

```
P1:             P2:
申请A;          申请B;
申请B;          申请A;
释放A;          释放B;
释放B;          释放A;
```

若P1持有A，P2持有B，然后P1申请B，P2申请A，就会发生死锁。

---

## 二、死锁产生的必要条件

### 2.1 四个必要条件

| 条件 | 说明 |
|------|------|
| **互斥条件** | 资源在一段时间内只能由一个进程使用 |
| **请求和保持条件** | 进程已保持至少一个资源，又提出新的资源请求，且该资源被其他进程占用 |
| **不可剥夺条件** | 进程已获得的资源在未使用完前不能被剥夺 |
| **循环等待条件** | 存在一个进程循环等待链，每个进程都等待下一个进程占有的资源 |

**注意：** 四个条件必须同时满足才会发生死锁。

---

## 三、死锁的处理策略

### 3.1 死锁预防
破坏死锁的四个必要条件之一。

### 3.2 死锁避免
在资源分配时，判断系统是否安全，若安全则分配。

### 3.3 死锁检测与解除
允许死锁发生，定期检测并解除。

### 3.4 死锁忽略
认为死锁不会发生，或发生后由用户处理。

---

## 四、死锁预防

### 4.1 破坏互斥条件
- 难实现，很多资源必须互斥访问

### 4.2 破坏请求和保持条件

**方法一：** 进程一次性申请所有需要的资源。
- 缺点：资源浪费，进程可能延迟运行

**方法二：** 进程申请新资源前释放已占用的资源。
- 缺点：实现复杂，可能反复申请释放

### 4.3 破坏不可剥夺条件

**方法：** 当进程请求的资源被占用时，若占用者是等待状态，则剥夺其资源。
- 缺点：实现复杂，可能导致进程反复被剥夺

### 4.4 破坏循环等待条件

**方法：** 对资源进行编号，进程按编号递增的顺序申请资源。
- 优点：简单有效
- 缺点：资源编号必须合理，限制了用户的自由

---

## 五、死锁避免

### 5.1 安全状态与不安全状态

**安全状态：** 存在一个安全序列，使所有进程都能依次完成。

**安全序列：** 进程序列{P1, P2, ..., Pn}，对于每个Pi，其剩余资源需求 ≤ 系统当前可用资源 + 所有Pj（j < i）已分配的资源。

**不安全状态：** 不存在安全序列。

**注意：** 安全状态一定不会死锁，不安全状态可能死锁。

---

### 5.2 银行家算法（Dijkstra算法）

#### 数据结构

| 名称 | 含义 | 维度 |
|------|------|------|
| Available | 可用资源数 | m维向量 |
| Max | 进程最大需求 | n×m矩阵 |
| Allocation | 进程已分配 | n×m矩阵 |
| Need | 进程剩余需求 | n×m矩阵 |

**Need = Max - Allocation**

#### 银行家算法步骤

**请求资源Request[i]：**

1. 若 Request[i] ≤ Need[i]，转2；否则出错
2. 若 Request[i] ≤ Available，转3；否则等待
3. 试分配：
   - Available = Available - Request[i]
   - Allocation[i] = Allocation[i] + Request[i]
   - Need[i] = Need[i] - Request[i]
4. 调用安全性算法，若安全则分配；否则回滚

#### 安全性算法

1. 设置两个向量：Work = Available，Finish = false
2. 查找满足条件的进程：
   - Finish[i] = false
   - Need[i] ≤ Work
3. 若找到：
   - Work = Work + Allocation[i]
   - Finish[i] = true
   - 回到步骤2
4. 若所有Finish[i] = true，则安全；否则不安全

---

#### 银行家算法示例

**已知：** 5个进程P0-P4，3类资源A(10)、B(5)、C(7)

| 进程 | Max | Allocation | Need | Available |
|------|-----|------------|------|-----------|
|      | A B C | A B C | A B C | A B C |
| P0 | 7 5 3 | 0 1 0 | 7 4 3 | 3 3 2 |
| P1 | 3 2 2 | 2 0 0 | 1 2 2 | |
| P2 | 9 0 2 | 3 0 2 | 6 0 0 | |
| P3 | 2 2 2 | 2 1 1 | 0 1 1 | |
| P4 | 4 3 3 | 0 0 2 | 4 3 1 | |

**安全性检查：**

Work = [3, 3, 2], Finish = [F,F,F,F,F]

找Need ≤ Work的进程：
- P1: [1,2,2] ≤ [3,3,2] ✓
- P3: [0,1,1] ≤ [3,3,2] ✓

选P1：
- Work = [3,3,2] + [2,0,0] = [5,3,2]
- Finish = [F,T,F,F,F]

找Need ≤ Work的进程：
- P3: [0,1,1] ≤ [5,3,2] ✓
- P4: [4,3,1] ≤ [5,3,2] ✓

选P3：
- Work = [5,3,2] + [2,1,1] = [7,4,3]
- Finish = [F,T,F,T,F]

找Need ≤ Work的进程：
- P0: [7,4,3] ≤ [7,4,3] ✓
- P2: [6,0,0] ≤ [7,4,3] ✓
- P4: [4,3,1] ≤ [7,4,3] ✓

选P4：
- Work = [7,4,3] + [0,0,2] = [7,4,5]
- Finish = [F,T,F,T,T]

选P2：
- Work = [7,4,5] + [3,0,2] = [10,4,7]
- Finish = [F,T,T,T,T]

选P0：
- Work = [10,4,7] + [0,1,0] = [10,5,7]
- Finish = [T,T,T,T,T]

所有Finish=T，安全！安全序列：P1→P3→P4→P2→P0

**现在P1请求[1,0,2]：**

检查Request1 ≤ Need1：[1,0,2] ≤ [1,2,2] ✓
检查Request1 ≤ Available：[1,0,2] ≤ [3,3,2] ✓

试分配：
- Available = [3,3,2] - [1,0,2] = [2,3,0]
- Allocation1 = [2,0,0] + [1,0,2] = [3,0,2]
- Need1 = [1,2,2] - [1,0,2] = [0,2,0]

检查安全性：
可以找到安全序列，如P1→P3→P0→P2→P4，所以可以分配。

## 六、死锁检测与解除

### 6.1 死锁检测

**资源分配图：**
- 圆形表示进程
- 矩形表示资源类
- 矩形中的圆点表示资源实例
- 进程→资源：请求边
- 资源→进程：分配边

**简化资源分配图：**
1. 找一个不阻塞且不孤立的进程节点
2. 释放它的所有资源，消去所有边
3. 重复上述步骤
4. 若所有节点都能消去，则无死锁；否则有死锁

---

### 6.2 死锁解除

**方法一：** 资源剥夺
- 挂起一些死锁进程，剥夺其资源给其他进程
- 选择原则：优先级、已运行时间、剩余时间等

**方法二：** 撤销进程
- 撤销所有死锁进程，或逐个撤销直到死锁解除
- 选择原则：优先级、消耗资源、已运行时间等

**方法三：** 进程回退
- 让进程回退到安全状态，释放资源
- 需要保存检查点
