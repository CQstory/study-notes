# 同步与互斥

[[第二章——进线程模型|← 返回目录]]

## 一、基本概念

### 1.1 进程同步
进程同步是指协调多个相关进程在执行次序上的关系，使它们能按一定的规则执行。

### 1.2 进程互斥
进程互斥是指多个进程不能同时进入临界区访问临界资源。

### 1.3 临界资源
一次仅允许一个进程使用的资源，如打印机、共享变量等。

### 1.4 临界区
访问临界资源的那段代码。

### 1.5 同步机制应遵循的准则

| 准则 | 说明 |
|------|------|
| **空闲让进** | 临界区空闲时，应允许进程进入 |
| **忙则等待** | 临界区正被访问时，其他进程必须等待 |
| **有限等待** | 进程应在有限时间内进入临界区，避免饥饿 |
| **让权等待** | 进程不能进入临界区时，应释放处理机 |

## 二、实现临界区互斥的软件方法

### 2.1 单标志法

```c
int turn = 0;  // 表示允许进入临界区的进程号

// P0
while (turn != 0);  // 忙等
临界区;
turn = 1;
剩余区;

// P1
while (turn != 1);  // 忙等
临界区;
turn = 0;
剩余区;
```

**缺点：** 强制轮流，违反空闲让进。

---

### 2.2 双标志法（先检查）

```c
bool flag[2] = {false, false};  // 表示进程是否想进入临界区

// P0
while (flag[1]);  // 检查P1是否想进入
flag[0] = true;   // 表示P0想进入
临界区;
flag[0] = false;
剩余区;

// P1
while (flag[0]);  // 检查P0是否想进入
flag[1] = true;   // 表示P1想进入
临界区;
flag[1] = false;
剩余区;
```

**缺点：** 可能两个进程同时进入临界区，违反忙则等待。

---

### 2.3 双标志法（后检查）

```c
bool flag[2] = {false, false};

// P0
flag[0] = true;   // 先表示想进入
while (flag[1]);  // 再检查P1是否想进入
临界区;
flag[0] = false;
剩余区;

// P1
flag[1] = true;   // 先表示想进入
while (flag[0]);  // 再检查P0是否想进入
临界区;
flag[1] = false;
剩余区;
```

**缺点：** 可能两个进程都无法进入临界区，饥饿，违反有限等待。

---

### 2.4 Peterson算法

```c
bool flag[2] = {false, false};
int turn = 0;

// P0
flag[0] = true;
turn = 1;               // 表示让对方先进入
while (flag[1] && turn == 1);  // 对方想进入且该对方进入时等待
临界区;
flag[0] = false;
剩余区;

// P1
flag[1] = true;
turn = 0;               // 表示让对方先进入
while (flag[0] && turn == 0);  // 对方想进入且该对方进入时等待
临界区;
flag[1] = false;
剩余区;
```

**优点：** 满足四个准则。

## 三、硬件实现方法

### 3.1 中断屏蔽

```
关中断;
临界区;
开中断;
```

**优点：** 简单
**缺点：** 权限大，不适合多CPU

---

### 3.2 Test-and-Set（TS指令）

```c
bool TS(bool *lock) {
    bool old = *lock;
    *lock = true;
    return old;
}

// 使用
bool lock = false;
while (TS(&lock));  // 忙等
临界区;
lock = false;
剩余区;
```

**特点：** 原子操作，忙等。

---

### 3.3 Swap指令

```c
void Swap(bool *a, bool *b) {
    bool temp = *a;
    *a = *b;
    *b = temp;
}

// 使用
bool lock = false;
bool key = true;
do {
    Swap(&lock, &key);
} while (key);  // 忙等
临界区;
lock = false;
剩余区;
```

## 四、信号量机制

### 4.1 整型信号量

```c
int S;

P操作：
wait(S) {
    while (S <= 0);  // 忙等
    S--;
}

V操作：
signal(S) {
    S++;
}
```

**缺点：** 忙等，不满足让权等待。

---

### 4.2 记录型信号量

```c
typedef struct {
    int value;
    struct process *L;  // 等待队列
} semaphore;

P操作：
wait(semaphore *S) {
    S->value--;
    if (S->value < 0) {
        block(S->L);  // 阻塞，加入等待队列
    }
}

V操作：
signal(semaphore *S) {
    S->value++;
    if (S->value <= 0) {
        wakeup(S->L);  // 唤醒等待队列中的进程
    }
}
```

**特点：** 不忙等，满足让权等待。

---

### 4.3 信号量的物理意义

- **S > 0**：表示可用资源数
- **S = 0**：表示无可用资源，也无等待进程
- **S < 0**：|S|表示等待队列中的进程数

---

### 4.4 信号量的应用

**互斥：**
```c
semaphore mutex = 1;

P0:
wait(mutex);
临界区;
signal(mutex);

P1:
wait(mutex);
临界区;
signal(mutex);
```

**同步：**
```c
semaphore S = 0;

P1:
x = 1;        // 先执行
signal(S);

P2:
wait(S);      // 等待P1完成
y = x + 1;    // 后执行
```

## 五、经典同步问题

### 5.1 生产者-消费者问题

**问题描述：** 一组生产者进程和一组消费者进程共享一个初始为空、大小为n的缓冲区。只有缓冲区未满时，生产者才能把消息放入缓冲区；只有缓冲区未空时，消费者才能从中取出消息。

**信号量设置：**
- `mutex`：互斥访问缓冲区，初值1
- `empty`：空缓冲区数，初值n
- `full`：满缓冲区数，初值0

**代码：**

```c
semaphore mutex = 1;
semaphore empty = n;
semaphore full = 0;

生产者() {
    while (true) {
        生产产品;
        wait(empty);
        wait(mutex);
        放入缓冲区;
        signal(mutex);
        signal(full);
    }
}

消费者() {
    while (true) {
        wait(full);
        wait(mutex);
        从缓冲区取出;
        signal(mutex);
        signal(empty);
        消费产品;
    }
}
```

**注意：** P操作顺序不能颠倒，否则可能死锁。

### 5.2 哲学家就餐问题

**问题描述：** 5个哲学家围坐在圆桌旁，每人左右各有一根筷子。哲学家思考时不影响他人，饥饿时试图拿起左右两根筷子，只有拿到两根筷子才能就餐，就餐后放下筷子继续思考。

**解法一：** 最多允许4个哲学家同时拿左边筷子

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};
semaphore count = 4;  // 最多4人同时拿左边筷子

哲学家i() {
    while (true) {
        思考;
        wait(count);
        wait(chopstick[i]);
        wait(chopstick[(i+1)%5]);
        就餐;
        signal(chopstick[i]);
        signal(chopstick[(i+1)%5]);
        signal(count);
    }
}
```

**解法二：** 奇数号哲学家先拿左边，偶数号先拿右边

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};

哲学家i() {
    while (true) {
        思考;
        if (i % 2 == 1) {
            wait(chopstick[i]);
            wait(chopstick[(i+1)%5]);
        } else {
            wait(chopstick[(i+1)%5]);
            wait(chopstick[i]);
        }
        就餐;
        signal(chopstick[i]);
        signal(chopstick[(i+1)%5]);
    }
}
```

### 5.3 读者-写者问题

**问题描述：** 多个读者可以同时读，但写者与其他进程（读者或写者）互斥。

**信号量设置：**
- `rw_mutex`：读写互斥，初值1
- `mutex`：保护readcount，初值1
- `readcount`：读者数量，初值0

**代码（读者优先）：**

```c
semaphore rw_mutex = 1;
semaphore mutex = 1;
int readcount = 0;

读者() {
    while (true) {
        wait(mutex);
        readcount++;
        if (readcount == 1) {
            wait(rw_mutex);  // 第一个读者负责加锁
        }
        signal(mutex);
        读文件;
        wait(mutex);
        readcount--;
        if (readcount == 0) {
            signal(rw_mutex);  // 最后一个读者负责解锁
        }
        signal(mutex);
    }
}

写者() {
    while (true) {
        wait(rw_mutex);
        写文件;
        signal(rw_mutex);
    }
}
```

**缺点：** 写者可能饥饿。可通过添加信号量实现写者优先。

### 5.4 吸烟者问题

**问题描述：** 一个供应者和三个吸烟者。供应者每次随机放两种原料在桌上，拥有第三种原料的吸烟者取走并吸烟。

**信号量设置：**
- `offer1`、`offer2`、`offer3`：表示桌上的原料组合
- `mutex`：互斥访问
- `finish`：表示吸烟完成

## 六、管程

### 6.1 管程的定义
管程是由一组局部于管程的共享数据、对数据进行操作的一组过程以及对数据进行初始化的代码组成的软件模块。

### 6.2 管程的特性
- 模块化
- 抽象数据类型
- 信息隐蔽
- 互斥：管程内的过程互斥执行

### 6.3 管程与信号量的关系
管程可以用信号量实现，信号量也可以用管程实现。

### 6.4 条件变量
管程中的进程可能需要等待某个条件，使用条件变量实现。

```c
wait(x);     // 等待条件x，释放管程
signal(x);   // 唤醒等待x的一个进程
broadcast(x); // 唤醒等待x的所有进程
```
