# 进线程模型简介

[[第二章——进线程模型|← 返回目录]]

## 一、进程的概念

### 1.1 进程的定义
进程是程序在一个数据集合上的运行过程，是系统进行资源分配和调度的一个独立单位。

**进程与程序的区别：**
- 程序是静态的，进程是动态的
- 程序是指令的有序集合，进程包含程序、数据和PCB
- 程序可以长期存在，进程有生命周期
- 一个程序可以对应多个进程

### 1.2 进程的特征
- **动态性**：进程的最基本特征，有创建、运行、消亡过程
- **并发性**：多个进程在一段时间内同时运行
- **独立性**：独立运行、独立获得资源、独立接受调度
- **异步性**：进程以不可预知的速度向前推进

### 1.3 进程的组成
进程由三部分组成：
1. **程序段**：进程执行的程序代码
2. **数据段**：进程运行时处理的数据
3. **进程控制块（PCB）**：进程存在的唯一标志

### 1.4 进程控制块（PCB）

**PCB的作用：**
- 作为独立运行基本单位的标志
- 能实现间断性运行方式
- 提供进程管理所需要的信息
- 提供进程调度所需要的信息
- 实现与其他进程的同步与通信

**PCB包含的信息：**
- **进程标识符**：唯一标识一个进程
- **处理机状态**：寄存器值、程序状态字PSW、栈指针等
- **进程调度信息**：进程状态、优先级、调度所需其他信息
- **进程控制信息**：程序和数据地址、同步和通信机制、资源清单

## 二、进程的状态与转换

### 2.1 进程的基本状态

| 状态 | 说明 |
|------|------|
| **运行态** | 进程正在处理机上运行 |
| **就绪态** | 已获得除处理机外的所有资源，等待分配处理机 |
| **阻塞态** | 因等待某事件发生而暂停运行（如I/O） |
| **创建态** | 进程正在创建，尚未就绪 |
| **终止态** | 进程结束，等待OS释放资源 |

### 2.2 状态转换图

```
创建态  →  就绪态  →  运行态  →  终止态
                ↑         ↓
               阻塞态  ←──
```

**状态转换说明：**
- 创建态 → 就绪态：进程创建完成，加入就绪队列
- 就绪态 → 运行态：进程调度程序选中该进程
- 运行态 → 就绪态：时间片用完，或有更高优先级进程进入
- 运行态 → 阻塞态：进程请求I/O或等待事件
- 阻塞态 → 就绪态：I/O完成或等待事件发生
- 运行态 → 终止态：进程正常结束或异常终止

## 三、进程控制

### 3.1 进程创建

**引起进程创建的事件：**
- 用户登录
- 作业调度
- 提供服务
- 应用请求（如父进程创建子进程）

**创建过程：**
1. 申请空白PCB
2. 为新进程分配资源
3. 初始化PCB
4. 将新进程插入就绪队列

### 3.2 进程终止

**引起进程终止的事件：**
- 正常结束
- 异常结束（越界、非法指令、除数为0等）
- 外界干预（操作员或操作系统终止、父进程请求）

**终止过程：**
1. 根据标识符查找PCB
2. 若进程正在运行，立即终止
3. 终止所有子孙进程
4. 将资源归还给父进程或系统
5. 将PCB从队列中移除

### 3.3 进程阻塞与唤醒

**阻塞过程：**
1. 立即停止执行
2. 将PCB中的状态从运行态改为阻塞态
3. 将PCB插入相应事件的等待队列
4. 转调度程序重新调度

**唤醒过程：**
1. 在等待队列中找到该进程的PCB
2. 将状态从阻塞态改为就绪态
3. 将PCB从等待队列移除，插入就绪队列

### 3.4 进程切换

**进程切换的时机：**
- 时间片到
- 有更高优先级进程到达
- 当前进程阻塞
- 当前进程结束

**切换过程：**
1. 保存处理机上下文到PCB
2. 更新当前进程PCB信息
3. 选择下一个要运行的进程
4. 恢复新进程的上下文

## 四、线程的概念

### 4.1 线程的引入
为了提高系统并发度，减少程序并发执行时的时空开销。

**进程的两个基本属性：**
- 资源分配单位
- 独立调度和分派单位

线程将这两个属性分离：
- 进程：资源分配单位
- 线程：调度和分派单位

### 4.2 线程的定义
线程是进程内的一个执行单元，是系统独立调度和分派的基本单位。

**线程与进程的关系：**
- 一个进程可以有多个线程
- 线程共享进程的资源
- 线程有自己的栈、寄存器和程序计数器

### 4.3 线程的优点
- 线程创建和切换开销小
- 通信容易（同一进程的线程共享地址空间）
- 能充分利用多处理器
- 响应速度快

### 4.4 线程的状态
与进程类似，线程也有运行态、就绪态、阻塞态等状态。

## 五、线程的实现方式

### 5.1 用户级线程（ULT）

**特点：**
- 线程管理由应用程序完成
- 内核不知道线程的存在
- 线程切换不需要内核态转换
- 线程调度算法可由应用程序决定

**缺点：**
- 一个线程阻塞，整个进程阻塞
- 不能利用多处理器的并行优势

### 5.2 内核级线程（KLT）

**特点：**
- 线程管理由内核完成
- 内核知道线程的存在
- 线程阻塞不影响其他线程
- 可以在多处理器上并行执行

**缺点：**
- 线程切换需要内核态转换，开销较大
- 调度算法由内核决定，应用程序无法控制

### 5.3 组合方式
结合用户级和内核级线程的优点，如多对一、一对一、多对多模型。

## 六、进程通信

### 6.1 通信方式分类

| 通信方式 | 特点 | 适用场景 |
|----------|------|----------|
| **共享存储** | 进程共享数据区，通过读写进行通信 | 频繁大量数据交换 |
| **消息传递** | 进程间通过发送/接收消息通信 | 同步通信、少量数据 |
| **管道通信** | 连接读写进程的共享文件 | 父子进程、单向传输 |

### 6.2 共享存储
- **低级方式**：基于数据结构
- **高级方式**：基于存储区

操作系统提供共享空间，进程负责同步控制。

### 6.3 消息传递
- **直接通信**：发送时指定接收进程
- **间接通信**：通过信箱（消息队列）进行

### 6.4 管道
- **无名管道**：父子进程间通信
- **命名管道**：任意进程间通信
