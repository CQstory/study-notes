## 5.1.1 I/O设备分类

I/O设备是计算机系统中除CPU和主存以外的所有设备，按不同标准可以分为以下几类。

### 按使用特性分类（重要）

| 类别 | 说明 | 特点 | 示例 |
|------|------|------|------|
| **人机交互类设备** | 用于与用户进行交互的设备 | 数据传输速度慢，以字符为单位 | 键盘、鼠标、显示器、打印机 |
| **存储类设备** | 用于存储信息的设备 | 数据传输速度快，以块为单位 | 磁盘、磁带、SSD、U盘 |
| **网络通信类设备** | 用于远程通信的设备 | 速度和单位介于前两者之间 | 网卡、调制解调器 |

### 按传输速率分类

| 类别 | 传输速率 | 示例 |
|------|----------|------|
| 低速设备 | 每秒几个字节到几百个字节 | 键盘、鼠标 |
| 中速设备 | 每秒数千到数万个字节 | 打印机 |
| 高速设备 | 每秒数十万个字节到数百万字节 | 磁盘、网卡 |

### 按信息交换单位分类

| 类别 | 说明 | 示例 |
|------|------|------|
| **块设备（Block Device）** | 以块为单位传输数据，可寻址，可随机读写 | 磁盘、SSD |
| **字符设备（Character Device）** | 以字符为单位传输数据，不可寻址，只能顺序读写 | 键盘、打印机、鼠标 |

> **考点提示**：
> 1. 块设备可以随机访问，字符设备只能顺序访问
> 2. 存储类设备属于块设备，人机交互类设备大多属于字符设备
> 3. 块设备的基本特征是可寻址，字符设备的基本特征是不可寻址

### 按从属关系分类

| 类别 | 说明 |
|------|------|
| 系统设备 | 操作系统生成时已配置的标准设备（如键盘、显示器） |
| 用户设备 | 用户自行安装的非标准设备（如扫描仪、绘图仪） |

## 5.1.2 I/O软件层次结构

I/O软件采用分层设计，从上到下分为四层：

```
┌─────────────────────────────────────┐
│         用户层I/O软件                │  ← 用户程序、库函数
├─────────────────────────────────────┤
│       设备独立性软件（设备无关软件）    │  ← 设备命名、保护、缓冲
├─────────────────────────────────────┤
│         设备驱动程序                  │  ← 设置设备寄存器
├─────────────────────────────────────┤
│         中断处理程序                  │  ← I/O完成后的中断响应
├─────────────────────────────────────┤
│            硬件                     │  ← 物理设备
└─────────────────────────────────────┘
```

### 各层功能详解

#### 1. 用户层I/O软件

**功能**：
- 提供用户与I/O系统交互的接口
- 提供库函数（如C语言的`printf`、`scanf`）
- 将用户请求翻译为系统调用
- SPOOLing系统的用户接口也在此层

**特点**：
- 面向用户，提供方便的I/O操作接口
- 通过系统调用与内核通信

#### 2. 设备独立性软件（设备无关软件）

**功能**：
- **设备命名**：将逻辑设备名映射为物理设备名
- **设备保护**：检查用户对设备的访问权限
- **设备分配与回收**：管理设备的分配和释放
- **缓冲管理**：提供缓冲区管理功能
- **差错处理**：处理可恢复的I/O错误
- **提供统一的设备接口**：屏蔽不同设备的差异

**设备独立性（设备无关性）**：
- 用户程序使用**逻辑设备名**请求I/O操作
- 操作系统通过**逻辑设备表（LUT）**将逻辑设备名映射为物理设备
- 好处：用户程序不依赖于具体的物理设备，提高了程序的通用性

```
逻辑设备表（LUT）：
┌──────────────┬──────────────┐
│ 逻辑设备名    │ 物理设备号    │
├──────────────┼──────────────┤
│ /dev/lp0     │ 3（打印机1）  │
│ /dev/lp1     │ 5（打印机2）  │
│ /dev/disk0   │ 7（磁盘1）    │
└──────────────┴──────────────┘
```

#### 3. 设备驱动程序

**功能**：
- 将上层的抽象I/O请求转换为具体的设备操作命令
- 设置设备控制器的寄存器
- 启动设备进行I/O操作
- 处理设备特有的操作

**特点**：
- 每类设备有对应的设备驱动程序
- 设备驱动程序是操作系统内核的一部分
- 直接与设备控制器交互

> **考点提示**：设备驱动程序是I/O软件中唯一直接与硬件交互的软件层。

#### 4. 中断处理程序

**功能**：
- I/O操作完成后，设备控制器发出中断信号
- 中断处理程序保存CPU现场
- 判断中断来源
- 调用相应的中断服务程序
- 恢复CPU现场，返回被中断的程序

**特点**：
- 位于I/O软件的最底层
- 与硬件紧密相关

### I/O软件层次调用关系

```
用户程序发出I/O请求
    ↓
用户层I/O软件（库函数）
    ↓ 系统调用
设备独立性软件（设备无关软件）
    ↓ 调用驱动程序接口
设备驱动程序
    ↓ 设置设备控制器寄存器
硬件（设备控制器执行I/O操作）
    ↓ I/O完成，发出中断
中断处理程序
    ↓ 唤醒等待的进程
设备驱动程序继续处理
    ↓
逐层返回结果给用户程序
```

## 5.1.3 I/O控制方式

I/O控制方式是指CPU与I/O设备之间数据传送的控制方式。从低级到高级共有四种方式。

### 1. 程序直接控制方式（Programmed I/O）

**基本思想**：CPU不断测试（轮询）设备控制器的状态寄存器，判断I/O是否完成。

**工作过程**：
```
CPU执行用户程序
    ↓
需要I/O时，CPU发出I/O命令
    ↓
CPU不断轮询设备状态（忙等待/自旋等待）
    ↓
设备完成I/O操作
    ↓
CPU读取数据
    ↓
CPU继续执行用户程序
```

**特点**：
- CPU全程参与数据传送
- 数据传送单位：**字（Word）**
- CPU利用率极低（忙等待期间CPU不能做其他事）

**优点**：实现简单

**缺点**：
- CPU大量时间浪费在等待I/O完成上
- CPU与I/O设备串行工作
- 只适用于CPU不繁忙且I/O速度很快的场景

### 2. 中断驱动方式（Interrupt-Driven I/O）

**基本思想**：CPU发出I/O命令后继续执行其他程序，I/O完成后由设备发出中断信号通知CPU。

**工作过程**：
```
CPU发出I/O命令
    ↓
CPU继续执行其他程序（不等待）
    ↓
I/O设备完成操作，发出中断信号
    ↓
CPU响应中断，执行中断处理程序
    ↓
CPU读取数据
    ↓
CPU恢复执行被中断的程序
```

**特点**：
- CPU发出I/O命令后可以做其他工作
- 数据传送单位：**字（Word）**
- 每传送一个字就要中断一次CPU

**优点**：
- CPU利用率比程序直接控制方式高
- CPU与I/O设备可以并行工作

**缺点**：
- 每传送一个字就中断一次，中断处理开销大
- 适用于低速设备（如键盘、鼠标）

### 3. DMA方式（Direct Memory Access，直接存储器存取）

**基本思想**：数据在I/O设备和内存之间直接传送，不经过CPU，由DMA控制器控制传送。

**工作过程**：
```
CPU发出DMA请求
    ↓
DMA控制器接管总线控制权
    ↓
DMA控制器在设备和内存之间直接传送数据
    ↓
传送完成，DMA控制器发出中断信号通知CPU
    ↓
CPU响应中断，处理后续工作
```

**DMA控制器组成**：
```
┌──────────────────────┐
│      命令/状态寄存器   │
├──────────────────────┤
│      内存地址寄存器    │  ← 数据在内存中的起始地址
├──────────────────────┤
│      数据计数器        │  ← 还需传送的数据量
├──────────────────────┤
│      设备地址寄存器    │  ← 数据在设备中的起始地址
├──────────────────────┤
│      数据寄存器        │  ← 暂存传送的数据
└──────────────────────┘
```

**特点**：
- 数据传送单位：**块（Block）**
- 数据不经过CPU，直接在设备和内存之间传送
- CPU只在传送开始和结束时参与
- 传送过程中CPU可以做其他工作

**优点**：
- CPU利用率高
- 传送速度快（以块为单位）
- 减少了中断次数（一块数据只中断一次）

**缺点**：
- 每次DMA传送只能传送一个连续的数据块
- 传送方向（读/写）、数据长度、起始地址等需要CPU设置
- 适用于高速设备（如磁盘）

### 4. 通道控制方式（Channel I/O）

**基本思想**：通道是一个专门控制I/O操作的处理器（I/O处理器），CPU只需发出通道程序，通道独立执行通道程序完成I/O操作。

**工作过程**：
```
CPU组织通道程序，存放在内存中
    ↓
CPU发出"启动I/O"指令，启动通道
    ↓
通道执行通道程序，控制I/O操作
    ↓
通道完成所有I/O操作后，向CPU发中断
    ↓
CPU响应中断，处理后续工作
```

**特点**：
- 通道是独立的处理器，有自己的指令系统
- 数据传送单位：**一组块**
- CPU只需启动通道，通道独立完成所有I/O操作
- 一个通道可以控制多个设备

**优点**：
- CPU利用率最高
- CPU与I/O设备高度并行
- 一个通道可以管理多台设备
- 适用于大量I/O操作的场景

**缺点**：
- 实现复杂，硬件成本高
- 通道程序需要占用内存空间

### 四种I/O控制方式对比（重要考点）

| 对比维度 | 程序直接控制 | 中断驱动方式 | DMA方式 | 通道控制方式 |
|----------|-------------|-------------|---------|-------------|
| **数据传送单位** | 字 | 字 | 块 | 一组块 |
| **数据传送路径** | CPU中转 | CPU中转 | 设备↔内存直传 | 设备↔内存直传 |
| **CPU参与程度** | 全程参与 | 传送前+后参与 | 启动+结束参与 | 仅启动参与 |
| **CPU利用率** | 最低 | 较低 | 较高 | 最高 |
| **中断次数** | 无 | 每字一次 | 每块一次 | 每组块一次 |
| **CPU与I/O并行** | 不能 | 可以 | 可以 | 高度并行 |
| **实现复杂度** | 最简单 | 简单 | 较复杂 | 最复杂 |
| **硬件成本** | 最低 | 低 | 较高 | 最高 |
| **适用设备** | 低速设备 | 低速设备 | 高速设备（磁盘） | 大量I/O设备 |
| **控制器** | 无 | 无 | DMA控制器 | 通道处理器 |

> **考点提示**：
> 1. 程序直接控制方式和中断驱动方式的数据传送都经过CPU
> 2. DMA方式和通道控制方式的数据传送不经过CPU（设备与内存直接传送）
> 3. 程序直接控制方式不使用中断，其余三种都使用中断
> 4. 通道控制方式中，CPU的参与程度最低，CPU利用率最高

## 5.1.4 缓冲技术

### 缓冲的引入目的

1. **缓和CPU与I/O设备速度不匹配的矛盾**
2. **减少CPU的中断频率**（以块为单位传送时减少中断次数）
3. **解决数据粒度不匹配问题**（CPU以字/字节处理，I/O以块传送）
4. **提高CPU与I/O设备的并行性**

### 1. 单缓冲（Single Buffer）

**基本思想**：在内存中设置一个缓冲区，操作系统在用户空间和I/O设备之间使用该缓冲区传递数据。

**工作过程**（以输入为例）：
```
时间轴：
|---T---|---M---|---T---|---M---|---T---|---M---|
 T = 从设备将数据送入缓冲区的时间
 M = CPU从缓冲区将数据送入用户工作区的时间

注意：T和M不能同时进行（共用一个缓冲区）
```

**平均处理时间**：
- 每块数据的处理时间 = $\max(T, M) + C$
- 其中 $C$ 为CPU处理数据的时间
- 若 $T > M$，则平均处理时间 = $T + C$
- 若 $M > T$，则平均处理时间 = $M + C$

**特点**：
- 设备输入和CPU处理不能并行
- 缓冲区只有一个，设备使用时CPU不能用，反之亦然

### 2. 双缓冲（Double Buffer）

**基本思想**：设置两个缓冲区，设备向一个缓冲区输入数据的同时，CPU可以从另一个缓冲区取出数据。

**工作过程**（以输入为例）：
```
时间轴：
缓冲区1：|---T1---|       |---T3---|
缓冲区2：       |---M1---|       |---M2---|

T1和M1可以并行！
```

**平均处理时间**：
- 每块数据的处理时间 = $\max(T, M + C)$
- 若 $T > M + C$，则平均处理时间 = $T$（设备是瓶颈）
- 若 $M + C > T$，则平均处理时间 = $M + C$（CPU是瓶颈）

**特点**：
- 设备输入和CPU处理可以并行
- 比单缓冲效率高
- 实现比单缓冲稍复杂

### 3. 循环缓冲（Circular Buffer）

**基本思想**：设置多个大小相等的缓冲区，链接成循环队列。

**结构示意**：
```
     ┌──→ [Buf1] ──→ [Buf2] ──→ [Buf3] ──→ [Buf4] ──┐
     └────────────────────────────────────────────────┘

指针：
- in：指向下一个可以输入数据的缓冲区
- out：指向下一个可以取出数据的缓冲区
```

**分类**：
- **输入缓冲**：设备向缓冲区输入数据，CPU从缓冲区取数据
- **输出缓冲**：CPU向缓冲区输出数据，设备从缓冲区取数据

**工作过程**：
- 设备填满一个缓冲区后，in指针前移
- CPU取空一个缓冲区后，out指针前移
- 当in追上out时，缓冲区满，设备需等待
- 当out追上in时，缓冲区空，CPU需等待

**特点**：
- 适合输入和输出速度相差不大的情况
- 多个缓冲区提高了并行性

### 4. 缓冲池（Buffer Pool）

**基本思想**：将多个缓冲区组成公共缓冲池，按使用状态分为三类队列管理。

**缓冲池组成**：
```
缓冲池
├── 空白缓冲队列（emq）：所有空闲缓冲区
├── 输入队列（inq）：已装满输入数据的缓冲区
└── 输出队列（outq）：已装满输出数据的缓冲区
```

**工作过程**：

**输入操作**：
1. 从空白队列（emq）取一个空白缓冲区
2. 设备将数据输入到该缓冲区
3. 将该缓冲区挂到输入队列（inq）
4. CPU需要数据时，从输入队列（inq）取出缓冲区
5. CPU处理完后，将缓冲区挂回空白队列（emq）

**输出操作**：
1. 从空白队列（emq）取一个空白缓冲区
2. CPU将数据写入该缓冲区
3. 将该缓冲区挂到输出队列（outq）
4. 设备从输出队列（outq）取出缓冲区，输出数据
5. 输出完后，将缓冲区挂回空白队列（emq）

**特点**：
- 缓冲区是公共资源，多个进程可以共享
- 缓冲区可以动态分配和回收
- 灵活性最高
- 现代操作系统广泛使用

### 四种缓冲技术对比

| 特征 | 单缓冲 | 双缓冲 | 循环缓冲 | 缓冲池 |
|------|--------|--------|----------|--------|
| 缓冲区数量 | 1个 | 2个 | 多个 | 多个 |
| 并行性 | 低 | 中 | 较高 | 最高 |
| 灵活性 | 低 | 低 | 中 | 最高 |
| 实现复杂度 | 简单 | 简单 | 中等 | 较复杂 |
| 缓冲区归属 | 专用 | 专用 | 专用 | 共享 |
| 适用场景 | 简单系统 | 一般场景 | 输入输出速度匹配 | 通用场景 |

> **考点提示**：
> 1. 单缓冲平均处理时间 = $\max(T, M) + C$
> 2. 双缓冲平均处理时间 = $\max(T, M + C)$
> 3. 缓冲池中缓冲区是共享的，可以动态分配回收

## 5.1.5 SPOOLing技术（假脱机技术）

### SPOOLing技术概述

**SPOOLing**（Simultaneous Peripheral Operations On-Line，假脱机技术）是用软件方式模拟脱机输入/输出技术，将独占设备改造为共享设备。

**基本思想**：
- 在外存（磁盘）中开辟输入井和输出井
- 用程序模拟脱机输入/输出的外围机
- 将独占设备（如打印机）改造为可共享的虚拟设备

### SPOOLing系统的组成

```
┌─────────────────────────────────────────────┐
│              SPOOLing系统                     │
│                                              │
│  ┌──────────┐     ┌──────────┐              │
│  │ 输入井    │     │ 输出井    │              │
│  │ (磁盘)    │     │ (磁盘)    │              │
│  └──────────┘     └──────────┘              │
│       ↑                 ↑                    │
│  ┌──────────┐     ┌──────────┐              │
│  │输入缓冲区 │     │输出缓冲区 │              │
│  └──────────┘     └──────────┘              │
│       ↑                 ↑                    │
│  ┌──────────┐     ┌──────────┐              │
│  │输入进程   │     │输出进程   │              │
│  │(SPi)     │     │(SPo)     │              │
│  └──────────┘     └──────────┘              │
│       ↑                 ↑                    │
│  ┌──────────┐     ┌──────────┐              │
│  │ 输入设备  │     │ 输出设备  │              │
│  │(如卡片机) │     │(如打印机) │              │
│  └──────────┘     └──────────┘              │
└─────────────────────────────────────────────┘
```

**组成部分**：

| 组成部分 | 说明 |
|----------|------|
| **输入井** | 磁盘上用于暂存输入数据的区域 |
| **输出井** | 磁盘上用于暂存输出数据的区域 |
| **输入缓冲区** | 内存中暂存从输入设备读入的数据 |
| **输出缓冲区** | 内存中暂存要输出到设备的数据 |
| **输入进程SPi** | 模拟脱机输入时的外围机，将输入数据从设备送入输入井 |
| **输出进程SPo** | 模拟脱机输出时的外围机，将输出数据从输出井送入设备 |

### 共享打印机原理（重要考点）

**问题**：打印机是独占设备，同一时间只能被一个进程使用。如何让多个进程"同时"使用打印机？

**SPOOLing解决方案**：

```
用户进程1请求打印 → 将打印数据写入输出井（磁盘文件）
用户进程2请求打印 → 将打印数据写入输出井（磁盘文件）
用户进程3请求打印 → 将打印数据写入输出井（磁盘文件）
    ↓
输出进程SPo按顺序从输出井取出数据
    ↓
依次发送到实际打印机打印
    ↓
所有进程的打印请求按先来先服务的顺序完成
```

**工作过程**：
1. 用户进程请求打印时，SPOOLing系统在输出井中为该进程申请一个空闲缓冲区（磁盘空间）
2. 将打印数据写入输出井中的缓冲区
3. 用户进程的打印请求完成（对用户进程来说，打印操作"瞬间完成"）
4. 输出进程SPo依次从输出井中取出各进程的打印数据，按顺序发送到打印机

**关键点**：
- 对用户进程来说，打印机变成了**虚拟的共享设备**
- 实际上打印机仍然是独占设备，但通过磁盘缓冲实现了逻辑上的共享
- 打印数据的实际打印是**异步**进行的
- 输出井中的文件称为**假脱机文件**

> **考点提示**：
> 1. SPOOLing技术的核心思想：用软件模拟脱机I/O，将独占设备改造为共享设备
> 2. 共享打印机是SPOOLing技术的典型应用
> 3. SPOOLing系统需要磁盘空间作为输入井和输出井
> 4. 用户进程的I/O请求实际上是对磁盘的读写，速度很快

### SPOOLing技术的优点

| 优点 | 说明 |
|------|------|
| 提高设备利用率 | 独占设备变为共享设备，减少设备空闲时间 |
| 加速用户进程执行 | 用户进程不需要等待慢速I/O设备完成 |
| 提供虚拟设备功能 | 将独占设备逻辑上改造为共享设备 |

### SPOOLing技术的缺点

| 缺点 | 说明 |
|------|------|
| 占用磁盘空间 | 输入井和输出井需要磁盘空间 |
| 增加系统开销 | 需要专门的输入/输出进程 |
| 实现复杂 | 需要软件模拟脱机I/O过程 |

## 考点总结

### 高频考点

1. **I/O控制方式对比**：四种方式的数据传送单位、CPU利用率、适用场景
2. **缓冲技术**：单缓冲和双缓冲的平均处理时间计算
3. **SPOOLing技术**：假脱机原理、共享打印机工作过程
4. **设备独立性**：逻辑设备名与物理设备名的映射
5. **I/O软件层次结构**：各层的功能和调用关系

### 易错点

1. 程序直接控制方式和中断驱动方式的数据传送**都经过CPU**，DMA和通道方式**不经过CPU**
2. 中断驱动方式每传送**一个字**就中断一次，DMA方式每传送**一块**才中断一次
3. 单缓冲中设备和CPU不能并行工作，双缓冲中可以并行
4. SPOOLing技术中，用户进程的打印请求实际上是对**磁盘**的写入
5. 通道控制方式中，通道是一个**独立的处理器**，有自己的指令系统
6. 缓冲池中的缓冲区是**共享**的，可以动态分配和回收

### 计算题型

1. **缓冲区平均处理时间**：给定T（输入时间）、M（移动时间）、C（处理时间），计算单缓冲和双缓冲的平均处理时间
2. **I/O控制方式效率对比**：给定数据量和传送参数，比较不同方式的效率
