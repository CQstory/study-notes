# 分段存储管理

[[03-内存管理|← 返回目录]]

> [!info] 本节定位
> 本节介绍分段存储管理的基本概念、段表与地址变换、分页与分段的对比，以及段页式存储管理。分页与分段的对比是408选择题中的高频考点。

---

## 一、分段的基本概念

### 1.1 为什么需要分段

分页存储管理中，进程的地址空间被等分为页，但这种方式**不考虑程序本身的逻辑结构**。实际上，程序是由若干逻辑段组成的（如主程序段、子程序段、数据段、栈段等），每个段有独立的逻辑意义。

分段存储管理按照程序的**逻辑结构**将地址空间划分为若干段，每段有段名和段长。

### 1.2 分段的基本思想

- 将进程的地址空间分为若干个**段（Segment）**，每段有段名和段长
- 每段从 0 开始编址（段内地址连续）
- 段与段之间**长度可以不同**
- 各段在内存中可以**离散存放**

```
逻辑地址空间                    物理内存
┌──────────┐                   ┌──────────┐
│ 主程序段  │ ─────→           │  主程序段  │
│ (段0)    │                   │  (段0)    │
├──────────┤                   ├──────────┤
│ 子程序段  │ ─────→           │  空闲区   │
│ (段1)    │                   ├──────────┤
├──────────┤                   │  子程序段  │
│ 数据段    │ ─────→           │  (段1)    │
│ (段2)    │                   ├──────────┤
├──────────┤                   │  栈段     │
│ 栈段      │ ─────→           │  (段3)    │
│ (段3)    │                   ├──────────┤
└──────────┘                   │  数据段   │
                                │  (段2)    │
                                └──────────┘
```

### 1.3 逻辑地址结构

分段方式下的逻辑地址由两部分组成：

```
逻辑地址
┌──────────────┬──────────────┐
│   段号 S     │  段内偏移 W   │
└──────────────┴──────────────┘
```

- **段号 S**：标识逻辑地址属于哪个段
- **段内偏移 W**：段内的偏移地址

> [!note] 与分页的区别
> 分页的页面大小是固定的（由硬件决定），而分段的段长是**可变的**（由程序逻辑决定）。

## 二、段表

### 2.1 段表的结构

操作系统为每个进程维护一张**段表**，记录各段在内存中的起始地址和段长：

| 段号 | 段长 | 基址（内存起始地址） |
|:----:|:----:|:-------------------:|
| 0 | 1000 | 5000 |
| 1 | 600 | 8000 |
| 2 | 500 | 3000 |
| 3 | 200 | 9000 |

> [!important] 与页表的区别
> - 页表项中存的是**页框号**（需要乘以页面大小才能得到物理地址）
> - 段表项中存的是**基址**（即物理地址的起始位置，直接可用）
> - 段表项中还需要存**段长**（用于越界检查），因为各段长度不同
> - 页表项中不需要存页长（因为所有页面大小相同）

### 2.2 段表寄存器

与分页类似，分段也需要两个寄存器：

| 寄存器 | 功能 |
|:-------|:-----|
| **段表基址寄存器** | 存放当前进程段表的起始地址 |
| **段表长度寄存器** | 存放当前进程段表的长度（段表项数） |

## 三、分段的地址变换过程

### 3.1 地址变换流程

```
CPU生成逻辑地址（段号S，段内偏移W）
       │
       ▼
  ┌─────────────────┐
  │ 检查 S < 段表长度？│  ← 段表长度寄存器
  └────────┬────────┘
           │
      ┌────┴────┐
      │         │
     是        否 → 越界中断
      │
      ▼
  ┌─────────────────┐
  │ 查段表          │  ← 段表基址寄存器
  │ S → 段长L, 基址B│
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 检查 W < 段长L？ │  ← 段内越界检查
  └────────┬────────┘
           │
      ┌────┴────┐
      │         │
     是        否 → 越界中断
      │
      ▼
  ┌─────────────────┐
  │ 物理地址 = B + W │
  └────────┬────────┘
           │
           ▼
      访问内存
```

### 3.2 两次越界检查

与分页不同，分段地址变换需要进行**两次越界检查**：
1. **段号越界检查**：段号 S < 段表长度
2. **段内偏移越界检查**：段内偏移 W < 段长 L

> [!important] 对比分页
> 分页只需要一次越界检查（页号 < 页表长度），因为页内偏移一定小于页面大小（由硬件保证）。
> 分段需要两次越界检查，因为段长不固定，段内偏移可能超出段长。

### 3.3 计算示例

> [!example] 例题
> 某进程的段表如下：
>
> | 段号 | 段长 | 基址 |
> |:----:|:----:|:----:|
> | 0 | 1000 | 5000 |
> | 1 | 600 | 8000 |
> | 2 | 500 | 3000 |
> | 3 | 200 | 9000 |
>
> 求逻辑地址（段号=1，段内偏移=200）对应的物理地址。
>
> **解**：
> 1. 检查段号：1 < 4（段表长度）→ 合法
> 2. 查段表：段号1 → 段长=600，基址=8000
> 3. 检查段内偏移：200 < 600 → 合法
> 4. 物理地址 = 8000 + 200 = **8200**

> [!example] 例题2
> 求逻辑地址（段号=2，段内偏移=600）对应的物理地址。
>
> **解**：
> 1. 检查段号：2 < 4 → 合法
> 2. 查段表：段号2 → 段长=500，基址=3000
> 3. 检查段内偏移：600 ≥ 500 → **越界中断！**

## 四、分页与分段的对比

### 4.1 核心区别

| 比较项 | 分页 | 分段 |
|:-------|:-----|:-----|
| **划分依据** | 物理大小（等分） | 逻辑结构（不等分） |
| **页面/段大小** | 固定，由硬件决定 | 可变，由程序决定 |
| **地址空间** | 一维（页号+偏移） | 二维（段号+段内偏移） |
| **碎片** | 内部碎片 | 外部碎片 |
| **共享** | 不方便（一页中可能混合代码和数据） | 方便（按逻辑段共享） |
| **保护** | 不方便 | 方便（按段设置权限） |
| **对程序员透明** | 是（程序员不可见） | 否（程序员可见） |
| **地址变换** | 页号→页框号（查页表） | 段号→基址（查段表） |
| **越界检查** | 一次（页号） | 两次（段号+段内偏移） |

### 4.2 详细对比分析

#### （1）划分方式

- **分页**：系统行为，对用户透明。用户不知道自己的程序被分成了多少页。
- **分段**：用户行为，对用户可见。用户（编译器）按照逻辑结构划分段。

#### （2）地址空间维度

- **分页**：逻辑地址空间是**一维**的。程序员只需使用单一的地址即可。
- **分段**：逻辑地址空间是**二维**的。程序员需要给出段号和段内偏移（但编译器通常自动处理）。

#### （3）碎片问题

- **分页**：产生**内部碎片**。最后一页可能未被完全利用。
- **分段**：产生**外部碎片**。段间可能存在无法利用的小空闲区域。可通过紧凑（Compaction）解决。

#### （4）共享与保护

- **分段**更容易实现共享和保护：
  - 可以按段设置**读/写/执行**权限
  - 可以将某个完整的段（如共享库）标记为共享
- **分页**共享较困难：
  - 一页中可能同时包含代码和数据
  - 不同进程的代码和数据在页中的偏移可能不同

#### （5）离散分配

- **分页**和**分段**都实现了离散分配，进程的各页/各段可以不连续存放

### 4.3 对比总结表

> [!important] 记忆要点
> | | 分页 | 分段 |
> |:--|:-----|:-----|
> | 目的 | 提高内存利用率 | 满足用户需求 |
> | 大小 | 固定 | 可变 |
> | 碎片 | 内部 | 外部 |
> | 地址空间 | 一维 | 二维 |
> | 共享 | 难 | 易 |
> | 透明性 | 透明 | 不透明 |

## 五、段页式存储管理

### 5.1 基本思想

段页式存储管理是**分段和分页的结合**：
- 先将进程按逻辑结构**分段**
- 再将每段按固定大小**分页**
- 内存以**页框**为单位分配

```
进程地址空间
┌──────────────────────────────────────┐
│ 段0                                  │
│ ┌──────┐┌──────┐┌──────┐             │
│ │ 页0  ││ 页1  ││ 页2  │             │
│ └──────┘└──────┘└──────┘             │
├──────────────────────────────────────┤
│ 段1                                  │
│ ┌──────┐┌──────┐                     │
│ │ 页0  ││ 页1  │                     │
│ └──────┘└──────┘                     │
├──────────────────────────────────────┤
│ 段2                                  │
│ ┌──────┐┌──────┐┌──────┐┌──────┐    │
│ │ 页0  ││ 页1  ││ 页2  ││ 页3  │    │
│ └──────┘└──────┘└──────┘└──────┘    │
└──────────────────────────────────────┘
```

### 5.2 逻辑地址结构

段页式存储管理的逻辑地址由三部分组成：

```
逻辑地址
┌──────────────┬──────────────┬──────────────┐
│   段号 S     │  段内页号 P   │  页内偏移 W   │
└──────────────┴──────────────┴──────────────┘
```

### 5.3 段页式地址变换过程

段页式存储管理需要**两次查表**：先查段表，再查页表。

```
逻辑地址（段号S，段内页号P，页内偏移W）
       │
       ▼
  ┌─────────────────┐
  │ 查段表           │
  │ S → 段长, 页表基址│
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 检查 P < 段内页数？│
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 查该段的页表     │
  │ P → 页框号 F     │
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │ 物理地址         │
  │ = F × 页面大小 + W│
  └─────────────────┘
```

### 5.4 计算示例

> [!example] 例题
> 某系统采用段页式存储管理，页面大小为 4KB。某进程的段表如下：
>
> | 段号 | 段长 | 页表基址 |
> |:----:|:----:|:---------:|
> | 0 | 16KB | 10000 |
> | 1 | 8KB | 20000 |
> | 2 | 12KB | 30000 |
>
> 段0的页表如下：
>
> | 页号 | 页框号 |
> |:----:|:------:|
> | 0 | 5 |
> | 1 | 12 |
> | 2 | 8 |
> | 3 | 20 |
>
> 求逻辑地址（段号=0，段内地址=5000）对应的物理地址。
>
> **解**：
> 1. 段号 S = 0，段内地址 = 5000
> 2. 查段表：段号0 → 段长=16KB，页表基址=10000
> 3. 段内页号 P = 5000 / 4096 = **1**，页内偏移 W = 5000 % 4096 = **904**
> 4. 检查：P=1 < 段内页数(16KB/4KB=4) → 合法
> 5. 查段0的页表：页号1 → 页框号 **12**
> 6. 物理地址 = 12 × 4096 + 904 = 49152 + 904 = **50056**

### 5.5 段页式的访存次数

| 情况 | 访存次数 |
|:-----|:--------:|
| 无TLB | **3次**（查段表 + 查页表 + 访问目标） |
| TLB命中 | **2次**（TLB中直接得到页框号 + 访问目标） |

> [!note] 说明
> 段页式存储管理的访存次数比纯分页多一次（多了查段表的开销）。TLB的重要性在段页式中更加凸显。

### 5.6 段页式的特点

| 优点 | 缺点 |
|:-----|:-----|
| 兼具分段的逻辑性和分页的离散性 | 硬件支持复杂 |
| 便于共享和保护 | 地址变换开销大（多次查表） |
| 无外部碎片 | 有内部碎片（最后一页可能不满） |
| 支持虚拟存储 | 管理软件复杂 |

## 六、信息共享与保护

### 6.1 分段系统中的共享

在分段系统中，可以方便地实现段的共享：

```
进程A的段表              进程B的段表
┌──────┬──────┐         ┌──────┬──────┐
│段号  │基址  │         │段号  │基址  │
├──────┼──────┤         ├──────┼──────┤
│ 0    │ ...  │         │ 0    │ ...  │
│ 1    │3000  │ ──共享──→│ 2    │3000  │
│ 2    │ ...  │         │ 3    │ ...  │
└──────┴──────┘         └──────┴──────┘
         ↑                    ↑
    共享段（如公共子程序）  共享段
```

- 在段表中设置**共享标志**
- 不同进程的段表项可以指向**同一段的物理地址**
- 共享段需要设置**只读**属性，防止被修改

### 6.2 分段系统中的保护

每段可以设置独立的保护属性：

| 保护方式 | 说明 |
|:---------|:-----|
| **越界保护** | 段内偏移不能超过段长 |
| **存取控制保护** | 设置读(R)、写(W)、执行(E)权限 |
| **段表保护** | 段号不能超过段表长度 |

### 6.3 分页系统中的共享

分页系统中也可以实现共享，但比较困难：

- 需要确保不同进程中共享的代码/数据在各自的逻辑地址空间中位于**相同的页号**
- 或者通过复杂的页表映射实现

> [!important] 考点
> - **分段系统更容易实现共享和保护**，因为段是逻辑单位
> - 分页系统共享困难，因为页是物理单位，一页中可能混合了不同类型的内容

## 七、考点总结

### 7.1 核心知识点

| 知识点 | 关键内容 |
|:-------|:---------|
| 分段基本概念 | 按逻辑结构划分，段长可变 |
| 段表结构 | 段号→（段长，基址） |
| 地址变换 | 两次越界检查，物理地址=基址+偏移 |
| 分页vs分段 | 大小/碎片/维度/共享/保护/透明性 |
| 段页式 | 先分段再分页，三次访存 |
| 共享与保护 | 分段更方便 |

### 7.2 分页 vs 分段速记

> [!tip] 记忆口诀
> - **页固定，段可变**
> - **页一维，段二维**
> - **页内碎，段外碎**
> - **页透明，段可见**
> - **页难共享，段易共享**
> - **页难保护，段易保护**

### 7.3 常考易错点

> [!danger] 易错点
> 1. **分段的地址空间是二维的**，分页是一维的
> 2. **分段有外部碎片**（不是内部碎片），可通过紧凑解决
> 3. **分段地址变换需要两次越界检查**（段号+段内偏移），分页只需一次（页号）
> 4. **段表项存的是基址**（物理地址），页表项存的是页框号（需要计算）
> 5. **段页式有内部碎片**（因为最终是按页分配），无外部碎片
> 6. **段页式需要查两次表**（段表+页表），访存次数为3次

### 7.4 与其他章节的联系

- 分段存储管理是 [[03-内存管理/分页存储管理|分页存储管理]] 的补充，两者可以结合为段页式
- 分段的共享与保护机制与 [[03-内存管理/内存管理基础|内存管理基础]] 中的内存保护密切相关
- 段页式的TLB机制与 [[03-内存管理/分页存储管理|分页存储管理]] 中讨论的快表原理相同
