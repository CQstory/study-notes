# I/O 控制方式（四种方式详解）

I/O 控制方式是指 CPU 控制 I/O 设备完成数据传输的方法。随着技术发展，I/O 控制方式不断进步，CPU 的干预越来越少，系统效率越来越高。

### 四种 I/O 控制方式对比

| 特性 | 程序直接控制方式 | 中断驱动方式 | DMA 方式 | 通道控制方式 |
|------|----------------|-------------|----------|-------------|
| **数据传送单位** | 字（Word） | 字（Word） | 数据块（Block） | 一组数据块 |
| **CPU 干预频率** | 极高（每个字） | 高（每个字） | 中（每个数据块） | 低（一组数据块） |
| **数据流向** | 设备 ↔ CPU ↔ 内存 | 设备 ↔ CPU ↔ 内存 | 设备 ↔ 内存（不经过 CPU） | 设备 ↔ 内存（不经过 CPU） |
| **并行性** | 无 | 部分并行 | 较高 | 最高 |
| **硬件复杂度** | 简单 | 较简单 | 较复杂 | 复杂 |
| **适用设备** | 简单、低速设备 | 低速字符设备 | 高速块设备 | 高速块设备 |
| **CPU 效率** | 最低 | 较低 | 较高 | 最高 |

### 1. 程序直接控制方式（程序查询方式）

#### 工作原理

CPU 通过轮询（Polling）不断查询设备状态，直到设备就绪后进行数据传输。

```
CPU ──→ 查询设备状态 ──→ 设备就绪？
              ↑                │
              └──── 否 ────────┘
                               │ 是
                               ↓
                    CPU ←──→ 数据传输
```

#### 工作流程

```c
// 程序直接控制方式伪代码
void programmed_io_read() {
    while (1) {
        // 1. 读取设备状态寄存器
        status = read_status_register();
        
        // 2. 检查设备是否就绪
        if (status == READY) {
            // 3. 从数据寄存器读取数据
            data = read_data_register();
            
            // 4. 将数据存入内存
            memory[addr++] = data;
            
            // 5. 检查是否传输完成
            if (transfer_complete()) break;
        }
        
        // 设备未就绪，继续轮询
    }
}
```

#### 特点分析

| 优点 | 缺点 |
|------|------|
| 硬件简单，实现容易 | CPU 需要不断轮询，效率极低 |
| 控制精确 | CPU 和 I/O 设备串行工作，无法并行 |
| | 浪费大量 CPU 时间在等待上 |

> [!warning] 致命缺陷
> 在程序直接控制方式中，CPU 需要**不断轮询**设备状态，导致 CPU 利用率极低。假设设备传输一个字需要 1ms，CPU 查询一次需要 1μs，则 CPU 有 99.9% 的时间浪费在轮询上。

### 2. 中断驱动方式

#### 工作原理

CPU 发出 I/O 命令后，无需等待，继续执行其他任务。当设备完成数据传输后，向 CPU 发送中断信号，CPU 响应中断并处理数据。

```
CPU ──→ 发出 I/O 命令 ──→ 继续执行其他任务
                               ↑
设备 ←── 传输数据 ──→ 传输完成 ──┘
                               │
                               ↓ 中断信号
                    CPU 保存现场 → 执行中断处理 → 恢复现场
```

#### 工作流程

```c
// 中断驱动方式伪代码

// 主程序
void main() {
    // 1. 发出 I/O 命令
    issue_io_command(READ, device_id, buffer);
    
    // 2. CPU 继续执行其他任务（无需等待）
    do_other_work();
}

// 中断处理程序（设备完成传输后调用）
void interrupt_handler() {
    // 1. 保存 CPU 现场
    save_context();
    
    // 2. 读取数据
    data = read_data_register();
    memory[buffer_addr++] = data;
    
    // 3. 检查是否完成
    if (!transfer_complete()) {
        // 继续下一次传输
        issue_io_command(READ, device_id, buffer);
    }
    
    // 4. 恢复 CPU 现场
    restore_context();
}
```

#### 特点分析

| 优点 | 缺点 |
|------|------|
| CPU 和 I/O 设备可以部分并行 | 每个字传输都需要中断，开销大 |
| 无需轮询，提高 CPU 利用率 | 数据传输仍需经过 CPU |
| 适合低速字符设备 | 高速设备会产生大量中断，影响性能 |

> [!note] 适用场景
> 中断驱动方式适合键盘、鼠标等低速字符设备，因为这些设备产生数据的频率较低，不会频繁触发中断。

### 3. DMA 方式（直接存储器存取）

#### 工作原理

DMA（Direct Memory Access）方式在内存和设备之间开辟直接数据通路，数据传输不经过 CPU，由 DMA 控制器控制完成。

```
        ┌─────────────────┐
        │      CPU        │
        │  （设置 DMA 参数）│
        └────────┬────────┘
                 │ 命令
                 ↓
        ┌─────────────────┐
        │   DMA 控制器     │←──── 控制数据传输
        │  （管理数据块传输）│
        └────────┬────────┘
                 │ 直接传输
        ┌────────┴────────┐
        ↓                 ↓
   ┌─────────┐      ┌─────────┐
   │  I/O 设备 │←────→│  内  存  │
   └─────────┘      └─────────┘
```

#### DMA 控制器结构

| 寄存器 | 功能 |
|--------|------|
| **内存地址寄存器（AR）** | 存放内存中要交换的数据的地址 |
| **字计数器（WC）** | 记录要传送的数据字（字节）数 |
| **数据缓冲寄存器（BR）** | 暂存每次传送的数据 |
| **控制/状态寄存器** | 存放控制字和状态字 |

#### 工作流程

```
1. CPU 初始化 DMA 控制器：
   - 设置内存起始地址（AR）
   - 设置传输数据量（WC）
   - 设置传输方向（读/写）

2. CPU 发出启动命令，DMA 控制器接管总线

3. DMA 控制器控制数据传输：
   - 从设备读取数据到 BR
   - 将 BR 中的数据写入内存（AR 指向的地址）
   - AR 自动增量，WC 自动减量
   - 重复直到 WC = 0

4. 传输完成，DMA 控制器向 CPU 发中断

5. CPU 响应中断，进行后续处理
```

#### 特点分析

| 优点 | 缺点 |
|------|------|
| 数据传输不经过 CPU，效率高 | 需要额外的 DMA 控制器硬件 |
| 以数据块为单位传输，减少中断次数 | 每个数据块传输前后仍需 CPU 干预 |
| 适合高速块设备 | 只能控制简单的数据传输，复杂操作仍需 CPU |

> [!important] DMA 与中断的区别
> - **中断驱动方式**：每个字传输完成都产生中断，数据经过 CPU
> - **DMA 方式**：每个数据块传输完成才产生一次中断，数据不经过 CPU

#### DMA 生命周期精讲（以"进程从磁盘读数据"为例）

```
阶段0：进程发起 I/O（系统调用）
   ↓
阶段1：CPU 预处理（初始化 DMA 控制器）
   ↓
阶段2：DMA 传输（总线仲裁 + 数据搬移循环）
   ↓
阶段3：传输完成 → 中断
   ↓
阶段4：中断处理 + 进程恢复
```

##### 阶段 0：进程发起 I/O（预处理①）

| 动作 | 细节 |
|:---|:---|
| 0.1 | 进程执行 `read(fd, buf, len)` 系统调用 → 陷入内核 |
| 0.2 | 检查参数：fd 有效、buf 合法、len 为正 |
| 0.3 | **缓冲区地址越界** → 返回 `EFAULT`，**不启动 DMA** |
| 0.4 | 检查缓冲区物理连续性（页框是否分散） |
| 0.5 | 不满足 DMA 要求 → 内核分配**物理连续缓冲区**（bounce buffer） |
| 0.6 | 由 fd 查打开文件表 → 定位设备（磁盘块号→柱面/扇区） |
| 0.7 | 设备忙 → 进程加入**设备等待队列**（阻塞） |
| 0.8 | 记录当前进程上下文（供后续唤醒） |

##### 阶段 1：CPU 初始化 DMA（预处理②）

| 动作 | 寄存器/对象 | 细节 |
|:---|:---|:---|
| 1.1 | **AR（内存地址寄存器）** | 写入内存目标起始地址（物理地址） |
| 1.2 | **WC（字计数器）** | 写入待传输字节数（如 4KB） |
| 1.3 | **控制寄存器** | 写入命令字：方向、传输模式（周期挪用/突发/透明） |
| 1.4 | **设备控制器** | 发出启动命令（如"磁盘从扇区 X 开始读"） |
| 1.5 | 进程状态 | 置阻塞态，让出 CPU |

> CPU 只做设置工作（1.1~1.4），之后就"撒手不管"——这是 DMA 与中断方式的本质区别。

##### 阶段 2：DMA 传输（核心循环）

| 动作 | 细节 |
|:---|:---|
| 2.1 | DMA 向总线发出**总线请求（BR）** |
| 2.2 | **总线仲裁**：CPU 正用总线 → DMA 等待（周期挪用） |
| 2.3 | 获得总线授权（BG）→ DMA 接管总线 |
| 2.4 | 从设备控制器读 1 块数据到自身**数据缓冲寄存器（BR）** |
| 2.5 | 将 BR 中数据写入内存（AR 指向的物理地址） |
| 2.6 | **AR += 块大小**（自动增量） |
| 2.7 | **WC -= 块大小**（自动减量） |
| 2.8 | **释放总线**，还给 CPU |
| 2.9 | `WC == 0?` → 否 → 回到 2.1；是 → 进入阶段 3 |

**三种传输模式**：

| 模式 | 行为 | 对 CPU 的影响 |
|:---|:---|:---|
| **周期挪用** | 每次只用一个总线周期，交错进行 | 几乎无感，最常用 |
| **突发模式（块传输）** | 连续占用总线传输整个块 | 传输期间 CPU 被"冻结" |
| **透明模式** | 只在 CPU 不用总线时传输 | 完全透明，但可能饿死 |

##### 阶段 3：传输完成 → 中断

| 动作 | 细节 |
|:---|:---|
| 3.1 | WC 减到 0 → 传输结束（完成标志置位） |
| 3.2 | DMA 向 CPU 发**中断请求（INTR）** |
| 3.3 | CPU 执行完当前指令后响应中断 |
| 3.4 | 保存现场（PC、PSW、寄存器入栈） |
| 3.5 | 查中断向量表 → 跳转 DMA 中断处理程序 |

##### 阶段 4：中断处理 + 进程恢复

| 动作 | 细节 |
|:---|:---|
| 4.1 | 读取 DMA 状态寄存器 |
| 4.2 | 验证传输结果（错误位？校验错误？） |
| 4.3 | 用内核缓冲 → 数据从内核缓冲区**拷贝到用户缓冲区** |
| 4.4 | 从设备等待队列取出进程 → **唤醒**（阻塞→就绪） |
| 4.5 | 更新文件偏移量（+= 读取字节数） |
| 4.6 | 恢复现场 → 中断返回 → 进程继续执行 |

##### 缓冲区细节（五种）

| 缓冲区 | 位置 | 用途 |
|:---|:---|:---|
| **① 用户缓冲区** | 用户空间 | 进程最终要的数据 |
| **② 内核缓冲区** | 内核空间 | 中转站（DMA 需物理连续内存） |
| **③ 弹跳缓冲区（bounce buffer）** | 内核空间 | 用户缓冲物理不连续时中转，**多一次拷贝** |
| **④ 双缓冲** | 内核/设备 | 一个在传输、一个在使用，交替提高吞吐 |
| **⑤ 设备控制器内部缓存** | 设备侧 | 缓存最近读写数据 |

##### 意外情况处理（十种）

| # | 意外情况 | 处理方案 |
|:---|:---|:---|
| 1 | 缓冲区地址非法 | 阶段 0 检查 → 返回 `EFAULT`，不启动 DMA |
| 2 | 缓冲区物理不连续 | bounce buffer 中转 或 分散/聚集 DMA（Scatter-Gather） |
| 3 | 总线忙 | 周期挪用：等下一总线周期；突发：等当前指令完成 |
| 4 | 设备故障（坏块/校验错） | 状态寄存器错误位 → 中断程序检查 → 返回 `EIO` |
| 5 | 传输中途取消/进程被杀 | 发"中止"命令；回收缓冲区；处理部分数据一致性 |
| 6 | **Cache 一致性问题** | DMA 写内存前：失效对应 Cache 行；DMA 读内存前：写回 Cache（或写直达策略） |
| 7 | 中断丢失 | I/O 超时定时器：超时强制检查设备状态 |
| 8 | 传输量超 WC 上限（16 位计数器最大 64KB） | 分段传输：拆成多个 ≤64KB 的 DMA 段 |
| 9 | 设备控制器忙（多进程请求） | 设备等待队列排队，一次服务一个 |
| 10 | DMA 目标内存被换出 | **锁页（pinned）**：确保目标页框驻留，防止被页面置换 |

> [!warning] 考点速记
> - "DMA 传输全程 CPU 不参与"——**❌**（初始化、中断处理、缓冲拷贝仍需 CPU）
> - "DMA 中断是每个字节发一次"——**❌**（每**块**发一次）
> - "DMA 使用逻辑地址"——**❌**（使用**物理地址**）
> - "周期挪用对 CPU 影响最小"——**✅**
> - "bounce buffer 会引入额外拷贝"——**✅**
> - "DMA 目标页可以被置换"——**❌**（必须锁页）

### 4. 通道控制方式

#### 工作原理

通道（I/O Channel）是一种专门的 I/O 处理机，具有自己的指令系统（通道指令），可以独立执行通道程序，控制多台设备完成复杂的 I/O 操作。

```
        ┌─────────────────┐
        │      CPU        │
        │ （启动通道、处理中断）│
        └────────┬────────┘
                 │ 启动命令
                 ↓
        ┌─────────────────┐
        │   I/O 通道       │←──── 执行通道程序
        │ （独立的 I/O 处理器）│     控制多台设备
        └────────┬────────┘
                 │
        ┌────────┼────────┐
        ↓        ↓        ↓
   ┌────────┐┌────────┐┌────────┐
   │ 设备 1  ││ 设备 2  ││ 设备 3  │
   └────────┘└────────┘└────────┘
```

#### 通道类型

| 类型 | 连接方式 | 特点 | 适用场景 |
|------|----------|------|----------|
| **字节多路通道** | 连接多台低速设备 | 字节交叉传输，分时服务 | 打印机、终端等低速字符设备 |
| **数组选择通道** | 连接一台高速设备 | 独占通道，传输速率高 | 磁盘等高速设备 |
| **数组多路通道** | 连接多台高速设备 | 块交叉传输，兼顾效率和并发 | 磁盘等高速设备 |

#### 通道指令（通道命令字 CCW）

通道程序由一系列通道指令组成，每条通道指令包含：

| 字段 | 说明 |
|------|------|
| 操作码 | 读、写、控制等操作 |
| 内存地址 | 数据传输的内存起始地址 |
| 传输计数 | 要传输的数据量 |
| 特征位 | 链指针、错误处理等标志 |

```
// 通道程序示例（读取磁盘数据）
通道指令 1：READ  内存地址 0x1000  传输计数 1024  特征位：继续
通道指令 2：READ  内存地址 0x1400  传输计数 1024  特征位：继续
通道指令 3：READ  内存地址 0x1800  传输计数 1024  特征位：结束
```

#### 工作流程

```
1. CPU 执行 "启动 I/O" 指令，启动指定通道

2. 通道从内存中获取通道程序（通道指令序列）

3. 通道独立执行通道程序：
   - 解析通道指令
   - 控制设备完成 I/O 操作
   - 管理数据传输
   - 处理设备状态

4. 通道程序执行完毕，向 CPU 发中断

5. CPU 响应中断，进行后续处理
```

#### 特点分析

| 优点 | 缺点 |
|------|------|
| CPU 干预最少，效率最高 | 硬件最复杂，成本高 |
| 可控制多台设备 | 需要专门的通道处理器 |
| 可执行复杂的 I/O 程序 | 系统设计和维护复杂 |
| 适合大型系统的高速 I/O | |

#### 通道生命周期精讲（五阶段）

以"进程从多台磁盘批量读数据"为例：

##### 阶段 0：进程发起 + 内核构建通道程序

| 动作 | 细节 |
|:---|:---|
| 0.1 | 进程执行 `read()` → 陷入内核 |
| 0.2 | 内核根据请求**构建通道程序**（一串通道指令） |
| 0.3 | 通道程序写入内存 |
| 0.4 | 将通道程序**首地址**写入 **CAW（通道地址字）** |
| 0.5 | 进程置阻塞态，加入设备等待队列 |

##### 阶段 1：CPU 启动通道

| 动作 | 细节 |
|:---|:---|
| 1.1 | CPU 执行特权指令 **"启动 I/O"（START I/O）** |
| 1.2 | 指定通道号 + 设备号 |
| 1.3 | 通道从 **CAW** 取出通道程序首地址 |
| 1.4 | CPU 立刻返回继续执行其他进程（**CPU 与通道并行**） |

> CPU 只做一件事：发"启动"命令并告知通道程序在哪。之后完全撒手。

##### 阶段 2：通道执行通道程序（核心循环）

```
┌─ 取一条通道指令 ──────────────────────────────┐
│ 2.1 从内存读出通道指令（操作码/地址/计数/特征位） │
│ 2.2 解析操作码（READ/WRITE/控制命令）           │
│ 2.3 向目标设备发控制命令（选设备、定扇区）        │
│ 2.4 执行数据传输：设备 ⇄ 内存（类似 DMA 搬数据） │
│ 2.5 传输计数减到 0 → 检查特征位：               │
│     ├─ 链命令标志=1 → 取下一条通道指令（回 2.1）  │
│     └─ 链命令标志=0（最后一条）→ 进入阶段 3      │
└─────────────────────────────────────────────┘
```

##### 阶段 3：通道结束 → 发通道中断

| 动作 | 细节 |
|:---|:---|
| 3.1 | 通道程序执行完毕（或发生异常） |
| 3.2 | 通道将结果写入 **CSW（通道状态字）**：正常/异常 + 错误类型 |
| 3.3 | 向 CPU 发出**通道中断** |

##### 阶段 4：CPU 处理通道中断

| 动作 | 细节 |
|:---|:---|
| 4.1 | CPU 完成当前指令 → 响应中断 |
| 4.2 | 读取 **CSW** 判断结果 |
| 4.3 | 正常结束 → 唤醒等待进程、更新文件偏移量 |
| 4.4 | 异常结束 → 按错误类型处理（重试/报错） |

#### 特征位深入（408 考点）

| 特征位 | 含义 |
|:---|:---|
| **CC（链命令）** | =1 表示后面还有下一条通道指令（链式执行） |
| **CD（链数据）** | 下一条指令与当前指令使用**同一内存缓冲**（数据连续） |
| **SL（禁止悬挂）** | 设备选择失败时不挂起，继续下一条 |
| **SK（跳过）** | 条件满足时跳过下一条指令（类似"跳转"） |

> 特征位使通道程序具备**分支、链接、条件执行**能力——这是通道超越 DMA 的本质。

#### 三种通道的工作细节（时序维度）

```
【字节多路】按字节交叉轮转（多台低速设备）：
设备A: 字节A1 ── 字节A2 ───── 字节A3 ──
设备B: ─ 字节B1 ── 字节B2 ── 字节B3 ───

【数组选择】一台设备独占直到传完：
设备A: [████████ 整个数组传输 ████████]
设备B:                                    [████████]

【数组多路】按数据块交叉轮转（多台高速设备）：
设备A: [块A整块传输]            [块A下一块]
设备B:              [块B整块传输]            [块B下一块]
```

| | 字节多路 | 数组选择 | 数组多路 |
|:---|:---|:---|:---|
| 设备类型 | 多台**低速** | 一台**高速** | 多台**高速** |
| 交叉粒度 | **字节** | 不交叉（独占） | **数据块** |
| 通道利用率 | 高 | **低**（独占等待） | 高 |
| 通道速率要求 | ≥ 各设备速率之和 | ≥ 单设备速率 | ≥ 各设备速率之和 |
| 综合 | 低速设备首选 | 利用率最低（缺陷） | **综合最优** |

#### 通道中断的两种类型（易错点）

| 类型 | 触发 | 含义 |
|:---|:---|:---|
| **正常结束中断** | 通道程序全部执行完 | I/O 成功，唤醒进程 |
| **异常结束中断** | 设备故障/通道忙/指令错/校验错 | I/O 失败，读 CSW 错误码处理 |

> ⚠️ DMA 只有"传完发中断"一种；**通道中断分正常/异常两类**。

#### 三级并行（通道方式的最大价值）

```
CPU：    [计算任务1][计算任务2][计算任务3] ...
通道：        [执行通道程序A][执行通道程序B] ...
设备：           [设备1传输] [设备2传输] [设备3传输] ...
```

- CPU 与通道并行；通道与设备并行；设备与设备并行 → **并行性最高**

#### 通道与 DMA 对比（核心考点）

| 维度 | DMA | 通道 |
|:---|:---|:---|
| **本质** | 专用**硬件控制器**（按参数搬数据） | 专用 **I/O 处理机**（执行程序） |
| **控制粒度** | 一次搬一块数据 | 执行一串通道指令（可跨设备、带分支） |
| **能否控制多设备** | ❌ 一次只管一个设备的传输 | ✅ 一个通道程序可调度多台设备 |
| **指令系统** | 无（CPU 写寄存器设参数） | **有**（通道指令/通道程序） |
| **中断频率** | 每块一次 | 每个**通道程序**一次（更低） |
| **硬件成本** | 较低 | 高（相当于第二台"小 CPU"） |
| **适用** | 中小型系统、单磁盘 | 大型机、多磁盘阵列 |
| **演进关系** | ← 通道是 DMA 的发展 | → 由 DMA 演化而来 |

#### 意外情况处理（七种）

| # | 意外情况 | 处理方案 |
|:---|:---|:---|
| 1 | 通道忙（被占用） | "启动 I/O"失败 → 进程进通道等待队列重试 |
| 2 | 设备选择失败 | 看特征位：SL=1 → 跳过继续；否则异常结束中断 |
| 3 | 数据校验错误 | 通道指令可设"重试"语义；重试失败 → 异常中断上报 |
| 4 | 通道指令非法 | 检测到非法操作码 → 异常结束中断 + CSW 记录 |
| 5 | 中途设备故障 | 已完成指令结果保留；从故障点异常中断；CPU 决策处理 |
| 6 | 中断丢失 | 超时机制（同 DMA） |
| 7 | 多通道程序竞争同一通道 | 排队；数组多路通道按块轮转天然支持并发 |

> [!warning] 考点速记
> - "通道是一台专门的 I/O 处理机"——**✅**
> - "通道程序存放在内存中"——**✅**（不是通道内部）
> - "CPU 通过 CAW 告知通道程序首地址"——**✅**
> - "数组选择通道利用率最高"——**❌**（独占等待，利用率最低）
> - "通道中断只有正常结束一种"——**❌**（正常/异常两类）
> - "通道方式并行性高于 DMA"——**✅**（CPU-通道-设备三级并行）
> - "通道由 DMA 发展而来"——**✅**

### I/O 控制方式演进总结

```
程序直接控制 ──→ 中断驱动 ──→ DMA ──→ 通道控制

CPU 干预：   极高        高        中        低
并行性：     无         部分      较高      最高
复杂度：     简单       较简单     较复杂     复杂
适用设备：   简单低速    低速字符   高速块设备  大型系统
```

> [!example] 真题示例
> **题目**：对于磁盘这类高速块设备，最适合采用哪种 I/O 控制方式？
> 
> **答案**：DMA 方式或通道控制方式。对于单台磁盘，DMA 方式即可；对于大型系统中的多台磁盘，通道控制方式效率更高。
