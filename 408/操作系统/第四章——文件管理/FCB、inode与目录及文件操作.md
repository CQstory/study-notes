# FCB、inode与目录及文件操作

## 4.1.6 文件控制块FCB与索引节点inode

### 文件控制块FCB（File Control Block）

**定义**：FCB是操作系统用于管理和控制文件的数据结构，每个文件都有一个FCB。

**FCB包含的信息**：
```
┌─────────────────────┐
│ 文件名（目录项）      │
│ 文件物理地址          │
│ 文件逻辑结构          │
│ 文件的物理结构         │
│ 文件的存取控制信息     │
│ 文件的管理信息         │
│   - 文件建立时间       │
│   - 文件修改时间       │
│   - 文件所有者         │
│   - 文件长度           │
│   - 文件权限           │
└─────────────────────┘
```

### 索引节点inode（Index Node）

**设计动机**：
- 在检索文件时，**文件名**只需要在目录查找阶段使用
- 找到文件后，后续操作（读写等）只需要FCB中的其他信息
- 因此将**文件名**与**文件描述信息**分离，文件描述信息单独存放，称为 **inode**

**inode结构**：
```
┌─────────────────────┐
│ 文件标识符（文件号）    │
│ 文件类型              │
│ 文件大小              │
│ 文件物理地址（索引表）  │
│ 文件的存取控制信息     │
│ 文件链接计数          │
│ 文件的各种时间信息     │
│   - 建立时间          │
│   - 修改时间          │
│   - 访问时间          │
└─────────────────────┘
```

**目录项结构变化**：
```
分离前（FCB方式）：
目录项 = [文件名 | FCB全部信息]  ← 目录项很大

分离后（inode方式）：
目录项 = [文件名 | inode号]     ← 目录项很小
inode = [文件描述信息（不含文件名）]
```

### FCB与inode的对比

| 特征 | FCB方式 | inode方式 |
|------|---------|-----------|
| 目录项大小 | 大（包含全部信息） | 小（仅文件名+inode号） |
| 文件查找速度 | 慢（需读入大量数据） | 快（目录项小，可缓存更多） |
| 磁盘I/O次数 | 多 | 少 |
| 内存利用率 | 低 | 高 |
| 实现复杂度 | 简单 | 较复杂 |

> **考点提示**：采用inode后，目录项只包含文件名和inode号，大大减小了目录项的大小。当查找文件时，只需将目录项读入内存，找到目标文件的inode号后，再根据inode号读取inode信息。这样可以减少磁盘I/O次数，提高文件检索效率。

### inode中的文件物理地址

inode中通常包含一个索引表，用于记录文件数据块的物理位置：

```
inode索引表：
┌──────┬──────┬──────┬──────┐
│直接地址│一次间接│二次间接│三次间接│
│ 10项 │ 1项  │ 1项  │ 1项  │
└──────┴──────┴──────┴──────┘
```

- **直接地址**：直接指向数据块，适合小文件
- **一次间接**：指向一个索引块，索引块中存放数据块号
- **二次间接**：指向一个索引块，该索引块指向一级索引块，一级索引块指向数据块
- **三次间接**：在二次间接基础上再加一级

## 4.1.7 文件目录

文件目录是用于组织和检索文件的数据结构，由若干**目录项**组成。

### 1. 单级目录结构

**定义**：整个系统只有一张目录表，所有文件的FCB（或目录项）都登记在这张表中。

```
目录表：
┌──────────┬──────────┐
│ 文件名   │ FCB信息   │
├──────────┼──────────┤
│ file1    │ → FCB1   │
│ file2    │ → FCB2   │
│ file3    │ → FCB3   │
└──────────┴──────────┘
```

**优点**：实现简单

**缺点**：
- **不允许文件重名**（不同用户的文件不能同名）
- 查找速度慢（文件多时线性查找效率低）
- 不便于文件共享

### 2. 两级目录结构

**定义**：将目录分为主文件目录（MFD）和用户文件目录（UFD）两级。MFD记录用户名及其UFD的位置，UFD记录该用户所有文件的信息。

```
主文件目录（MFD）：
┌──────────┬──────────┐
│ 用户名   │ UFD指针   │
├──────────┼──────────┤
│ user1    │ → UFD1   │
│ user2    │ → UFD2   │
└──────────┴──────────┘

用户文件目录（UFD1）：
┌──────────┬──────────┐
│ 文件名   │ FCB信息   │
├──────────┼──────────┤
│ file1    │ → FCB1   │
│ file2    │ → FCB2   │
└──────────┴──────────┘
```

**优点**：
- 不同用户的文件可以重名
- 按用户分类管理，一定程度上提高了检索效率

**缺点**：
- 缺乏灵活性，不能对文件进行分类管理
- 不便于文件共享

### 3. 树形目录结构（多级目录结构）

**定义**：将两级目录推广为多级，形成树形结构的目录树。每个目录项要么是文件，要么是子目录。

```
根目录 /
├── 用户1/
│   ├── 文档/
│   │   ├── file1.txt
│   │   └── file2.txt
│   └── 程序/
│       ├── prog1.c
│       └── prog2.c
├── 用户2/
│   ├── file3.txt
│   └── file4.txt
└── 系统/
    ├── config.sys
    └── kernel.exe
```

**路径名**：
- **绝对路径**：从根目录开始的完整路径，如 `/用户1/文档/file1.txt`
- **相对路径**：从当前工作目录开始的路径，如 `文档/file1.txt`

**优点**：
- 层次清晰，便于分类管理
- 不同目录下的文件可以重名
- 检索效率较高

**缺点**：
- 不便于文件共享（一个文件只能在一个目录下）

> **考点提示**：树形目录结构是现代操作系统（如Windows、Linux）最常用的目录结构。

### 4. 无环图目录结构

**定义**：在树形目录的基础上，允许同一个文件或子目录被多个目录项指向，形成有向无环图（DAG）。

**实现方式**：
- **硬链接**：不同目录项指向同一个inode，共享计数器记录链接数
- 当链接数为0时，才真正删除文件

```
根目录 /
├── 用户1/
│   └── myfile.txt ──┐
├── 用户2/            │
│   └── myfile.txt ───┘  （指向同一个inode）
```

**优点**：
- 支持文件共享
- 不同用户可以通过不同路径访问同一个文件

**缺点**：
- 结构更复杂
- 需要维护共享计数器
- 遍历时可能需要特殊处理（避免重复访问）

### 四种目录结构对比

| 特征 | 单级目录 | 两级目录 | 树形目录 | 无环图目录 |
|------|----------|----------|----------|-----------|
| 文件能否重名 | 不能 | 不同用户可重名 | 不同目录可重名 | 不同目录可重名 |
| 检索效率 | 低 | 中 | 较高 | 较高 |
| 文件共享 | 不支持 | 不支持 | 不支持 | 支持 |
| 层次结构 | 无 | 两层 | 多层 | 多层（有共享） |
| 实现复杂度 | 简单 | 简单 | 中等 | 较复杂 |
| 应用场景 | 简单系统 | 早期系统 | 现代OS | 现代OS（共享需求） |

### 目录的操作与实现（408 高频考点）

> 目录本质是一个**特殊文件**，其内容是目录项集合。目录的操作 = 对目录文件中目录项的增删改查。

**六种基本操作**：

| 操作 | 说明 | 对目录的影响 |
|:---|:---|:---|
| **搜索（search）** | 按文件名/路径查找目录项 | 只读 |
| **创建文件（create）** | 新增一个目录项 | 目录项 +1 |
| **删除文件（delete）** | 移除一个目录项 | 目录项 −1 |
| **显示目录（read）** | 列出所有目录项 | 只读 |
| **修改目录（modify）** | 修改目录项属性 | 更新单个项 |
| **重命名（rename）** | 修改目录项中的文件名 | 替换文件名字段 |

#### （1）搜索的实现

**单级目录**：遍历目录项，逐个比对文件名 → 找到则返回 inode 号。

**树形目录（路径搜索）**：

```
打开 "/home/user/report.txt"：
1. 读入根目录 → 搜索 "home" → 得 inode 号 3
2. 读入 inode 3 → 得 /home 的磁盘块 → 读入 → 搜索 "user" → 得 inode 号 17
3. 读入 inode 17 → 得 /home/user 的磁盘块 → 读入 → 搜索 "report.txt" → 得 inode 号 56
4. 读入 inode 56 → 得文件数据块地址 → 打开
```

> 路径每一级都需要**读一次目录 + 搜索一次**。现代系统有目录缓存（dentry cache）加速。

#### （2）创建文件的实现

```
1. 检查权限：用户对目标目录有"写"权限？
2. 检查重名：在目标目录中搜索同名文件 → 存在则报错
3. 分配 inode：从空闲 inode 表取一个
4. 分配磁盘块：从空闲块表取数据块
5. 初始化 inode：大小=0、权限、属主、时间
6. 添加目录项：[文件名 | inode号] 写入目标目录
7. 更新父目录：修改时间、链接计数
```

#### （3）删除文件的实现

**前提条件**：用户有写权限 + 文件未被占用。

```
1. 搜索定位：按路径找到目录项 [filename | inode=42]
2. 读入 inode 42 → 获取链接计数
3. 判断：
   ├─ 链接计数 > 1 → 仅减 1，文件数据保留，只删目录项
   └─ 链接计数 = 1 → 真正删除：
       4. 释放所有磁盘块（归还空闲块表）
       5. 释放 inode（归还空闲 inode 表）
       6. 从目录中删除该目录项
       7. 更新父目录（修改时间、链接计数−1）
```

> [!warning] 硬链接陷阱
> 删除有硬链接的文件时，若链接计数 >1，**文件数据不会被删除**——只是少了一个目录项指向它。只有计数降为 0 才真正回收磁盘块和 inode。

#### （4）操作与磁盘 I/O 次数

| 操作 | 典型磁盘 I/O | 说明 |
|:---|:---:|:---|
| **搜索**（单级） | 1~N | 读目录块 |
| **创建** | 3~5 | 读目录+分配块+写inode+写目录 |
| **删除** | 3~6 | 读目录+读inode+释放块+写目录+更新父 |
| **重命名** | 2 | 读目录+写回（只改文件名） |
| **显示** | 1 | 只读目录 |

### 文件的基本操作（八大类）

| 操作 | 对应 CRUD | 系统调用 | 核心作用 |
|:---|:---:|:---:|:---|
| **创建** | 增 | `creat()` | 新建文件 |
| **删除** | 删 | `unlink()` | 删除文件 |
| **打开** | — | `open()` | 加载元数据到内存 |
| **关闭** | — | `close()` | 释放文件资源 |
| **读** | 查 | `read()` | 读取文件内容 |
| **写** | 改 | `write()` | 写入文件内容 |
| **截断** | 改 | `truncate()` | 清空内容但保留文件 |
| **定位** | — | `lseek()` | 移动读写指针 |

#### （1）打开（Open）—— 读写前的必经步骤

```
1. 按路径搜索 → 找到目录项 → 得到 inode 号
2. 读入 inode → 得到数据块地址、大小、权限
3. 检查访问权限（读/写/执行）
4. 在系统级打开文件表中创建记录：
   - 文件偏移量（初始=0）
   - 访问模式（只读/只写/读写/追加）
   - 指向 inode 的指针
5. 在进程级打开文件表中创建条目 → 返回文件描述符（fd）
```

> 打开操作**不读文件内容**，只加载元数据（inode）。

#### （2）读（Read）

```
1. 由 fd 定位打开文件表条目
2. 获取当前偏移量
3. 由偏移量计算目标磁盘块号（查 inode 索引表）
4. 从磁盘/缓冲区读入数据 → 拷贝到用户缓冲区
5. 更新偏移量
```

#### （3）写（Write）

```
1. 检查权限（文件必须可写）
2. 由偏移量计算目标磁盘块号
3. 若偏移量超过文件大小 → 分配新磁盘块
4. 将数据写入磁盘块
5. 更新 inode：文件大小、修改时间
6. 更新偏移量
```

#### （4）截断（Truncate）

```
1. 释放文件的所有数据块
2. 文件大小改为 0
3. 保留 inode 和目录项（文件"存在但为空"）
```

> 截断 ≠ 删除：截断保留文件壳；删除连 inode 和目录项都销毁。

#### （5）关闭（Close）

```
1. 将缓冲区中未写回的数据刷入磁盘
2. 更新 inode（大小、修改时间）
3. 系统打开文件表链接计数 −1
4. 若计数=0 → 释放系统级打开文件表条目
5. 释放进程级打开文件表条目
```
