# 文件系统布局（磁盘管理）

## 4.2.3 磁盘管理

### 磁盘的格式化

磁盘在使用前需要经过两个步骤的格式化：

**1. 低级格式化（物理格式化）**
- 将磁盘划分为磁道和扇区
- 为每个扇区写入特定的数据结构（如扇区头、数据区、纠错码）
- 通常由磁盘制造商完成

**2. 逻辑格式化（高级格式化）**
- 创建文件系统
- 建立空闲空间管理的数据结构
- 建立根目录
- 初始化文件系统管理信息

### 引导块（Boot Block）

**定义**：计算机启动时，需要从磁盘读取一段引导程序（Bootstrap），这段程序存放在磁盘的**引导块**中。

**引导过程**：
1. 计算机加电启动
2. CPU执行ROM中的自举程序
3. 自举程序读取磁盘的**第一个块**（引导块/主引导记录MBR）
4. 引导块中的程序加载操作系统内核到内存
5. 跳转到操作系统入口，完成启动

```
整个磁盘的完整布局：
┌─────────────────────────────┐
│ 主引导记录（MBR）              │ ← 磁盘最开头（不属于任何分区）
│ 引导程序 + 分区表              │   管整个磁盘的分区划分
├─────────────────────────────┤
│ 分区1（文件系统）              │
│ ┌─────────────────────────┐ │
│ │ 引导块（Boot Block）      │ │ ← 分区第1块，自举程序
│ ├─────────────────────────┤ │
│ │ 超级块（Super Block）     │ │ ← 文件系统总控信息
│ ├─────────────────────────┤ │
│ │ 空闲空间管理信息           │ │ ← 哪些块空闲
│ ├─────────────────────────┤ │
│ │ inode 表                 │ │ ← 所有文件的元数据
│ ├─────────────────────────┤ │
│ │ 数据块区域                 │ │ ← 文件内容 + 目录内容
│ └─────────────────────────┘ │
├─────────────────────────────┤
│ 分区2 ...                    │
└─────────────────────────────┘
```

### 各组成部分及作用

| 组成 | 层级 | 内容 | 作用 |
|:---|:---|:---|:---|
| **主引导记录（MBR）** | 磁盘级 | 引导程序 + 分区表 | 开机第一个被读取，决定启动哪个分区 |
| **引导块（Boot Block）** | 分区级 | 该分区的自举程序 | 从该分区启动时加载操作系统内核 |
| **超级块（Super Block）** | 分区级 | 文件系统总控信息（魔数、块大小、总块数、区域位置） | 描述整个文件系统的元数据 |
| **空闲空间管理信息** | 分区级 | 位示图/空闲链表/成组链接栈 | 记录哪些磁盘块空闲，用于分配 |
| **inode 表** | 分区级 | 所有文件的 inode（大小、权限、数据块指针） | 记录每个文件的元数据 |
| **数据块区域** | 分区级 | 文件的实际内容 + 目录内容 | 存放真正的文件数据 |

> [!warning] MBR vs 引导块（易混点）
> - **MBR** 是**磁盘级**：位于磁盘第 0 扇区，管"分区表"，不属于任何分区
> - **引导块** 是**分区级**：位于每个分区开头，管"本分区的启动"
> - 引导过程：开机 → 读 MBR → MBR 根据分区表找到活动分区 → 读该分区引导块 → 加载内核

> [!tip] 分区布局速记
> **引导块 → 超级块 → 空闲空间管理 → inode 表 → 数据块区**（磁盘级还有 MBR 在最前）

### 超级块（Super Block）的内容

> **超级块** = 文件系统的**总控信息块**，记录整个文件系统的全局元数据。每个文件系统（分区）有且仅有一个超级块，通常位于分区的第 2 个块（第 1 块是引导块）。
> 类比：文件系统是一栋大楼，超级块就是这栋楼的"物业管理档案"。

#### 超级块包含的四大类信息

**（1）文件系统基本信息**

| 内容 | 说明 |
|:---|:---|
| 魔数（Magic Number） | 标识文件系统类型 |
| 文件系统类型 | FAT / ext4 / NTFS 等 |
| 块大小 | 每个磁盘块/簇的大小 |
| 总块数 / 空闲块数 | 块的使用情况 |
| 总 inode 数 / 空闲 inode 数 | inode 的使用情况 |
| 卷名 | 文件系统名称 |

**（2）空闲空间管理信息**

| 内容 | 说明 |
|:---|:---|
| 空闲块管理 | 空闲块栈（成组链接法）/ 位示图指针 / 空闲链表头 |
| 空闲 inode 管理 | 空闲 inode 栈/链 |

**（3）关键区域的指针/位置**

| 内容 | 说明 |
|:---|:---|
| inode 表起始位置 | inode 区在磁盘上的起始块号 |
| 数据区起始位置 | 数据块区的起始块号 |
| 根目录位置 | 根目录的 inode 号 |
| 空闲空间管理结构位置 | 位示图/空闲链表的位置 |

**（4）时间与管理信息**

| 内容 | 说明 |
|:---|:---|
| 创建时间 / 最后挂载时间 / 最后修改时间 | 时间戳 |
| 挂载计数 | 已挂载次数 |
| 日志信息 | 日志块位置、大小（有日志文件系统） |

#### 超级块在磁盘与内存中

```
磁盘：超级块位于引导块之后（第1块）
内存：挂载时读入"内存超级块副本"，运行时修改内存副本，定期写回磁盘
```

> [!warning] 超级块损坏 = 文件系统灾难
> 超级块存全局元数据，一旦损坏整个文件系统可能无法挂载。因此 ext 系列会**备份多份超级块**分布在不同块组中。

#### 考点速记

```
超级块 = 文件系统"总控信息"，四大类：
① 基本信息（魔数、类型、块大小、总块数/总inode数）
② 空闲管理（空闲块栈/位示图位置、空闲inode数）
③ 区域指针（inode表起始、数据区起始、根目录位置）
④ 时间管理（创建/挂载/修改时间、日志信息）
```

| 判断题 | 答案 |
|:---|:---:|
| "每个文件都有一个超级块" | ❌（每个文件系统/分区一个） |
| "超级块记录单个文件的属性" | ❌（那是 inode；超级块记全局信息） |
| "超级块损坏会导致文件系统无法挂载" | ✅ |
| "运行时直接修改磁盘上的超级块" | ❌（改内存副本，定期写回） |

### 坏块管理

磁盘使用过程中可能出现坏块（物理损坏），需要妥善处理：

**1. 简单的坏块处理（如FAT文件系统）**
- 在格式化时检测坏块，在FAT表中标记为"坏块"
- 分配空间时跳过坏块

**2. 扇区备用（如UNIX系统）**
- 在磁盘上预留一些备用扇区
- 发现坏块时，将数据迁移到备用扇区
- 更新坏块列表，将坏块重定向到备用扇区

**3. 磁盘控制器处理**
- 现代磁盘控制器通常内置坏块管理功能
- 对操作系统透明，自动进行坏块替换

### 文件系统在内存中的结构

> 文件系统运行时，内存中维护一系列结构加速文件访问。与"磁盘布局"互补：磁盘存的是持久数据，内存存的是运行时状态。

```
内存中的文件系统结构：
┌──────────────────────────────────────────┐
│ ① 安装表（Mount Table）                    │
│    记录所有挂载的文件系统                     │
│    （哪个分区挂在哪个目录）                   │
├──────────────────────────────────────────┤
│ ② 内存超级块副本                            │
│    每个挂载文件系统一份                       │
├──────────────────────────────────────────┤
│ ③ 内存目录项缓存（dentry cache）            │
│    最近访问过的目录项（加速路径搜索）          │
├──────────────────────────────────────────┤
│ ④ 内存 inode 缓存（inode cache）            │
│    最近打开过的文件的 inode（避免重复读盘）    │
├──────────────────────────────────────────┤
│ ⑤ 系统级打开文件表                           │
│    每个被打开的文件一条记录                   │
│    （偏移量、访问模式、打开计数）              │
├──────────────────────────────────────────┤
│ ⑥ 进程级打开文件表                           │
│    每个进程一张（即 fd 表）                   │
├──────────────────────────────────────────┤
│ ⑦ 缓冲区（Buffer Cache）                   │
│    缓存最近读写的磁盘块                       │
└──────────────────────────────────────────┘
```

#### 两级打开文件表（408 考点）

```
进程A 的进程打开文件表        系统打开文件表          内存inode表
┌────┬────┐              ┌────────────┐        ┌──────────┐
│ fd0│ → ─┼─────────────→│ 条目1：     │───────→│ inode 42 │
│ fd1│ → ─┼──────┐       │ 偏移量=100  │        │          │
└────┴────┘      │       │ 模式=读写   │        └──────────┘
                 └──────→│ 打开计数=2  │
                          └────────────┘
进程B 的进程打开文件表
┌────┬────┐
│ fd0│ → ─┼──────────────→（另一系统条目，独立偏移量）
└────┴────┘                        └────→（指向同一内存 inode 42）
```

| 结构 | 数量 | 内容 |
|:---|:---|:---|
| 进程级打开文件表 | 每进程一张 | fd → 系统表条目的指针 |
| 系统级打开文件表 | 全系统一张 | 偏移量、访问模式、打开计数、指向内存 inode |
| 内存 inode 表 | 全系统一张 | 被打开文件的 inode 副本（共享） |

> [!important] 关键辨析
> 两个进程打开**同一文件** → 各自有独立的系统表条目（**偏移量独立**），但指向**同一个内存 inode**（元数据共享）。

### 文件系统的层次架构

```
┌────────────────────────────────────┐
│ 用户层：open() / read() / write()    │  ← 用户调用
├────────────────────────────────────┤
│ 逻辑文件系统：文件→块号转换            │  ← 元数据、目录、保护
├────────────────────────────────────┤
│ 文件组织模块：块号→磁盘地址转换        │  ← 物理分配（连续/链接/索引）
├────────────────────────────────────┤
│ 基本文件系统：块号→驱动请求            │  ← 缓冲区、块 I/O
├────────────────────────────────────┤
│ I/O 控制：中断、调度、驱动             │  ← 第五章内容
└────────────────────────────────────┘
```

| 层次 | 职责 | 关键结构 |
|:---|:---|:---|
| **逻辑文件系统** | 管理元数据、目录结构、保护 | inode、目录项、打开文件表 |
| **文件组织模块** | 逻辑块号 → 物理块号 | 分配方式（连续/链接/索引） |
| **基本文件系统** | 发出磁盘读写命令、缓冲区管理 | 块号、缓冲区 |
| **I/O 控制** | 中断处理、设备驱动、磁盘调度 | 设备驱动、I/O 请求队列 |
