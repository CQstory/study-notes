# 文件概念与逻辑结构

## 4.1.1 文件的概念

### 文件的定义

文件是以计算机硬盘为载体的存储在外存上的信息集合。从用户角度看，文件是操作系统中信息存储的最小单位，用户通过文件名来访问文件。

### 文件的属性

| 属性 | 说明 |
|------|------|
| 文件名 | 用户标识文件的名称 |
| 标识符（文件号） | 系统内部唯一标识文件的编号 |
| 文件类型 | 标识文件的类别（如文本文件、二进制文件等） |
| 文件大小 | 文件的当前大小 |
| 文件的物理位置（指针） | 文件在磁盘上的起始位置信息 |
| 文件的建立时间 | 文件创建的日期和时间 |
| 文件的修改时间 | 文件最后一次修改的日期和时间 |
| 文件的拥有者（所有者） | 文件的属主 |
| 文件的访问权限 | 控制不同用户对文件的访问权限 |
| 文件的保护信息 | 文件的保护级别和加密信息 |

### 文件的分类

#### 按用途分类

| 类型 | 说明 | 示例 |
|------|------|------|
| 系统文件 | 操作系统及其他系统程序的数据 | 内核代码、设备驱动 |
| 用户文件 | 用户委托系统管理的文件 | 用户文档、程序源码 |
| 库文件 | 标准子程序及常用实用程序 | C标准库、动态链接库 |

#### 按数据形式分类

| 类型 | 说明 |
|------|------|
| 源文件 | 由源程序和数据构成的文件（ASCII码/汉字） |
| 目标文件 | 源程序经编译后的二进制文件 |
| 可执行文件 | 目标文件经链接后生成的可执行文件 |

#### 按组织形式分类（重要）

文件按组织形式分为**有结构文件**和**无结构文件**两类。

---

## 4.1.2 有结构文件（记录式文件）

有结构文件由若干个**记录**组成，每条记录由若干个**数据项**构成。根据记录的组织方式不同，可分为以下几种：

### 1. 顺序文件

**定义**：记录按某种顺序（可以是按关键字排序，也可以是按存入时间先后）排列。

**分类**：
- **串结构**：记录按存入时间先后排列，检索效率低
- **顺序结构**：记录按关键字排序，检索效率较高

**存储方式**：
- **串结构**：可以顺序存储，也可以链式存储
- **顺序结构**：只能顺序存储

**优点**：
- 批量存取效率高，适合顺序访问
- 存储密度大，空间利用率高

**缺点**：
- 增删记录困难，需要大量移动记录
- 按关键字查找速度慢（只能顺序查找，或折半查找但增删困难）
- 不适合随机访问

> **考点提示**：顺序文件是最简单的有结构文件组织方式，适合存储变动不大的数据。

### 2. 索引文件

**定义**：为变长记录文件建立一张**索引表**，索引表的每一项包含记录的关键字和指向该记录的指针。

**结构**：
```
索引表（定长记录）：
┌──────────┬──────────┐
│ 关键字   │ 记录指针  │
├──────────┼──────────┤
│ 001      │ → 记录1   │
│ 003      │ → 记录2   │
│ 007      │ → 记录3   │
└──────────┴──────────┘

数据区（变长记录）：
┌──────────────────┐
│ 记录1（长度不定）  │
├──────────────────┤
│ 记录2（长度不定）  │
├──────────────────┤
│ 记录3（长度不定）  │
└──────────────────┘
```

**优点**：
- 支持随机访问，检索速度快
- 适合变长记录

**缺点**：
- 需要额外的索引表空间
- 索引表本身需要维护

> **考点提示**：索引表本身是定长记录的顺序文件，因此可以对索引表进行折半查找。

### 3. 索引顺序文件

**定义**：是顺序文件和索引文件的结合体。将记录分为若干组，为每组建立一条索引项，通常还会建立多级索引。

**结构**：
```
主索引表：
┌──────────┬──────────┐
│ 最大关键字│ 子索引指针│
├──────────┼──────────┤
│ 100      │ → 子索引1 │
│ 300      │ → 子索引2 │
│ 500      │ → 子索引3 │
└──────────┴──────────┘

子索引表（每个子索引对应一组记录）：
┌──────────┬──────────┐
│ 关键字   │ 记录指针  │
├──────────┼──────────┤
│ ...      │ ...      │
└──────────┴──────────┘

数据区：各组记录按关键字有序排列
```

**优点**：
- 检索速度快（先查主索引，再查子索引，最后查记录）
- 支持随机访问
- 索引表比纯索引文件小得多

**缺点**：
- 增删记录需要维护索引
- 组织方式复杂

> **考点提示**：索引顺序文件是最常用的有结构文件组织方式，VSAM（虚拟存储存取方法）就是一种索引顺序文件组织。

### 三种有结构文件对比

| 特征 | 顺序文件 | 索引文件 | 索引顺序文件 |
|------|----------|----------|--------------|
| 记录长度 | 定长/变长 | 变长 | 定长/变长 |
| 记录排列 | 按关键字有序/无序 | 无序（索引表有序） | 按关键字有序分组 |
| 访问方式 | 顺序访问 | 随机访问 | 随机访问 |
| 检索速度 | 慢（顺序查找） | 较快（查索引表） | 快（多级索引） |
| 空间开销 | 小 | 较大（索引表） | 中等 |
| 增删灵活性 | 差 | 较好 | 较好 |
| 适用场景 | 批量存取 | 随机访问变长记录 | 大规模数据随机访问 |

## 4.1.3 无结构文件（流式文件）

**定义**：无结构文件是由字符流构成的文件，文件内部没有明确的结构划分，以字节为单位。

**特点**：
- 文件内部没有结构，只是一串字符流
- 以字节（Byte）为基本单位进行存取
- 管理简单，用户可以自由定义文件格式

**应用场景**：
- 文本文件（.txt）
- 二进制可执行文件（.exe）
- 多媒体文件（图片、音频、视频）

> **考点提示**：现代操作系统（如Linux、Windows）中，**无结构文件**是主流文件形式。

### 有结构 vs 无结构：举例对比

> [!example] 具体例子
> **有结构文件**：学生成绩表
> ```
> 记录1: 学号=001, 姓名=张三, 高数=92, 英语=88
> 记录2: 学号=002, 姓名=李四, 高数=85, 英语=91
> 记录3: 学号=003, 姓名=王五, 高数=78, 英语=83
> ```
> 每条记录结构相同（学号+姓名+成绩），系统知道"记录"边界，可按学号做索引检索。
>
> **无结构文件**：一张照片 `cat.jpg`
> ```
> [FF D8 FF E0 00 10 4A 46 49 46 ...]  ← 全是字节流，共 2,048,576 字节
> ```
> OS 不关心里面是 JPEG 头还是像素数据；图片查看器自己解析格式。

| 维度 | 有结构文件 | 无结构文件 |
|:---|:---|:---|
| **内部组织** | 由**记录**组成（定长/变长） | 字节流，无内部划分 |
| **基本单位** | 记录（Record） | 字节（Byte） |
| **访问方式** | 可按记录号/关键字随机访问 | 只能按偏移量读写 |
| **索引** | 系统可建索引加速检索 | 系统不建索引 |
| **谁解释内容** | **操作系统**理解记录结构 | **应用程序**自己解释 |
| **典型例子** | 数据库表、银行交易记录、成绩单 | .txt、.jpg、.mp4、.exe、.pdf |
| **现代主流** | 数据库等专用场景 | ✅ **主流**（Linux/Windows 全用） |

> [!important] 408 关键结论
> **现代 OS 的文件系统只管理无结构文件**——文件对 OS 来说就是一个字节数组，格式由应用程序决定。有结构文件的"记录"逻辑由上层（数据库、电子表格）自己处理，不依赖底层文件系统。

## 4.1.4 文件的逻辑结构

文件的逻辑结构是从用户角度看到的文件组织形式，与文件的物理存储方式无关。

### 逻辑结构分类

```
文件的逻辑结构
├── 无结构文件（流式文件）
│   └── 字符流，无记录概念
└── 有结构文件（记录式文件）
    ├── 顺序文件
    ├── 索引文件
    └── 索引顺序文件
```

### 逻辑结构与物理结构的关系

> 逻辑结构是用户视角的组织方式，物理结构是操作系统视角的存储方式。一种逻辑结构可以映射到多种物理结构上。

| 逻辑结构 | 可映射的物理结构 |
|----------|-----------------|
| 流式文件 | 连续分配、链接分配、索引分配均可 |
| 顺序文件 | 连续分配最合适 |
| 索引文件 | 索引分配最合适 |
| 索引顺序文件 | 索引分配最合适 |
