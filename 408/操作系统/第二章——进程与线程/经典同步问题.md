# 经典同步问题

## 五、经典同步问题

> [!important] 核心考点
> 经典同步问题是408综合应用题的常考内容，必须熟练掌握。

### 5.1 生产者-消费者问题

#### 问题描述

生产者生产产品放入缓冲区，消费者从缓冲区取产品消费。缓冲区容量有限。

#### 约束条件

1. **互斥**：生产者和消费者不能同时访问缓冲区
2. **同步**：缓冲区满时生产者必须等待；缓冲区空时消费者必须等待

#### 信号量设置

```c
semaphore mutex = 1;     // 互斥信号量，保证对缓冲区的互斥访问
semaphore empty = n;     // 同步信号量，表示空缓冲区数量（初值=缓冲区容量）
semaphore full = 0;      // 同步信号量，表示满缓冲区数量（初值=0）
```

#### 完整代码

```c
// 生产者
void Producer() {
    while (true) {
        /* 生产一个产品 */
        
        P(empty);        // 申请一个空缓冲区（若无则阻塞）
        P(mutex);        // 申请进入临界区
        
        /* 将产品放入缓冲区 */
        
        V(mutex);        // 退出临界区
        V(full);         // 满缓冲区数加1，可能唤醒消费者
    }
}

// 消费者
void Consumer() {
    while (true) {
        P(full);         // 申请一个满缓冲区（若无则阻塞）
        P(mutex);        // 申请进入临界区
        
        /* 从缓冲区取出产品 */
        
        V(mutex);        // 退出临界区
        V(empty);        // 空缓冲区数加1，可能唤醒生产者
        
        /* 消费产品 */
    }
}
```

> [!warning] 注意P操作的顺序
> **必须先执行同步信号量的P操作，再执行互斥信号量的P操作**。如果顺序相反：
> ```c
> P(mutex);    // 先申请互斥
> P(empty);    // 再申请空缓冲区
> ```
> 若缓冲区已满，生产者会在持有mutex的情况下阻塞，导致消费者无法进入临界区取产品，形成**死锁**。

#### 多生产者多消费者变体

> [!example] 2021年408真题变体
> 有多个生产者和多个消费者，缓冲区大小为n，每个生产者每次生产1个产品，每个消费者每次消费1个产品。
>
> **分析**：上述代码已经适用于多生产者多消费者情况，因为mutex保证了互斥，empty和full保证了同步。

### 5.2 哲学家就餐问题

#### 问题描述

5个哲学家围坐在圆桌旁，每人左右各有一根筷子。哲学家只有同时拿到左右两根筷子才能吃饭。

#### 约束条件

1. **互斥**：筷子是临界资源，一次只能被一个哲学家使用
2. **避免死锁**：防止所有哲学家同时拿起左边筷子，导致死锁

#### 信号量设置

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};  // 5根筷子，每根初值为1
```

#### 基本解法（可能导致死锁）

```c
// 哲学家i（i = 0, 1, 2, 3, 4）
void Philosopher(int i) {
    while (true) {
        /* 思考 */
        
        P(chopstick[i]);           // 拿起左边筷子
        P(chopstick[(i+1)%5]);     // 拿起右边筷子
        
        /* 吃饭 */
        
        V(chopstick[(i+1)%5]);     // 放下右边筷子
        V(chopstick[i]);           // 放下左边筷子
    }
}
```

> [!danger] 死锁风险
> 若5个哲学家同时拿起左边筷子，则每人都在等待右边筷子，形成死锁。

#### 解决方案

| 方案 | 思路 | 代码 |
|:-----|:-----|:-----|
| **方案1：最多允许4个哲学家同时就餐** | 限制同时就餐人数 | 增加信号量 `room = 4`，就餐前P(room)，就餐后V(room) |
| **方案2：奇偶号哲学家不同顺序拿筷子** | 破坏循环等待 | 奇数号先左后右，偶数号先右后左 |
| **方案3：同时拿两根筷子（AND型信号量）** | 一次性申请所有资源 | `Swait(chopstick[i], chopstick[(i+1)%5])` |

#### 方案1完整代码

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};
semaphore room = 4;      // 最多允许4个哲学家同时就餐

void Philosopher(int i) {
    while (true) {
        /* 思考 */
        
        P(room);                     // 申请进入餐厅
        P(chopstick[i]);             // 拿左边筷子
        P(chopstick[(i+1)%5]);       // 拿右边筷子
        
        /* 吃饭 */
        
        V(chopstick[(i+1)%5]);       // 放右边筷子
        V(chopstick[i]);             // 放左边筷子
        V(room);                     // 离开餐厅
    }
}
```

#### 方案2完整代码

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};

void Philosopher(int i) {
    while (true) {
        /* 思考 */
        
        if (i % 2 == 0) {            // 偶数号哲学家
            P(chopstick[(i+1)%5]);   // 先拿右边
            P(chopstick[i]);         // 再拿左边
        } else {                      // 奇数号哲学家
            P(chopstick[i]);         // 先拿左边
            P(chopstick[(i+1)%5]);   // 再拿右边
        }
        
        /* 吃饭 */
        
        V(chopstick[i]);
        V(chopstick[(i+1)%5]);
    }
}
```

> [!note] 方案2的原理
> 由于至少有一个哲学家与相邻哲学家的拿筷子顺序不同，不会出现所有人同时拿一根筷子的情况，从而避免死锁。

### 5.3 读者-写者问题

#### 问题描述

多个进程共享一个数据区，读者只读数据，写者可以读写数据。

#### 约束条件

1. **读者之间不互斥**：多个读者可以同时读
2. **写者之间互斥**：多个写者不能同时写
3. **读者和写者互斥**：读和写不能同时进行

#### 信号量设置

```c
semaphore rw = 1;        // 互斥信号量，用于读者和写者、写者和写者互斥
int count = 0;           // 记录当前读者数量
semaphore mutex = 1;     // 互斥信号量，保护count变量
```

#### 读者优先代码

```c
// 读者
void Reader() {
    while (true) {
        P(mutex);            // 保护count
        if (count == 0) {
            P(rw);           // 第一个读者申请读权限
        }
        count++;             // 读者数加1
        V(mutex);
        
        /* 读数据 */
        
        P(mutex);            // 保护count
        count--;             // 读者数减1
        if (count == 0) {
            V(rw);           // 最后一个读者释放读权限
        }
        V(mutex);
    }
}

// 写者
void Writer() {
    while (true) {
        P(rw);               // 申请写权限
        
        /* 写数据 */
        
        V(rw);               // 释放写权限
    }
}
```

> [!warning] 读者优先的问题
> 如果有读者持续到来，写者可能永远等待（饥饿）。

#### 写者优先代码

```c
semaphore rw = 1;
int count = 0;
semaphore mutex = 1;
semaphore w = 1;         // 新增：用于实现写者优先

// 读者
void Reader() {
    while (true) {
        P(w);                // 检查是否有写者等待
        P(mutex);
        if (count == 0) {
            P(rw);
        }
        count++;
        V(mutex);
        V(w);                // 允许其他读者进入
        
        /* 读数据 */
        
        P(mutex);
        count--;
        if (count == 0) {
            V(rw);
        }
        V(mutex);
    }
}

// 写者
void Writer() {
    while (true) {
        P(w);                // 申请写权限，阻止新读者进入
        P(rw);               // 申请读写权限
        
        /* 写数据 */
        
        V(rw);
        V(w);                // 释放，允许读者进入
    }
}
```

#### 读者-写者问题总结

| 版本 | 特点 | 问题 |
|:-----|:-----|:-----|
| **读者优先** | 读者可以同时读，新读者可以插队 | 写者可能饥饿 |
| **写者优先** | 写者到达后阻止新读者进入 | 读者可能饥饿 |
| **公平版本** | 读者和写者按到达顺序排队 | 实现复杂 |
