# 信号量机制

## 四、信号量机制

> [!important] 重中之重
> 信号量机制是408考试最核心的内容之一，必须熟练掌握整型信号量、记录型信号量以及PV操作。

### 4.1 信号量的概念

**信号量（Semaphore）** 是一个整型变量，用于表示系统中某种资源的数量。信号量只能通过两个原子操作来访问：**P操作**（等待）和**V操作**（信号）。

> [!note] P、V名称来源
> P和V来自荷兰语：
> - **P**roberen（测试/尝试）
> - **V**erhogen（增加）

### 4.2 整型信号量

#### 定义

```c
int S;  // 信号量，表示资源数量
```

#### P、V操作

```c
// P操作（Wait/Down）：申请资源
void P(int &S) {
    while (S <= 0);     // 若资源不足，则忙等
    S--;                // 占用一个资源
}

// V操作（Signal/Up）：释放资源
void V(int &S) {
    S++;                // 释放一个资源
}
```

#### 特点

| 优点 | 缺点 |
|:-----|:-----|
| 实现简单 | 不满足"让权等待"（使用while忙等） |
| | 可能导致饥饿 |

### 4.3 记录型信号量

> [!success] 记录型信号量是考试重点

#### 定义

```c
typedef struct {
    int value;              // 资源数量
    struct PCB *queue;      // 等待队列（阻塞队列）
} semaphore;
```

#### P、V操作

```c
// P操作：申请资源
void P(semaphore &S) {
    S.value--;              // 占用一个资源
    if (S.value < 0) {      // 若资源不足
        block(S.queue);     // 将进程阻塞，插入等待队列
    }
}

// V操作：释放资源
void V(semaphore &S) {
    S.value++;              // 释放一个资源
    if (S.value <= 0) {     // 若有进程在等待
        wakeup(S.queue);    // 唤醒等待队列中的一个进程
    }
}
```

> [!important] 关键理解
> - `S.value > 0`：表示可用资源数量
> - `S.value = 0`：表示资源刚好用完，没有进程等待
> - `S.value < 0`：表示有`|S.value|`个进程在等待该资源

#### 特点

| 优点 | 说明 |
|:-----|:-----|
| 满足"让权等待" | 资源不足时进程阻塞，不占用CPU |
| 避免饥饿 | 等待队列按FIFO管理 |

### 4.4 信号量的物理意义

| 信号量值 | 含义 |
|:---------|:-----|
| **S.value > 0** | 可用资源的数量 |
| **S.value = 0** | 无可用资源，无等待进程 |
| **S.value < 0** | 有 \|S.value\| 个进程在等待 |

```
初始时：S.value = 3（有3个资源）

P1执行P(S): S.value = 2
P2执行P(S): S.value = 1
P3执行P(S): S.value = 0
P4执行P(S): S.value = -1, P4阻塞
P5执行P(S): S.value = -2, P5阻塞

P2执行V(S): S.value = -1, 唤醒P4
P1执行V(S): S.value = 0, 唤醒P5
```

#### 反推题型：给S值推断系统状态（选择题高频）

**恒等式**：每执行一次P，S减1；每执行一次V，S加1，故：

$$\#P - \#V = S_0 - S_{\text{当前}}$$

**判读公式**（初值为 $k$ 的资源信号量）：

| 当前S值 | 含义 |
|:-------|:-----|
| **S ≥ 0** | 剩余可用资源数 = S；**无**等待进程 |
| **S < 0** | 资源已全部占用；**等待进程数 = \|S\|** |

**临界区内进程数** = $\#P - \#V - |S|$（S<0时），即"拿到资源尚未V的进程数"。

> [!example] 例题
> 某信号量初值为5，经过若干次PV操作后值为−1，能得出什么结论？
>
> **解**：
> 1. $\#P - \#V = 5 - (-1) = 6$，即P比V多6次 ✓
> 2. 等待进程数 = $|-1|$ = **1个** ✓
> 3. 临界区内进程数 = 6 − 1 = **5个**（资源全部占满，临界区满员） ✓
>
> 三条推断均成立。

> [!warning] 推断成立的三个前提（选择题陷阱）
> 1. **S是资源/互斥信号量**：P、V成对包裹临界区；若P、V用于同步（初值0），"临界区"说法不成立
> 2. **所有PV都针对这一个信号量**：没有别的场景混入
> 3. **没有进程在临界区内未V就终止**：否则资源泄漏，临界区计数失真

### 4.5 信号量的应用

#### 互斥信号量

用于实现进程互斥访问临界资源。

```c
semaphore mutex = 1;     // 互斥信号量，初值为1

void Pi() {
    P(mutex);            // 申请进入临界区
    /* 临界区 */
    V(mutex);            // 退出临界区
}
```

> [!tip] 互斥信号量的特点
> - 初值为1
> - P、V操作成对出现，包裹临界区
> - 同一进程中，P在前，V在后

#### 同步信号量

用于实现进程间的同步关系。

```c
semaphore S = 0;         // 同步信号量，初值通常为0

// 进程P1（前驱）
void P1() {
    /* 执行某些操作 */
    V(S);                // 通知P2可以执行
}

// 进程P2（后继）
void P2() {
    P(S);                // 等待P1的通知
    /* 执行后续操作 */
}
```

> [!tip] 同步信号量的特点
> - 初值根据具体同步需求确定
> - P、V操作分别在不同进程中
> - V操作在前驱进程中，P操作在后继进程中
> - 信号量**无所有权**：任何进程都可执行V（这正是与互斥锁的本质区别，见下节）

#### 互斥锁（mutex）

互斥锁本质是**二值信号量 + 所有权语义**：加锁时记录拥有者，**只有加锁的进程/线程才能解锁**。

**适用范围**：既可用于多线程互斥，也可用于多进程互斥（锁置于共享内存即可）。

```c
mutex lock;                  // 互斥锁，初态为"空闲"

void Pi() {
    lock(&lock);             // 加锁：若已被占用则等待（通常阻塞让权）
    /* 临界区：访问临界资源 */
    unlock(&lock);           // 解锁：必须由加锁者执行，否则非法（所有权检查）
}
```

**与信号量的对比**：

| 对比项 | 互斥锁（mutex） | 信号量 |
|:-------|:---------------|:-------|
| **所有权** | **有**——谁加锁谁解锁 | **无**——任何进程都可V |
| 加/解锁位置 | 必须在同一执行实体 | 可在不同进程（同步用法） |
| 取值 | 只有0/1（二值） | 可为任意非负初值 |
| 用途 | 专用于**互斥** | 互斥 + **同步** |
| 典型实现 | 阻塞型（抢锁失败让权等待）；自旋锁则忙等 | 阻塞式信号量 |
| 可重入 | 可扩展为可重入锁（同一线程重复加锁） | 不支持（P两次直接阻塞） |

> [!warning] 选择题陷阱（判断正误）
> - "互斥锁可用于多线程和多进程，但只有加锁者可以解锁" → **正确**（408原题考点）
> - ❌ "互斥锁只能用于线程间"（共享内存场景下可用于进程间）
> - ❌ "任何线程都可以释放互斥锁"（仅加锁者）

#### 前驱图与前驱关系（408大题固定考点）

**前驱关系**：并发执行的进程/语句之间存在"A必须在B之前完成"的先后约束，用**前驱图**（有向无环图）表示：节点=进程/语句，边=前驱约束。

并发进程的执行顺序本来不确定（异步性），而前驱关系要求严格顺序——必须让后继者在前驱者没做完时**阻塞等待**、做完时被**唤醒**，这正是P（等待）、V（通知）的原生语义。

**实现规则**：每条前驱边设一个同步信号量，**初值为0**；前驱节点执行完后V，后继节点执行前P。

> [!example] 例题：为前驱图编写同步程序
> 前驱关系：S1→S2、S1→S3、S2→S4、S3→S4
>
> ```
> S1 ──→ S2 ──┐
>  └──→ S3 ──┴─→ S4
> ```
>
> **解**：4条边设4个信号量，初值全为0：
>
> ```c
> semaphore a = b = c = d = 0;
>
> S1: /* 执行S1 */;  V(a); V(b);     // 完成后通知S2、S3
> S2: P(a); /* 执行S2 */;  V(c);     // 等S1完成，做完通知S4
> S3: P(b); /* 执行S3 */;  V(d);
> S4: P(c); P(d); /* 执行S4 */;      // 必须等S2、S3都完成
> ```

> [!warning] 易错点
> 1. **初值必须为0**：若初值为1，后继的P直接通过，可能跑在前驱前面，约束失效
> 2. **一个前驱多个后继（扇出）**：前驱节点要V**每一个**对应信号量各一次（如S1的V(a)、V(b)）
> 3. **多个前驱一个后继（汇聚）**：后继要把每个前驱的信号量都P一遍（如S4的P(c)、P(d)）
> 4. **前驱图必须无环**：有环意味着循环依赖，必然死锁
