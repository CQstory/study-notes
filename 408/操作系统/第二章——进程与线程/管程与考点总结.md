# 管程与考点总结

## 六、管程

### 6.1 管程的概念

**管程（Monitor）** 是一种高级同步机制，它将共享变量和对共享变量的操作封装在一起，形成一个独立的模块。

> [!info] 管程的提出
> 管程由Hoare和Brinch Hansen于1970年代提出，目的是简化同步编程，避免程序员直接使用信号量时容易出错的问题。

### 6.2 管程的组成

```
┌─────────────────────────────────────┐
│           管程（Monitor）            │
├─────────────────────────────────────┤
│  共享变量声明                        │
│  条件变量声明                        │
├─────────────────────────────────────┤
│  初始化代码                          │
├─────────────────────────────────────┤
│  过程1：对共享变量的操作              │
│  过程2：对共享变量的操作              │
│  ...                                │
└─────────────────────────────────────┘
```

#### 各组成部分详解（必背）

| 组成部分 | 作用 | 要点 |
|:---------|:-----|:-----|
| **管程名** | 标识管程 | 进程通过"管程名.过程名"调用 |
| **共享变量声明** | 管程内的局部共享数据（临界资源） | 只能被管程内的过程访问，**外部不可见** |
| **条件变量声明** | 同步机制，每个条件变量对应一个等待队列 | 其上只有 wait / signal 两种操作 |
| **初始化代码** | 初始化共享变量 | 管程创建时**仅执行一次** |
| **一组过程（操作）** | 对共享变量的全部操作 | 进程进入管程的**唯一入口**，过程间自动互斥 |

#### 管程的重要性质（408 考点）

> [!important] 四条性质逐句背
> 1. **互斥自动实现**：任何时刻最多只有一个进程在管程内活动，互斥由编译器/系统自动保证，程序员无需手写互斥逻辑（这是与信号量最大的区别）
> 2. **封装性**：共享变量是管程私有，外部进程不能直接读写，只能通过调用管程的过程间接访问
> 3. **入口唯一**：进程只能通过管程提供的过程进入管程，无其他途径
> 4. **条件变量的语义**：`wait()` 阻塞当前进程并**释放管程入口**，进入该条件变量的等待队列；`signal()` 唤醒等待队列中的一个进程；**无等待者时 signal 什么也不做**（不像信号量V会累计）
> 5. （Hoare语义）被 signal 唤醒的进程需等发出 signal 的进程离开管程后才能继续执行，发出者进入紧急队列等待。
> 6. 每个条件变量都有独立的等待队列，等待条件相同的进程排在一起。
> 7. 等待条件建议用 **while 循环**而非 if 判断（被唤醒后需重新检查条件）。
> 8. 管程内部不需要也不允许再出现互斥操作（互斥已自动完成）。
> 9. 管程内**不允许阻塞式等待外部事件**（如I/O），否则会独占管程——临界区尽量短的规则同样适用。
> 10. 死锁预防：若多个过程互相 wait 且无人 signal，仍会死锁，设计上要保证每个 wait 都有对应的 signal 来源。

#### 具体例子：银行账户管程（带组成标注）

```pascal
monitor Account {                    // ① 管程名：外部通过 Account.deposit() 调用
    var balance: integer;            // ② 共享变量声明：账户余额（临界资源，外部不可直接访问）
    condition hasMoney;              // ③ 条件变量声明："余额充足"条件，对应一个等待队列
    { balance := 0; }                // ④ 初始化代码：管程创建时执行一次，余额清零
    procedure deposit(x)             // ⑤ 过程（唯一入口）：存款与取款互斥自动保证，无需手写锁！
    begin
        balance := balance + x;      //   临界资源操作：修改余额，无需担心并发冲突（管程已互斥）
        hasMoney.signal();           //   唤醒因余额不足而等待的取款进程（无等待者则空操作）
    end
    procedure withdraw(x)
    begin
        while balance < x do         //   while 重检查：余额不足则等待（被唤醒后还需再验）
            hasMoney.wait();         //   阻塞自己并释放管程，进入 hasMoney 等待队列，让出入口给其他进程（如存款者）
        balance := balance - x;      //   到这里余额必然充足：wait 已保证条件成立，且管程互斥保证中途无人改值，故无需再检查竞争（与信号量方案的关键区别）
    end                              //   过程结束：自动离开管程，下一个等待进入的进程方可进入（互斥由系统保证）
}
```

**外部进程的使用方式**：

```pascal
process 存款者:  Account.deposit(100);    // 只能通过过程访问，无法直接读写 balance（封装性）
process 取款者:  Account.withdraw(50);    // 余额不足时自动在 hasMoney 上等待，存款到账后被唤醒完成取款（同步自动完成）
```

**与信号量方案的对照**（帮助理解）：

| 信号量方案 | 管程中的对应物 | 区别 |
|:-----------|:---------------|:-----|
| 临界资源（共享变量） | 管程内的共享变量 | 管程将其私有化，外部不可直接访问 |
| 临界区代码 | 管程的过程 | 管程自动保证互斥，无需手写 P/V |
| P/V 操作 | wait / signal | wait=阻塞并释放管程；signal=唤醒，无计数功能，无等待者时不累计 |
| 程序员保证互斥与同步 | 编译器/系统保证 | 管程更安全，不易因 P/V 顺序错误导致死锁 |

### 6.3 管程的特点

| 特点 | 说明 |
|:-----|:-----|
| **封装性** | 共享变量只能被管程内的过程访问 |
| **互斥性** | 任何时候只有一个进程在管程中执行 |
| **同步机制** | 通过条件变量实现进程同步 |

### 6.4 条件变量

**条件变量（Condition Variable）** 是管程内用于进程同步的特殊变量。

#### 条件变量的操作

| 操作 | 说明 |
|:-----|:-----|
| **wait()** | 阻塞当前进程，将其插入该条件变量的等待队列 |
| **signal()** | 唤醒该条件变量等待队列中的一个进程 |

```pascal
// 管程中的条件变量使用示例
monitor ProducerConsumer {
    item buffer[N];
    int in = 0, out = 0, count = 0;
    condition notFull, notEmpty;
    
    procedure put(item x) {
        if (count == N) notFull.wait();   // 缓冲区满，等待
        buffer[in] = x;
        in = (in + 1) % N;
        count++;
        notEmpty.signal();                 // 通知消费者
    }
    
    procedure get(item &x) {
        if (count == 0) notEmpty.wait();  // 缓冲区空，等待
        x = buffer[out];
        out = (out + 1) % N;
        count--;
        notFull.signal();                  // 通知生产者
    }
}
```

> [!note] 条件变量 vs 信号量
> - **信号量**：有计数功能，V操作会累加信号量值
> - **条件变量**：没有计数功能，signal()如果没有等待进程则信号丢失

### 6.5 管程与信号量的比较

| 特性 | 信号量 | 管程 |
|:-----|:-------|:-----|
| **编程复杂度** | 复杂（需要程序员自己保证正确性） | 简单（同步由编译器实现） |
| **安全性** | 容易出错（P/V顺序错误导致死锁） | 更安全 |
| **互斥实现** | 程序员实现 | 自动实现 |
| **语言支持** | 任何语言 | 需要语言支持（如Java的synchronized） |

## 七、考点总结

> [!success] 核心考点清单

### 必考点

1. **同步四准则**：空闲让进、忙则等待、有限等待、让权等待
2. **软件实现方法**：单标志法、双标志先检查、双标志后检查、Peterson算法的原理和缺陷
3. **信号量机制**：整型信号量、记录型信号量、PV操作
4. **信号量物理意义**：value>0、=0、<0分别表示什么
5. **经典同步问题**：生产者-消费者、哲学家就餐、读者-写者

### 常考点

6. **硬件实现方法**：中断屏蔽、TS指令、Swap指令
7. **管程概念**：条件变量、wait/signal操作
8. **PV操作顺序**：同步P在前还是互斥P在前

### 易混淆点

| 概念A | 概念B | 区别 |
|:------|:------|:-----|
| 互斥信号量 | 同步信号量 | 初值不同，P/V位置不同 |
| P操作 | V操作 | 申请资源 vs 释放资源 |
| 整型信号量 | 记录型信号量 | 是否满足让权等待 |
| 读者优先 | 写者优先 | 谁可能饥饿 |
| 信号量 | 条件变量 | 是否有计数功能 |

### 真题回顾

> [!question] 2024年统考真题
> 在生产者-消费者问题中，若交换P(mutex)和P(empty)的顺序，会导致（）
> A. 生产者无法生产  B. 消费者无法消费  C. 可能死锁  D. 无影响
>
> **答案：C**
> **解析**：若先P(mutex)再P(empty)，当缓冲区满时，生产者持有mutex后阻塞在P(empty)，消费者无法进入临界区消费，形成死锁。

> [!question] 2023年统考真题
> 下列关于Peterson算法的叙述中，正确的是（）
> A. 满足空闲让进、忙则等待、有限等待、让权等待
> B. 不满足空闲让进
> C. 不满足让权等待
> D. 不满足忙则等待
>
> **答案：C**
> **解析**：Peterson算法满足前三个准则，但不满足让权等待（使用while忙等）。

> [!question] 2022年统考真题
> 使用记录型信号量实现互斥时，信号量的初值应设为（）
> A. -1  B. 0  C. 1  D. 任意值
>
> **答案：C**
> **解析**：互斥信号量初值为1，表示临界资源可用。P操作后变为0，表示资源被占用。
