# 同步与互斥

> [!abstract] 知识定位
> 本节是操作系统进程管理中最核心的内容之一，涵盖临界资源与临界区、同步机制准则、软件和硬件实现方法、信号量机制以及经典同步问题。在408统考中，本节内容通常以2-3道选择题或综合应用题的形式出现，重点考查信号量的应用和经典同步问题的解法。

## 一、临界资源与临界区

### 1.1 临界资源

**临界资源** 是指一次仅允许一个进程使用的资源。如打印机、磁带机、共享变量等。

> [!warning] 临界资源的特点
> - 互斥使用：同一时间只能有一个进程使用
> - 不可抢占：使用完毕后主动释放

### 1.2 临界区

**临界区（Critical Section）** 是指访问临界资源的那段代码。

```
进程代码结构：
┌─────────────────────────────────────┐
│  entry section    ← 进入区（申请进入临界区）│
├─────────────────────────────────────┤
│  critical section ← 临界区（访问临界资源）  │
├─────────────────────────────────────┤
│  exit section     ← 退出区（释放临界区）    │
├─────────────────────────────────────┤
│  remainder section ← 剩余区（其他代码）     │
└─────────────────────────────────────┘
```

### 1.3 同步机制应遵循的准则

> [!important] 四准则（必背）

| 准则 | 说明 | 违反后果 |
|:-----|:-----|:---------|
| **空闲让进** | 临界区空闲时，允许请求进入的进程立即进入 | 资源浪费 |
| **忙则等待** | 临界区有进程时，其他进程必须等待 | 数据不一致 |
| **有限等待** | 等待进入临界区的进程应在有限时间内进入 | 饥饿（Starvation） |
| **让权等待** | 等待时应释放CPU（阻塞），而不是忙等 | CPU资源浪费 |

> [!note] 准则关系
> - 空闲让进和忙则等待是**基本要求**
> - 有限等待是**公平性要求**
> - 让权等待是**性能要求**

## 二、软件实现方法

> [!important] 核心考点
> 各种软件实现方法的原理、代码和是否满足四准则是408考试的高频考点。

### 2.1 单标志法

#### 算法思想

用一个整型变量 `turn` 表示允许进入临界区的进程号。

#### 代码实现

```c
// 共享变量
int turn = 0;  // turn=0表示允许P0进入，turn=1表示允许P1进入

// 进程P0
void P0() {
    while (turn != 0);   // 进入区：若turn≠0，则忙等
    /* 临界区 */          // 临界区
    turn = 1;            // 退出区：允许P1进入
    /* 剩余区 */          // 剩余区
}

// 进程P1
void P1() {
    while (turn != 1);   // 进入区：若turn≠1，则忙等
    /* 临界区 */          // 临界区
    turn = 0;            // 退出区：允许P0进入
    /* 剩余区 */          // 剩余区
}
```

#### 准则检查

| 准则 | 是否满足 | 说明 |
|:-----|:--------:|:-----|
| 空闲让进 | ❌ 不满足 | 如果turn=0但P0不想进入，P1也无法进入 |
| 忙则等待 | ✅ 满足 | |
| 有限等待 | ✅ 满足 | |
| 让权等待 | ❌ 不满足 | 使用while忙等，不释放CPU |

> [!danger] 单标志法的问题
> **强制轮流进入**，违背了"空闲让进"原则。两个进程必须交替进入临界区，如果一方不想进入，另一方也无法进入。

### 2.2 双标志先检查法

#### 算法思想

每个进程设置一个标志位 `flag[i]`，表示进程i是否想进入临界区。进入临界区前先检查对方是否想进入。

#### 代码实现

```c
// 共享变量
bool flag[2] = {false, false};  // flag[i]=true表示进程Pi想进入临界区

// 进程P0
void P0() {
    while (flag[1]);     // 先检查：若P1想进入，则等待
    flag[0] = true;      // 后设置：P0想进入
    /* 临界区 */
    flag[0] = false;     // 退出：P0不想进入了
    /* 剩余区 */
}

// 进程P1
void P1() {
    while (flag[0]);     // 先检查：若P0想进入，则等待
    flag[1] = true;      // 后设置：P1想进入
    /* 临界区 */
    flag[1] = false;     // 退出：P1不想进入了
    /* 剩余区 */
}
```

#### 准则检查

| 准则 | 是否满足 | 说明 |
|:-----|:--------:|:-----|
| 空闲让进 | ✅ 满足 | |
| 忙则等待 | ❌ 不满足 | 可能同时进入临界区（见下方分析） |
| 有限等待 | - | |
| 让权等待 | ❌ 不满足 | 使用while忙等 |

> [!danger] 双标志先检查法的问题
> **可能同时进入临界区**。考虑以下执行序列：
> 1. P0执行 `while(flag[1])`，flag[1]=false，跳出循环
> 2. **切换到P1**，P1执行 `while(flag[0])`，flag[0]=false，跳出循环
> 3. P1执行 `flag[1]=true`，进入临界区
> 4. **切换到P0**，P0执行 `flag[0]=true`，进入临界区
> 
> 此时P0和P1同时进入临界区，违反了"忙则等待"原则。

### 2.3 双标志后检查法

#### 算法思想

先设置自己的标志，再检查对方的标志。

#### 代码实现

```c
// 共享变量
bool flag[2] = {false, false};

// 进程P0
void P0() {
    flag[0] = true;      // 先设置：P0想进入
    while (flag[1]);     // 后检查：若P1想进入，则等待
    /* 临界区 */
    flag[0] = false;
    /* 剩余区 */
}

// 进程P1
void P1() {
    flag[1] = true;      // 先设置：P1想进入
    while (flag[0]);     // 后检查：若P0想进入，则等待
    /* 临界区 */
    flag[1] = false;
    /* 剩余区 */
}
```

#### 准则检查

| 准则 | 是否满足 | 说明 |
|:-----|:--------:|:-----|
| 空闲让进 | ✅ 满足 | |
| 忙则等待 | ✅ 满足 | |
| 有限等待 | ❌ 不满足 | 可能双方都无限等待（死锁） |
| 让权等待 | ❌ 不满足 | 使用while忙等 |

> [!danger] 双标志后检查法的问题
> **可能双方都无法进入临界区（死锁/饥饿）**。考虑以下执行序列：
> 1. P0执行 `flag[0]=true`
> 2. **切换到P1**，P1执行 `flag[1]=true`
> 3. P1执行 `while(flag[0])`，flag[0]=true，忙等
> 4. **切换到P0**，P0执行 `while(flag[1])`，flag[1]=true，忙等
>
> 双方都在等待对方，形成死锁，违反了"有限等待"原则。

### 2.4 Peterson算法

#### 算法思想

结合单标志法和双标志法的思想，既设置标志又设置轮流变量。

#### 代码实现

```c
// 共享变量
bool flag[2] = {false, false};
int turn = 0;

// 进程P0
void P0() {
    flag[0] = true;          // 表示P0想进入临界区
    turn = 1;                // 表示轮到P1（礼让）
    while (flag[1] && turn == 1);  // 若P1想进入且轮到P1，则等待
    /* 临界区 */
    flag[0] = false;         // P0退出临界区
    /* 剩余区 */
}

// 进程P1
void P1() {
    flag[1] = true;          // 表示P1想进入临界区
    turn = 0;                // 表示轮到P0（礼让）
    while (flag[0] && turn == 0);  // 若P0想进入且轮到P0，则等待
    /* 临界区 */
    flag[1] = false;         // P1退出临界区
    /* 剩余区 */
}
```

#### 准则检查

| 准则 | 是否满足 | 说明 |
|:-----|:--------:|:-----|
| 空闲让进 | ✅ 满足 | |
| 忙则等待 | ✅ 满足 | |
| 有限等待 | ✅ 满足 | |
| 让权等待 | ❌ 不满足 | 使用while忙等 |

> [!success] Peterson算法的正确性
> Peterson算法满足前三个准则，但不满足"让权等待"（因为使用忙等）。
>
> **互斥性证明**：假设P0和P1同时进入临界区。
> - P0进入意味着：`flag[1]==false || turn==0`
> - P1进入意味着：`flag[0]==false || turn==1`
> - 若P0先执行`turn=1`，后P1执行`turn=0`，则P0看到turn=0，P1看到turn=1，不可能同时满足。

### 2.5 软件方法总结

| 方法 | 空闲让进 | 忙则等待 | 有限等待 | 让权等待 |
|:-----|:--------:|:--------:|:--------:|:--------:|
| **单标志法** | ❌ | ✅ | ✅ | ❌ |
| **双标志先检查** | ✅ | ❌ | - | ❌ |
| **双标志后检查** | ✅ | ✅ | ❌ | ❌ |
| **Peterson算法** | ✅ | ✅ | ✅ | ❌ |

## 三、硬件实现方法

### 3.1 中断屏蔽

#### 原理

通过**关中断**来禁止CPU响应中断，从而保证临界区代码不被打断。

```c
// 进入临界区前关中断
cli();           // 关中断（Clear Interrupt）
/* 临界区 */
sti();           // 开中断（Set Interrupt）
/* 剩余区 */
```

#### 特点

| 优点 | 缺点 |
|:-----|:-----|
| 简单高效 | 关中断时间过长影响系统性能和实时性 |
| | 不适用于多CPU系统（只能屏蔽当前CPU的中断） |
| | 用户程序不能随意使用（特权指令） |

> [!warning] 限制
> 中断屏蔽只适用于单CPU系统，且关中断时间应尽量短。

### 3.2 测试并设置指令（TS指令/TestAndSet）

#### 指令定义

```c
// 原子操作：测试并设置
bool TestAndSet(bool *lock) {
    bool old = *lock;    // 保存旧值
    *lock = true;        // 设置锁为true
    return old;          // 返回旧值
}
```

#### 实现互斥

```c
// 共享变量
bool lock = false;       // 锁，false表示未上锁

// 进程Pi
void Pi() {
    while (TestAndSet(&lock));  // 若lock为true，则忙等
    /* 临界区 */
    lock = false;               // 解锁
    /* 剩余区 */
}
```

#### 特点

| 优点 | 缺点 |
|:-----|:-----|
| 适用于多CPU系统 | 不满足"让权等待"（忙等） |
| 实现简单 | 可能出现饥饿 |

### 3.3 交换指令（Swap/Exchange）

#### 指令定义

```c
// 原子操作：交换两个变量的值
void Swap(bool *a, bool *b) {
    bool temp = *a;
    *a = *b;
    *b = temp;
}
```

#### 实现互斥

```c
// 共享变量
bool lock = false;

// 进程Pi
void Pi() {
    bool key = true;
    while (key == true) {
        Swap(&lock, &key);   // 交换lock和key的值
    }
    /* 临界区 */
    lock = false;            // 解锁
    /* 剩余区 */
}
```

#### 特点

与TS指令类似，同样不满足"让权等待"。

### 3.4 硬件方法总结

| 方法 | 适用场景 | 满足准则 | 主要缺点 |
|:-----|:---------|:---------|:---------|
| **中断屏蔽** | 单CPU系统 | 忙则等待 | 影响性能，不适用多CPU |
| **TS指令** | 多CPU系统 | 前三条 | 不满足让权等待 |
| **Swap指令** | 多CPU系统 | 前三条 | 不满足让权等待 |

## 四、信号量机制

> [!important] 重中之重
> 信号量机制是408考试最核心的内容之一，必须熟练掌握整型信号量、记录型信号量以及PV操作。

### 4.1 信号量的概念

**信号量（Semaphore）** 是一个整型变量，用于表示系统中某种资源的数量。信号量只能通过两个原子操作来访问：**P操作**（等待）和**V操作**（信号）。

> [!note] P、V名称来源
> P和V来自荷兰语：
> - **P**roberen（测试/尝试）
> - **V**erhogen（增加）

### 4.2 整型信号量

#### 定义

```c
int S;  // 信号量，表示资源数量
```

#### P、V操作

```c
// P操作（Wait/Down）：申请资源
void P(int &S) {
    while (S <= 0);     // 若资源不足，则忙等
    S--;                // 占用一个资源
}

// V操作（Signal/Up）：释放资源
void V(int &S) {
    S++;                // 释放一个资源
}
```

#### 特点

| 优点 | 缺点 |
|:-----|:-----|
| 实现简单 | 不满足"让权等待"（使用while忙等） |
| | 可能导致饥饿 |

### 4.3 记录型信号量

> [!success] 记录型信号量是考试重点

#### 定义

```c
typedef struct {
    int value;              // 资源数量
    struct PCB *queue;      // 等待队列（阻塞队列）
} semaphore;
```

#### P、V操作

```c
// P操作：申请资源
void P(semaphore &S) {
    S.value--;              // 占用一个资源
    if (S.value < 0) {      // 若资源不足
        block(S.queue);     // 将进程阻塞，插入等待队列
    }
}

// V操作：释放资源
void V(semaphore &S) {
    S.value++;              // 释放一个资源
    if (S.value <= 0) {     // 若有进程在等待
        wakeup(S.queue);    // 唤醒等待队列中的一个进程
    }
}
```

> [!important] 关键理解
> - `S.value > 0`：表示可用资源数量
> - `S.value = 0`：表示资源刚好用完，没有进程等待
> - `S.value < 0`：表示有`|S.value|`个进程在等待该资源

#### 特点

| 优点 | 说明 |
|:-----|:-----|
| 满足"让权等待" | 资源不足时进程阻塞，不占用CPU |
| 避免饥饿 | 等待队列按FIFO管理 |

### 4.4 信号量的物理意义

| 信号量值 | 含义 |
|:---------|:-----|
| **S.value > 0** | 可用资源的数量 |
| **S.value = 0** | 无可用资源，无等待进程 |
| **S.value < 0** | 有 \|S.value\| 个进程在等待 |

```
初始时：S.value = 3（有3个资源）

P1执行P(S): S.value = 2
P2执行P(S): S.value = 1
P3执行P(S): S.value = 0
P4执行P(S): S.value = -1, P4阻塞
P5执行P(S): S.value = -2, P5阻塞

P2执行V(S): S.value = -1, 唤醒P4
P1执行V(S): S.value = 0, 唤醒P5
```

### 4.5 信号量的应用

#### 互斥信号量

用于实现进程互斥访问临界资源。

```c
semaphore mutex = 1;     // 互斥信号量，初值为1

void Pi() {
    P(mutex);            // 申请进入临界区
    /* 临界区 */
    V(mutex);            // 退出临界区
}
```

> [!tip] 互斥信号量的特点
> - 初值为1
> - P、V操作成对出现，包裹临界区
> - 同一进程中，P在前，V在后

#### 同步信号量

用于实现进程间的同步关系。

```c
semaphore S = 0;         // 同步信号量，初值通常为0

// 进程P1（前驱）
void P1() {
    /* 执行某些操作 */
    V(S);                // 通知P2可以执行
}

// 进程P2（后继）
void P2() {
    P(S);                // 等待P1的通知
    /* 执行后续操作 */
}
```

> [!tip] 同步信号量的特点
> - 初值根据具体同步需求确定
> - P、V操作分别在不同进程中
> - V操作在前驱进程中，P操作在后继进程中

## 五、经典同步问题

> [!important] 核心考点
> 经典同步问题是408综合应用题的常考内容，必须熟练掌握。

### 5.1 生产者-消费者问题

#### 问题描述

生产者生产产品放入缓冲区，消费者从缓冲区取产品消费。缓冲区容量有限。

#### 约束条件

1. **互斥**：生产者和消费者不能同时访问缓冲区
2. **同步**：缓冲区满时生产者必须等待；缓冲区空时消费者必须等待

#### 信号量设置

```c
semaphore mutex = 1;     // 互斥信号量，保证对缓冲区的互斥访问
semaphore empty = n;     // 同步信号量，表示空缓冲区数量（初值=缓冲区容量）
semaphore full = 0;      // 同步信号量，表示满缓冲区数量（初值=0）
```

#### 完整代码

```c
// 生产者
void Producer() {
    while (true) {
        /* 生产一个产品 */
        
        P(empty);        // 申请一个空缓冲区（若无则阻塞）
        P(mutex);        // 申请进入临界区
        
        /* 将产品放入缓冲区 */
        
        V(mutex);        // 退出临界区
        V(full);         // 满缓冲区数加1，可能唤醒消费者
    }
}

// 消费者
void Consumer() {
    while (true) {
        P(full);         // 申请一个满缓冲区（若无则阻塞）
        P(mutex);        // 申请进入临界区
        
        /* 从缓冲区取出产品 */
        
        V(mutex);        // 退出临界区
        V(empty);        // 空缓冲区数加1，可能唤醒生产者
        
        /* 消费产品 */
    }
}
```

> [!warning] 注意P操作的顺序
> **必须先执行同步信号量的P操作，再执行互斥信号量的P操作**。如果顺序相反：
> ```c
> P(mutex);    // 先申请互斥
> P(empty);    // 再申请空缓冲区
> ```
> 若缓冲区已满，生产者会在持有mutex的情况下阻塞，导致消费者无法进入临界区取产品，形成**死锁**。

#### 多生产者多消费者变体

> [!example] 2021年408真题变体
> 有多个生产者和多个消费者，缓冲区大小为n，每个生产者每次生产1个产品，每个消费者每次消费1个产品。
>
> **分析**：上述代码已经适用于多生产者多消费者情况，因为mutex保证了互斥，empty和full保证了同步。

### 5.2 哲学家就餐问题

#### 问题描述

5个哲学家围坐在圆桌旁，每人左右各有一根筷子。哲学家只有同时拿到左右两根筷子才能吃饭。

#### 约束条件

1. **互斥**：筷子是临界资源，一次只能被一个哲学家使用
2. **避免死锁**：防止所有哲学家同时拿起左边筷子，导致死锁

#### 信号量设置

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};  // 5根筷子，每根初值为1
```

#### 基本解法（可能导致死锁）

```c
// 哲学家i（i = 0, 1, 2, 3, 4）
void Philosopher(int i) {
    while (true) {
        /* 思考 */
        
        P(chopstick[i]);           // 拿起左边筷子
        P(chopstick[(i+1)%5]);     // 拿起右边筷子
        
        /* 吃饭 */
        
        V(chopstick[(i+1)%5]);     // 放下右边筷子
        V(chopstick[i]);           // 放下左边筷子
    }
}
```

> [!danger] 死锁风险
> 若5个哲学家同时拿起左边筷子，则每人都在等待右边筷子，形成死锁。

#### 解决方案

| 方案 | 思路 | 代码 |
|:-----|:-----|:-----|
| **方案1：最多允许4个哲学家同时就餐** | 限制同时就餐人数 | 增加信号量 `room = 4`，就餐前P(room)，就餐后V(room) |
| **方案2：奇偶号哲学家不同顺序拿筷子** | 破坏循环等待 | 奇数号先左后右，偶数号先右后左 |
| **方案3：同时拿两根筷子（AND型信号量）** | 一次性申请所有资源 | `Swait(chopstick[i], chopstick[(i+1)%5])` |

#### 方案1完整代码

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};
semaphore room = 4;      // 最多允许4个哲学家同时就餐

void Philosopher(int i) {
    while (true) {
        /* 思考 */
        
        P(room);                     // 申请进入餐厅
        P(chopstick[i]);             // 拿左边筷子
        P(chopstick[(i+1)%5]);       // 拿右边筷子
        
        /* 吃饭 */
        
        V(chopstick[(i+1)%5]);       // 放右边筷子
        V(chopstick[i]);             // 放左边筷子
        V(room);                     // 离开餐厅
    }
}
```

#### 方案2完整代码

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1};

void Philosopher(int i) {
    while (true) {
        /* 思考 */
        
        if (i % 2 == 0) {            // 偶数号哲学家
            P(chopstick[(i+1)%5]);   // 先拿右边
            P(chopstick[i]);         // 再拿左边
        } else {                      // 奇数号哲学家
            P(chopstick[i]);         // 先拿左边
            P(chopstick[(i+1)%5]);   // 再拿右边
        }
        
        /* 吃饭 */
        
        V(chopstick[i]);
        V(chopstick[(i+1)%5]);
    }
}
```

> [!note] 方案2的原理
> 由于至少有一个哲学家与相邻哲学家的拿筷子顺序不同，不会出现所有人同时拿一根筷子的情况，从而避免死锁。

### 5.3 读者-写者问题

#### 问题描述

多个进程共享一个数据区，读者只读数据，写者可以读写数据。

#### 约束条件

1. **读者之间不互斥**：多个读者可以同时读
2. **写者之间互斥**：多个写者不能同时写
3. **读者和写者互斥**：读和写不能同时进行

#### 信号量设置

```c
semaphore rw = 1;        // 互斥信号量，用于读者和写者、写者和写者互斥
int count = 0;           // 记录当前读者数量
semaphore mutex = 1;     // 互斥信号量，保护count变量
```

#### 读者优先代码

```c
// 读者
void Reader() {
    while (true) {
        P(mutex);            // 保护count
        if (count == 0) {
            P(rw);           // 第一个读者申请读权限
        }
        count++;             // 读者数加1
        V(mutex);
        
        /* 读数据 */
        
        P(mutex);            // 保护count
        count--;             // 读者数减1
        if (count == 0) {
            V(rw);           // 最后一个读者释放读权限
        }
        V(mutex);
    }
}

// 写者
void Writer() {
    while (true) {
        P(rw);               // 申请写权限
        
        /* 写数据 */
        
        V(rw);               // 释放写权限
    }
}
```

> [!warning] 读者优先的问题
> 如果有读者持续到来，写者可能永远等待（饥饿）。

#### 写者优先代码

```c
semaphore rw = 1;
int count = 0;
semaphore mutex = 1;
semaphore w = 1;         // 新增：用于实现写者优先

// 读者
void Reader() {
    while (true) {
        P(w);                // 检查是否有写者等待
        P(mutex);
        if (count == 0) {
            P(rw);
        }
        count++;
        V(mutex);
        V(w);                // 允许其他读者进入
        
        /* 读数据 */
        
        P(mutex);
        count--;
        if (count == 0) {
            V(rw);
        }
        V(mutex);
    }
}

// 写者
void Writer() {
    while (true) {
        P(w);                // 申请写权限，阻止新读者进入
        P(rw);               // 申请读写权限
        
        /* 写数据 */
        
        V(rw);
        V(w);                // 释放，允许读者进入
    }
}
```

#### 读者-写者问题总结

| 版本 | 特点 | 问题 |
|:-----|:-----|:-----|
| **读者优先** | 读者可以同时读，新读者可以插队 | 写者可能饥饿 |
| **写者优先** | 写者到达后阻止新读者进入 | 读者可能饥饿 |
| **公平版本** | 读者和写者按到达顺序排队 | 实现复杂 |

## 六、管程

### 6.1 管程的概念

**管程（Monitor）** 是一种高级同步机制，它将共享变量和对共享变量的操作封装在一起，形成一个独立的模块。

> [!info] 管程的提出
> 管程由Hoare和Brinch Hansen于1970年代提出，目的是简化同步编程，避免程序员直接使用信号量时容易出错的问题。

### 6.2 管程的组成

```
┌─────────────────────────────────────┐
│           管程（Monitor）            │
├─────────────────────────────────────┤
│  共享变量声明                        │
│  条件变量声明                        │
├─────────────────────────────────────┤
│  初始化代码                          │
├─────────────────────────────────────┤
│  过程1：对共享变量的操作              │
│  过程2：对共享变量的操作              │
│  ...                                │
└─────────────────────────────────────┘
```

### 6.3 管程的特点

| 特点 | 说明 |
|:-----|:-----|
| **封装性** | 共享变量只能被管程内的过程访问 |
| **互斥性** | 任何时候只有一个进程在管程中执行 |
| **同步机制** | 通过条件变量实现进程同步 |

### 6.4 条件变量

**条件变量（Condition Variable）** 是管程内用于进程同步的特殊变量。

#### 条件变量的操作

| 操作 | 说明 |
|:-----|:-----|
| **wait()** | 阻塞当前进程，将其插入该条件变量的等待队列 |
| **signal()** | 唤醒该条件变量等待队列中的一个进程 |

```pascal
// 管程中的条件变量使用示例
monitor ProducerConsumer {
    item buffer[N];
    int in = 0, out = 0, count = 0;
    condition notFull, notEmpty;
    
    procedure put(item x) {
        if (count == N) notFull.wait();   // 缓冲区满，等待
        buffer[in] = x;
        in = (in + 1) % N;
        count++;
        notEmpty.signal();                 // 通知消费者
    }
    
    procedure get(item &x) {
        if (count == 0) notEmpty.wait();  // 缓冲区空，等待
        x = buffer[out];
        out = (out + 1) % N;
        count--;
        notFull.signal();                  // 通知生产者
    }
}
```

> [!note] 条件变量 vs 信号量
> - **信号量**：有计数功能，V操作会累加信号量值
> - **条件变量**：没有计数功能，signal()如果没有等待进程则信号丢失

### 6.5 管程与信号量的比较

| 特性 | 信号量 | 管程 |
|:-----|:-------|:-----|
| **编程复杂度** | 复杂（需要程序员自己保证正确性） | 简单（同步由编译器实现） |
| **安全性** | 容易出错（P/V顺序错误导致死锁） | 更安全 |
| **互斥实现** | 程序员实现 | 自动实现 |
| **语言支持** | 任何语言 | 需要语言支持（如Java的synchronized） |

## 七、考点总结

> [!success] 核心考点清单

### 必考点

1. **同步四准则**：空闲让进、忙则等待、有限等待、让权等待
2. **软件实现方法**：单标志法、双标志先检查、双标志后检查、Peterson算法的原理和缺陷
3. **信号量机制**：整型信号量、记录型信号量、PV操作
4. **信号量物理意义**：value>0、=0、<0分别表示什么
5. **经典同步问题**：生产者-消费者、哲学家就餐、读者-写者

### 常考点

6. **硬件实现方法**：中断屏蔽、TS指令、Swap指令
7. **管程概念**：条件变量、wait/signal操作
8. **PV操作顺序**：同步P在前还是互斥P在前

### 易混淆点

| 概念A | 概念B | 区别 |
|:------|:------|:-----|
| 互斥信号量 | 同步信号量 | 初值不同，P/V位置不同 |
| P操作 | V操作 | 申请资源 vs 释放资源 |
| 整型信号量 | 记录型信号量 | 是否满足让权等待 |
| 读者优先 | 写者优先 | 谁可能饥饿 |
| 信号量 | 条件变量 | 是否有计数功能 |

### 真题回顾

> [!question] 2024年统考真题
> 在生产者-消费者问题中，若交换P(mutex)和P(empty)的顺序，会导致（）
> A. 生产者无法生产  B. 消费者无法消费  C. 可能死锁  D. 无影响
>
> **答案：C**
> **解析**：若先P(mutex)再P(empty)，当缓冲区满时，生产者持有mutex后阻塞在P(empty)，消费者无法进入临界区消费，形成死锁。

> [!question] 2023年统考真题
> 下列关于Peterson算法的叙述中，正确的是（）
> A. 满足空闲让进、忙则等待、有限等待、让权等待
> B. 不满足空闲让进
> C. 不满足让权等待
> D. 不满足忙则等待
>
> **答案：C**
> **解析**：Peterson算法满足前三个准则，但不满足让权等待（使用while忙等）。

> [!question] 2022年统考真题
> 使用记录型信号量实现互斥时，信号量的初值应设为（）
> A. -1  B. 0  C. 1  D. 任意值
>
> **答案：C**
> **解析**：互斥信号量初值为1，表示临界资源可用。P操作后变为0，表示资源被占用。
