# 同步与互斥基础（临界区与软硬件实现）

## 一、临界资源与临界区

### 1.1 临界资源

**临界资源** 是指一次仅允许一个进程使用的资源。如打印机、磁带机、共享变量等。

> [!warning] 临界资源的特点
> - 互斥使用：同一时间只能有一个进程使用
> - 不可抢占：使用完毕后主动释放

**常见临界资源分类**：

| 类别 | 常见例子 |
|:-----|:---------|
| **独占设备** | 打印机、磁带机（物理上只能串行使用） |
| **共享数据结构** | 公共队列（就绪队列、缓冲队列、消息队列）、共享缓冲区/缓冲池、共享栈 |
| **共享变量与系统表** | 共享变量、全局计数器、空闲分区表、文件分配表、位示图、打开文件表 |
| **同步机制自身变量** | `mutex`、`turn`、`flag[]` 等也必须互斥访问 |

> [!tip] 判别口诀
> 凡是"多进程同时读写会互相干扰"的资源就是临界资源——队列的入队/出队会改头尾指针，缓冲区的读写会改计数，所以都是。

### 1.2 临界区

**临界区（Critical Section）** 是指访问临界资源的那段代码。

```
进程代码结构：
┌─────────────────────────────────────┐
│  entry section    ← 进入区（申请进入临界区）│
├─────────────────────────────────────┤
│  critical section ← 临界区（访问临界资源）  │
├─────────────────────────────────────┤
│  exit section     ← 退出区（释放临界区）    │
├─────────────────────────────────────┤
│  remainder section ← 剩余区（其他代码）     │
└─────────────────────────────────────┘
```

#### 四个区详解（配代码）

| 区 | 职责 | 关键要求 |
|:---|:-----|:---------|
| **进入区** | 申请进入临界区：检查/争夺访问权，未获权则等待 | 必须保证互斥的正确性 |
| **临界区** | 实际访问临界资源的代码 | 尽量短，不做阻塞操作 |
| **退出区** | 释放访问权，标记临界区空闲，唤醒等待者 | 必须执行，否则锁泄漏 |
| **剩余区** | 与临界资源无关的其他代码 | 无需任何同步约束 |

```c
semaphore mutex = 1;          // 互斥信号量，初值1（临界区空闲）

void Pi() {
    /* 剩余区：普通计算，与临界资源无关 */
    P(mutex);                 // 进入区：申请访问权，失败则阻塞等待（让权等待）
    /* ===== 临界区：访问临界资源（读改共享变量/操作打印机）===== */
    V(mutex);                 // 退出区：释放访问权，唤醒等待进程（若有）
    /* 剩余区：后续无关操作 */
}
```

> [!tip] 对照记忆：软件法的进入/退出区是 while 循环检查标志变量（如 `while(flag[j]);`），硬件法是一条原子指令（TS/swap），信号量法就是 P、V 操作——四区结构不变，只是实现手段不同。

#### 临界区的数量（高频考点）

| 要点 | 说明 |
|:-----|:-----|
| **一个进程可有多个临界区** | 访问几种临界资源就有几个临界区 |
| **每个临界区对应一种临界资源** | 不同临界资源各用一把锁保护 |
| **同一临界资源的多个访问点共用同一把锁** | 锁按资源而非按代码段划分 |
| **临界区个数 ≠ 进程个数** | n个进程访问同一资源，共有n段临界区代码，但只需**一把锁** |
| **临界区应尽可能短小精悍** | 减少互斥时间，提高并发度 |
| **临界区可嵌套** | 嵌套访问不同资源时需按固定顺序加锁，否则易死锁 |

> [!example] 例：一个进程，两种临界资源 → 两个临界区、两把锁
>
> ```c
> semaphore mutex_printer = 1;   // 保护打印机（临界区1）
> semaphore mutex_queue   = 1;   // 保护公共队列（临界区2）
>
> void Pi() {
>     P(mutex_queue);            // 进入区1：操作队列前加锁，用完立即释放（避免持双锁）
>     /* 临界区1：出队操作 */
>     V(mutex_queue);            // 退出区1：先放队锁，再申请打印机锁，减小互斥时间、避免死锁风险
>
>     P(mutex_printer);          // 进入区2：申请打印机，失败则阻塞等待（让权等待）
>     /* 临界区2：打印操作 */
>     V(mutex_printer);          // 退出区2：释放打印机，唤醒等待进程（若有）
> }
> ```

### 1.3 同步机制应遵循的准则

> [!important] 四准则（必背）

| 准则 | 说明 | 违反后果 |
|:-----|:-----|:---------|
| **空闲让进** | 临界区空闲时，允许请求进入的进程立即进入 | 资源浪费 |
| **忙则等待** | 临界区有进程时，其他进程必须等待 | 数据不一致 |
| **有限等待** | 等待进入临界区的进程应在有限时间内进入 | 饥饿（Starvation） |
| **让权等待** | 等待时应释放CPU（阻塞），而不是忙等 | CPU资源浪费 |

> [!note] 准则关系
> - 空闲让进和忙则等待是**基本要求**
> - 有限等待是**公平性要求**
> - 让权等待是**性能要求**

### 1.4 临界区内被阻塞现象（高频辨析）

**问题**：一个正在访问临界资源的进程因申请I/O被阻塞，会发生什么？——需分机制讨论：

| 互斥机制 | 后果 |
|:---------|:-----|
| **阻塞式信号量** | 其他进程P(mutex)后阻塞进等待队列（让权等待，不烧CPU）；临界资源**空闲但不可用**，并发度下降；**不会死锁**（I/O完成唤醒后V(mutex）） |
| **忙等机制**（软件法/TS、Swap指令） | 其他进程在CPU上**无限空转**，白白浪费处理机 |
| **中断屏蔽法** | 关着中断请求I/O并阻塞 → I/O完成中断无法被响应 → **永远不被唤醒**（自造死锁）；故关中断只适合内核极短临界区 |

**类似情况归纳**：

| 情形 | 后果 |
|:-----|:-----|
| 临界区内调用可能阻塞的系统调用 | 锁被长期持有，并发下降 |
| 临界区内嵌套P另一个信号量 | 可能引发**死锁**（注意加锁顺序） |
| 持锁时时间片用完 | 无碍：被调度走不影响锁的正确性，只是等待者继续等 |
| 持锁时进程**终止** | 危险：锁永不释放，其他进程无限等待（资源泄漏型饥饿） |

> [!important] 两条铁律（由此得出）
> 1. **临界区尽量短**：临界区内不做I/O、不调用阻塞原语、不嵌套加锁
> 2. **临界区内阻塞本身不破坏正确性**（阻塞式信号量下不死锁），但会拉长互斥时间、降低并发度——这是违背"空闲让进"精神而非违反正确性

## 二、软件实现方法

> [!important] 核心考点
> 各种软件实现方法的原理、代码和是否满足四准则是408考试的高频考点。

### 2.1 单标志法

#### 算法思想

用一个整型变量 `turn` 表示允许进入临界区的进程号。

#### 代码实现

```c
// 共享变量
int turn = 0;  // turn=0表示允许P0进入，turn=1表示允许P1进入

// 进程P0
void P0() {
    while (turn != 0);   // 进入区：若turn≠0，则忙等
    /* 临界区 */          // 临界区
    turn = 1;            // 退出区：允许P1进入
    /* 剩余区 */          // 剩余区
}

// 进程P1
void P1() {
    while (turn != 1);   // 进入区：若turn≠1，则忙等
    /* 临界区 */          // 临界区
    turn = 0;            // 退出区：允许P0进入
    /* 剩余区 */          // 剩余区
}
```

#### 准则检查

| 准则 | 是否满足 | 说明 |
|:-----|:--------:|:-----|
| 空闲让进 | ❌ 不满足 | 如果turn=0但P0不想进入，P1也无法进入 |
| 忙则等待 | ✅ 满足 | |
| 有限等待 | ✅ 满足 | |
| 让权等待 | ❌ 不满足 | 使用while忙等，不释放CPU |

> [!danger] 单标志法的问题
> **强制轮流进入**，违背了"空闲让进"原则。两个进程必须交替进入临界区，如果一方不想进入，另一方也无法进入。

### 2.2 双标志先检查法

#### 算法思想

每个进程设置一个标志位 `flag[i]`，表示进程i是否想进入临界区。进入临界区前先检查对方是否想进入。

#### 代码实现

```c
// 共享变量
bool flag[2] = {false, false};  // flag[i]=true表示进程Pi想进入临界区

// 进程P0
void P0() {
    while (flag[1]);     // 先检查：若P1想进入，则等待
    flag[0] = true;      // 后设置：P0想进入
    /* 临界区 */
    flag[0] = false;     // 退出：P0不想进入了
    /* 剩余区 */
}

// 进程P1
void P1() {
    while (flag[0]);     // 先检查：若P0想进入，则等待
    flag[1] = true;      // 后设置：P1想进入
    /* 临界区 */
    flag[1] = false;     // 退出：P1不想进入了
    /* 剩余区 */
}
```

#### 准则检查

| 准则 | 是否满足 | 说明 |
|:-----|:--------:|:-----|
| 空闲让进 | ✅ 满足 | |
| 忙则等待 | ❌ 不满足 | 可能同时进入临界区（见下方分析） |
| 有限等待 | - | |
| 让权等待 | ❌ 不满足 | 使用while忙等 |

> [!danger] 双标志先检查法的问题
> **可能同时进入临界区**。考虑以下执行序列：
> 1. P0执行 `while(flag[1])`，flag[1]=false，跳出循环
> 2. **切换到P1**，P1执行 `while(flag[0])`，flag[0]=false，跳出循环
> 3. P1执行 `flag[1]=true`，进入临界区
> 4. **切换到P0**，P0执行 `flag[0]=true`，进入临界区
> 
> 此时P0和P1同时进入临界区，违反了"忙则等待"原则。

### 2.3 双标志后检查法

#### 算法思想

先设置自己的标志，再检查对方的标志。

#### 代码实现

```c
// 共享变量
bool flag[2] = {false, false};

// 进程P0
void P0() {
    flag[0] = true;      // 先设置：P0想进入
    while (flag[1]);     // 后检查：若P1想进入，则等待
    /* 临界区 */
    flag[0] = false;
    /* 剩余区 */
}

// 进程P1
void P1() {
    flag[1] = true;      // 先设置：P1想进入
    while (flag[0]);     // 后检查：若P0想进入，则等待
    /* 临界区 */
    flag[1] = false;
    /* 剩余区 */
}
```

#### 准则检查

| 准则 | 是否满足 | 说明 |
|:-----|:--------:|:-----|
| 空闲让进 | ✅ 满足 | |
| 忙则等待 | ✅ 满足 | |
| 有限等待 | ❌ 不满足 | 可能双方都无限等待（死锁） |
| 让权等待 | ❌ 不满足 | 使用while忙等 |

> [!danger] 双标志后检查法的问题
> **可能双方都无法进入临界区（死锁/饥饿）**。考虑以下执行序列：
> 1. P0执行 `flag[0]=true`
> 2. **切换到P1**，P1执行 `flag[1]=true`
> 3. P1执行 `while(flag[0])`，flag[0]=true，忙等
> 4. **切换到P0**，P0执行 `while(flag[1])`，flag[1]=true，忙等
>
> 双方都在等待对方，形成死锁，违反了"有限等待"原则。

### 2.4 Peterson算法

#### 算法思想

结合单标志法和双标志法的思想，既设置标志又设置轮流变量。

#### 代码实现

```c
// 共享变量
bool flag[2] = {false, false};
int turn = 0;

// 进程P0
void P0() {
    flag[0] = true;          // 表示P0想进入临界区
    turn = 1;                // 表示轮到P1（礼让）
    while (flag[1] && turn == 1);  // 若P1想进入且轮到P1，则等待
    /* 临界区 */
    flag[0] = false;         // P0退出临界区
    /* 剩余区 */
}

// 进程P1
void P1() {
    flag[1] = true;          // 表示P1想进入临界区
    turn = 0;                // 表示轮到P0（礼让）
    while (flag[0] && turn == 0);  // 若P0想进入且轮到P0，则等待
    /* 临界区 */
    flag[1] = false;         // P1退出临界区
    /* 剩余区 */
}
```

#### 准则检查

| 准则 | 是否满足 | 说明 |
|:-----|:--------:|:-----|
| 空闲让进 | ✅ 满足 | |
| 忙则等待 | ✅ 满足 | |
| 有限等待 | ✅ 满足 | |
| 让权等待 | ❌ 不满足 | 使用while忙等 |

> [!success] Peterson算法的正确性
> Peterson算法满足前三个准则，但不满足"让权等待"（因为使用忙等）。
>
> **互斥性证明**：假设P0和P1同时进入临界区。
> - P0进入意味着：`flag[1]==false || turn==0`
> - P1进入意味着：`flag[0]==false || turn==1`
> - 若P0先执行`turn=1`，后P1执行`turn=0`，则P0看到turn=0，P1看到turn=1，不可能同时满足。

### 2.5 软件方法总结

| 方法 | 空闲让进 | 忙则等待 | 有限等待 | 让权等待 |
|:-----|:--------:|:--------:|:--------:|:--------:|
| **单标志法** | ❌ | ✅ | ✅ | ❌ |
| **双标志先检查** | ✅ | ❌ | - | ❌ |
| **双标志后检查** | ✅ | ✅ | ❌ | ❌ |
| **Peterson算法** | ✅ | ✅ | ✅ | ❌ |

## 三、硬件实现方法

### 3.1 中断屏蔽

#### 原理

通过**关中断**来禁止CPU响应中断，从而保证临界区代码不被打断。

```c
// 进入临界区前关中断
cli();           // 关中断（Clear Interrupt）
/* 临界区 */
sti();           // 开中断（Set Interrupt）
/* 剩余区 */
```

#### 特点

| 优点 | 缺点 |
|:-----|:-----|
| 简单高效 | 关中断时间过长影响系统性能和实时性 |
| | 不适用于多CPU系统（只能屏蔽当前CPU的中断） |
| | 用户程序不能随意使用（特权指令） |

> [!warning] 限制
> 中断屏蔽只适用于单CPU系统，且关中断时间应尽量短。

### 3.2 测试并设置指令（TS指令/TestAndSet）

#### 指令定义

```c
// 原子操作：测试并设置
bool TestAndSet(bool *lock) {
    bool old = *lock;    // 保存旧值
    *lock = true;        // 设置锁为true
    return old;          // 返回旧值
}
```

#### 实现互斥

```c
// 共享变量
bool lock = false;       // 锁，false表示未上锁

// 进程Pi
void Pi() {
    while (TestAndSet(&lock));  // 若lock为true，则忙等
    /* 临界区 */
    lock = false;               // 解锁
    /* 剩余区 */
}
```

#### 特点

| 优点 | 缺点 |
|:-----|:-----|
| 适用于多CPU系统 | 不满足"让权等待"（忙等） |
| 实现简单 | 可能出现饥饿 |

### 3.3 交换指令（Swap/Exchange）

#### 指令定义

```c
// 原子操作：交换两个变量的值
void Swap(bool *a, bool *b) {
    bool temp = *a;
    *a = *b;
    *b = temp;
}
```

#### 实现互斥

```c
// 共享变量
bool lock = false;

// 进程Pi
void Pi() {
    bool key = true;
    while (key == true) {
        Swap(&lock, &key);   // 交换lock和key的值
    }
    /* 临界区 */
    lock = false;            // 解锁
    /* 剩余区 */
}
```

#### 特点

与TS指令类似，同样不满足"让权等待"。

### 3.4 硬件方法总结

| 方法 | 适用场景 | 满足准则 | 主要缺点 |
|:-----|:---------|:---------|:---------|
| **中断屏蔽** | 单CPU系统 | 忙则等待 | 影响性能，不适用多CPU |
| **TS指令** | 多CPU系统 | 前三条 | 不满足让权等待 |
| **Swap指令** | 多CPU系统 | 前三条 | 不满足让权等待 |
