# 线程

## 五、线程的概念

### 5.1 线程的引入

> [!info] 为什么引入线程？
> 进程是资源分配单位，创建、切换、通信开销大。引入线程是为了**减小程序并发执行时的时空开销**，使并发粒度更细，并发性更好。

#### 引入线程的好处

| 好处 | 说明 |
|:-----|:-----|
| **创建更快** | 无需分配大量资源，只需创建线程控制块 |
| **切换更快** | 只需保存/恢复寄存器和栈，无需切换地址空间 |
| **通信更方便** | 同一进程内的线程共享地址空间，可直接读写数据 |
| **并发度更高** | 线程是更小的调度单位，可以更好地利用多核CPU |

### 5.2 线程的定义

**线程（Thread）** 是进程中的一个实体，是被系统独立调度和分派的基本单位。线程只拥有少量必不可少的资源（程序计数器、寄存器组、栈），但可与同属一个进程的其他线程共享进程的全部资源。

### 5.3 线程与进程的比较

> [!success] 必背对比表

| 对比项 | 进程 | 线程 |
|:-------|:-----|:-----|
| **资源拥有** | 拥有独立的地址空间和系统资源 | 共享进程的地址空间和资源 |
| **调度单位** | 传统OS中是调度单位 | 现代OS中是调度单位 |
| **并发性** | 进程间可并发 | 线程间可并发，同一进程的线程也可并发 |
| **系统开销** | 大（创建、撤销、切换开销大） | 小（创建、撤销、切换开销小） |
| **独立性** | 独立性强，一个进程崩溃不影响其他进程 | 独立性弱，一个线程崩溃可能导致整个进程崩溃 |
| **通信方式** | 需要IPC机制（管道、消息队列等） | 直接读写进程数据，无需特殊机制 |
| **切换开销** | 需要切换页表、刷新TLB | 只需保存/恢复寄存器 |

### 5.4 线程的属性

1. **轻型实体**：线程中的实体基本上不拥有系统资源
2. **独立调度和分派的基本单位**：线程是CPU调度的基本单位
3. **可并发执行**：同一进程的线程之间可以并发执行
4. **共享进程资源**：线程可以共享进程的资源

## 六、线程的实现方式

> [!important] 核心考点
> 线程的三种实现方式（用户级、内核级、组合方式）的对比是408考试的高频考点。

### 6.1 用户级线程（ULT, User-Level Thread）

#### 实现原理

用户级线程由**用户空间的线程库**实现，操作系统内核并不知道线程的存在，内核只调度进程。

```
用户空间                    内核空间
┌─────────────────┐        ┌─────────────┐
│  线程库管理      │        │             │
│  ┌───┐ ┌───┐   │        │   进程A      │
│  │T1 │ │T2 │   │───────▶│  （内核视角）│
│  └───┘ └───┘   │        │             │
│  ┌───┐ ┌───┐   │        └─────────────┘
│  │T3 │ │T4 │   │
│  └───┘ └───┘   │
└─────────────────┘
```

#### 特点

| 方面 | 说明 |
|:-----|:-----|
| **管理主体** | 用户空间的线程库 |
| **内核感知** | 内核不知道线程存在，只调度进程 |
| **切换开销** | 小，无需切换到内核态 |
| **阻塞影响** | 一个线程阻塞，整个进程阻塞 |
| **并行性** | 不能利用多核CPU并行（内核只看到一个进程） |
| **调度** | 由线程库调度 |

#### 优点与缺点

| 优点 | 缺点 |
|:-----|:-----|
| 线程切换不需要内核介入，开销小 | 一个线程阻塞会导致整个进程阻塞 |
| 线程库可在任何操作系统上运行，可移植性好 | 不能利用多核CPU的并行性 |
| 用户可自定义调度算法 | 内核只将CPU时间分配给进程，线程间时间分配不公平 |

### 6.2 内核级线程（KLT, Kernel-Level Thread）

#### 实现原理

内核级线程由**操作系统内核**直接支持，线程的创建、撤销、切换都在内核态完成。

```
用户空间                    内核空间
┌─────────────────┐        ┌─────────────┐
│                 │        │  线程T1      │
│   进程A          │◀───────│  线程T2      │
│                 │        │  线程T3      │
└─────────────────┘        │  线程T4      │
                           └─────────────┘
```

#### 特点

| 方面 | 说明 |
|:-----|:-----|
| **管理主体** | 操作系统内核 |
| **内核感知** | 内核知道每个线程的存在 |
| **切换开销** | 大，需要切换到内核态 |
| **阻塞影响** | 一个线程阻塞，不影响同进程的其他线程 |
| **并行性** | 可以利用多核CPU并行 |
| **调度** | 由内核调度 |

#### 优点与缺点

| 优点 | 缺点 |
|:-----|:-----|
| 一个线程阻塞不影响同进程的其他线程 | 线程切换需要内核介入，开销大 |
| 可以利用多核CPU的并行性 | 线程管理需要内核支持，可移植性差 |
| 内核可以将CPU时间直接分配给线程 | 创建线程需要内核参与，开销大 |

### 6.3 组合方式（多对多模型）

#### 实现原理

组合方式将**多个用户级线程映射到多个内核级线程**上，兼顾了两者的优点。

```
用户空间                    内核空间
┌─────────────────┐        ┌─────────────┐
│  用户线程        │        │  内核线程    │
│  ┌───┐ ┌───┐   │        │  ┌───┐      │
│  │T1 │ │T2 │   │───────▶│  │K1 │      │
│  └───┘ └───┘   │        │  └───┘      │
│  ┌───┐ ┌───┐   │        │  ┌───┐      │
│  │T3 │ │T4 │   │───────▶│  │K2 │      │
│  └───┘ └───┘   │        │  └───┘      │
│  ┌───┐         │        │  ┌───┐      │
│  │T5 │         │───────▶│  │K3 │      │
│  └───┘         │        │  └───┘      │
└─────────────────┘        └─────────────┘
```

#### 特点

| 方面 | 说明 |
|:-----|:-----|
| **映射关系** | 多对多（n个用户线程映射到m个内核线程，n ≥ m） |
| **灵活性** | 用户线程可自由创建，不受内核线程数量限制 |
| **并行性** | 可以利用多核CPU并行 |
| **阻塞影响** | 一个内核线程阻塞，只影响映射到它的用户线程 |

### 6.4 三种实现方式对比

> [!success] 必背对比表

| 特性 | 用户级线程（ULT） | 内核级线程（KLT） | 组合方式 |
|:-----|:----------------|:------------------|:---------|
| **管理者** | 用户空间线程库 | 操作系统内核 | 两者结合 |
| **切换开销** | 小（无需内核态） | 大（需要内核态） | 中等 |
| **阻塞影响** | 一个阻塞，整个进程阻塞 | 只阻塞该线程 | 只阻塞映射的线程 |
| **多核并行** | 不支持 | 支持 | 支持 |
| **线程数量** | 不受限制 | 受内核资源限制 | 用户线程不受限制 |
| **可移植性** | 好 | 差 | 较好 |
| **调度灵活性** | 高（用户自定义） | 低（内核统一调度） | 中等 |
| **代表系统** | POSIX Pthreads（用户模式） | Windows、Linux | Solaris |

### 6.5 线程模型总结

```
线程模型
├── 一对一模型（1 ULT : 1 KLT）
│   └── 每个用户线程对应一个内核线程
│   └── 并发性好，但开销大
├── 多对一模型（n ULT : 1 KLT）
│   └── 多个用户线程映射到一个内核线程
│   └── 开销小，但无法并行
└── 多对多模型（n ULT : m KLT）
    └── 多个用户线程映射到多个内核线程
    └── 兼顾灵活性和并发性
```

### 6.6 线程调度与切换

> [!important] 核心考点
> 线程切换"保存什么、切换什么"以及跨进程线程切换的开销，是线程考点中最易出错的部分。

#### 线程私有 vs 进程共享

| 归属 | 内容 | 线程切换时 |
|:-----|:-----|:---------|
| **线程私有** | PC、寄存器组、栈指针SP、线程栈、线程状态（TCB） | **必须保存/恢复** |
| **进程共享** | 地址空间（页表）、代码段、数据段、打开文件等资源 | 同进程内切换**不动** |

一句话：**线程切换 = 只换"执行现场"，不换"资源环境"**——这是它比进程切换快的根本原因。

#### 分场景对比

| 切换场景 | 保存/恢复 | 切换地址空间 | 进内核态 | 开销 |
|:---------|:---------|:---:|:---:|:---:|
| 同进程、用户级线程间 | 寄存器、PC、SP | 否 | **否** | 最小 |
| 同进程、内核级线程间 | 寄存器、PC、SP | 否 | **是** | 小 |
| 跨进程线程间 | 线程现场 + 进程上下文 | **是**（换页表基址、刷TLB） | 是 | 大（等同进程切换） |

> [!warning] 易错点
> "线程切换都不需要切换地址空间"是错的——跨进程的线程切换照样要换地址空间；只有**同一进程内**的线程切换才省去这一步。

#### 多进程并行时的线程切换

在**内核级线程**系统（Windows/Linux）中，内核调度的直接对象是**线程**，不是进程。时间片用完或线程阻塞时，内核挑选下一个线程，两种结果：

```
内核选中下一个线程
├── 属于当前进程 → 只切换线程现场（不换地址空间）→ 开销小
└── 属于其他进程 → 线程现场 + 地址空间都切换     → 开销大
```

即：多个进程并行时，**进程切换被"内嵌"在线程切换里**——内核一步选出线程，线程属于哪个进程，CPU 就切换到哪个进程的上下文。

其他模型：

| 模型 | 多进程并行时的切换行为 |
|:-----|:---------------------|
| **用户级线程**（多对一） | 内核只在进程间切换（换地址空间，开销大）；进程内由线程库在用户态切换（开销小） |
| **组合方式**（多对多） | 两级调度：内核先选内核线程（相当于选进程，分配物理CPU），用户级调度器再把用户线程分派到内核线程 |
| **多核情形** | 多个内核线程（同进程或不同进程）在不同核上真正同时执行，核间不发生切换，只有同一核上的时间片轮转才产生切换 |

> [!tip] 速记口诀
> 同进程切线程——换现场不换空间；跨进程切线程——现场空间一起换；ULT——内核只见进程不见线程。
