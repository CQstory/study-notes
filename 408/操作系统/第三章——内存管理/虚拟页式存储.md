# 虚拟页式存储

## 四、虚拟页式存储管理

### 4.1 虚拟存储器的基本概念

#### （1）传统存储管理的缺陷（引入虚存的动机）

> [!warning] 传统存储管理的两大缺陷
> | 缺陷 | 含义 | 后果 |
> |:---|:---|:---|
> | **一次性** | 作业必须**一次性全部装入内存**才能运行 | 内存放不下大程序 → 不能运行；多道程序度受限于物理内存总量 |
> | **驻留性** | 作业装入后**全程驻留内存**，直到结束 | 可能只用很小一部分代码和数据，却占着整块内存不释放 |
>
> 正是"一次性 + 驻留性"，导致内存利用极低。能运行的程序大小不能超过物理内存，多道程序度也严重受限。

#### （2）局部性原理

> ✅ 笔记已有，见下表的完整内容

| 类型 | 说明 | 示例 |
|:-----|:-----|:-----|
| **时间局部性** | 刚被访问的单元近期会再次被访问 | 循环语句、栈操作 |
| **空间局部性** | 被访问单元附近的单元也会被访问 | 顺序执行、数组遍历 |

基于局部性原理，程序执行时其访问的页面集中在**一小部分页面（工作集）**上，**不需要全部装入**即可运行。

#### （3）虚拟存储器的定义与三大特征

**定义**：将**物理内存**和**外存（对换区）**统一管理，形成逻辑上远大于物理内存的地址空间——用户看到的"虚拟地址空间"由 OS + MMU 共同维护，部分驻留物理内存，部分暂存外存。

| 特征 | 含义 | 与传统对比 |
|:---|:---|:---|
| **多次性** | 作业被分成**多次**调入内存（不是一次性全部装入） | 传统：一次性 |
| **对换性** | 运行过程中允许**换入换出**（不再全程驻留） | 传统：驻留性 |
| **虚拟性** | 从逻辑上**扩充**了内存容量，用户看到的空间 > 物理空间 | 传统：不扩充 |

> 这三个特征常作填空题/简答题，与"两次性、驻留性"对应。

**虚拟存储器的容量**（高频选择题）：

```
虚拟存储器最大容量 = min(逻辑地址空间大小, 物理内存 + 外存对换区)
```

- 实际中通常受限的是**地址结构**（32 位最多 4GB，64 位极大）
- 例：32 位 CPU、32GB 内存、1TB 磁盘 → 虚存最大 **4GB**，不是因为磁盘大就能超过地址范围

#### （3.5）虚拟地址与物理地址：本质区别（408 易混点）

> [!warning] 常见误解纠正
> - "虚拟地址 = CPU 能访问的极限"——**❌**。CPU 不能直接访问虚拟地址，它只能通过 MMU 翻译后发物理地址。
> - "物理地址 = CPU 一次能读取的极限"——**❌**。"一次读多少"由**数据总线**决定（如 64 位 = 一次 8 字节），物理地址宽度决定的是"能装多少内存"。

| | **虚拟地址** | **物理地址** | **数据总线** |
|:---|:---|:---|:---|
| **本质** | 程序逻辑上能编址的范围（指令中地址字段宽度） | 地址总线能送达的范围（地址引脚数） | 一次搬运的数据量 |
| **由谁定** | CPU 指令集架构 | 芯片封装工艺（引脚数） | 芯片封装工艺 |
| **能否直接访存** | ❌ 必须经 MMU 翻译 | ✅ 直接放到地址总线上 | — |
| **比喻** | 通讯录里记的门牌号 | 小区真正的门牌号 | 一次搬几箱东西 |
| **决定** | 进程可见的地址空间大小 | 最大可寻址物理内存 | 内存带宽 / 一次读写量 |

> [!important] 三种宽度完全独立（计组考点）
> **地址总线宽度 ≠ 数据总线宽度 ≠ 虚拟地址位数**。三者由不同硬件设计决定，408 常设陷阱混淆。
> - 地址总线（物理地址）：决定"去哪"→ 最大可装内存量 = $2^{\text{地址位数}}$
> - 数据总线：决定"搬多少"→ 一次读写量 = 数据位数 / 8 字节
> - 虚拟地址：决定"程序看到多大"→ 由指令集架构规定，与物理无关

**本机实例**（AMD Ryzen 9 8945HX, 64位 Windows）：

| 层面 | 值 | 说明 |
|:---|:---:|:---|
| 虚拟地址位数 | 64 位（实际用 48 位） | 每进程用户态最大 **8 TB** |
| 物理地址位数 | 48 位 | 理论最大 **256 TB** |
| 实际物理内存 | **31.1 GB** | 主板只插了 32 GB 条 |
| 数据总线 | 64 位 | 一次读 **8 字节** |
| 页面文件 | 6.2 GB | C:\pagefile.sys |
| 系统虚拟内存 | 37.3 GB | = 31.1 GB 物理 + 6.2 GB 页面文件 |
| 进程实际 | Qoder IDE 虚拟占 3.5 TB，物理仅 733 MB | 虚拟/物理比 ≈ 4909:1 |

> 物理地址上限(256TB) > 虚拟地址(8TB/进程)的原因：物理地址要覆盖**整台机器所有硬件**（RAM+GPU显存+ROM+外设MMIO），虚拟地址只是**一个进程眼中的自己**。二者不可直接比较。

#### （4）基本分页 vs 请求分页（12 维度全面对比）

> 二者的本质关系：**基本分页 = 离散分配基本框架；请求分页 = 基本分页 + 虚拟存储。** 请求分页不是替代基本分页，而是在其之上增加"请求调入+页面置换"。

| 维度 | 基本分页 | 请求分页 |
|:---|:---|:---|
| **目的** | 解决连续分配的外部碎片问题（离散分配） | 在离散分配基础上解决"内存装不下大程序"问题（虚拟存储） |
| **装入方式** | **一次性全部装入** | **部分装入即可运行**，其余按需调入 |
| **进程大小限制** | 进程大小 ≤ 物理内存 | 进程大小可 > 物理内存（上限=虚存地址空间） |
| **多道程序度** | 受限于物理内存总量（全部驻留） | 同一内存可驻留更多进程（各进程只保持部分页面） |
| **页表字段** | 仅页框号 | 页框号 + 状态位 + 访问位 + 修改位 + 外存地址 |
| **缺页可能性** | 0——页必须全部在内存 | 频繁发生（正是虚存的常态） |
| **页面置换** | 不需要（无缺页） | **核心机制**——内存满时选页面换出 |
| **地址变换链路** | 逻辑地址→分解→越界检查→查页表→物理地址 | 同左，但**先查状态位**：(在)→查页框号→物理地址；(缺页)→缺页中断→置换→调入→重执行 |
| **运行前提** | 进程全部在内存才能执行 | 只需工作集在内存即可执行 |

**共同点**（选择题常混淆，互相并列）✅ 全部已有：

| 共同点 | 详情 |
|:---|:---|
| **分配粒度** | 都以页为单位离散分配 |
| **外部碎片** | 都无外部碎片（离散分配的本质优点） |
| **内部碎片** | 都有内部碎片（最后一页可能不满） |
| **地址变换** | 都用页表基址寄存器 + 页表长度寄存器 |
| **TLB** | 都需要 TLB 加速地址变换 |
| **进程切换** | 都需要换页表基址/长度寄存器 + 刷 TLB（见 §2.6） |
| **多级页表** | 都可使用多级页表（见 §三） |
| **逻辑地址结构** | 完全一致：页号 P + 页内偏移 W |

> [!tip] 区分核心（判断题速记）
> - "基本分页不使用置换算法"——**✅**（不需要置换，因为无缺页）
> - "请求分页的基本思想是离散分配"——**❌**（离散分配是基本分页就有的，请求分页的核心是虚拟存储）
> - "基本分页的页表项需要包含状态位"——**❌**（页全部在内存，不需状态位）
> - "两种方式下TLB进程切换时都需刷新"——**✅**（共同点）

#### （5）提供虚拟存储技术的存储管理方法（必背判断表）

| 存储管理方法 | 能否提供虚存 | 原因 |
|:---|:---:|:---|
| **请求分页** | ✅ | 按页请求调入，缺页时置换 |
| **请求分段** | ✅ | 按段请求调入，缺段时置换 |
| **请求段页式** | ✅ | 段+页两级请求调入 |
| 基本分页 | ❌ | 一次性全部装入，无缺页机制 |
| 基本分段 | ❌ | 一次性全部装入 |
| 固定分区分配 | ❌ | 一次性全部装入 |
| 动态分区分配 | ❌ | 一次性全部装入 |
| 单一连续分配 | ❌ | 一次性全部装入 |

> [!important] 一句话判断
> **凡是带"请求"二字的 = 虚拟存储；不带的 = 非虚拟存储。** 连续分配方式（固定分区、动态分区、单一连续）都不提供虚存。

#### （6）连续分配与非连续分配分类总表

| 大类 | 方法 | 分配粒度 | 是否提供虚存 |
|:---|:---|:---|:---:|
| **连续分配** | 单一连续分配 | 整个用户区 | ❌ |
| | 固定分区分配 | 固定大小分区 | ❌ |
| | 动态分区分配 | 按需连续分区 | ❌ |
| **非连续（离散）** | 基本分页 | 页 | ❌ |
| | **请求分页** | 页 | ✅ |
| | 基本分段 | 段 | ❌ |
| | **请求分段** | 段 | ✅ |
| | 基本段页式 | 段→页 | ❌ |
| | **请求段页式** | 段→页 | ✅ |

> [!tip] 分类口诀
> **连续三兄弟**：单一、固定、动态 → 都一次性装入，都不提供虚存。
> **离散六兄弟**：基本/请求 × 分页/分段/段页式 → 带"请求"的才有虚存。

### 4.2 虚拟页式存储的实现

在基本分页的基础上增加以下机制：

1. **页表扩展**：增加"是否在内存"（有效/无效位）和"外存地址"字段
2. **缺页中断**：访问不在内存的页面时，产生缺页中断，从外存调入
3. **页面置换**：内存满时，选择一个页面换出到外存

```
扩展后的页表项：
┌──────────┬──────────┬──────────┬──────────┐
│  页框号   │ 状态位   │ 访问字段  │ 修改位   │
│(若在内存) │(在/不在) │(引用次数) │(是否修改) │
├──────────┴──────────┼──────────┴──────────┤
│                    │ 外存地址（若不在内存） │
└────────────────────┴─────────────────────┘
```

#### 内存映射（地址映射机制总览）

"内存映射"= **逻辑地址 → 物理地址的转换机制**，是地址重定位的具体实现。按映射方式分三种：

| 映射方式 | 时机 | 机制 | 适用 |
|:---|:---|:---|:---|
| **静态映射** | 装入时一次完成 | 装入程序改写所有地址 | 可重定位装入 |
| **动态映射（加法）** | 运行时每次访存 | 重定位寄存器 + 逻辑地址 | 连续分配 |
| **动态映射（查表）** | 运行时每次访存 | 页表/段表 | 离散分配（分页/分段） |

**分页系统的内存映射**：

```
逻辑地址  →  页号 P + 偏移 W
                │
                ▼
        ┌───────────────┐
        │  查页表/查TLB  │  ← 关键：映射规则由页表决定
        └───────┬───────┘
                │
                ▼
        页框号 F
                │
                ▼
物理地址 = F × 页大小 + W
```

**分段系统的内存映射**：

```
逻辑地址  →  段号 S + 偏移 W
                │
                ▼
        ┌───────────────┐
        │  查段表        │  ← 得到段始址 B、段长 L
        └───────┬───────┘
                │
                ▼
物理地址 = B + W    （前提：W < L，否则越界中断）
```

**映射的四个关键性质**：

| 性质 | 说明 |
|:---|:---|
| **粒度** | 分页以页为单位；分段以段为单位（不是字节级） |
| **可变性** | 页表可修改 → 映射关系随时改变（换入换出） |
| **进程隔离** | 不同进程有独立页表 → 同一虚地址映射到不同物理地址 |
| **保护功能** | 映射过程附带越界检查 + 读写权限检查 |

### 4.3 缺页中断

缺页中断是一种**内中断（异常）**，处理过程如下：

```
CPU访问某页面
       │
       ▼
  ┌─────────────┐
  │ 检查页表    │
  │ 该页在内存？│
  └──────┬──────┘
         │
    ┌────┴────┐
    │         │
   是        否
    │         │
    ▼         ▼
 正常访问   产生缺页中断
    │         │
    │    ┌────┴────────┐
    │    │ 检查内存    │
    │    │ 是否有空闲？│
    │    └────┬────────┘
    │         │
    │    ┌────┴────┐
    │    │         │
    │   有        无
    │    │         │
    │    │    ┌────┴────┐
    │    │    │页面置换 │
    │    │    │选择淘汰 │
    │    │    │页面     │
    │    │    └────┬────┘
    │    │         │
    │    ▼         ▼
    │    调入所需页面
    │    更新页表
    │         │
    └────┬────┘
         │
         ▼
    重新执行被中断的指令
```

> [!important] 缺页中断的特点
> - 缺页中断属于**内中断（异常）**，不是外中断
> - 缺页中断在**指令执行期间**产生（不是指令执行完后）
> - 一条指令可能产生**多次**缺页中断（如跨页的指令）
> - 缺页中断处理后，需要**重新执行**被中断的指令

**缺页中断 vs 普通 I/O 中断**（对比辨析）：

| | 缺页中断（内中断/异常） | 普通 I/O 中断（外中断） |
|:---|:---|:---|
| 触发时机 | **指令执行期间**（CPU 访存时发现缺页） | **指令执行完毕**采样中断信号 |
| 能否屏蔽 | 不能（必须处理，否则无法继续执行） | 可以屏蔽 |
| 一条指令可能触发次数 | **多次**（跨页指令减少缺页） | 通常一次 |

#### 地址变换的完整分层决策（TLB → 页表 → 缺页）

```
CPU发出虚拟地址
    │
    ▼
查 TLB（快表）
    │
    ├─ 命中 ────────────────────────────────┐
    │   直接拿到页框号                        │
    │   物理地址 = 页框号 × 页大小 + 偏移      │
    │   【数据一定在 RAM 中，1次访存搞定】      │
    │                                        │
    └─ 未命中 ──→ 查页表（慢表）               │
                    │                        │
                    ├─ 状态位=1（在内存）       │
                    │   查页框号 → 物理地址      │
                    │   【数据在 RAM，2次访存】   │
                    │   同时写入 TLB            │
                    │                         │
                    └─ 状态位=0（缺页）         │
                        缺页中断！             │
                        查页表"外存地址"字段    │
                        从辅存读入 → (内存满→置换) │
                        更新页表 → 重新执行指令    │
                        【数据原本在辅存】        │
```

> [!important] TLB 里存什么、不存什么？
> | | TLB 缓存 | 页表才有 |
> |:---|:---:|:---:|
> | 页框号 | ✅ | ✅ |
> | 状态位 | ✅（隐含） | ✅ |
> | **外存地址** | ❌ **不存** | ✅（缺页时才查） |
> | 访问位/修改位 | 通常不存 | ✅ |
>
> **TLB 只缓存"已经在内存里的页"的映射**。状态位=0 的表项不会出现在 TLB 中。
> 所以：**TLB 命中 = 数据一定在 RAM，不在辅存**。

#### TLB 命中与缺页的逻辑关系（选择题必考）

| 场景 | TLB | 页表状态位 | 结果 |
|:---|:---:|:---:|:---|
| ① 热点页面反复访问 | 命中 | 1 | 直接访存，1 次，**不缺页** |
| ② 第一次访问某页 | 未命中 | 1 | 查页表→访存，2 次，**不缺页** |
| ③ 很久没用的页 | 未命中 | 0 | 缺页中断→磁盘I/O，**缺页** |
| ④ ？ | 命中 | 0 | **不可能存在**（状态=0 不进 TLB） |

逻辑关系：
- **TLB 命中 → 不缺页**（✅ 充分条件）
- **不缺页 → TLB 命中？**（❌ 可能是场景②）
- **缺页 → TLB 一定未命中**（✅ 逆否命题）

> [!tip] 选择题陷阱速记
> - "若 TLB 未命中，则一定缺页"——**❌**（场景②：页在内存但 TLB 没缓存）
> - "若未缺页，则 TLB 一定命中"——**❌**（场景②）
> - "若 TLB 命中，则一定不缺页"——**✅**（TLB 只缓存在内存的页）
> - "缺页时数据在辅存，与 TLB 无关"——**✅**（TLB 不存辅存信息）
> - "TLB 存外存地址"——**❌**（外存地址只在页表里）
> - "TLB 命中 = 知道数据在辅存哪里"——**❌**（恰好相反！命中 = 在 RAM 里）
