# 基本分页与地址变换（分页+TLB+多级页表）

## 一、基本分页存储管理

### 1.1 基本思想

将进程的逻辑地址空间分成大小相等的**页（Page）**，将物理内存分成与页大小相同的**页框（Page Frame，又称页帧、物理块）**。以页为单位离散分配，页可以不连续存放。

```
逻辑地址空间                    物理内存
┌──────┐                      ┌──────┐
│ 页0  │ ─────→              │页框3 │
├──────┤                      ├──────┤
│ 页1  │ ─────→              │页框7 │
├──────┤                      ├──────┤
│ 页2  │ ─────→              │页框1 │
├──────┤                      ├──────┤
│ 页3  │ ─────→              │页框5 │
└──────┘                      ├──────┤
                              │空闲  │
                              └──────┘
```

### 1.2 基本概念

| 概念 | 说明 |
|:-----|:-----|
| **页（Page）** | 进程逻辑地址空间的划分单位，大小固定 |
| **页框（Page Frame）** | 物理内存的划分单位，大小与页相同 |
| **页号** | 标识逻辑地址属于哪一页 |
| **页内偏移** | 页内的偏移量 |
| **页表** | 记录页号到页框号的映射关系 |

### 1.3 页面大小

- 页面大小由硬件决定，通常是 **2 的幂次**（如 1KB、2KB、4KB）
- 常见页面大小：**4KB**（主流）

> [!note] 为什么是2的幂？
> 页面大小为 $2^n$ 时，逻辑地址的分解非常方便：低 $n$ 位为页内偏移，高位为页号，只需位移操作，无需除法。

### 1.4 逻辑地址结构

若页面大小为 $2^k$ 字节，逻辑地址空间大小为 $2^m$ 字节：

```
逻辑地址（m位）
┌──────────────┬──────────────┐
│   页号 P     │  页内偏移 W   │
│  (m-k 位)    │   (k 位)     │
└──────────────┴──────────────┘
```

- **页号 P** = 逻辑地址 / 页面大小 = 逻辑地址 >> k（右移k位）
- **页内偏移 W** = 逻辑地址 % 页面大小 = 逻辑地址 & (2^k - 1)（取低k位）

> [!example] 示例
> 页面大小为 4KB（$2^{12}$），逻辑地址为 8196（$0x2004$）：
> - 页号 P = 8196 / 4096 = **2**
> - 页内偏移 W = 8196 % 4096 = **4**
> - 用二进制验证：$8196 = 10\ 000000000100_2$，低12位 = $000000000100_2 = 4$，高 位 = $10_2 = 2$

### 1.5 页表

页表是操作系统为每个进程维护的一张映射表：

| 页号 | 页框号 | 是否在内存 |
|:----:|:------:|:----------:|
| 0 | 3 | 1 |
| 1 | 7 | 1 |
| 2 | 1 | 1 |
| 3 | 5 | 1 |
| 4 | — | 0 |

> [!note] 说明
> - 页表项中**不需要存储页号**，因为页号就是页表的下标
> - 页表项中存储的是**页框号**（物理块号）
> - 在虚拟页式存储中，还需要一个标志位表示该页是否在内存中

### 1.6 基本地址变换过程

```
CPU生成逻辑地址
       │
       ▼
  ┌─────────────┐
  │ 分解页号P   │
  │ 和偏移W     │
  └──────┬──────┘
         │
         ▼
  ┌─────────────┐
  │ 查页表      │  ← 页表基址寄存器（页表始址）
  │ P → 页框号F │
  └──────┬──────┘
         │
         ▼
  ┌─────────────┐
  │ 拼接物理地址 │
  │ F × 页面大小 │
  │ + W         │
  └──────┬──────┘
         │
         ▼
    物理地址
```

**详细步骤**：
1. 从逻辑地址中提取页号 P 和页内偏移 W
2. 页表基址寄存器中存放页表的起始地址
3. 以页号 P 为索引，查找页表，得到对应的页框号 F
4. 物理地址 = 页框号 F × 页面大小 + 页内偏移 W

> [!example] 计算示例
> 页面大小为 4KB，页表如下：
>
> | 页号 | 页框号 |
> |:----:|:------:|
> | 0 | 5 |
> | 1 | 8 |
> | 2 | 3 |
> | 3 | 1 |
>
> 求逻辑地址 4100（十进制）对应的物理地址。
>
> **解**：
> - 页号 P = 4100 / 4096 = **1**（取整）
> - 页内偏移 W = 4100 % 4096 = **4**
> - 查页表：页号 1 → 页框号 **8**
> - 物理地址 = 8 × 4096 + 4 = **32772**

### 1.7 地址变换机构

地址变换由硬件完成，主要涉及以下寄存器：

| 寄存器 | 功能 |
|:-------|:-----|
| **页表基址寄存器**（页表始址寄存器） | 存放当前进程页表的起始物理地址 |
| **页表长度寄存器** | 存放当前进程页表的长度（页表项数） |

> [!important] 地址越界检查
> 在查页表之前，需要检查**页号 P 是否小于页表长度**。若 P ≥ 页表长度，说明越界，产生越界中断。

## 二、快表（TLB，Translation Lookaside Buffer）

### 2.1 为什么需要快表

基本分页每次访存都需要**两次访问内存**：
1. 第一次：访问内存中的页表，得到页框号
2. 第二次：访问目标内存单元

这导致访存速度减半。为了解决这个问题，引入了**快表（TLB）**。

### 2.2 快表的工作原理

快表是一种**高速缓存**（associative memory），存放最近访问的页表项。

```
CPU生成逻辑地址
       │
       ▼
  ┌─────────────┐
  │ 查快表TLB   │
  └──────┬──────┘
         │
    ┌────┴────┐
    │ 命中？  │
    └────┬────┘
     是  │  否
    ┌────┴────┐
    │         │
    ▼         ▼
 直接得到   查内存页表
 页框号    得到页框号
    │         │
    │         ▼
    │    更新快表
    │    （将新项写入）
    │         │
    └────┬────┘
         │
         ▼
    计算物理地址
    访问内存
```

### 2.3 TLB命中与未命中

| 情况 | 访问次数 | 说明 |
|:-----|:--------:|:-----|
| TLB命中 | **1次**访存 | 直接从TLB获得页框号，只需访问目标内存 |
| TLB未命中 | **2次**访存 | 先访问内存页表，再访问目标内存 |

### 2.4 有效访问时间（EAT）计算

设：
- 访问内存的时间为 $t$（即一次内存访问的时间）
- TLB的访问时间极短，忽略不计（或设为 $\varepsilon$）
- TLB命中率为 $p$

$$EAT = p \times 1t + (1-p) \times 2t = t + (1-p) \times t = (2-p) \times t$$

> [!example] 例题
> 某系统采用基本分页存储管理，内存访问时间为 100ns，TLB 命中率为 80%。
>
> 求：有效访问时间（EAT）。
>
> **解**：
> - TLB命中时：1次访存 = 100ns
> - TLB未命中时：2次访存 = 200ns
> - $EAT = 0.8 \times 100 + 0.2 \times 200 = 80 + 40 = \textbf{120ns}$

> [!example] 例题2
> 某系统 TLB 访问时间为 10ns，内存访问时间为 100ns，TLB 命中率为 90%。
>
> 求：有效访问时间（EAT）。
>
> **解**：
> - TLB命中时：TLB(10ns) + 内存(100ns) = 110ns
> - TLB未命中时：TLB(10ns) + 内存查页表(100ns) + 内存访问(100ns) = 210ns
> - $EAT = 0.9 \times 110 + 0.1 \times 210 = 99 + 21 = \textbf{120ns}$

> [!important] 注意
> 当题目给出TLB本身的访问时间时，无论命中与否都需要先访问TLB，因此：
> - 命中：TLB时间 + 1次内存时间
> - 未命中：TLB时间 + 2次内存时间

### 2.5 快表的特点

| 特点 | 说明 |
|:-----|:-----|
| 速度极快 | 基于相联存储器（CAM），硬件并行查找 |
| 容量小 | 成本高，通常只有几十到几百个表项 |
| 基于局部性原理 | 程序在短时间内倾向于访问相同的页面 |
| 进程切换时清空 | 不同进程的页表不同，需要清空或更新TLB |

### 2.6 页式系统中的进程切换流程

> [!important] 核心考点
> 页式管理下的进程切换 = 通用切换步骤 + **页表机构相关寄存器的切换与TLB刷新**，是内存管理与进程管理交叉的高频简答题。

**通用切换步骤**（详见 [[第二章——进程与线程/调度基础（概念、时机与性能指标）|调度基础]]）：

```
1. 保存当前进程的CPU现场（寄存器、PC、PSW）到其PCB
2. 修改当前进程状态（运行 → 就绪/阻塞）
3. 将当前进程PCB移入相应队列
4. 按调度算法选取新进程
5. 从新进程PCB恢复CPU现场
6. 置新进程为运行态，跳转到其PC所指位置执行
```

**页式管理额外的操作**：

| 步骤 | 操作 | 说明 |
|:-----|:-----|:-----|
| 7 | 保存旧进程页表信息 | 页表基址、页表长度写入旧PCB（内存信息区） |
| 8 | **切换页表基址寄存器** | 装入新进程页表的起始物理地址 |
| 9 | **切换页表长度寄存器** | 装入新进程页表长度，供越界检查用 |
| 10 | **清空/刷新TLB** | 旧进程的"页号→页框号"映射全部失效 |
| 11 | 切换内核栈 | 每个进程有自己的内核栈 |

> [!warning] 两个易错点
> 1. **TLB为什么必须清空**：TLB表项里只有"页号→页框号"，不含进程标识，换进程后若不刷，会用旧映射访问新进程的地址空间（带ASID/进程标识的TLB可不清空，408默认按"清空"处理）
> 2. **页表本身不用搬动**：页表始终存放在内存中，切换只换"指向页表的寄存器"，不是搬运页表内容

**开销对比**：

```
进程切换开销 = 通用现场保存/恢复 + 换页表基址/长度 + 刷TLB + (Cache失效)
同进程线程切换 = 只保存/恢复寄存器、PC、SP（不动页表、不刷TLB）
```

> [!tip] 简答题答题模板
> 保存旧进程现场及页表信息到PCB → 改状态、挪队列 → 选新进程 → 恢复现场 → **装入新进程页表基址和页表长度 → 清空TLB** → 置运行态、转PC执行。

## 三、两级页表与多级页表

### 3.1 为什么需要多级页表

现代系统中逻辑地址空间很大（如32位地址空间有 $2^{32}$ 字节），如果页面大小为4KB：
- 页表项数 = $2^{32} / 2^{12} = 2^{20}$ = 1M 个页表项
- 每个页表项占 4 字节
- 页表大小 = $2^{20} \times 4 = 4\text{MB}$

**问题**：4MB的页表需要**连续存放**，但内存中很难找到这么大的连续空闲区域。

### 3.2 两级页表的思想

将页表本身也分页，建立**页目录表**（外层页表）来记录页表的存放位置。

```
逻辑地址（32位）
┌──────────────┬──────────────┬──────────────┐
│ 一级页号 P1  │ 二级页号 P2  │  页内偏移 W   │
│  (10 位)     │  (10 位)     │  (12 位)      │
└──────────────┴──────────────┴──────────────┘
```

### 3.3 两级页表的地址变换

```
逻辑地址 → 分解 P1, P2, W
    │
    ▼
查页目录（P1 → 得到二级页表的起始地址）
    │
    ▼
查二级页表（P2 → 得到页框号 F）
    │
    ▼
物理地址 = F × 页面大小 + W
```

> [!example] 例题
> 32位逻辑地址，页面大小4KB，页表项4字节，采用两级页表。
>
> - 页内偏移：12位
> - 剩余20位分为两级：各10位
> - 一级页号 P1：10位 → 最多 $2^{10} = 1024$ 个页目录项
> - 二级页号 P2：10位 → 每个二级页表最多 $2^{10} = 1024$ 个页表项
> - 页目录大小：$1024 \times 4\text{B} = 4\text{KB}$（恰好一页）
> - 每个二级页表大小：$1024 \times 4\text{B} = 4\text{KB}$（恰好一页）

### 3.4 多级页表

对于64位系统，两级页表仍然不够，需要三级甚至四级页表。

```
64位逻辑地址（以四级页表为例）
┌────┬────┬────┬────┬──────────┐
│P1  │P2  │P3  │P4  │  偏移W   │
│9位 │9位 │9位 │9位 │  12位    │
└────┴────┴────┴────┴──────────┘
```

> [!note] Linux实际使用
> Linux在x86_64架构上使用**四级页表**（PGD → PUD → PMD → PTE），后来扩展为五级页表。

### 3.5 多级页表的代价

| 优点 | 缺点 |
|:-----|:-----|
| 不需要页表连续存放 | 增加访存次数（每多一级多一次访存） |
| 按需创建页表 | 地址变换时间增加 |
| 节省内存 | TLB的重要性更加凸显 |

> [!important] 考点
> - n级页表需要 **n+1** 次访存（n次查各级页表 + 1次访问目标内存）
> - 加上TLB后，TLB命中只需1次访存
