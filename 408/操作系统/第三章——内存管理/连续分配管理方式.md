# 连续分配管理方式

[[第三章——内存管理|← 返回目录]]

> [!info] 本节定位
> 连续分配是指为每个进程分配一段**连续的**物理内存区域。本节介绍三种连续分配方式：单一连续分配、固定分区分配和动态分区分配，并讨论内部碎片与外部碎片的概念。

---

## 一、单一连续分配

### 1.1 基本思想

将内存分为两个区域：

```
┌────────────────────────────────────┐
│          系统区（OS）               │
├────────────────────────────────────┤
│                                    │
│        用户区（单道程序）           │
│                                    │
├────────────────────────────────────┤
│          空闲区                     │
└────────────────────────────────────┘
```

- 内存中**只有一道用户程序**运行
- 用户区被一个进程独占
- 适用于**单道批处理系统**

### 1.2 特点

| 优点 | 缺点 |
|:-----|:-----|
| 实现简单 | 只能单道运行，内存利用率极低 |
| 无外部碎片 | 有**内部碎片**（用户区可能装不满） |
| 管理开销小 | 无法支持多道程序设计 |

> [!note] 碎片说明
> 单一连续分配中，如果用户程序只有 50KB，但分配了 100KB 的用户区，则剩余的 50KB 无法被其他进程使用，这就是**内部碎片**。

---

## 二、固定分区分配

### 2.1 基本思想

将用户空间**预先划分为若干个大小固定的分区**，每个分区可以装入一道作业。

```
┌────────────────────────────────────┐
│          操作系统                   │
├──────────┬─────────────────────────┤
│ 分区1    │  20KB                    │
│  (20KB)  │  ← 作业A (15KB)         │
├──────────┼─────────────────────────┤
│ 分区2    │  40KB                    │
│  (40KB)  │  ← 作业B (30KB)         │
├──────────┼─────────────────────────┤
│ 分区3    │  60KB                    │
│  (60KB)  │  ← 作业C (55KB)         │
├──────────┼─────────────────────────┤
│ 分区4    │  80KB                    │
│  (80KB)  │  ← 空闲                 │
└──────────┴─────────────────────────┘
```

### 2.2 分区划分方式

| 方式 | 说明 |
|:-----|:-----|
| **等大小分区** | 所有分区大小相同，简单但不灵活 |
| **不等大小分区** | 分区大小不等，兼顾小作业和大作业 |

> [!tip] 实际应用
> 通常采用**不等大小分区**，以适应不同大小的作业需求。

### 2.3 分区使用表

操作系统维护一张**分区说明表**，记录各分区的状态：

| 分区号 | 大小 | 起始地址 | 状态 |
|:------:|:----:|:--------:|:----:|
| 1 | 20KB | 100K | 已分配 |
| 2 | 40KB | 120K | 已分配 |
| 3 | 60KB | 160K | 已分配 |
| 4 | 80KB | 220K | 空闲 |

### 2.4 特点

| 优点 | 缺点 |
|:-----|:-----|
| 支持多道程序 | 存在**内部碎片** |
| 实现简单 | 分区总数固定，限制了并发程序数 |
| 无外部碎片 | 不能运行大于最大分区的程序 |

> [!important] 碎片分析
> 固定分区分配中，每个分区可能未被完全利用。例如作业A只需15KB但占用了20KB的分区，多出的5KB就是**内部碎片**。
>
> - **有内部碎片，无外部碎片**
> - 内部碎片 = 分区内未被利用的空间

---

## 三、动态分区分配（可变分区分配）

### 3.1 基本思想

不预先划分分区，而是根据进程的实际需要**动态地分配**内存。

```
初始状态：内存全部可用（除OS区域）
┌────────────────────────────────────┐
│          操作系统                   │
├────────────────────────────────────┤
│                                    │
│         空闲区 (全部可用)           │
│                                    │
└────────────────────────────────────┘

装入作业A(30KB)、作业B(50KB)、作业C(20KB)后：
┌────────────────────────────────────┐
│          操作系统                   │
├────────────────┬───────────────────┤
│   作业A(30KB)  │   作业B(50KB)     │
├────────────────┼───────────────────┤
│   作业C(20KB)  │    空闲区          │
└────────────────┴───────────────────┘

作业B结束后：
┌────────────────┬───────────────────┐
│   作业A(30KB)  │    空闲区(50KB)    │
├────────────────┼───────────────────┤
│   作业C(20KB)  │    空闲区          │
└────────────────┴───────────────────┘
```

### 3.2 数据结构

动态分区分配需要维护空闲分区信息，常用以下数据结构：

#### （1）空闲分区链

将空闲分区用链表连接起来，每个空闲分区的首部和尾部存放分区大小和指向下一个分区的指针。

#### （2）空闲分区表

用表格记录所有空闲分区：

| 分区号 | 大小 | 起始地址 | 状态 |
|:------:|:----:|:--------:|:----:|
| 1 | 50KB | 130K | 空闲 |
| 2 | 100KB | 220K | 空闲 |

### 3.3 动态分区分配算法

当有多个空闲分区都能满足进程需求时，操作系统需要决定将进程分配到哪个分区。这就是分配算法要解决的问题。

#### （1）首次适应算法（First Fit, FF）

**策略**：从头到尾搜索空闲分区链，将进程分配到**第一个**能满足大小的空闲分区。

```
空闲分区链：[20KB] → [50KB] → [100KB] → [30KB] → [80KB]

请求 40KB → 分配到 [50KB]（第一个 >= 40KB 的分区）
```

| 优点 | 缺点 |
|:-----|:-----|
| 简单、开销小 | 低地址端产生很多小碎片 |
| 高地址端保留大分区 | 查找效率随分配次数下降 |

> [!tip] 实现方式
> 空闲分区按**地址递增**排列，每次从链首开始查找。

#### （2）最佳适应算法（Best Fit, BF）

**策略**：搜索所有空闲分区，将进程分配到**能满足需求的最小**空闲分区。

```
空闲分区链：[20KB] → [50KB] → [100KB] → [30KB] → [80KB]

请求 40KB → 分配到 [50KB]（最小的 >= 40KB 的分区）
```

| 优点 | 缺点 |
|:-----|:-----|
| 每次分配尽量少浪费 | 产生大量**难以利用的小碎片** |
| 大分区得以保留 | 查找效率低（需要遍历整个链） |

> [!warning] 问题
> 最佳适应算法看似"最佳"，实际上会产生很多**很小的外部碎片**，这些碎片因为太小而无法被利用，反而降低了内存利用率。

#### （3）最差适应算法（Worst Fit, WF）

**策略**：搜索所有空闲分区，将进程分配到**最大**的空闲分区。

```
空闲分区链：[20KB] → [50KB] → [100KB] → [30KB] → [80KB]

请求 40KB → 分配到 [100KB]（最大的空闲分区）
```

| 优点 | 缺点 |
|:-----|:-----|
| 减少小碎片的产生 | 大分区很快被消耗 |
| 分割后剩余分区仍较大 | 大作业到来时可能无足够空间 |

#### （4）邻近适应算法（Next Fit, NF）

**策略**：从**上次查找结束的位置**开始继续查找，将进程分配到第一个能满足大小的空闲分区。

```
空闲分区链（循环）：[20KB] → [50KB] → [100KB] → [30KB] → [80KB]
                              ↑ 上次分配位置

请求 40KB → 从 [100KB] 开始查找 → 分配到 [100KB]
```

| 优点 | 缺点 |
|:-----|:-----|
| 查找速度快（不用每次从头开始） | 高地址和大分区容易被用完 |
| 避免低地址端碎片过多 | 缺乏大分区导致大作业无法分配 |

### 3.4 四种算法对比总结

| 算法 | 查找策略 | 排列方式 | 优点 | 缺点 |
|:-----|:---------|:---------|:-----|:-----|
| **FF** | 第一个满足的 | 地址递增 | 简单快速 | 低地址碎片多 |
| **BF** | 最小满足的 | 大小递增 | 浪费最少 | 小碎片多 |
| **WF** | 最大满足的 | 大小递减 | 减少小碎片 | 大分区消耗快 |
| **NF** | 从上次位置继续 | 地址递增（循环） | 查找均匀 | 大分区易耗尽 |

> [!important] 考点总结
> - **首次适应算法**通常被认为是综合性能最好的算法
> - **最佳适应算法**产生的外部碎片最多（很多很小的碎片）
> - **最差适应算法**不利于大作业
> - **首次适应**和**邻近适应**的空闲分区按地址排序，**最佳适应**按大小递增排序，**最差适应**按大小递减排序

## 四、内部碎片与外部碎片

### 4.1 定义

| 碎片类型 | 定义 | 产生场景 |
|:---------|:-----|:---------|
| **内部碎片** | 分区内部的空闲空间（分配了但未使用） | 固定分区、分页存储 |
| **外部碎片** | 分区外部的空闲空间（太小无法分配） | 动态分区、分段存储 |

### 4.2 图解

**内部碎片**：
```
┌──────────────────────┐
│   已分配区域          │
│   ┌────────────────┐ │
│   │ 作业使用部分    │ │
│   ├────────────────┤ │
│   │ 内部碎片        │ │  ← 分区内浪费的空间
│   └────────────────┘ │
└──────────────────────┘
```

**外部碎片**：
```
┌──────┬──────┬──────┬──────┐
│作业A │碎片1 │作业B │碎片2 │
│      │2KB   │      │3KB   │
└──────┴──────┴──────┴──────┘
                    ↑
            碎片1+碎片2=5KB
            但不连续，无法分配给需要5KB的作业
```

### 4.3 各种分配方式的碎片情况

| 分配方式 | 内部碎片 | 外部碎片 |
|:---------|:--------:|:--------:|
| 单一连续分配 | 有 | 无 |
| 固定分区分配 | **有** | 无 |
| 动态分区分配 | 无 | **有** |
| 基本分页存储 | **有** | 无 |
| 基本分段存储 | 无 | **有** |
| 段页式存储 | **有** | 无 |

> [!important] 记忆口诀
> - **固定分区 → 内部碎片**（分区固定，装不满就浪费）
> - **动态分区 → 外部碎片**（分区可变，但碎片散落在外）
> - **分页 → 内部碎片**（页面固定，最后一页可能不满）
> - **分段 → 外部碎片**（段长可变，段间有空隙）

### 4.4 外部碎片的解决方法

#### （1）紧凑（Compaction）

将所有进程向内存一端移动，将外部碎片合并为一个大的空闲分区。

```
紧凑前：                          紧凑后：
┌──┬────┬──┬────┬──┬────┐       ┌────┬────┬────┬──────────┐
│A │碎片│B │碎片│C │碎片│       │ A  │ B  │ C  │ 空闲区   │
└──┴────┴──┴────┴──┴────┘       └────┴────┴────┴──────────┘
```

- 需要**动态重定位**的支持（运行时才能移动）
- 开销较大

#### （2）离散分配

将进程分散到不连续的内存区域中，从根本上消除外部碎片：
- 分页存储管理
- 分段存储管理

> [!note] 离散分配是解决外部碎片的主要方法，也是后续章节讨论的重点。

## 五、动态分区分配的完整示例

### 5.1 例题

假设内存空间为 1024KB，操作系统占用 100KB，用户可用空间为 924KB（地址 100~1023）。

初始状态：空闲区 [100, 1024, 924KB]

按以下顺序请求和释放：

| 序号 | 操作 | 大小 |
|:----:|:-----|:----:|
| 1 | 分配 | 130KB |
| 2 | 分配 | 60KB |
| 3 | 分配 | 100KB |
| 4 | 释放 | 作业2 (60KB) |
| 5 | 分配 | 200KB |
| 6 | 释放 | 作业1 (130KB) |
| 7 | 分配 | 140KB |
| 8 | 释放 | 作业3 (100KB) |

### 5.2 首次适应算法执行过程

```
初始状态：
  空闲：[100, 1024, 924KB]

① 分配 130KB → 从地址100开始分配
  已分配：作业1 [100, 230, 130KB]
  空闲：[230, 1024, 794KB]

② 分配 60KB → 从地址230开始分配
  已分配：作业1 [100, 230, 130KB]，作业2 [230, 290, 60KB]
  空闲：[290, 1024, 734KB]

③ 分配 100KB → 从地址290开始分配
  已分配：作业1 [100, 230, 130KB]，作业2 [230, 290, 60KB]，作业3 [290, 390, 100KB]
  空闲：[390, 1024, 634KB]

④ 释放 作业2 (60KB) → 释放 [230, 290, 60KB]
  已分配：作业1 [100, 230, 130KB]，作业3 [290, 390, 100KB]
  空闲：[230, 290, 60KB]，[390, 1024, 634KB]

⑤ 分配 200KB → 从地址230开始，60KB不够，从390开始分配
  已分配：作业1 [100, 230, 130KB]，作业4 [390, 590, 200KB]，作业3 [290, 390, 100KB]
  空闲：[230, 290, 60KB]，[590, 1024, 434KB]

⑥ 释放 作业1 (130KB) → 释放 [100, 230, 130KB]
  已分配：作业4 [390, 590, 200KB]，作业3 [290, 390, 100KB]
  空闲：[100, 230, 130KB]，[230, 290, 60KB]，[590, 1024, 434KB]

⑦ 分配 140KB → 从地址100开始，130KB不够，60KB不够，434KB够
  已分配：作业5 [590, 730, 140KB]，作业4 [390, 590, 200KB]，作业3 [290, 390, 100KB]
  空闲：[100, 230, 130KB]，[230, 290, 60KB]，[730, 1024, 294KB]

⑧ 释放 作业3 (100KB) → 释放 [290, 390, 100KB]
  已分配：作业5 [590, 730, 140KB]，作业4 [390, 590, 200KB]
  空闲：[100, 230, 130KB]，[230, 290, 60KB]，[290, 390, 100KB]，[730, 1024, 294KB]
```

> [!note] 观察
> 可以看到，经过多次分配和释放后，内存中出现了多个不连续的小空闲区（外部碎片），这就是动态分区分配的主要问题。

## 六、考点总结

### 6.1 核心知识点

| 知识点 | 关键内容 |
|:-------|:---------|
| 单一连续分配 | 单道程序，有内部碎片 |
| 固定分区 | 预先划分，有内部碎片，无外部碎片 |
| 动态分区 | 按需分配，无内部碎片，有外部碎片 |
| FF算法 | 第一个满足的，综合性能最好 |
| BF算法 | 最小满足的，小碎片最多 |
| WF算法 | 最大满足的，大分区消耗快 |
| NF算法 | 循环查找，大分区易耗尽 |
| 内部碎片 | 分区内浪费，固定大小方案产生 |
| 外部碎片 | 分区间浪费，可变大小方案产生 |
| 紧凑技术 | 解决外部碎片，需动态重定位支持 |

### 6.2 常考选择题

> [!danger] 易错点
> 1. 固定分区有**内部碎片**无外部碎片，动态分区有**外部碎片**无内部碎片
> 2. 首次适应算法按**地址递增**排列，不是按大小
> 3. 最佳适应算法按**大小递增**排列
> 4. 最差适应算法按**大小递减**排列
> 5. 紧凑技术需要**动态重定位**的支持（不是静态重定位）

### 6.3 与后续章节的联系

- 动态分区分配的碎片问题推动了 [[分页存储管理]] 中**离散分配**技术的发展
- 紧凑技术与 [[内存管理基础]] 中讨论的**动态重定位**密切相关
- 分配算法的思想在 [[分页存储管理]] 的**页面置换算法**中有类似体现
