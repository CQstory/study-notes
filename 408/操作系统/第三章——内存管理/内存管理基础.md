# 内存管理基础

## 一、内存管理的概念与功能

### 1.1 内存管理的目标

操作系统对内存的管理主要实现以下目标：

| 功能 | 说明 |
|:-----|:-----|
| **内存分配与回收** | 为各进程分配所需的内存空间，进程结束后及时回收 |
| **地址变换** | 将程序中的逻辑地址转换为物理地址（即内存中的实际地址） |
| **内存保护** | 确保各进程只能访问自己的内存空间，互不干扰 |
| **内存扩充** | 借助虚拟存储技术，从逻辑上扩充内存容量 |

### 1.2 内存管理的层次

```
用户程序
    ↓ 逻辑地址
操作系统（内存管理模块）
    ↓ 地址变换 + 内存保护
物理内存（硬件）
```

> [!note] 关键理解
> 用户程序中使用的是**逻辑地址**（也叫虚拟地址），而实际存放在内存中的位置是**物理地址**（也叫绝对地址）。操作系统负责完成从逻辑地址到物理地址的映射。

### 1.3 对换（Swapping）

对换是把内存中暂时不能运行的进程**换出**到外存的**对换区**，再把外存中已具备运行条件的进程**换入**内存——是**中级调度（内存调度）**的核心操作，也是**内存扩充**的手段之一。

```
外存对换区  ⇄  内存
   换入 ↑      ↓ 换出
   （调入就绪进程）  （调出暂不能运行/低优先级进程）
```

**易混概念**（选择题常考）：

| 技术 | 粒度 | 说明 |
|:---|:---|:---|
| **覆盖（Overlay）** | 作业内**模块**级 | 程序员手工安排模块复用同一内存区，作业级、人为控制 |
| **对换（Swapping）** | **进程**级 | OS 自动把整个进程换入换出 |
| **虚拟存储** | **页/段**级 | 部分调入调出，可运行"比内存大的程序" |

> 对换是"整个进程进出内存"，虚存是"进程的一部分进出内存"——**对换是虚存的前身和基础**。

**换出时机与对象**（考选择题）：

- **时机**：① 内存不够用；② CPU 空闲而就绪队列空转
- **对象顺序**：先选**阻塞进程**（反正不能运行）→ 其中优先选**驻留时间长**的 → 再考虑就绪进程中的**低优先级/驻留久**者
- **防抖动**：不选"刚换出又会被换入"的进程

**对换区 vs 文件区**（高频对比）：

| | 对换区（swap区） | 文件区 |
|:---|:---|:---|
| 内容 | 换出的进程映像 | 各类文件 |
| 分配方式 | **连续分配**（速度快） | **离散分配**（索引结构） |
| 追求 | **速度**（换入换出频繁） | 空间利用率 + 查找便利 |

**对换过程**：

```
1. 换出：暂停进程（置挂起态）→ 进程映像写入对换区 → 释放其内存分区（回收）
2. 记录：PCB 中登记外存地址、状态等（换出进程的 PCB 仍留在内存，以便调度）
3. 换入：调度程序选择就绪挂起进程 → 在对换区按连续分配找空间 → 读入内存
4. 重定位：换入后可能回不到原来的内存位置：
   - 静态重定位 → 需再次改写全部地址（代价大）
   - 动态重定位 → 只需修改重定位寄存器（见 [[专题总结/专题03——程序装入方式与内存分配方式的适配分析|专题03]]）
```

**与虚拟存储的本质区别**（大题/辨析）：

| | 对换 | 虚拟存储 |
|:---|:---|:---|
| 调入单位 | 整个进程 | 页/段（部分） |
| 运行前提 | 进程必须**全部**在内存才能运行 | 只需**部分**在内存即可运行 |
| 解决 | 内存放不下时把进程整体移走 | 内存放不下"更大"的程序 |
| 地位 | 内存扩充的初级手段 | 内存扩充的高级手段（请求分页/分段） |

> [!tip] 一句话记忆
> **对换是"整进整出"，虚存是"按需调入"；对换靠中级调度，虚存靠请求调页/段 + 页面置换。**

#### 1.3.1 减少对换数量与系统性能

**为什么减少对换能改善性能**：对换的代价本质是"**用磁盘时间换内存空间**"，一次对换 = 两次磁盘 I/O（换出写盘 + 换入读盘）：

| 代价环节 | 说明 |
|:---|:---|
| **I/O 时间巨大** | 进程映像整体读写磁盘：内存访问纳秒级、磁盘毫秒级，相差 **10⁵~10⁶ 倍** |
| **进程挂起** | 对换期间进程不能运行，CPU 等待 I/O 完成（速度严重不匹配） |
| **占用磁盘带宽** | 干扰其他进程的 I/O 请求，形成通道竞争 |
| **换入后重定位** | 动态重定位改寄存器轻；静态重定位要重写全部地址 |
| **抖动放大** | 频繁对换 → 大部分时间在"搬运"而非"执行" → 吞吐量骤降，极端时瘫痪 |

> [!tip] 一句话
> **CPU 有效工作时间占比 = 系统性能。对换越少 → 磁盘 I/O 越少 → CPU 越集中执行进程 → 吞吐量越高。** 这正是虚拟存储、紧凑等技术存在的意义。

**实现减少对换的机制（五层答题主线）**：

| 层次 | 机制 | 原理 |
|:---|:---|:---|
| ① 装得下 | 分配算法（FF/BF/WF/NF）+ **紧凑** | 减少碎片，避免"有空间却装不下"被迫对换；紧凑代价远小于换出整个进程到磁盘 |
| ② 不必整搬 | **虚拟存储**（请求分页/分段） | 进程只需部分在内存即可运行 → 驻留更多进程 → 不必整进程换出 |
| ③ 搬得少 | 页面置换算法（LRU 等）、**工作集模型** | 用"页级置换"替代"进程级对换"，一次只搬一页而非整个映像；工作集驻留防止抖动 |
| ④ 源头少触发 | 长程/中级调度控制**多道程序度** | 避免内存超载，从源头减少对换触发 |
| ⑤ 万不得已也快 | 对换区**连续分配** | 对换区追求速度，缩短单次对换时间 |

> [!important] 递进主线
> **装得下（分配算法/紧凑）→ 不必整搬（虚存按需调入）→ 搬得少（置换算法/工作集防抖动）→ 源头少触发（调度控制）→ 万不得已也快（对换区连续分配）**

## 二、程序的装入与链接

### 2.1 程序处理的全过程

一个源程序从编写到执行，需要经历以下三个阶段：

```
源程序 (.c)  →  编译  →  目标模块 (.o)  →  链接  →  装入模块  →  装入  →  内存中执行
```

### 2.2 编译阶段

- **编译程序**将源程序翻译成目标模块
- 目标模块中使用的是**逻辑地址**（从0开始的相对地址）
- 编译时无法确定模块最终在内存中的位置

### 2.3 链接阶段

链接是将多个目标模块（以及所需的库函数）组装成一个完整的装入模块的过程。链接有以下三种方式：

| 链接方式 | 说明 | 特点 |
|:---------|:-----|:-----|
| **静态链接** | 在装入之前，将所有目标模块链接成一个完整的可执行文件 | 链接后不再拆分，运行时无需链接 |
| **装入时动态链接** | 在装入内存时，边装入边链接 | 便于目标模块的共享和更新 |
| **运行时动态链接** | 在程序运行过程中需要某模块时才对其进行链接 | 最灵活，实现共享库（DLL/SO）的基础 |

> [!important] 考点
> - 静态链接：装入前完成，生成完整的可执行文件
> - 装入时动态链接：装入时完成
> - 运行时动态链接：运行时按需链接，如动态链接库
> - **运行时动态链接**最适合实现目标模块的共享

### 2.4 装入阶段

装入是将装入模块放入内存中的过程。根据地址变换方式的不同，装入有以下三种方式：

#### （1）绝对装入（Absolute Loading）

- 编译时确定物理地址
- 程序中使用的就是物理地址
- 仅适用于**单道程序环境**
- 现代操作系统基本不使用

#### （2）可重定位装入（Relocatable Loading）

- 又称**静态重定位**
- 装入时将逻辑地址转换为物理地址（由装入程序完成）
- 装入后**不能移动**（地址已固定）
- 无需专门硬件支持，变换在装入时一次性完成

> [!example] 示例
> 假设目标模块的逻辑地址从0开始，装入到内存地址1000处：
> - 逻辑地址 50 → 物理地址 50 + 1000 = 1050
> - 逻辑地址 200 → 物理地址 200 + 1000 = 1200

#### （3）动态运行时装入（Dynamic Run-time Loading）

- 又称**动态重定位**
- 装入时程序不移动，地址变换推迟到**运行时**进行
- 需要**重定位寄存器**（基址寄存器）的支持
- 运行过程中程序可以移动（通过修改重定位寄存器的值）

> [!important] 对比总结
> | 装入方式 | 变换时机 | 能否移动 | 适用环境 |
> |:---------|:---------|:---------|:---------|
> | 绝对装入 | 编译时 | 否 | 单道 |
> | 可重定位装入 | 装入时 | 否 | 多道 |
> | 动态运行时装入 | 运行时 | **能** | 多道 |

> [!warning] 重点
> **动态运行时装入**是现代操作系统中最常用的方式，它允许程序在运行过程中在内存中移动，为后续的虚拟存储、页面置换等技术提供了基础。
>
> 三种装入方式与七种内存分配方式如何配对（适配矩阵、碎片治理因果链），详见 [[专题总结/专题03——程序装入方式与内存分配方式的适配分析|专题03——装入方式与分配方式的适配分析]]。

## 三、逻辑地址与物理地址

### 3.1 基本概念

| 地址类型 | 别名 | 说明 |
|:---------|:-----|:-----|
| **逻辑地址** | 虚拟地址、相对地址 | CPU生成的地址，从0开始编址 |
| **物理地址** | 绝对地址、实地址 | 内存单元的真实地址 |

### 3.2 地址空间

- **逻辑地址空间**：程序所使用的地址范围，从0开始
- **物理地址空间**：内存中实际可用的地址范围

### 3.3 地址重定位

将逻辑地址转换为物理地址的过程称为**地址重定位**（或地址映射）。

- **静态重定位**：在装入时完成，通过修改指令中的地址字段实现
- **动态重定位**：在运行时完成，通过硬件（重定位寄存器）实现

```
逻辑地址 ──→ [重定位寄存器（基址）] ──→ 物理地址
                  +
              逻辑地址
                  =
              物理地址
```

#### 动态重定位的三个依赖条件（选择题原题考点）

> [!important] 原题表述
> "动态重定位依赖：可重定位装入程序、重定位寄存器、地址变换机构"——**目标程序是干扰项**。

**完整过程**：

```
① 装入阶段：可重定位装入程序把目标程序装入内存
   —— 不做任何地址修改，程序内逻辑地址保持原样（从0开始）
   —— 程序装到哪个空闲区，装入程序记录/上报实际装入始址
② 设置阶段：操作系统把该始址装入重定位寄存器（基址寄存器）
   —— 同时设置界限寄存器 = 程序长度
③ 运行阶段：每条访存指令由地址变换机构自动执行：
   物理地址 = 逻辑地址 + 重定位寄存器值（先做越界检查）
④ 移动时：紧凑只需修改重定位寄存器的值，程序本身一个字节都不用动
```

**三个依赖项的作用**（正好覆盖"装得进 → 记得住 → 变得快"）：

| 依赖项 | 环节 | 作用 | 缺了会怎样 |
|:-------|:-----|:-----|:-----------|
| **可重定位装入程序** | 装入 | 装入时**不修改地址**，保留逻辑地址，并记录实际装入位置 | 若装入时就写死地址（静态重定位），程序永远不能移动 |
| **重定位寄存器（基址寄存器）** | 记基址 | 存放进程内存区的起始地址，作为每次变换的偏移基准；切换进程时其值换入换出（值存PCB） | 没有基准，逻辑地址无法映射到实际位置 |
| **地址变换机构** | 运行时变换 | MMU中的硬件电路，每条访存指令**自动**完成变换与越界检查 | 靠软件逐次换算，速度慢到不可用 |

> [!warning] 目标程序为什么是干扰项
> 1. **身份不对**：题目问的是机制的**依赖条件**（工具+硬件），目标程序是被加工的**对象**——类比"翻译小说依赖译者、词典、语法，而不是小说本身"
> 2. **无特殊性**：动态重定位对目标程序没有额外要求（逻辑地址从0开始即可），任何目标程序都适用，故不构成依赖条件

> [!note] 静态 vs 动态的依赖对比
> - 静态重定位：依赖**装入程序**即可，无特殊硬件要求，装入后不可移动
> - 动态重定位：三者缺一不可，程序运行中可移动——是紧凑、虚拟存储的基础

### 3.4 计算示例

> [!example] 地址变换计算
> 某进程被装入到内存起始地址为 1000 的位置，重定位寄存器中存放的值为 1000。
>
> - 逻辑地址 0 → 物理地址 = 0 + 1000 = **1000**
> - 逻辑地址 256 → 物理地址 = 256 + 1000 = **1256**
> - 逻辑地址 1023 → 物理地址 = 1023 + 1000 = **2023**

> [!note] 说明
> 在基本分页存储管理中，地址变换不是简单的加法，而是通过**页表**进行查表映射。这在 [[第三章——内存管理/基本分页与地址变换（分页+TLB+多级页表）|基本分页与地址变换]] 中详细讨论。

## 四、内存保护

内存保护的目的是确保每个进程在自己的地址空间中运行，不能访问其他进程的内存区域，也不能访问操作系统的内存区域。

### 4.1 上下限寄存器法

使用两个寄存器来限定进程的合法访问范围：

```
┌─────────────────────────────────────────────┐
│  上限寄存器（上界寄存器）= 物理地址上限      │
│  下限寄存器（下界寄存器）= 物理地址下限      │
└─────────────────────────────────────────────┘

访问条件：下限 ≤ 物理地址 ≤ 上限
```

**工作原理**：
1. CPU生成逻辑地址后，先通过地址变换得到物理地址
2. 将物理地址与上限寄存器、下限寄存器的值进行比较
3. 若物理地址在范围内，允许访问
4. 若物理地址超出范围，产生**越界中断**（地址越界异常）

> [!example] 示例
> 某进程的内存区域为物理地址 1000~2000：
> - 访问物理地址 1500 → 1000 ≤ 1500 ≤ 2000 → **允许访问**
> - 访问物理地址 500 → 500 < 1000 → **越界中断**
> - 访问物理地址 2500 → 2500 > 2000 → **越界中断**

### 4.2 基址限长寄存器法（基地址寄存器 + 限长寄存器）

这是现代操作系统中最常用的内存保护方式：

```
┌─────────────────────────────────────────────┐
│  基址寄存器（重定位寄存器）= 起始物理地址    │
│  限长寄存器（界限寄存器）= 最大逻辑地址      │
└─────────────────────────────────────────────┘

物理地址 = 逻辑地址 + 基址寄存器值
访问条件：逻辑地址 < 限长寄存器值
```

**工作原理**：
1. CPU生成逻辑地址
2. 检查逻辑地址是否小于限长寄存器的值
3. 若合法，计算物理地址 = 逻辑地址 + 基址寄存器的值
4. 若不合法，产生越界中断

> [!example] 示例
> 某进程的基址寄存器值为 1000，限长寄存器值为 1000（即进程大小为1000）：
> - 逻辑地址 500 → 500 < 1000（合法）→ 物理地址 = 500 + 1000 = **1500** → 允许
> - 逻辑地址 1200 → 1200 ≥ 1000（非法）→ **越界中断**
> - 逻辑地址 999 → 999 < 1000（合法）→ 物理地址 = 999 + 1000 = **1999** → 允许

### 4.3 两种保护方式对比

| 比较项 | 上下限寄存器法 | 基址限长寄存器法 |
|:-------|:---------------|:-----------------|
| 寄存器数量 | 2个（上限 + 下限） | 2个（基址 + 限长） |
| 检查方式 | 检查物理地址范围 | 检查逻辑地址是否越界 |
| 是否支持重定位 | 不直接支持 | **支持**（基址即重定位） |
| 现代OS使用 | 较少 | **广泛使用** |
| 也可用于存储保护 | 是 | 是 |

> [!important] 考点总结
> - **基址限长寄存器法**既能实现地址重定位（基址寄存器），又能实现内存保护（限长寄存器），因此是现代操作系统首选方案
> - 上下限寄存器法只能做保护，不能做重定位
> - 两种方法都依赖硬件支持，属于**硬件保护**机制

## 五、内存共享

### 5.1 共享的目的

- 节省内存空间
- 实现进程间通信

### 5.2 可共享的内容

| 共享类型 | 说明 |
|:---------|:-----|
| **代码共享** | 多个进程共享同一段代码（如编辑器程序） |
| **数据共享** | 多个进程共享某些数据（如共享内存通信） |

### 5.3 共享的要求

- 代码段必须是**可重入代码**（纯代码/Reentrant Code）
- 可重入代码在执行过程中不修改自身
- 共享的代码段需要设置**只读**属性

> [!note] 可重入代码
> 可重入代码是一种允许多个进程同时访问的代码，它在执行过程中不会修改自身的任何部分。可重入代码通常是**纯代码**，只包含指令和常量。

## 六、考点总结

### 6.1 核心概念速记

| 概念 | 一句话记忆 |
|:-----|:-----------|
| 逻辑地址 | 程序看到的地址，从0开始 |
| 物理地址 | 内存条上的真实地址 |
| 静态重定位 | 装入时改地址，之后不能动 |
| 动态重定位 | 运行时查寄存器，随时能移动 |
| 内存保护 | 防止进程越界访问 |
| 可重入代码 | 不修改自身的代码，可被共享 |

### 6.2 常考易错点

> [!danger] 易错点
> 1. **混淆装入方式**：绝对装入、可重定位装入、动态运行时装入的区别在于**地址变换的时机**不同
> 2. **混淆链接方式**：静态链接在装入前完成，装入时动态链接在装入时完成，运行时动态链接在运行时完成
> 3. **上下限 vs 基址限长**：上下限寄存器检查的是物理地址，基址限长寄存器检查的是逻辑地址
> 4. **动态重定位 ≠ 动态链接**：重定位解决的是地址映射问题，链接解决的是模块组装问题
