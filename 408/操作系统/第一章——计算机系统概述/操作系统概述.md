# 操作系统概述

[[第一章——计算机系统概述|← 返回目录]]

## 一、操作系统的定义

### 1.1 操作系统的概念

操作系统（Operating System, OS）是控制和管理整个计算机系统的硬件与软件资源，合理地组织、调度计算机的工作与资源的分配，进而为用户和其他软件提供方便接口与环境的程序集合。操作系统是计算机系统中**最基本的系统软件**。

### 1.2 操作系统的目标

| 目标 | 说明 |
|------|------|
| 方便性 | 为用户提供方便的用户接口，屏蔽硬件细节 |
| 有效性 | 提高系统资源利用率和系统吞吐量 |
| 可扩充性 | 方便地增加新的功能和模块 |
| 开放性 | 遵循国际标准，使系统之间能互操作 |

### 1.3 操作系统的作用

1. **作为用户与计算机硬件之间的接口**
   - 命令接口（联机命令接口、脱机命令接口）
   - 程序接口（系统调用）
   - 图形用户界面（GUI）

2. **作为计算机系统资源的管理者**
   - 处理机管理
   - 存储器管理
   - 文件管理
   - 设备管理

3. **作为扩充机器（虚拟机）**
   - 将裸机改造成功能更强、使用更方便的虚拟机

## 二、操作系统的功能

### 2.1 处理机管理（进程管理）

处理机管理的主要任务是对处理机进行分配，并对进程进行有效的控制和管理。

**主要功能包括：**

| 功能 | 说明 |
|------|------|
| 进程控制 | 进程的创建、撤销、阻塞、唤醒 |
| 进程同步 | 协调并发进程的执行顺序（信号量机制等） |
| 进程通信 | 进程间的信息交换（共享存储、消息传递、管道） |
| 进程调度 | 按一定算法将处理机分配给就绪进程 |

> [!tip] 考点提示
> 处理机管理是操作系统的核心功能，也是408考试的重点章节。进程管理中的调度算法、同步互斥问题是高频考点。

### 2.2 存储器管理（内存管理）

存储器管理的主要任务是为多道程序的运行提供良好的环境，提高存储器的利用率。

**主要功能包括：**

| 功能 | 说明 |
|------|------|
| 内存分配与回收 | 按策略为进程分配内存，及时回收 |
| 地址映射 | 将逻辑地址转换为物理地址（重定位） |
| 内存保护与共享 | 防止越界访问，支持进程间内存共享 |
| 内存扩充 | 借助虚拟存储技术，从逻辑上扩充内存 |

**内存分配方式：**

- **静态分配**：作业装入时一次性分配，运行期间不再改变
- **动态分配**：运行过程中根据需要动态分配和释放

### 2.3 文件管理

文件管理的主要任务是对用户文件和系统文件进行有效管理，实现按名存取。

**主要功能包括：**

| 功能 | 说明 |
|------|------|
| 文件存储空间管理 | 对磁盘空间进行分配和回收 |
| 目录管理 | 建立和维护文件目录结构 |
| 文件读写管理与保护 | 控制文件的读写操作，实现存取控制 |
| 文件共享与保护 | 支持多用户共享文件，提供安全保护机制 |

**文件系统的层次结构：**

```
用户接口层
    ↓
文件目录系统
    ↓
存取控制模块
    ↓
逻辑文件系统
    ↓
物理文件系统（设备驱动）
```

### 2.4 设备管理

设备管理的主要任务是管理各类外部设备，完成用户提出的I/O请求。

**主要功能包括：**

| 功能 | 说明 |
|------|------|
| 缓冲管理 | 使用缓冲区缓解CPU与I/O设备速度差异 |
| 设备分配 | 按策略为进程分配所需设备 |
| 设备处理（驱动） | 控制设备完成I/O操作 |
| 设备独立性（无关性） | 用户程序不依赖具体物理设备 |

**设备分类：**

- 按使用特性：人机交互设备、存储设备、网络通信设备
- 按传输速率：低速、中速、高速设备
- 按资源分配：独占设备、共享设备、虚拟设备

### 2.5 用户接口

操作系统为用户提供以下几种接口：

| 接口类型 | 说明 | 示例 |
|----------|------|------|
| 联机命令接口（交互式） | 用户输入命令，系统立即执行 | Linux shell命令 |
| 脱机命令接口（批处理） | 用户提交一组命令，系统按序执行 | Shell脚本、批处理文件 |
| 程序接口（系统调用） | 用户程序通过系统调用请求OS服务 | `read()`, `write()`, `fork()` |
| 图形用户界面（GUI） | 通过窗口、图标等图形元素操作 | Windows桌面、GNOME |

> [!important] 考点区分
> - **联机命令接口**：交互式，一条一条执行
> - **脱机命令接口**：批处理，一组一组执行
> - **程序接口**：即系统调用（广义指令），是应用程序请求OS服务的唯一方式

## 三、操作系统的特征

### 3.1 并发（Concurrence）

**并发**是指两个或多个事件在**同一时间间隔内**发生。在多道程序环境下，多个程序同时在计算机中运行，宏观上是同时的，微观上是交替的。

> [!warning] 并发 vs 并行
> - **并发**：同一时间**间隔**内发生，宏观同时微观交替（单CPU）
> - **并行**：同一时间**时刻**发生，真正的同时执行（多CPU）
>
> 并行是并发的特例，并发是并行的扩展。408考试中经常考查这两个概念的区别。

**并发的关键实现技术：**
- 进程（进程是并发执行的基本单位）
- 线程（轻量级进程，更小的并发单位）
- 时间片轮转调度

### 3.2 共享（Sharing）

**共享**是指系统中的资源可供内存中多个并发执行的进程共同使用。

**两种共享方式：**

| 共享方式 | 说明 | 示例 |
|----------|------|------|
| 互斥共享 | 资源在一段时间内只允许一个进程访问 | 打印机、磁带机 |
| 同时共享 | 允许多个进程在同一时间段内"同时"访问 | 磁盘文件、共享内存 |

> [!tip] 考点提示
> - 互斥共享称为**临界资源**，需要同步机制保护
> - 同时共享在微观上仍然是交替访问（如磁盘）
> - 并发和共享是操作系统两个最基本的特征，二者互为存在条件

### 3.3 虚拟（Virtual）

**虚拟**是指把物理上的一个实体变为逻辑上的多个对应物，或把物理上的多个实体变为逻辑上的一个对应物。

**常见的虚拟技术：**

| 虚拟类型 | 说明 | 示例 |
|----------|------|------|
| 时分复用技术 | 利用时间片轮转实现虚拟 | 虚拟处理器（多道程序） |
| 空分复用技术 | 利用存储空间的空闲区域实现虚拟 | 虚拟存储器 |
| 虚拟设备 | 利用SPOOLing技术将独占设备虚拟为共享设备 | 虚拟打印机 |

> [!important] 考点
> - 虚拟处理器：通过多道程序设计技术，让多个用户感觉各自独占CPU
> - 虚拟存储器：通过虚拟存储技术，让用户感觉拥有比实际更大的内存
> - 如果没有并发性，就谈不上虚拟性

### 3.4 异步（Asynchronism）

**异步**是指多个进程按照各自独立的、不可预知的速度向前推进。由于并发执行的进程争用资源，进程的执行速度不可预知。

> [!tip] 理解要点
> - 只要运行环境相同，OS必须保证结果相同（可再现性）
> - 异步性是并发和共享的必然结果
> - 操作系统通过进程同步机制来应对异步性带来的问题

### 3.5 四大特征的关系

```
并发 ──┐
      ├──→ 共享 ←──┐
      │            │
      └──→ 虚拟     │
                   │
      异步 ←───────┘
```

- **并发**和**共享**是两个最基本的特征
- 并发是共享的前提，共享是并发的保证
- 虚拟以并发为前提
- 异步是并发和共享的结果

## 四、操作系统的发展历程

### 4.1 手工操作阶段

- 无操作系统
- 用户独占全机，CPU利用率极低
- 人机矛盾突出：人工操作速度远慢于CPU计算速度

### 4.2 批处理系统

#### 单道批处理系统

| 特点 | 说明 |
|------|------|
| 自动性 | 作业自动过渡，减少了人工干预 |
| 顺序性 | 作业按顺序依次处理 |
| 单道性 | 内存中只有一道程序 |

**缺点：**
- 资源利用率低：CPU等待I/O时空闲
- 内存中仅有一道程序，无法充分利用资源

#### 多道批处理系统

| 特点 | 说明 |
|------|------|
| 多道性 | 内存中同时驻留多道程序 |
| 调度性 | 按调度策略选择作业运行 |
| 无序性 | 作业完成的顺序与提交顺序无关 |
| 交互性差 | 用户无法与程序交互 |

**优点：**
- 资源利用率高：CPU忙碌时I/O工作，I/O忙碌时CPU计算
- 系统吞吐量大：单位时间内完成的作业多

> [!important] 考点
> - 多道批处理系统是**操作系统形成的标志**
> - 引入了中断技术来实现多道程序的并发执行
> - 多道程序设计技术是操作系统发展的基础

### 4.3 分时操作系统

**分时操作系统**是将CPU的时间划分成很短的时间片，轮流分配给各个联机终端用户使用。

| 特点 | 说明 |
|------|------|
| 同时性 | 多个终端用户同时使用 |
| 交互性 | 用户可以与系统进行人机对话 |
| 独立性 | 用户之间互不干扰 |
| 及时性 | 用户请求能在短时间内得到响应 |

> [!tip] 考点对比
> - **多道批处理**：吞吐量大，但无交互性，平均周转时间长
> - **分时系统**：交互性好，响应及时，但吞吐量较小

### 4.4 实时操作系统

**实时操作系统**是指系统能够及时响应外部事件请求，在规定时间内完成对该事件的处理，并控制所有实时任务协调一致地运行。

| 类型 | 说明 | 示例 |
|------|------|------|
| 硬实时系统 | 必须在严格时限内完成，否则造成严重后果 | 导弹控制、心脏起搏器 |
| 软实时系统 | 偶尔违反时限可以接受 | 视频播放、在线订票 |

**实时系统的特点：**
- 及时性：响应时间有严格限制
- 可靠性：系统必须高度可靠
- 交互性：根据应用不同，交互能力不同

### 4.5 网络操作系统与分布式操作系统

| 特性 | 网络操作系统 | 分布式操作系统 |
|------|-------------|---------------|
| 概念 | 各计算机通过网络互联，各自有独立OS | 多台计算机协同工作，对用户透明 |
| 耦合度 | 松耦合 | 紧耦合 |
| 透明性 | 低 | 高（用户感觉是一台计算机） |
| 分布性 | 各计算机独立处理 | 任务分布到各节点并行处理 |
| 并发性 | 各节点独立并发 | 全局并发 |
| 示例 | Windows Server、Linux网络服务 | Amoeba、Chorus |

> [!warning] 考点
> - 网络OS：用户知道多台计算机的存在
> - 分布式OS：用户感觉只有一台计算机（透明性）
> - 分布式OS是网络OS的进一步发展

### 4.6 操作系统发展历程总结

```
手工操作 → 单道批处理 → 多道批处理 → 分时系统 → 实时系统 → 网络OS → 分布式OS
   │           │            │            │          │          │          │
   ↓           ↓            ↓            ↓          ↓          ↓          ↓
 无OS      无并发       有并发       有交互    有实时性   多机互联   透明性
```

## 五、操作系统的运行环境

### 5.1 内核态与用户态

#### 特权指令与非特权指令

| 类型 | 说明 | 示例 |
|------|------|------|
| 特权指令 | 只能在内核态下执行的指令 | I/O指令、置中断指令、存取特殊寄存器、清内存、修改PSW |
| 非特权指令 | 在用户态和内核态下都可以执行 | 算术运算、逻辑运算、取数指令、访管指令 |

#### 处理器运行模式

| 模式 | 说明 | 权限 |
|------|------|------|
| 内核态（核心态/管态） | 运行操作系统内核程序 | 可执行所有指令，访问所有资源 |
| 用户态（目态） | 运行用户应用程序 | 只能执行非特权指令 |

> [!important] 考点
> - 用户态 → 内核态：通过**中断或异常**（唯一途径）
> - 内核态 → 用户态：通过执行一条特权指令（如iret），修改PSW中的模式位
> - 用户程序不能直接执行I/O操作，必须通过**系统调用**请求OS代为完成

#### 模式切换示意图

```
用户程序执行中
    │
    ├─ 需要I/O操作 → 陷入指令（trap） → 切换到内核态
    │                                      │
    │                                 OS执行I/O操作
    │                                      │
    │                                 返回用户态 ←── iret指令
    │
    └─ 继续执行用户程序
```

### 5.2 中断与异常

#### 中断（Interrupt）

**中断**是CPU对系统中发生的某个事件作出的一种反应。中断是操作系统工作的基础，是操作系统得以并发执行的前提。

**中断的分类：**

| 分类方式 | 类别 | 说明 |
|----------|------|------|
| 按来源 | 外中断（中断/硬件中断） | 来自CPU外部，如I/O完成、时钟中断、键盘中断 |
| 按来源 | 内中断（异常/例外） | 来自CPU内部，如程序性异常、硬件故障 |
| 按是否可屏蔽 | 可屏蔽中断 | 可通过中断屏蔽字屏蔽，如I/O中断 |
| 按是否可屏蔽 | 不可屏蔽中断 | 不可屏蔽，如电源故障、内存校验错 |

#### 异常（Exception / Trap）

**异常（内中断）**是CPU执行指令时本身出现的问题（如除零、越界、缺页等）。

| 异常类型 | 说明 | 处理方式 |
|----------|------|----------|
| 陷阱（Trap/陷入） | 有意而为的异常，如系统调用 | 返回到下一条指令 |
| 故障（Fault） | 可恢复的错误，如缺页异常 | 返回到当前指令重新执行 |
| 终止（Abort） | 不可恢复的致命错误 | 终止程序，不返回 |

> [!tip] 考点区分
> - **陷阱（Trap）**：用户程序主动请求OS服务（系统调用），返回到**下一条**指令
> - **故障（Fault）**：如缺页中断，处理后返回到**当前**指令重新执行
> - **终止（Abort）**：硬件故障等，直接终止，不返回
> - **外中断**：与当前执行的指令无关，返回到**下一条**指令

#### 中断处理过程

```
1. 中断发生
    ↓
2. CPU检测到中断信号
    ↓
3. 保存当前程序的上下文（PC、PSW、通用寄存器等）
    ↓
4. 根据中断类型查找中断向量表，确定中断服务程序入口
    ↓
5. 切换到内核态
    ↓
6. 执行中断服务程序
    ↓
7. 恢复被中断程序的上下文
    ↓
8. 切换回用户态，继续执行被中断的程序
```

> [!important] 考点
> - 中断是操作系统工作的动力（"操作系统是由中断驱动的"）
> - 每条指令执行结束后，CPU都会检查是否有中断信号
> - 中断向量表存放各类中断处理程序的入口地址

### 5.3 系统调用

#### 系统调用的概念

**系统调用**是操作系统提供给应用程序（程序员）使用的接口，是应用程序请求操作系统服务的唯一方式。

> [!warning] 考点
> - 库函数不等于系统调用。部分库函数（如`printf`）会调用系统调用，部分（如`strlen`）不会
> - 凡是涉及资源管理、与硬件相关的操作，都必须通过系统调用完成

#### 系统调用的分类

| 分类 | 功能 | 常见系统调用 |
|------|------|-------------|
| 设备管理 | 请求/释放设备、I/O读写 | `read()`, `write()`, `ioctl()` |
| 文件管理 | 创建/删除/读/写文件 | `open()`, `close()`, `read()`, `write()` |
| 进程控制 | 创建/撤销进程、进程同步 | `fork()`, `exec()`, `wait()`, `exit()` |
| 进程通信 | 消息传递、共享内存 | `pipe()`, `shmget()`, `mmap()` |
| 内存管理 | 内存分配/回收 | `brk()`, `mmap()`, `munmap()` |
| 信息维护 | 获取/设置系统信息 | `getpid()`, `gettimeofday()` |

#### 系统调用的执行过程

```
用户程序
    ↓
① 传递系统调用参数（通过寄存器或栈）
    ↓
② 执行陷入指令（trap / int / syscall）
    ↓
③ CPU切换到内核态
    ↓
④ 根据系统调用号查系统调用表，找到对应的服务程序
    ↓
⑤ 执行系统调用服务程序
    ↓
⑥ 返回结果到用户程序
    ↓
⑦ CPU切换回用户态（执行iret）
    ↓
继续执行用户程序
```

**系统调用过程示例（伪代码）：**

```c
// 用户程序中调用 write() 系统调用
int fd = open("test.txt", O_RDONLY);  // 系统调用：打开文件
char buf[1024];
int n = read(fd, buf, 1024);          // 系统调用：读取文件
write(1, buf, n);                      // 系统调用：写入标准输出
close(fd);                             // 系统调用：关闭文件

// 系统调用在内核中的大致流程：
// 1. 用户态：将参数放入寄存器
// 2. 执行陷入指令（如 x86 的 int 0x80 或 syscall）
// 3. 内核态：保存用户态上下文
// 4. 根据 syscall 号查表，跳转到对应内核函数
// 5. 执行内核函数（如 sys_read）
// 6. 将结果放入寄存器
// 7. 恢复用户态上下文，返回用户程序
```

> [!important] 考点
> - **陷入指令（trap）**是在用户态执行的，但它是一条特殊的非特权指令
> - 陷入指令是唯一一个只能在用户态执行的指令（其功能是切换到内核态）
> - 系统调用发生在内核态，但发起系统调用的程序运行在用户态
> - 系统调用需要CPU从用户态切换到内核态，开销比普通函数调用大

#### 系统调用与库函数的区别

| 比较项 | 系统调用 | 库函数 |
|--------|----------|--------|
| 执行位置 | 内核态 | 用户态 |
| 开销 | 大（涉及模式切换） | 小（普通函数调用） |
| 调用方式 | 陷入指令 | 函数调用指令（call） |
| 是否可替换 | 不可替换 | 可替换 |
| 示例 | `write()` | `printf()`, `strlen()` |

### 6.2 易错点

1. **陷入指令不是特权指令**：陷入指令是在用户态执行的，其作用是引起陷入，切换到内核态
2. **系统调用不是特权指令**：系统调用是通过陷入指令实现的，陷入指令本身不是特权指令
3. **中断处理程序在内核态执行**：无论是外中断还是内中断，中断处理程序都在内核态运行
4. **缺页中断是内中断中的故障**：缺页中断属于故障（Fault），处理后返回当前指令重新执行
5. **库函数 ≠ 系统调用**：库函数运行在用户态，系统调用运行在内核态

### 6.3 记忆口诀

- **四大特征**：并发共享最基本，虚拟异步紧相连
- **OS功能**：处理机、存储器、文件、设备加接口
- **发展历程**：手工→单道→多道→分时→实时→网络→分布式
- **中断分类**：外中断来自外部（I/O、时钟），内中断来自内部（陷阱、故障、终止）
