# 专题01——AVL树的增删改查语句级精讲

> [!abstract] 知识定位
> 本专题把 AVL 树的**查、增、删、改**四类操作拆到**每一条指针赋值语句**的粒度：每条语句"断开谁、接上谁"、语句顺序为什么不能换、旋转后新根如何"还给"父节点。四种旋转（LL/RR/LR/RL）的**定义与形态图**见 [[第六章——查找|第六章]] §5.2，本专题不重复画图定义，专讲**语句执行过程**；AVL 的定义与平衡因子见 [[第四章——树与二叉树|第四章]] §3.2。

---

## 一、预备：语句级读法的三条铁律

所有树/链表的指针操作，都遵守同一套"改接"纪律。以单链表在 `s` 之后插入 `p` 为例：

```c
p->next = s->next;   // ① 先保存旧关系：p 接管 s 的后继
s->next = p;         // ② 再覆盖旧关系：s 的后继改成 p
```

**顺序不能颠倒**：若先执行 `s->next = p`，则 `s->next` 的旧值（原后继节点地址）被覆盖丢失，`p->next = s->next` 就变成 `p->next = p`，链尾整段断链。

由此提炼三条铁律，AVL 的所有旋转语句都是它们的实例：

| 铁律 | 内容 | AVL 中的体现 |
|:-----|:-----|:------------|
| 铁律一 | **先保存，再覆盖**：凡是会被 `=` 左侧覆盖掉的旧值，必须先被某处（临时变量或另一条指针）接住 | 右旋第一句 `b = a->lchild` 先接住 b，之后 `a->lchild` 才敢改写 |
| 铁律二 | **先接孙子，再转正儿子**：新根原来伸向"转轴内侧"的那棵子树，必须先挂到旧根手上，新根才能腾出该指针指向旧根 | 右旋中 `a->lchild = b->rchild` 必须在 `b->rchild = a` 之前 |
| 铁律三 | **高度自底向上更新**：`height(x)` 依赖两个孩子的高度，所以必须**先更新两个孩子，再更新自己** | 每次旋转的收尾两句 `updateHeight(a); updateHeight(b);` 顺序固定 |

> [!tip] 读代码的口诀
> 每条 `x->field = y;` 都读成一句话："**x 的 field 指针，改为指向 y**"。写代码前先问：这条语句覆盖的旧值，被谁接住了？

## 二、节点结构与辅助函数

### 2.1 结构体定义

```c
typedef struct AVLNode {
    int key;                  // 关键字（BST 性质作用于它）
    int height;               // 以该节点为根的子树高度（空树高度定义为 0）
    struct AVLNode *lchild;   // 左孩子指针
    struct AVLNode *rchild;   // 右孩子指针
} AVLNode, *AVLTree;
```

> **约定**：本专题取**空树高度 = 0**，单节点高度 = 1。王道部分版本在节点里存 `bf`（平衡因子）而非 `height`，二者可互相换算（`bf = H(左) − H(右)`），语句结构完全一致，只是失衡判断从 `|bf| > 1` 换成 `bf == ±2`。

### 2.2 三个辅助函数

```c
// 取高度：把"空指针"翻译成 0，避免每次判空
int Height(AVLNode *p) {
    return p == NULL ? 0 : p->height;
}

// 取平衡因子：bf = 左子树高 − 右子树高，合法值 ∈ {-1, 0, 1}
int BalanceFactor(AVLNode *p) {
    return Height(p->lchild) - Height(p->rchild);
}

// 更新高度：必须放在两个孩子高度都正确之后调用（铁律三）
void updateHeight(AVLNode *p) {
    int hl = Height(p->lchild), hr = Height(p->rchild);
    p->height = (hl > hr ? hl : hr) + 1;
}
```

### 2.3 最小不平衡子树

**定义**：插入/删除后，**以离被改动节点最近的失衡节点为根**的子树。

> [!important] 为什么只需调整这一棵
> 失衡只可能沿着"改动点到根"这条路径向上传播；第一个失衡节点 A 把不平衡"挡住"之后，对 A 做旋转恢复平衡，且**插入场景下**旋转后子树总高度与插入前相同——A 的祖先看到的这棵子树高度没变，不可能因此失衡。所以插入最多旋转一次、只动最小不平衡子树。删除场景不同，见 §六。

## 三、查（Search）

AVL 首先是 BST，查找语句与 BST 完全相同，**不需要任何旋转或平衡判断**——平衡性只保证树高是 O(log n)，从而查找稳定。

### 3.1 递归版

```c
AVLNode *Search(AVLTree T, int key) {
    if (T == NULL || T->key == key)   // 空树失败，或命中
        return T;
    if (key < T->key)
        return Search(T->lchild, key);   // 小往左
    else
        return Search(T->rchild, key);   // 大往右
}
```

### 3.2 非递归版（语句级）

```c
AVLNode *Search(AVLTree T, int key) {
    AVLNode *p = T;                       // p 是当前考察节点
    while (p != NULL && p->key != key) {  // 未失败且未命中才继续
        if (key < p->key)
            p = p->lchild;                // 指针下移一层：p 改指左孩子
        else
            p = p->rchild;                // p 改指右孩子
    }
    return p;                             // NULL=查找失败；非空=命中节点
}
```

每条语句的作用：`p = p->lchild` 是**指针下移**（不是赋值数据），循环出口有两种——`p == NULL`（走到空，失败）或 `p->key == key`（命中）。比较次数 ≤ 树高 h ≤ 1.44·log₂(n+2)。

## 四、旋转：四条语句的逐句执行

旋转是 AVL 唯一的"改接"动作，全部符合铁律一、二。下面以**右旋**为母版逐句拆，左旋镜像。

### 4.1 右旋（RightRotate）——LL 型用

失衡形态（在 B 的左子树侧插入导致 A 的 bf = +2）：

```
        A (bf=+2)                记号：
       / \                        h 为子树高度，
      B   AR      h(C)=h+1        AR/BR/CL/CR 是四棵"整体搬运"的子树，
     / \         h(BR)=h          旋转中它们自身不动，
    C   BR       或两者相等        只是换挂到别的父节点下
```

目标形态：

```
        B (bf=0)
       / \
      C   A
     / \ / \
   ... BR CL AR
```

```c
AVLNode *RightRotate(AVLNode *a) {
    AVLNode *b = a->lchild;      // ① 保存：b 接住 A 的左孩子（新根候选）
    a->lchild = b->rchild;       // ② 接孙子：B 的右子树 BR 整体挂到 A 的左指针上
    b->rchild = a;               // ③ 转正：A 成为 B 的右孩子
    updateHeight(a);             // ④ 先更新旧根 A（此时 A 的左=BR、右=AR 已定稿）
    updateHeight(b);             // ⑤ 再更新新根 B（铁律三：先孩子后自己）
    return b;                    // ⑥ 把新根还给调用者
}
```

逐句解读（对着图执行）：

| 语句 | 断开了谁 | 接上了谁 | 依据 |
|:-----|:--------|:--------|:-----|
| ① `b = a->lchild` | — | 临时变量 b 指向 B | 铁律一：②③ 即将改写 `a->lchild` 与 `b->rchild`，B 的地址必须先存住 |
| ② `a->lchild = b->rchild` | A—B 父子边；B—BR 父子边 | A—BR 父子边 | BR 被 A 接住后，`b->rchild` 才允许被 ③ 覆盖 |
| ③ `b->rchild = a` | — | B—A 父子边（A 降为右孩子） | 此时 BR 已有新父（A），覆盖安全 |
| ④ `updateHeight(a)` | — | — | A 的孩子已定稿（左 = BR、右 = AR，AR 全程未被碰过），先算 A |
| ⑤ `updateHeight(b)` | — | — | B 的孩子（C、A）高度都已正确，最后算 B |
| ⑥ `return b` | 旧的"父 → A"边 | 调用者负责改成"父 → B" | 见 §4.4 回接问题 |

> **注意 ④ 的括号内容**：右旋后 A 的左孩子是 BR、右孩子仍是 AR——A 的 `rchild` 从头到尾没被碰过，这正是旋转"只动三条边"的体现：断 A—B、断 B—BR 两条旧边，接 A—BR、接 B—A 两条新边，加上 ① 的临时保存与 ⑥ 的返回，共六条语句。

### 4.2 左旋（LeftRotate）——RR 型用

与右旋**完全镜像**：`lchild` 与 `rchild` 互换即可。

```c
AVLNode *LeftRotate(AVLNode *a) {
    AVLNode *b = a->rchild;      // ① 保存：接住 A 的右孩子 B
    a->rchild = b->lchild;       // ② 接孙子：B 的左子树 BL 挂到 A 的右指针
    b->lchild = a;               // ③ 转正：A 成为 B 的左孩子
    updateHeight(a);             // ④ 先旧根
    updateHeight(b);             // ⑤ 后新根
    return b;                    // ⑥ 还新根
}
```

### 4.3 LR 与 RL：两次单旋的复合

**LR 型**（在 A 的左孩子 B 的右子树上插入，A 的 bf = +2、B 的 bf = −1）：

```c
AVLNode *LeftRightRotate(AVLNode *a) {
    a->lchild = LeftRotate(a->lchild);   // 第一步：对 B 左旋，形态变成 LL
    return RightRotate(a);               // 第二步：对 A 右旋
}
```

**RL 型**（镜像）：

```c
AVLNode *RightLeftRotate(AVLNode *a) {
    a->rchild = RightRotate(a->rchild);  // 第一步：对 B 右旋，形态变成 RR
    return LeftRotate(a);                // 第二步：对 A 左旋
}
```

语句级的关键在第一行：**第一步旋转的新根必须写回 `a->lchild`**。以 LR 为例，对 B 左旋后新根是 C，若不执行 `a->lchild = C` 的回写，A 仍指向旧根 B，第二步右旋就会绕着错误的轴转——这是手写代码最高频的错误。

LR 复合过程中子树的最终归属（设 C 的左子树 CL、右子树 CR）：

| 子树 | 旋转前挂在 | 旋转后挂在 |
|:-----|:----------|:----------|
| CL | C 左 | **B 右**（第一步左旋时按 4.2 ② 移交） |
| CR | C 右 | **A 左**（第二步右旋时按 4.1 ② 移交） |
| BR | B 右 | 不动，仍在 B 右 |
| AR | A 右 | 不动，仍在 A 右 |

### 4.4 被忽略的第六条语句：新根回接

`return b` 只是"报告新根"，真正把新根接回树上的是**调用处**：

- **递归写法**：父层用 `T->lchild = Insert(T->lchild, key)` 这种"返回值回写"句式，天然完成回接（见 §5.2）。
- **非递归写法**：若失衡节点 A 就是整棵树的根，必须改树头指针 `T = b`；若 A 有父节点 P，需记住 P 以及 A 是 P 的左孩子还是右孩子，旋转后执行 `P->lchild = b` 或 `P->rchild = b`。

> [!warning] 常见错误
> 只做 ①②③④⑤ 五句、丢掉回接：旋转在局部看是对的，但 A 的父节点仍指向 A，整棵树从父节点看进去形态错乱（甚至 A 与 B 互为父子成环）。

## 五、增（Insert）

### 5.1 三步模型

1. **按 BST 规则递归下降找位置**——与普通 BST 插入完全相同；
2. **新节点必是叶子**，创建后开始**回溯**；
3. **回溯途中逐层更新高度、检查 bf**，在第一个失衡处（最小不平衡子树根）旋转一次，回写新根，继续返回。

### 5.2 完整代码与逐句注释

```c
AVLNode *Insert(AVLTree &T, int key) {
    // ---- 第一步：BST 下降 ----
    if (T == NULL) {                        // 找到空位
        T = (AVLNode *)malloc(sizeof(AVLNode));
        T->key = key;
        T->height = 1;                      // 单节点高度 = 1
        T->lchild = T->rchild = NULL;       // 新节点必是叶子
        return T;
    }
    if (key == T->key) return T;            // AVL 不允许重复关键字，直接返回
    if (key < T->key)
        T->lchild = Insert(T->lchild, key); // 递归 + 返回值回写（见下注）
    else
        T->rchild = Insert(T->rchild, key);

    // ---- 第二步：回溯时维护 ----
    updateHeight(T);                        // 孩子高度已定稿，更新自己（铁律三）
    int bf = BalanceFactor(T);

    // ---- 第三步：失衡分诊（四种情况）----
    if (bf > 1) {                           // 左侧重（bf = +2）
        if (BalanceFactor(T->lchild) >= 0)  // 左孩子也左侧重或平 → LL
            T = RightRotate(T);
        else                                // 左孩子右侧重 → LR
            T = LeftRightRotate(T);
    } else if (bf < -1) {                   // 右侧重（bf = −2）
        if (BalanceFactor(T->rchild) <= 0)  // 右孩子右侧重或平 → RR
            T = LeftRotate(T);
        else                                // 右孩子左侧重 → RL
            T = RightLeftRotate(T);
    }
    return T;                               // 失衡时这里返回的已是新根，由上一层回写
}
```

> [!important] `T->lchild = Insert(T->lchild, key)` 这一句式的三重身份
> ① 普通递归调用；② 把子树（可能已旋转换根）的新根**回写**到 T 的指针域，完成 §4.4 的回接；③ 参数用引用 `AVLTree &T`，使 `T = RightRotate(T)` 能改到调用者手中的指针。这三件事用一句代码同时完成，是递归版 AVL 最紧凑的写法。

**分诊逻辑的两级判断**（先定大方向，再定子方向）：

| A 的 bf | 看谁 | 孩子的 bf | 类型 | 旋转 |
|:-------|:-----|:---------|:-----|:-----|
| +2 | 左孩子 B | ≥ 0（左重或平） | LL | 对 A 右旋 |
| +2 | 左孩子 B | −1（右重） | LR | 先 B 左旋，再 A 右旋 |
| −2 | 右孩子 B | ≤ 0（右重或平） | RR | 对 A 左旋 |
| −2 | 右孩子 B | +1（左重） | RL | 先 B 右旋，再 A 左旋 |

> **口诀**：同侧单旋，异侧双旋；LL 右旋、RR 左旋（失衡在哪边，就往**反方向**转）。

### 5.3 实例推演：依次插入 3, 2, 1, 4, 5, 6, 7

| 步骤 | 插入 | 回溯检查（自底向上） | 触发的语句 |
|:-----|:-----|:---------------------|:-----------|
| 1 | 3 | — | 走 `T == NULL` 分支建叶子：`3(0)` |
| 2 | 2 | 2 挂 3 左；bf(3) = +1 | 无失衡，得 `3(+1)` |
| 3 | 1 | 1 挂 2 左；bf(2) = +1 → bf(3) = +2，左孩子 2 的 bf = +1 → **LL** | `RightRotate(3)`：b=2；3->lchild=NULL（2 本无右子树）；2->rchild=3。得 `2(0)`：左 1、右 3 |
| 4 | 4 | 4 挂 3 右；bf(3) = −1 → bf(2) = −1 | 无失衡 |
| 5 | 5 | 5 挂 4 右；bf(4) = −1 → **bf(3) = −2**，右孩子 4 的 bf = −1 → **RR** → bf(2) = −1 | `LeftRotate(3)`：b=4；3->rchild=NULL（4 本无左子树）；4->lchild=3；回写 `2->rchild = 4` |
| 6 | 6 | 6 挂 5 右；bf(5) = −1 → **bf(4) = −1，平衡，继续上溯** → bf(2) = −2，右孩子 4 的 bf = −1 → **RR（失衡点在根 2）** | `LeftRotate(2)`：b=4；2->rchild=4->lchild 即 3；4->lchild=2；树头指针改接 `T = 4`（§4.4 的"失衡点即根"情形） |
| 7 | 7 | 7 挂 6 右；bf(6) = −1 → **bf(5) = −2**，右孩子 6 的 bf = −1 → **RR** → bf(4) = 0 | `LeftRotate(5)`：b=6；5->rchild=NULL；6->lchild=5；回写 `4->rchild = 6` |

每步之后的精确树形（已用 C 程序逐步模拟验证，含 BST 合法性检查）：

```
插 5 后：                插 6 后：                插 7 后（最终树）：

     2(−1)                  4(0)                    4(0)
    /    \                /     \                  /     \
  1(0)   4(0)          2(0)     5(−1)           2(0)     6(0)
        /    \         /   \        \           /   \    /   \
      3(0)   5(0)   1(0)  3(0)     6(0)      1(0) 3(0) 5(0) 7(0)
```

> [!warning] 第 6 步是全例最易算错的一步
> 插入 6 后，回溯**经过 5、4 时它们都没失衡**（bf(5) = −1、bf(4) = 1−2 = −1），真正的失衡点在**根 2**（bf = 1−3 = −2）。心算时极易在 4 处提前误判失衡、或在 2 处漏判。防错办法只有一条：**逐层算 bf、见 ±2 才转、转完重算再上溯**。此时失衡点恰好是树根，旋转后新根 4 通过树头指针回接（`T = 4`），这是 §4.4 非递归回接的实例。

> [!tip] 方法论
> 本推演经过可执行 C 程序逐步模拟验证（每步输出树形与 bf，并检查 BST 合法性）。手绘推演 AVL 时，"哪一层先失衡"完全取决于各子树的**精确高度**，心算高度是最大错误源——考场上建议像本表一样，在每个节点旁标注高度再算 bf。

### 5.4 插入为什么最多旋转一次

设最小不平衡子树的根为 A（|bf(A)| = 2）。插入前 A 是平衡的且**在插入路径上**，可推出插入前 A 的两侧子树高恰差 1（重侧 h+1、轻侧 h，A 高 h+2）；插入使重侧再长高 1，A 高 h+3、失衡。以 LL 为例：A 的左孩子 B 高 h+2（bf = +1），B 的左子树 C 高 h+1、右子树 BR 高 h 或 h+1，A 的右子树 AR 高 h。右旋后新根 B 的左子树 C 高 h+1、右子树（A：左 BR、右 AR）高 ≤ h+1，故 **B 高 = h+2，恰好恢复为插入前 A 的高度**。其余三型同理。

A 的父节点看到的这棵子树高度与插入前一模一样，bf 不变，故失衡不会继续上传。→ 插入 = 一次下降 O(h) + **至多一次旋转**（约 6 条指针语句）+ 回溯 O(h) 次高度更新。对照 §5.3：7 次插入共触发 4 次旋转，**每次插入都不超过 1 次**——第 6 步回溯路过 5、4 时它们未失衡，旋转只在真正的失衡点 2 发生一次。

## 六、删（Delete）

### 6.1 与 BST 删除的衔接

删除按 BST 规则分三种情况，前两种**不产生新节点、只改指针**；第三种**转化为前两种**：

| 情况 | 操作 | 语句 |
|:-----|:-----|:-----|
| 叶子节点 | 直接摘除 | 父节点相应指针置 NULL；`free(p)` |
| 只有一棵子树 | 子树顶替 | `parent->lchild(或 rchild) = p->lchild(或 p->rchild)`（一条改接语句，顺序无关——只有一个孩子，不存在覆盖丢失） |
| 有两棵子树 | **换值 + 转删** | ① 找直接前驱（左子树最右）或直接后继（右子树最左）s；② `p->key = s->key`（只搬关键字，不动指针）；③ 到 s 所在子树里**递归删除 s**——s 必是叶子或单分支，落回前两种情况 |

```c
AVLNode *Delete(AVLTree &T, int key) {
    if (T == NULL) return NULL;                       // 没找到，直接返回
    if (key < T->key) {
        T->lchild = Delete(T->lchild, key);           // 去左子树删，回写新根
    } else if (key > T->key) {
        T->rchild = Delete(T->rchild, key);           // 去右子树删，回写新根
    } else {                                          // 命中目标节点 T
        if (T->lchild != NULL && T->rchild != NULL) { // 情况三：双子
            AVLNode *s = T->rchild;                   // 找直接后继：右子树最左
            while (s->lchild != NULL) s = s->lchild;
            T->key = s->key;                          // 换值（数据搬移，指针不动）
            T->rchild = Delete(T->rchild, s->key);    // 转删后继（后继必无左孩子）
        } else {                                      // 情况一/二：叶或单分支
            AVLNode *q = T;
            T = (T->lchild != NULL) ? T->lchild : T->rchild;  // 孩子顶替（叶子时顶替为 NULL）
            free(q);                                  // 释放旧节点
        }
    }
    if (T == NULL) return NULL;                       // 子树删空，无需平衡

    // ---- 回溯维护：与插入同构，但循环检查到底 ----
    updateHeight(T);
    int bf = BalanceFactor(T);
    if (bf > 1) {
        if (BalanceFactor(T->lchild) >= 0) T = RightRotate(T);      // LL
        else                               T = LeftRightRotate(T);  // LR
    } else if (bf < -1) {
        if (BalanceFactor(T->rchild) <= 0) T = LeftRotate(T);       // RR
        else                               T = RightLeftRotate(T);  // RL
    }
    return T;                                         // 可能被父层再次检查、再次旋转
}
```

### 6.2 与插入的本质区别：回溯不停

删除使某侧子树**变矮**，旋转恢复的是"当前节点"的平衡，但旋转后该子树高度**可能仍比删除前矮 1**，于是失衡继续向祖先传播：

| 维度 | 插入 | 删除 |
|:-----|:-----|:-----|
| 失衡传播 | 到最小不平衡子树为止 | 可能一路传到根 |
| 旋转次数 | 至多 1 次 | 最坏 O(log n) 次（每层一次） |
| 回溯终止条件 | 旋转后即可直接 return | 每层都必须算 bf，直到根 |
| 递归代码差异 | 分诊后 return | 分诊后**继续 return 给上层再查**（代码形式相同，语义不同：上层不会跳过检查） |

> [!tip] 记忆点
> 插入"长高"被一次旋转压回去就完事；删除"变矮"会像多米诺一样逐层传染——**删除后从改动点一直检查到根**。

### 6.3 换值语句 `T->key = s->key` 的两句辨析

- **为什么搬值不搬节点**：s 有自己的孩子（可能有右子树），把 s 的节点结构整体挪到 T 的位置需要重接 2~3 条边；而只搬 `key` 后，删 s 落回"叶/单分支"简单情况，总共只需一条顶替语句。代价是数据搬移，但指针操作最少、最不易错。
- **408 手绘题惯例**：教材与真题常取**直接前驱**（左子树最右节点）作替换；代码实现取前驱或后继都正确，考试按题目指定（无指定时两种都给分，但全程要一致）。

## 七、改（Update）

AVL 无独立的"修改"操作——**改 = 删 + 增**：

```c
void Update(AVLTree &T, int oldKey, int newKey) {
    T = Delete(T, oldKey);        // ① 按 §六 删除，回溯平衡（可能多次旋转）
    T = Insert(T, newKey);        // ② 按 §五 插入，回溯平衡（至多一次旋转）
}
```

原因：直接改写 `p->key = newKey` 会破坏 BST 值序约束（p 的祖先划分依据全部失效），除非 newKey 恰好仍落在 p 的合法区间内。删+增虽然做两遍 O(log n)，但每步都自动维持了 AVL 不变量。

> **带卫星数据的场景**（如 key 是学号、还挂着姓名等记录）：若只改卫星数据不改 key，直接 `p->name = ...` 即可，树结构不受影响，无需删增。

## 八、复杂度与高度界

| 操作 | 时间复杂度 | 指针语句量级 |
|:-----|:----------|:------------|
| 查找 | O(log n)，h ≤ 1.44·log₂(n+2) | 每层 1 条 `p = p->child` |
| 插入 | O(log n) | 下降 O(h) + 至多 1 次旋转（约 6 条）+ 回溯 O(h) 次 updateHeight |
| 删除 | O(log n) | 下降 O(h) + 最坏 O(h) 次旋转 |
| 改 | O(log n) | 删 + 增 |

高度界 1.44·log₂n 的来源（408 结论级）：设高度为 h 的 AVL 最少节点数 $N_h = N_{h-1} + N_{h-2} + 1$（斐波那契型），解得 h 与 n 的对数关系，系数 $\log_2 \varphi \approx 1.44$。

## 九、口诀与易错点清单

**总口诀**：

> 先保存、再接孙、后转正；
> 先孩子、后自己（更新高度）；
> 新根必须还给父（回写/回接）；
> 插入一转封顶，删除查到底。

**易错点**：

1. **旋转语句顺序**：先 `a->lchild = b->rchild` 后 `b->rchild = a`，颠倒则 BR 子树丢失（铁律一/二）。
2. **高度更新顺序**：先旧根后新根；颠倒则新根用了旧根的过期高度（铁律三）。
3. **忘记回接**：旋转函数返回新根后，调用处必须写回 `T = ...` 或 `P->child = ...`（§4.4）。
4. **LR/RL 第一步后忘记回写**：`a->lchild = LeftRotate(a->lchild)` 中的赋值不能丢（§4.3）。
5. **删除照搬插入的"转一次就停"**：删除必须逐层检查到根（§6.2）。
6. **双子删除时搬指针不搬值**：正确做法是 `T->key = s->key` 后转删 s（§6.3）。
7. **空树高度约定不统一**：本专题取空树高 0、单节点高 1；若教材取单节点高 0，所有 height 初值与 updateHeight 同步调整，bf 判断不变。
8. **误以为查找需要判平衡**：查找就是 BST 下降，平衡性只影响高度上界。
